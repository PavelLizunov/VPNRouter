# v2.32.0 — Android custom sing-box JSON ConfigMode (AND-CC)

## Триггер

Power users on Android can't use niche configs (Hysteria2 + obfs combos,
custom DNS chains, multiple outbound groups, mixed protocols). Pre-CC the
Android form only takes one of two inputs:

1. `vless://` / `hysteria2://` / `tuic://` / `ss://` share-link URI.
2. `https://…/sub` subscription URL.

Desktop has had a third `ConfigMode = "custom"` since v1.19.0 — user
provides a full pre-rendered sing-box JSON (any protocol combination)
and we inject only process-routing rules + Clash API for hot-reload.

This task ports that to Android.

## Симптом

User pastes custom JSON in a chat for help → answer is "sorry, not on
mobile yet, use desktop." Force users to a different platform for any
config that isn't a single-protocol share-link.

## Root cause

`AndroidConfigBuilder.BuildConfigJson` is hard-wired to a single
`VlessServerEntry` → `ConfigGenerator.Generate` pipeline. Storage layer
has no `configMode` enum (it derives mode implicitly from which key is
populated: `vless_uri` vs `subscription_url`).

## Fix strategy

### Storage — explicit ConfigMode + custom JSON keys

`AndroidStorage.cs`:
- New keys: `config_mode` (`"subscribe"` | `"manual"` | `"custom"`),
  `custom_config_json` (raw paste), `custom_config_name` (display label).
- `GetConfigMode()` migrates legacy installs: derive from which legacy
  key is populated (subscription wins, then manual). Default = "subscribe".
- `SetConfigMode(value)` is the new explicit flip.

Mirrors desktop's `AppSettings.App.ConfigMode` (YAML field).

### Config builder — new `BuildConfigJsonFromCustom`

`AndroidConfigBuilder.cs`:
- New static method `BuildConfigJsonFromCustom(string rawJson, string?
  logOutputPath)`.
- Internally:
  1. `CustomConfigInjector.Inject(rawJson, processNames=[],
     settings)` — reuses desktop's full inject pipeline including
     `StripUnsupportedFeatures` (1.13 schema migration: legacy DNS →
     type-based, deprecated outbound types, default_domain_resolver,
     etc.).
  2. `PatchLogPathForAndroid(injectedJson, logOutputPath)` — same
     post-processor as the URI path: `auto_route=false`,
     `stack=gvisor`, `MTU=1500`, log rewrite.
- `processNames=[]` because Android's per-app filter is at the
  `VpnService.Builder` layer (`addAllowed/Disallowed`), not via
  sing-box `process_name` (which requires kernel `/proc` reads
  unavailable on non-rooted Android).

### MainActivity — branch on `ConfigMode`

`MainActivity.StartTunnelService`:
- Read `AndroidStorage.GetConfigMode()` early.
- If `"custom"`: read `GetCustomConfigJson()`, call
  `BuildConfigJsonFromCustom`, dump config-json for offline inspection,
  jump to `DispatchTunnelStart(configJson)`.
- Else: existing flow (test-uri.txt override → `GetActiveServer`
  fallback → placeholder URI), `BuildConfigJson(entry)`, then
  `DispatchTunnelStart`.

`DispatchTunnelStart` is a new helper extracted from the bottom of
`StartTunnelService` so per-app filter forwarding +
`StartForegroundService` aren't duplicated.

### UI — 3-segment ConfigMode picker + paste section

`AndroidApp.axaml.cs` `BuildSimplePageView`:
- New `ccModeRow` (3-segment grid) at the top of the input section:
  - "Подписка" / "Subscription"
  - "Сервер" / "Server"
  - "Свой JSON" / "Custom JSON"
- `_ccUriSection` wraps existing URI inputs; `_ccCustomSection` is the
  new paste UI:
  - Multi-line TextBox (`AcceptsReturn=true`, `AcceptsTab=true`,
    `FontFamily=monospace`, `MinHeight=180`, `MaxHeight=360`).
  - Hint TextBlock (RU/EN).
  - Status TextBlock (initially hidden; populated by Validate / Save
    flows; colored DangerFg / WarningFg / SuccessFg).
  - 3 button row: Validate / Save / Clear.
- `IsVisible` flips: only one section visible at a time.

`OnCcModeXxxClicked` handlers persist mode to storage + repaint
visuals. `ApplyCcModeVisuals` mirrors `ApplyPickerModeVisuals` from the
per-app picker.

`OnCcValidateClicked` → `CustomConfigInjector.Validate(raw)`. On
failure shows error list; on success runs `ParseConfigInfo` to display
detected protocols + server.

`OnCcSaveCustomClicked` → persist + flip mode to "custom". If invalid,
saves anyway (so user doesn't lose paste) but shows a warning so they
know sing-box may reject it on Connect.

`OnCcClearCustomClicked` → wipe stored JSON + clear input. Mode stays
"custom" so user can paste a different config.

`UpdateConfigSummary` switch'd from binary (subscription vs manual) to
3-way per `GetConfigMode`. Adds "свой JSON" / "custom JSON" source
label.

### Localization — 17 new strings

`Localization.cs` (RU + EN):
- 3 mode segment labels: `CcModeSubscription`, `CcModeManual`,
  `CcModeCustom`
- 3 custom section labels: `CcCustomLabel`, `CcCustomHint`,
  `CcCustomWatermark`
- 3 button captions: `CcValidateButton`, `CcSaveButton`,
  `CcClearButton`
- 1 source label: `CcSourceCustom`
- 6 status messages (validation OK / failed / parse-error / save-empty
  / save-OK / save-invalid)

## Storage delta (desktop ↔ Android)

| Field | Desktop (YAML) | Android (SharedPreferences) |
|---|---|---|
| ConfigMode enum | `app.config_mode` | `config_mode` |
| Custom JSON path | `app.custom_config` (filesystem path) | `custom_config_json` (raw text) |
| Custom configs list | `app.custom_configs[]` | (single-entry only — no list UI yet) |

Android stores raw JSON instead of a path because:
1. SharedPreferences doesn't have a "scoped path" concept; we'd need
   to create a file under `Application.FilesDir` per JSON. Adds
   complexity for negligible gain (we already have `xcopy /R` parity
   pain on desktop).
2. Storage size: a typical sing-box config is 5-15 KB. SharedPreferences
   handles this trivially.
3. Multi-config UI is deferred — single custom config covers the v3.0
   alpha use-case.

## Per-app filter compatibility

`ConfigMode = "custom"` does NOT inject `process_name` rules into the
sing-box config (Android can't read /proc on non-rooted devices). Per-
app filtering still works via `VpnService.Builder.addAllowedApplication`
/ `addDisallowedApplication`, set in `VpnRouterService.openTun()` from
the EXTRA_PER_APP_MODE / EXTRA_PER_APP_PACKAGES intent extras. So:

- Custom JSON's outbounds + route rules are honored verbatim.
- Per-app filter still routes only allowed / excluded apps via the
  TUN; everything else uses the underlying network directly.
- Same as `ConfigMode = "manual"` / `"subscribe"` — Android's per-app
  filter is mode-orthogonal.

## Live phone test report

KYOCERA A101BM (Android 12 / API 31), build APK v3.0.0-android-alpha
with AND-CC patches.

### PASS
- **3-segment mode picker rendered**: Subscription / Server / Custom JSON
  visible at the top of the form card (test-screenshots/and-cc-1.png).
  Subscription active by default on fresh install.
- **Mode flip swaps sections**: tapping "Custom JSON" segment hides the
  URI input + Save/QR/Refresh buttons, shows the multi-line paste
  TextBox + Validate/Save/Clear buttons + monospace watermark
  `{ "log": {…}, "dns": {…}, "inbounds": […], "outbour…`
  (test-screenshots/and-cc-2.png). Config row at top updates to
  "custom JSON · all traffic" via the new `CcSourceCustom` label.
- **Validate flags invalid JSON**: typed `garbage_text_not_json` + tap
  Validate → red error banner shows
  `✗ Invalid: Invalid JSON: Unexpected character encountered while
  parsing value: g. Path '', line 0, position 0.`
  (test-screenshots/and-cc-5.png). `CustomConfigInjector.Validate`
  bubbles the JsonReaderException up, mapped via
  `CcValidationParseError` template.
- **Mode persistence across app restart**: force-stop + relaunch →
  Custom JSON segment still active, Config row still shows
  "custom JSON · all traffic" (test-screenshots/and-cc-10.png). Storage
  round-trips `config_mode = "custom"` correctly.

### DEFERRED (out of adb-driven test scope)
- **Paste a real Hy2 sing-box JSON + Validate success path + Connect +
  outbound IP check**. `adb shell input text` does not reliably
  encode JSON's `{`, `}`, `"`, `,`, `:` chars — they get partially
  literally inserted as `%7B%22...` etc. So the success-path Validate
  + Save + Connect + `curl ifconfig.io` ritual needs a manual paste
  on the device (or a future test-only debug override that loads JSON
  from `getExternalFilesDir()/test-config.json` like the existing
  `test-uri.txt` URI override). Validation logic is the same shared
  `CustomConfigInjector.Validate` desktop unit-tests cover (22+ cases
  in VPNRouter.Tests/UnitTest1.cs CustomConfigInjectorTests), so the
  parser side is solid. The connect path is the standard
  `BuildConfigJsonFromCustom` → `PatchLogPathForAndroid` →
  `DispatchTunnelStart` flow; same machinery the URI path uses post-
  ConfigGenerator, just sourced from raw JSON instead.

### Per-app filter compatibility
Untouched by AND-CC. `MainActivity.DispatchTunnelStart` reads
`AndroidStorage.GetPerAppMode()` + `GetPerAppPackages()` and forwards
to `VpnRouterService` regardless of which path produced `configJson`.
sing-box's per-config layer is not touched (`processNames=[]` passed
to `CustomConfigInjector.Inject`, so process_name rules aren't
injected; per-app filtering happens at VpnService.Builder level).
