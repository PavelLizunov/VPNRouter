# v2.32.0 — Android Zapret port (AND-ZAPRET)

**Status:** code shipped on `claude/pensive-joliot-1f80bf`, awaiting live tcpdump + UI verification on KYOCERA.

**Reference:** `plans/vpnrouter-android-handbook.md` §1.1 + §3.5 +
§7 Phase 8.4 (this doc fulfils that placeholder).

## Why

Desktop has a working DPI-bypass feature ("Zapret") that runs
[Flowseal/zapret-discord-youtube](https://github.com/Flowseal/zapret-discord-youtube)'s
`winws.exe` — a userspace WinDivert-based packet rewriter that
fragments TLS handshakes and spoofs SNI to bypass Russian ISP DPI.

That binary cannot run on Android:

* It depends on WinDivert (Windows-only kernel driver).
* Even if it could, non-rooted Android doesn't grant the
  `CAP_NET_ADMIN` / packet-capture capabilities the DPI-bypass
  technique requires.
* Bundling a 3.5 MB external binary plus its strategy library would
  bloat the APK well past the threshold most users tolerate
  (current APK is ~42 MB at debug).

Sing-box has shipped a native equivalent since 1.13.0:
[`tls_fragment` + `udp_fragment` outbound dialer options](https://sing-box.sagernet.org/configuration/shared/dial/).
These run inside the tunnel — no extra userspace process, no kernel
module, no APK size hit. The Android port leans on this entirely.

## Strategy matrix

Mirrors the desktop "Strategy" picker semantically — different
implementation, same UX intent.

| Mode | tls_fragment.size | tls_fragment.sleep | udp_fragment | When |
|---|---|---|---|---|
| `off` | _not injected_ | _not injected_ | _not injected_ | Default. No DPI bypass. |
| `standard` | `"10-100"` | `"10-50"` | _not injected_ | Default for users who turn the toggle on. Moderate fragmentation against most Russian ISP DPI layers. |
| `aggressive` | `"5-20"` | `"50-150"` | `true` | Smaller fragments + UDP fragmentation for QUIC. Use when "standard" doesn't bypass. Trades a small connection-setup latency for higher bypass success rate. |

Rationale for the chosen ranges:

* The "standard" `10-100 / 10-50` matches sing-box upstream
  documentation's recommended starting values.
* The "aggressive" `5-20 / 50-150` pushes harder: tinier fragments
  defeat fragment-reassembly DPI; the 150 ms upper sleep gives the
  middlebox time to drop the half-handshake before the second
  fragment lands.
* `udp_fragment` only in aggressive: TCP-flow protocols (vless+TCP,
  Reality) get nothing from UDP fragmentation, but QUIC carriers
  (Hysteria2, TUIC) do — so the toggle stays meaningful for the
  protocol mix the user is most likely running when they need
  aggressive mode.

## UI flow

1. Open Settings (kebab menu → Diagnostics → "Настройки").
2. Scroll to "Маршрутизация" / "Routing" section.
3. New "DPI bypass (Zapret)" card sits below the "Russian traffic
   via real IP" checkbox.
4. ComboBox: Off / Standard / Aggressive. Selection writes through
   to SharedPreferences immediately (no Apply button — matches the
   rest of the Settings overlay).
5. Picking Standard or Aggressive turns the Zapret chip in the
   sub-header on (green) when VPN is active, yellow-pulse during
   connect, off when disconnected. Picking Off turns the chip off
   regardless of VPN state.
6. Next "Подключить" rebuilds the sing-box config — `InjectDpiBypass`
   adds `tls_fragment` + (optionally) `udp_fragment` to all proxy
   outbounds before libbox starts.

## Zapret chip 3-state truth table

```
DPI bypass mode  ×  VPN state    →  Zapret chip
────────────────────────────────────────────────────
"off"            ×  any          →  Off (grey)
"standard"       ×  Off          →  Off (grey)
"standard"       ×  Connecting   →  Connecting (yellow pulse)
"standard"       ×  On           →  On (green)
"aggressive"     ×  Off          →  Off (grey)
"aggressive"     ×  Connecting   →  Connecting (yellow pulse)
"aggressive"     ×  On           →  On (green)
```

Rule: when DPI bypass is configured, the chip mirrors the VPN chip's
phase exactly — because the bypass only applies inside the active
tunnel. When DPI bypass is off, the chip is always off.

## Implementation notes

### Idempotency and overwrite policy

`InjectDpiBypass` overwrites any existing `tls_fragment` / `udp_fragment`
on a proxy outbound. Rationale: the most recent action wins. If a
user pastes a custom JSON that explicitly sets `tls_fragment.size =
"50-100"` and then picks "aggressive" in the picker, we want the
picker's `5-20` to take effect — the picker is the more recent
action. Counter-policy ("explicit JSON wins") would create a
confusing dead toggle. The escape hatch for power users who want
their custom values: keep the picker on "Off", which bypasses the
mutation entirely (no-op early return).

### Why outbound-level, not TLS-level

The model already has `tls.record_fragment` (bool) and `tls.fragment`
(bool) on `TlsConfig` — sing-box 1.12+ TLS-level fragmentation.
We deliberately don't use them on Android because:

* Boolean flags don't carry size/sleep tuning, so we couldn't
  expose a "standard vs aggressive" picker through them.
* They only target TLS; `tls_fragment` at outbound dialer level
  also covers Reality and other handshake-fragmenting protocols.
* `udp_fragment` is only available at the dialer level, so we
  needed to be there anyway for QUIC.

### Why JSON post-processing (not typed model fields)

Adding `TlsFragment`, `UdpFragment` structured fields to
`SingBoxOutbound` would require editing `VPNRouter.Core/Models/VPNConfig.cs`,
which would propagate to desktop config generation too. Desktop
already has its own DPI-bypass story (winws.exe) and we don't
want to duplicate the mechanism on the desktop output. Mutating
the JSON after generation, only on the Android path, keeps the
change isolated to the platform that needs it.

### Tests + fresh installs

`AndroidStorage.GetDpiBypassMode()` returns `"off"` when the key is
missing (first launch) and `"off"` when `Application.Context` is null
(headless tests). So the existing `ConfigGenerator` regression tests
that snapshot the JSON shape stay green — `InjectDpiBypass` exits
on the first line when mode is `off`.

## Live test procedure (for the next session)

```bash
# from Mac, with KYOCERA on adb
cd ~/Project/VPNRouter
git pull origin claude/pensive-joliot-1f80bf
# Build is already done in the worktree on the VM, but if rebuilding:
dotnet build VPNRouter.Android/VPNRouter.Android.csproj -c Debug \
  -p:AndroidSdkDirectory="$ANDROID_HOME" -p:JavaSdkDirectory="$JAVA_HOME"

# Push to phone
adb install -r VPNRouter.Android/bin/Debug/net8.0-android/com.ninitux.vpnrouter-Signed.apk

# Start app, paste a working VLESS URI, connect — verify chip flow.
# Then enable DPI bypass:
#   Kebab → Settings → Routing → "DPI bypass (Zapret)" → Standard
# Reconnect. Inspect generated config:
adb shell run-as com.ninitux.vpnrouter cat \
  files/.config/vpnrouter/config/current.json | grep -A3 tls_fragment

# Capture pcap during a TLS site load:
adb shell tcpdump -i any -n -s0 -w /sdcard/zapret.pcap port 443 \
  and host <vless-server-ip>
# Browse to a TLS site for ~10 s, then Ctrl-C tcpdump.
adb pull /sdcard/zapret.pcap
# Open in Wireshark; filter `tls.handshake.type == 1` (Client Hello).
# Expected: Client Hello split across multiple TCP segments,
# fragment sizes within 10–100 bytes (standard) or 5–20 (aggressive).
```

If the pcap shows a single un-fragmented Client Hello, the mutation
didn't reach the dialer — check `current.json` for the `tls_fragment`
block presence on the proxy outbound. If the block is there but the
pcap is not fragmented, sing-box may not have honoured it (libbox
version mismatch); check `singbox.log` for any `tls_fragment`-related
warning.

## Out of scope (not ported in this iteration)

| Desktop feature | Why deferred |
|---|---|
| Hosts file Discord patches | Android requires root for `/system/etc/hosts`. Could be added via a per-app DNS rule in sing-box config later. |
| Game filter (TCP-only / UDP-only DPI bypass) | Desktop's filter is winws-arg-based; on Android we'd express it via outbound-routing rules. Defer until a user reports a use case. |
| IPSet filter (limit DPI bypass to a curated IP list) | Same shape as game filter. Defer. |
| `Run diagnostics` button | Diagnostics on desktop runs winws --diag; Android equivalent would be a config-readback. Skipped for the first port. |
| Auto-update IPSet/Zapret binary | Not applicable — no external binary. |
| Hosts manager / Flowseal hosts | Same Hosts-file blocker. |

## Roll-back plan

If Standard mode breaks connections on a release build, ship
`-r(N+1)` with the picker hidden behind a feature flag in
AndroidStorage and the post-processor wrapped in:

```csharp
return InjectDpiBypass(patched, AndroidStorage.GetDpiBypassMode());
// →
var mode = AndroidStorage.GetFeatureFlag("dpi_bypass") ?
    AndroidStorage.GetDpiBypassMode() : "off";
return InjectDpiBypass(patched, mode);
```

Worst-case full rollback: revert this commit. The `tls_fragment` /
`udp_fragment` mutation is the only behaviour change; pre-AND-ZAPRET
JSON shape is preserved on `mode == "off"`.
