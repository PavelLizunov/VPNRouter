> **TL;DR:** Module C24 (`FreeConfigs` subsystem and `ServerUriParser`) provides the end-to-end pipeline for discovering, fetching, parsing, GeoIP-enriching, multi-stage testing (TCP, TLS, and deep isolated sing-box SOCKS sandbox verification), caching, and freshness-tracking of free community proxy endpoints, alongside the central multi-protocol share-link URI parsing gateway supporting 7 distinct VPN protocols. # Exhaustive Code Inventory & Audit: Core FreeConfigs Subsystem & ServerUriParser (Module C24 / Batch B027_C24)

## 1. SUMMARY & PURPOSE

### Subsystem Roles & Responsibilities

1. **`ServerUriParser`**:
   - Universal share-link URI parsing engine and gateway for inbound proxy definitions.
   - Detects and dispatches schemes across 7 core protocols: VLESS (`vless://`), Hysteria2 (`hysteria2://`, `hy2://`), TUIC v5 (`tuic://`), Shadowsocks (`ss://` with SIP002 base64/base64url and modern RFC 8089 URI forms), NaiveProxy (`naive://`, `naive+https://`, `naive+quic://`), DNS-Tunnel / Slipstream (`dns-tunnel://<base64url-json>`), and AmneziaWG (`awg://`, `awg3://`, `amneziawg://`, `amneziawg3://`) as well as native WireGuard/AmneziaWG INI `.conf` formats.
   - Enforces platform runtime gates (`NaiveRuntimeAvailable` requires Windows/Linux Cronet; `SlipstreamRuntimeAvailable` requires the native picoquic Rust sidecar; `SingBoxFeatures.AwgAvailable` requires `with_awg` build).
   - Integrates `PlaceholderDefense.Inspect` to reject known smoke-test dummy credentials and localhost IPs before configurations can enter settings or trigger runtime crashes.
   - Preserves literal `+` characters in query string parsing for WireGuard standard base64 keys (`private_key`, `preshared_key`).

2. **`FreeConfigAggregator` & Pipeline Ingestion**:
   - Orchestrates the full Free Configs lifecycle: fetching remote pools or per-source raw lines, parsing entries via `ServerUriParser`, deduplicating by cryptographic hash ID, enriching with GeoIP metadata, and conducting shallow and deep verification.
   - Coordinates multi-tier UI progress notifications (`OnStageChanged`, `OnTestProgress`).
   - Implements historical preservation logic (`PreservePreviousValidation`) so that previously verified working configs are not lost when upstream pools rotate every 6 hours.

3. **Pool & Source Crawling (`FreeConfigPoolFetcher` & `FreeConfigFetcher`)**:
   - `FreeConfigPoolFetcher`: Downloads pre-aggregated `pool.json.gz` (primary ~3.9 MB compressed asset) or fallback `pool.json` (~27 MB) from GitHub Releases using HTTP ETag conditional GETs (`304 Not Modified`). Implements streaming bounded decompression (`DecompressBoundedAsync`) with hard caps (32 MB compressed, 128 MB expanded) to neutralize decompression bombs.
   - `FreeConfigFetcher`: Fallback crawler that fetches 17 built-in public sources (and user-configured custom URLs) with a 4 MB per-source payload limit, base64 payload sniffing/decoding, and regex-free line enumeration.

4. **Multi-Stage Verification (`FreeConfigTester` & `FreeConfigDeepVerifier`)**:
   - `FreeConfigTester`: High-concurrency (80 workers) shallow probing using `TcpTlsProbe` (1.5s TCP timeout, 3s TLS timeout), enforcing SNI/SAN certificate validation and an implausible RTT threshold ($\ge 5\text{ ms}$) to filter out local honeypots and TUN loops.
   - `FreeConfigDeepVerifier`: Spawns isolated ephemeral `sing-box` processes with custom SOCKS loopback inbounds (no TUN interception) to execute real HTTP GET requests to `http://cp.cloudflare.com/generate_204` through the proxy outbound. Optionally tests 5 MB download throughput (`MeasureBandwidthMbps`).

5. **Metadata Enrichment & Country Resolution (`FreeConfigGeoIp` & `IFreeConfigCountryLookup`)**:
   - Resolves hostnames to IPv4 addresses using host deduplication (reducing DNS traffic by ~90%) with 30 concurrent workers and a 3s per-lookup timeout.
   - Enriches entries with 2-letter ISO country codes via injected offline readers (`IFreeConfigCountryLookup`, e.g. MaxMind MMDB) or rate-limited batch queries to `ip-api.com` (100 IPs per batch, 1.5s delay to stay within free-tier limits).

6. **Persistence, Retention & Freshness (`FreeConfigCache`, `FreeConfigKeepPolicy`, `FreeConfigFreshness`)**:
   - `FreeConfigCache`: Atomic schema-versioned persistence (`free_configs.json`) utilizing `SemaphoreSlim(1, 1)` file locks, temporary file writes (`.tmp.{guid}`) with atomic `File.Move(..., overwrite: true)`, and corrupt file quarantine via `CacheRecovery`. Automatically heals historical sub-threshold latency values (<5 ms).
   - `FreeConfigKeepPolicy`: Enforces session retention policies: keeps only `Verified` entries in live cache across searches, and retains `Verified` entries in the persistent saved list for up to 30 days.
   - `FreeConfigFreshness`: Pure functional tier classification (`Fresh`, `Ageing`, `Stale`, `Failed`), visual opacity mapping, sort key generation (failed entries sink to the bottom), snapshot capture (`RecheckSnapshot`), and cancellation-safe state merging.

## 4. CONCURRENCY, LOCKS & LIFECYCLE

### 4.1. Synchronization Primitives

| Component | Synchronization Primitive | Scope / Target | Invariant Enforced |
|---|---|---|---|
| `FreeConfigCache` | `SemaphoreSlim _ioLock = new(1, 1)` | File access (`free_configs.json`) | Enforces strictly serial read/write access across both sync (`Load`/`Save`) and async (`LoadAsync`/`SaveAsync`) callers. |
| `FreeConfigGeoIp` | `SemaphoreSlim _rateLimit = new(1, 1)` | Egress calls to `ip-api.com` | Enforces a minimum delay of 1500 ms between outbound HTTP batches to stay under the 45 req/min threshold. |
| `FreeConfigGeoIp` | `SemaphoreSlim sem = new(30)` | Hostname DNS lookups | Restricts concurrent OS DNS resolution queries to 30 workers, preventing thread pool socket exhaustion. |
| `FreeConfigTester` | `SemaphoreSlim sem = new(MaxConcurrency = 80)` | TCP/TLS socket probing | Caps concurrent socket connections to 80, keeping ephemeral port usage safely under Windows/Linux exhaustion limits (~9600 ports in TIME_WAIT). |
| `FreeConfigDeepVerifier` | `SemaphoreSlim sem = new(MaxConcurrency = 5)` | Ephemeral `sing-box` execution | Restricts simultaneous sing-box subprocesses to 5 to prevent CPU/memory thrashing during process startup and TLS negotiation. |

### 4.2. Asynchronous Flow & Cancellation Handling

- **Cooperative Cancellation**: `CancellationToken` is passed throughout all pipelines (`FetchPoolAsync`, `TestAllAsync`, `VerifyBatchAsync`, `EnrichAsync`).
- **Cancellation Propagation vs. Suppression**:
  - `FreeConfigFetcher.FetchAsync`: Rethrows `OperationCanceledException` when `ct.IsCancellationRequested` is true. Transport timeouts from inner HTTP clients are logged as warnings and return empty lists.
  - `FreeConfigPoolFetcher.TryFetchAsync`: Explicitly rethrows `OperationCanceledException` to allow cancellation of long pool downloads.
  - `FreeConfigGeoIp.QueryBatchAsync`: Specifically catches `OperationCanceledException when (ct.IsCancellationRequested)` and rethrows; a secondary catch handles the internal 15s HTTP timeout without canceling the outer loop.
  - `FreeConfigDeepVerifier.VerifyOneAsync`: Catches `OperationCanceledException`, logs timeout diagnostics, records `LastError = "deep verify timeout"`, and ensures process cleanup in `finally`.
  - `FreeConfigFreshness.RestorePriorState`: Provides a dedicated rollback helper invoked by command handlers when cancellation occurs, ensuring entries are not left in half-mutated error states.

### 4.3. Process Lifecycle & Subprocess Teardown

- **Ephemeral Subprocess Management (`FreeConfigDeepVerifier`)**:
  - For each verified entry, a new `Process` instance running `sing-box run -c <tmpConfigPath>` is spawned.
  - **Deadlock & Crash Callback Guard**: `process.EnableRaisingEvents = false` is explicitly set to prevent unintended process exit callbacks from executing on the thread pool during controlled shutdowns.
  - **Teardown Guarantee**: The `finally` block in `VerifyOneAsync` guarantees cleanup:
    ```csharp
    if (process != null && !process.HasExited)
    {
        process.Kill(entireProcessTree: true);
        process.WaitForExit(2000);
    }
    process?.Dispose();
    if (tmpConfigPath != null) File.Delete(tmpConfigPath);
    ```
  - **Diagnostic Stream Redirection**: `RedirectStandardOutput` and `RedirectStandardError` are captured asynchronously with line-buffered sanitization (`DeepVerifyProbe.AppendSanitizedLine`) bounded by a maximum character budget to prevent memory leaks from runaway log emitters.

## 5. SECURITY & PRIVILEGE BOUNDARIES

### 5.1. Privilege Boundaries & Execution Context

- Module C24 operates entirely within standard user privilege space. It does not invoke UAC elevation, `sudo`, or raw network interface drivers.
- `FreeConfigDeepVerifier` explicitly utilizes SOCKS inbounds on loopback ports (`127.0.0.1:<random>`), bypassing TUN interface configuration and packet-capturing drivers, which permits non-elevated verification.

### 5.2. File System Paths & Permissions

| Path | Purpose | Permissions / Hardening |
|---|---|---|
| `%ProgramData%\VPNRouter\cache\free_configs.json` | Persistent free configuration cache | Standard application cache permissions. Saved atomically via `.tmp.{guid}` and `File.Move`. |
| `%ProgramData%\VPNRouter\cache\pool.json[.gz.etag]` | Downloaded pool cache and ETag files | Standard application cache permissions. Atomic replace. |
| `Path.GetTempPath()/sb-verify-{guid}.json` | Temporary sing-box verification config | Created in user `%TEMP%`. Contains proxy credentials. |

### 5.3. Network Egress & Untrusted Input Sanitization

- **Decompression Bomb Protection**: `FreeConfigPoolFetcher.DecompressBoundedAsync` protects against hostile or corrupted gzip payloads by enforcing a 32 MB compressed cap and aborting decompression if expanded bytes exceed 128 MB (`MaxExpandedBytes`).
- **Response Size Capping**: `FreeConfigFetcher` limits raw source downloads to 4 MB (`MaxSourceBytes`), preventing memory exhaustion from oversized public feeds.
- **Redaction of Sensitive URI Details**:
  - `ServerUriParser.Parse` applies `CanaryPolicy.RedactUrl` before printing malformed URIs in exception messages.
  - `FreeConfigFetcher` routes error messages through `DiagnosticsRedactor.RedactLogText`.
- **Placeholder Attack Defense (`PlaceholderDefense.Inspect`)**:
  - `ServerUriParser` actively screens parsed `VlessServerEntry` objects for known test reality public keys, short IDs, and loopback/placeholder server IPs (e.g. `127.0.0.1`, dummy RFC 5737 IPs), throwing `PlaceholderConfigException` before unverified test credentials can enter the application state.
- **Literal `+` Preservation in Query Strings**: Standard `HttpUtility.ParseQueryString` erroneously replaces `+` with spaces (` `). In `ServerUriParser.ParseAmneziaWg`, `ParseQueryPreservingPlus` decodes only percent-encoded sequences (`%XX`), keeping standard base64 WireGuard private keys intact.

## 6. SUSPICIOUS PATTERNS / DEFECT CANDIDATES

### 6.1. Defect Candidate 1: `FreeConfigDeepVerifier` treats `dns-tunnel` as standard VLESS

- **Location**: `VPNRouter.Core/Services/FreeConfigs/FreeConfigDeepVerifier.cs:356–364`
- **Issue**: In `BuildSingleOutboundConfig`:
  ```csharp
  outbound = protocol switch
  {
      "hysteria2" or "hy2"  => VlessDeepVerifier.BuildHysteria2Outbound(s),
      "tuic"                => VlessDeepVerifier.BuildTuicOutbound(s),
      "shadowsocks" or "ss" => VlessDeepVerifier.BuildShadowsocksOutbound(s),
      "naive"               => VlessDeepVerifier.BuildNaiveOutbound(s),
      _                     => VlessDeepVerifier.BuildVlessOutbound(s),
  };
  ```
  If a configuration with `Protocol == "dns-tunnel"` is verified, the switch falls into the wildcard branch `_ => VlessDeepVerifier.BuildVlessOutbound(s)`.
- **Impact**: `BuildVlessOutbound` expects VLESS-specific fields and attempts to construct a direct VLESS outbound to the DNS tunnel's domain. In sing-box, this outbound will fail to connect or crash, because `dns-tunnel` requires the external `slipstream-client` sidecar process rather than a direct VLESS TCP/TLS connection.
- **Remediation**: Explicitly intercept `protocol == "dns-tunnel"` and either skip deep verification with a clear diagnostic or integrate with the slipstream sidecar.

### 6.2. Defect Candidate 2: Cleartext HTTP Egress for GeoIP Queries

- **Location**: `VPNRouter.Core/Services/FreeConfigs/FreeConfigGeoIp.cs:168–169`
- **Issue**: `QueryBatchAsync` sends outbound batch queries over plaintext HTTP:
  ```csharp
  using var req = new HttpRequestMessage(HttpMethod.Post, "http://ip-api.com/batch?fields=query,countryCode")
  ```
- **Impact**: In adversarial or censored environments (e.g. Russia, China, Iran), local network operators and ISPs can observe in plaintext the exact batch of IP addresses being tested as censorship-circumvention proxies. An ISP can actively log or block these endpoints.
- **Remediation**: Switch to `https://` if supported, or rely primarily on local offline GeoIP databases (`IFreeConfigCountryLookup`).

### 6.3. Defect Candidate 3: Hardcoded Direct Google DoH Detour in Ephemeral sing-box Configs

- **Location**: `VPNRouter.Core/Services/FreeConfigs/FreeConfigDeepVerifier.cs:381–386`
- **Issue**: The generated DNS configuration in `BuildSingleOutboundConfig` configures:
  ```json
  "servers": [
    { "type": "https", "tag": "dns-google", "server": "8.8.8.8", "path": "/dns-query", "detour": "dns-direct-out" }
  ]
  ```
- **Impact**: In environments where direct access to Google DNS (`8.8.8.8:443` or `8.8.8.8:53`) is blocked by state censors, sing-box cannot resolve server domains during deep verification. Any VLESS or proxy entry specified as a domain hostname (rather than a raw IP) will fail DNS resolution and be falsely marked as `TlsFailed` or `sing-box didn't bind`, generating widespread false negatives.
- **Remediation**: Use the system resolver or tunnel the DNS resolution through the proxy outbound itself, or ensure IP addresses are resolved prior to deep verification.

### 6.4. Defect Candidate 4: Heap Allocation Burst in `TestAllAsync` and `EnrichAsync`

- **Location**: `VPNRouter.Core/Services/FreeConfigs/FreeConfigTester.cs:60–73` & `FreeConfigGeoIp.cs:68–93`
- **Issue**:
  ```csharp
  var tasks = configs.Select(async cfg => {
      await sem.WaitAsync(ct);
      try { await TestOneAsync(cfg, ct); }
      finally { sem.Release(); ... }
  });
  await Task.WhenAll(tasks);
  ```
- **Impact**: When `configs` contains 25,000 entries (the size of a typical fetched pool), calling `configs.Select(...)` and `Task.WhenAll(tasks)` allocates 25,000 async state machine instances and task promises on the managed heap simultaneously before the `SemaphoreSlim(80)` can throttle them. This causes GC pressure and memory spikes (~12–15 MB of task overhead).
- **Remediation**: Use `Parallel.ForEachAsync` with `MaxDegreeOfParallelism` to bound task instantiation.

### 6.5. Defect Candidate 5: Unstripped Inline Comments in `ServerUriParser.ParseWireGuardConf`

- **Location**: `VPNRouter.Core/Services/ServerUriParser.cs:623–633`
- **Issue**: `ParseWireGuardConf` splits lines on `=` and trims whitespace, but does not strip trailing inline comments:
  ```csharp
  var eq = line.IndexOf('=');
  var key = line.Substring(0, eq).Trim();
  var val = line.Substring(eq + 1).Trim();
  ```
- **Impact**: If a user pastes a WireGuard configuration containing inline comments (e.g. `PrivateKey = aaaa... # client key` or `Endpoint = 1.2.3.4:51820 ; primary`), the comment string is retained inside `PrivateKey` or `Endpoint`, resulting in base64 decode failures or socket connection errors.
- **Remediation**: Strip inline comments beginning with `#` or `;` when parsing values.

### 6.6. Defect Candidate 6: Temporary File Exposure on Multi-User Unix Systems

- **Location**: `VPNRouter.Core/Services/FreeConfigs/FreeConfigDeepVerifier.cs:156`
- **Issue**: `tmpConfigPath = Path.Combine(Path.GetTempPath(), $"sb-verify-{Guid.NewGuid():N}.json");` writes full proxy credentials (UUIDs, keys, passwords) to `/tmp` using standard default permissions.
- **Impact**: On multi-user Linux/macOS systems, files created in `/tmp` without explicit `0600` permissions may be readable by other local users before deletion.
- **Remediation**: Use secure file creation permissions (`FileMode.CreateNew`, Unix file mode `0600`) or place temporary files in the application's secure data directory.
