> **TL;DR:** Module C04 (`AppPaths.cs` and `AppVersion.cs`) defines the fundamental filesystem hierarchy, security boundaries, and version provenance across Windows, macOS, Linux, and Android. The audit revealed key findings: static `_dataDir` initialization is thread-unsafe under concurrent cold reads (`??=`) and mutates globally across tests without synchronization; Windows ACL hardening functions (`SEC-01`, `SEC-02`) swallow all exceptions silently and risk `NullReferenceException` on `WindowsIdentity.GetCurrent().User!`; and path resolution relies on `%ProgramData%` environment expansion rather than `SpecialFolder.CommonApplicationData`.

# Exhaustive Code Inventory & Audit: Core Paths & Version (Module C04 / Batch B018_C04)

## 1. SUMMARY & PURPOSE

Module `C04` comprises the foundational path resolution and version identity components in `VPNRouter.Core`:
- **`VPNRouter.Core/AppPaths.cs` (328 LOC)**: Centralized cross-platform path resolution, directory scaffolding, file permission hardening, and security boundary enforcement.
- **`VPNRouter.Core/AppVersion.cs` (32 LOC)**: Single immutable source of truth for the application version string across all runtime targets, enforcing SemVer rolling-rN policy and PE metadata `#US` heap alignment.

### Component Roles & Responsibilities

1. **`AppPaths.cs`**:
   - **Cross-Platform Directory Resolution**: Resolves canonical data directories based on operating system idioms:
     - Windows: `%ProgramData%\VPNRouter\` (system-wide application data).
     - macOS: `~/Library/Application Support/VPNRouter/` (user-scoped application support).
     - Linux: `$XDG_CONFIG_HOME/vpnrouter` or fallback `~/.config/vpnrouter/`.
     - Android: Configurable at runtime via `OverrideDataDir(string path)` (redirecting to `Context.getFilesDir()`).
   - **Subsystem Path Mapping**: Standardizes locations for configs (`config/`, `current.json`, `config.yaml`), logs (`logs/`, `singbox.log`, `slipstream.log`), binaries (`bin/`, `sing-box`, `slipstream-client`), cache (`cache/`), routing profiles (`profiles/`), geo-routing rules (`geo/`, `geoip-ru.srs`, `geosite-ru.srs`), runtime state (`state.json`), and DNS-tunnel sidecar assets (`slipstream/`, `active-leaf.pem`, `version.txt`).
   - **Privilege & Access Control Hardening**:
     - **POSIX / Unix (`0700` / `0600`)**: Creates and verifies owner-only directories (`PrivateUnixDirectoryMode = 0700`) and secret-bearing files (`PrivateUnixFileMode = 0600`).
     - **Symlink & Reparse Point Defense**: Enforces strict rejection of symbolic links and reparse points during directory creation and file writes to prevent symlink traversal and file-overwrite attacks.
     - **Umask Mitigation**: Implements `CreatePrivateFile` utilizing `FileStreamOptions.UnixCreateMode` and handle-based permissions verification to guarantee files are never exposed through permissive process umasks.
     - **Windows ACL Lockdown (SEC-01 & SEC-02)**: Configures NTFS Access Control Lists (ACLs) using locale-independent well-known SIDs (`LocalSystem`, `BuiltinAdministrators`, `BuiltinUsers`) to prevent unprivileged users from replacing executable binaries in `bin\` (SEC-01) or reading confidential configuration and credentials in `DataDir` (SEC-02).

2. **`AppVersion.cs`**:
   - **Single Source of Truth**: Provides the static immutable version string (`AppVersion.Version`) utilized by Windows GUI (`AppBranding`), Mac GUI (`MainWindowViewModel`), CLI (`VPNRouter.CLI.Program`), Background Services, crash reporters, telemetry headers, diagnostic bundles, and auto-updaters.
   - **Rolling-rN Release Contract**: Encodes the release version along with the prerelease/revision tag (e.g., `2.50.0-r9`). This is critical for `UpdateChecker` to preserve SemVer monotonicity and detect updates across rolling release revisions.
   - **PE Metadata Alignment Guarantee**: Declared as `public static readonly string` rather than `const string`. This ensures the literal is emitted into the CLR `#US` (UserString) metadata heap via `ldstr` at a guaranteed 2-byte alignment, preventing CI release verification tools (`verify-release-integrity.yml`) from missing the version string due to odd-byte alignment in the metadata `Constant` table.

## 4. CONCURRENCY, LOCKS & LIFECYCLE

### 4.1 Concurrency & Thread-Safety Assessment

1. **Non-Atomic Lazy Initialization (`DataDir`)**:
   - `DataDir => _dataDir ??= ResolveDataDir();`
   - In C#, the compound assignment operator `??=` on a static field is not thread-safe and executes without memory barriers or synchronization.
   - If multiple threads access `AppPaths.DataDir` concurrently during process startup before `_dataDir` has been populated, `ResolveDataDir()` may be evaluated concurrently across multiple threads. While `ResolveDataDir()` is idempotent and produces the same string, torn references or redundant environment expansions can occur.
2. **Unsynchronized Mutation (`OverrideDataDir`)**:
   - `OverrideDataDir(string path)` assigns `_dataDir = path` without locking, memory barriers, or volatile semantics.
   - If one thread calls `OverrideDataDir` while other threads are reading `DataDir` or any of its 18 derived static path properties (`ConfigDir`, `CurrentConfigPath`, etc.), readers may observe stale or inconsistent paths.
   - The XML doc explicitly notes: *"Subsequent calls update the value (this is a static field, so a stale reader could see the previous path; callers must order initialisation accordingly)."*
3. **Cross-Test Pollution & State Leakage in Test Suite**:
   - In `VPNRouter.Tests`, over 25 test classes call `AppPaths.OverrideDataDir(tempDir)` to redirect filesystem operations to an isolated temporary directory, and restore the previous path in a `finally` block or `Dispose()`.
   - Because xUnit executes test classes in parallel by default, any test that runs concurrently with an `OverrideDataDir` modification can suffer race conditions where `AppPaths.DataDir` unexpectedly switches between production paths and arbitrary temporary directories, leading to intermittent test failures.
4. **File Sharing & Lock Contention (`CreatePrivateFile`)**:
   - `CreatePrivateFile` configures `Share = FileShare.None`.
   - Concurrent calls attempting to open or write the same file (e.g. concurrent updates to `current.json` or `config.yaml`) will throw an `IOException` due to the exclusive OS-level file lock, which protects file integrity from partial or overlapping writes.

### 4.2 Lifecycle & Teardown

- `AppPaths` and `AppVersion` are static classes with application-domain lifetimes.
- No teardown or reset logic is provided by design. State mutation is restricted to setting `_dataDir` via `OverrideDataDir`.

## 5. SECURITY & PRIVILEGE BOUNDARIES

### 5.1 Operating System Privilege & Execution Contexts

In VPNRouter architecture, components operate across distinct privilege levels:
- **Windows**: The GUI (`VPNRouter.App`) runs as an unelevated standard user, whereas the background service (`VPNRouter.Service`), TUN driver operations, and firewall modifications require elevated Administrator or `LocalSystem` privileges.
- **Linux/macOS**: Standard GUI/CLI runs as the logged-in user, but spawns privileged processes via `pkexec`, `sudo`, or POSIX capabilities (`CAP_NET_ADMIN`).

### 5.2 Windows Privilege Escalation Defense: SEC-01 (`RestrictWindowsBinDirAcl`)

- **Vulnerability Context**: On Windows, `%ProgramData%` inherits ACLs that permit members of `BUILTIN\Users` to write files and create directories under standard application subfolders. If elevated processes (e.g. Windows Service running as `LocalSystem`) execute binaries from `%ProgramData%\VPNRouter\bin\sing-box.exe`, an unprivileged attacker could replace the executable with a malicious binary, achieving full local privilege escalation (LPE).
- **Defense Mechanism**:
  - `RestrictWindowsBinDirAcl` calls `security.SetAccessRuleProtection(isProtected: true, preserveInheritance: false)`.
  - Drops all inherited rules from `%ProgramData%`.
  - Grants `FullControl` strictly to `LocalSystem` (SID: `S-1-5-18`) and `BuiltinAdministrators` (SID: `S-1-5-32-544`).
  - Restricts `BuiltinUsers` (SID: `S-1-5-32-545`) strictly to `FileSystemRights.ReadAndExecute`. Non-admin users cannot overwrite, create, append, or delete binaries in `BinDir`.

### 5.3 Windows Credential Protection: SEC-02 (`TryRestrictWindowsDataDirAcl`)

- **Vulnerability Context**: Standard `%ProgramData%` permissions permit any local user to read directory contents. VPNRouter stores sensitive assets in `DataDir`, including VLESS private keys, subscription credentials, Clash API bearer tokens, and traffic logs.
- **Defense Mechanism**:
  - `TryRestrictWindowsDataDirAcl` detects if `BUILTIN\Users` possesses Read permissions via `HasBuiltinUsersReadAccess`.
  - Explicitly breaks inheritance while preserving existing rules (`preserveInheritance: true`).
  - Grants `FullControl` to `LocalSystem` and `BuiltinAdministrators`.
  - Grants `Modify` to the invoking user (`WindowsIdentity.GetCurrent().User!`).
  - Calls `security.RemoveAccessRuleAll` for `BuiltinUsersSid`, eliminating all read access for other unprivileged local users.
  - Utilizes `WellKnownSidType` enum to construct SIDs rather than string names, ensuring immunity to OS language/locale variations (e.g. German "Benutzer", French "Utilisateurs", Russian "Пользователи").

### 5.4 Unix File & Symlink Traversal Hardening

- **Owner-Only Permissions (`0700` and `0600`)**:
  - Directories: `PrivateUnixDirectoryMode = UnixFileMode.UserRead | UnixFileMode.UserWrite | UnixFileMode.UserExecute` (`0700`).
  - Files: `PrivateUnixFileMode = UnixFileMode.UserRead | UnixFileMode.UserWrite` (`0600`).
  - Directory and file creation explicitly verify permissions using `File.GetUnixFileMode(path)` and throw `IOException` if permissions do not match the expected mode.
- **Symlink & Reparse Point Rejection**:
  - In `EnsurePrivateUnixDirectory` and `EnsurePrivateUnixFile`:
    ```csharp
    if (info.LinkTarget is not null)
        throw new IOException($"Refusing symbolic-link ...: {path}");
    if ((File.GetAttributes(path) & FileAttributes.ReparsePoint) != 0)
        throw new IOException($"Refusing symbolic-link ...: {path}");
    ```
  - This prevents pre-creation attacks where an unprivileged attacker plants a symlink in `~/.config/vpnrouter/` pointing to a sensitive file (e.g., `/etc/shadow` or user SSH keys) before VPNRouter starts, tricking an elevated process into overwriting or changing permissions on the target.
- **Umask Bypass Mitigation (`CreatePrivateFile`)**:
  - When creating files in standard .NET, permissions are masked by the process `umask` (e.g., `0022` results in `0644`).
  - `CreatePrivateFile` sets `FileStreamOptions.UnixCreateMode = PrivateUnixFileMode` (`0600`), and immediately applies and validates `File.SetUnixFileMode(stream.SafeFileHandle, PrivateUnixFileMode)` directly on the kernel file descriptor before returning the stream.
