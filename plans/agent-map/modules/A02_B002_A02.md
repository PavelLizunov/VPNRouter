> **TL;DR:** Module A02 (Batch B002_A02) encompasses the UI ViewModels for Application Routing (`AppGroupViewModel`, `AppItemViewModel`), Subscription Status Resolution (`AutoSelectStatus`), Custom Configuration Management (`CustomConfigViewModel`), Network Custom Routing Rules (`CustomRuleViewModel`), and Free Configuration Aggregation/Verification (`FreeConfigItemViewModel`, `FreeConfigsPageViewModel`). The audit identified an unhandled `ArgumentOutOfRangeException` risk in `FlagFor` when processing non-ASCII country codes, redundant double-loops in `SelectAll`/`ClearAll` batch updates, a blocking synchronous `File.ReadAllText` inside `CustomConfigViewModel`'s constructor, background thread collection enumeration in `RecheckAllStaleAsync`, and ~350 lines of dead/unbound legacy code in `FreeConfigsPageViewModel` (including `DeepVerifyTopAsync` and `UserSources` management).

Module A02 provides the core reactive presentation models (ViewModels) for VPNRouter's desktop GUI (Avalonia 12.x on .NET 10). It bridges desktop user actions to underlying Core engine services, configuration models, and background execution pipelines.

## 3. DATA FLOWS & STATE MACHINES

### 3.1. Application Routing Bridge Flow (`AppItemViewModel` & `AppGroupViewModel`)
```
[User Toggles Checkbox in UI]
             │
             ▼
AppItemViewModel.IsChecked.set
             │
      ┌──────┴───────────────────────────┐
      │ (Bridged Mode: Read/WriteMode)   │ (Fallback Mode)
      ▼                                  ▼
WriteMode(ProcessName, value)     _isCheckedFallback = value
      │
      ▼
MainWindowViewModel:
  Writes into active list
  (RoutingAppsInclude or Exclude)
  + Updates CustomCategory / Profile
      │
      ▼
AppItemViewModel.OnPropertyChanged(IsChecked)
```
- **Group Cascade**: When `AppGroupViewModel.IsChecked` changes, `OnIsCheckedChanged` triggers `BeginBatchUpdate?.Invoke()`, then loops over each `AppItemViewModel` setting `IsChecked = value`. Each item routes into its respective bridge, which updates `MainWindowViewModel`'s underlying collections.

### 3.2. Custom Rules Live Synchronization (`CustomRuleViewModel`)
```
[User Edits Field in UI] (Action / Type / Value / Enabled)
             │
             ▼
CommunityToolkit Setter -> OnPropertyChanged
             │
      ┌──────┴───────────────────────────┐
      │ Computed Property?               │ Real Model Property?
      ▼                                  ▼
   (Suppress)                   _onChanged?.Invoke(this)
                                         │
                                         ▼
                               MainWindowViewModel:
                                 OnCustomRuleRowChanged
                                         │
                                         ▼
                               SyncCustomRules() -> SaveSettings()
```

### 3.3. Free Configs Batched Overlapping Pipeline (`FreeConfigsPageViewModel.RefreshAsync`)
```
[RefreshAsync Triggered]
             │
             ▼
Stage 1: FetchPoolAsync(sources) -> pool (20k-30k raw entries)
             │
             ▼
RuFilter & Sort: Cached Verified first -> queue
             │
             ▼
Stage 2: Cross-Batch Overlapping Loop (BatchSize = 500)
  ┌────────────────────────────────────────────────────────┐
  │ For batch K:                                           │
  │   1. Acquire TCP+TLS results (prefetched or fresh)     │
  │   2. Kick off prefetched TCP+TLS for batch K+1         │
  │   3. Filter Ok/Verified subset                         │
  │   4. Spawn sing-box deep verify (global deepCap sem)   │
  │   5. Upon each Verified passing goal:                  │
  │        - Append to verifiedList                        │
  │        - UpsertSavedConfig(_savedConfigs)              │
  │        - Dispatcher: ApplyFiltersAndStats()            │
  │        - ProgressDone++                                │
  │   6. MaxBatchesInFlight=2 gate                         │
  └────────────────────────────────────────────────────────┘
             │
             ▼
Stage 3: Finalize & Persist
  - Drain in-flight deep verify waves
  - Persist _savedConfigs to free_configs_saved.json
  - Drop references (queue=null, pool=null)
  - ReclaimPostSearchMemory() (LOH CompactOnce + GC.Collect + Skia Purge)
```

## 4. CONCURRENCY, LOCKS & LIFECYCLE

### 4.1. Concurrency Primitives & Synchronization Mechanisms
1. **`SemaphoreSlim deepSem` in `RefreshAsync`**:
   - Initialized to `ComputeAdaptiveDeepCap()` (3 on 1-3 cores, 5 on 4-7 cores, 8 on 8+ cores).
   - Serves as the global gate limiting simultaneous `sing-box` child process spawns across all overlapping in-flight batches.
2. **`SemaphoreSlim sem` in `RecheckAllStaleAsync`**:
   - Fixed 5-permit semaphore throttling concurrent sing-box verifications during bulk rechecks.
3. **`lock (verifiedList)` in `RefreshAsync`**:
   - Protects multi-threaded mutations and reads of `verifiedList`:
     - `lock (verifiedList) found = verifiedList.Count;` (progress checks)
     - `lock (verifiedList) { if (verifiedList.Count >= target) return; verifiedList.Add(cfg); added = true; }` (target gate + append)
     - `lock (verifiedList) snapshot = new List<FreeConfigEntry>(verifiedList);` (snapshot for UI dispatch)
4. **`Interlocked` in `RecheckAllStaleAsync`**:
   - `Interlocked.Increment(ref verified)`, `Interlocked.Increment(ref failed)`, `Interlocked.Increment(ref done)` for thread-safe scalar telemetry across parallel tasks.
5. **`CancellationTokenSource _refreshCts`**:
   - Instantiated on operation start (`RefreshAsync`, `RecheckOneAsync`, `RecheckAllStaleAsync`, `RetestAsync`).
   - Propagated to child tasks; cancelled via `Cancel()` or `Dispose()`.

### 4.2. UI Thread Marshaling
- Long-running work runs on worker threads (`Task.Run` or async I/O).
- All mutations to bound observable collections (`DisplayedConfigs`, `DisplayedSavedConfigs`, `Countries`) and UI properties (`StatusText`, `ProgressDone`) are marshaled via `Dispatcher.UIThread.InvokeAsync` or `Dispatcher.UIThread.Post`.
- Status updates in `RunTcpTlsBatchAsync` are throttled to at most one update per 200 ms (`DateTime.UtcNow - lastStatusUpdate < 200`) to prevent UI dispatcher message starvation.

### 4.3. Lifecycle & Disposal
- `FreeConfigsPageViewModel.Dispose()`:
  - Idempotent disposal guarded by `_disposed`.
  - Unsubscribes event handlers from `_aggregator` (`OnStageChanged`, `OnTestProgress`).
  - Cancels and disposes active `_refreshCts`.
- `AppGroupViewModel`, `AppItemViewModel`, `CustomConfigViewModel`, `CustomRuleViewModel`, `FreeConfigItemViewModel`:
  - Do not hold unmanaged resources or long-lived static event subscriptions; rely on standard GC cleanup.

## 5. SECURITY & PRIVILEGE BOUNDARIES

### 5.1. Input Validation & Schema Enforcement
1. **User Free Source URL Sanitization (`AddUserSource`)**:
   - Enforces absolute URI validation: `Uri.TryCreate(url, UriKind.Absolute, out var uri)`.
   - Strictly restricts schemes to HTTP and HTTPS: `(uri.Scheme == Uri.UriSchemeHttp || uri.Scheme == Uri.UriSchemeHttps)`.
   - Rejects empty, whitespace-only, or duplicate URLs.
2. **Free Config Connect Gate (`ApplySelectedAsync`)**:
   - Strictly enforces that only configs with `Status == FreeConfigStatus.Verified` can be adopted:
     ```csharp
     if (sel.Entry.Status != FreeConfigStatus.Verified)
     {
         StatusText = Strings.FcConnectNeedsVerify;
         return;
     }
     ```
   - Prevents users or rogue UI events from directing system network traffic through unverified or dead endpoints.
3. **Process Execution Sandboxing (`OpenLogs`)**:
   - Uses `ProcessStartInfo` with `UseShellExecute = false` and adds paths via `ArgumentList.Add(logsDir)` instead of command-line string concatenation, preventing command injection vulnerabilities on Windows, macOS, and Linux.

### 5.2. File System Boundaries & Environment Expansion
- **`CustomConfigViewModel` Path Resolution**:
  - Uses `Environment.ExpandEnvironmentVariables(entry.Path)`.
  - Note: Path is expanded and read without checking against an allowed base directory (e.g. `AppPaths.ConfigDir`). While configs are loaded from `config.yaml` (which is stored in `%ProgramData%\VPNRouter` or `~/.config/vpnrouter`), reading arbitrary file paths defined in user settings is allowed.

## 6. SUSPICIOUS PATTERNS / DEFECT CANDIDATES

### 6.1. Defect Candidate 1: Unicode Exception Risk in `FreeConfigItemViewModel.FlagFor`
- **Location**: `VPNRouter.App/ViewModels/FreeConfigs/FreeConfigItemViewModel.cs` (lines 177–187)
- **Code**:
  ```csharp
  public static string FlagFor(string? cc)
  {
      if (string.IsNullOrEmpty(cc) || cc.Length != 2) return "🌐";

      var upper = cc.ToUpperInvariant();
      // Regional Indicator Symbol Letter A = U+1F1E6, 'A' = 0x41.
      var chars = new int[2];
      chars[0] = 0x1F1E6 + (upper[0] - 'A');
      chars[1] = 0x1F1E6 + (upper[1] - 'A');
      return char.ConvertFromUtf32(chars[0]) + char.ConvertFromUtf32(chars[1]);
  }
  ```
- **Severity**: Moderate / Crash Risk.
- **Mechanism**: The method assumes `upper[0]` and `upper[1]` are ASCII uppercase letters `'A'..'Z'`. If an upstream source, GeoIP lookup, or corrupt entry contains a 2-character code with non-letters (such as `"12"`, `"A!"`, or Cyrillic `"РУ"`):
  - `'1' (0x31) - 'A' (0x41) = -16`.
  - `0x1F1E6 - 16 = 0x1F1D6`.
  - In Cyrillic, `'Р' (U+0420) - 'A' (0x41) = 991`.
  - If the computed codepoint falls into the UTF-16 surrogate range `0xD800..0xDFFF` or is negative or exceeds `0x10FFFF`, `char.ConvertFromUtf32` throws `ArgumentOutOfRangeException`.
- **Fix**: Validate that both characters satisfy `char.IsAsciiLetterUpper(upper[0]) && char.IsAsciiLetterUpper(upper[1])` before calculating codepoints.

### 6.2. Defect Candidate 2: Redundant Double-Loop in `AppGroupViewModel.SelectAll()` and `ClearAll()`
- **Location**: `VPNRouter.App/ViewModels/AppGroupViewModel.cs` (lines 51–72)
- **Code**:
  ```csharp
  partial void OnIsCheckedChanged(bool value)
  {
      using var _ = BeginBatchUpdate?.Invoke();
      foreach (var app in Apps)
          app.IsChecked = value;
  }

  [RelayCommand]
  private void SelectAll()
  {
      IsChecked = true;
      using var _ = BeginBatchUpdate?.Invoke();
      foreach (var app in Apps) app.IsChecked = true;
  }
  ```
- **Severity**: Low / Performance Inefficiency.
- **Mechanism**: Setting `IsChecked = true` immediately invokes CommunityToolkit's partial method `OnIsCheckedChanged(true)`. That method opens a batch update and sets `app.IsChecked = true` on every child in `Apps`. Once that completes, `SelectAll()` proceeds to open a *second* batch update and executes the exact same foreach loop setting `app.IsChecked = true` a second time. The same redundant cascade occurs in `ClearAll()`.
- **Fix**: Remove the redundant loop from `SelectAll()` and `ClearAll()`, or have them set `IsChecked = true` directly without repeating the loop.

### 6.4. Defect Candidate 4: Unsynchronized Background Enumeration of `_savedConfigs` in `RecheckAllStaleAsync`
- **Location**: `VPNRouter.App/ViewModels/FreeConfigs/FreeConfigsPageViewModel.cs` (lines 1176–1184)
- **Code**:
  ```csharp
  await Task.WhenAll(tasks);

  SaveSavedConfigsToCache();
  await Dispatcher.UIThread.InvokeAsync(() =>
  {
      RebuildSavedDisplayList();
      NotifySavedTabBindings();

  });
  ```
- **Severity**: Moderate / Race Condition.
- **Mechanism**: In `RecheckAllStaleAsync`, `SaveSavedConfigsToCache()` is called on a worker thread after `Task.WhenAll`. Inside `SaveSavedConfigsToCache()`, `_savedConfigs.ToList()` enumerates `_savedConfigs`. However, `_savedConfigs` is normally owned and mutated on the UI thread (via `UpsertSavedConfig`, `RemoveFromSaved`, `ClearAllSaved`). Calling `_savedConfigs.ToList()` from a worker thread without a lock or dispatcher invocation introduces a collection modification race (`InvalidOperationException`).
