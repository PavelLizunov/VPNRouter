> **TL;DR:** The `VPNRouter.CLI` module (Module L01 / Batch B066_L01) is the headless command-line interface and automation harness for VPNRouter, built on Spectre.Console 0.49.1 with a custom DI activator (`SettingsAwareTypeRegistrar`), fine-grained process-ownership guards (`StateFile` and `StopCommand`), and comprehensive lifecycle orchestration (`StartCommand`, `StatusCommand`, `DoctorCommand`, `ServiceCommand`, `ProfilesCommand`, and `TestUpdateCommand`). Key findings include hardcoded `%ProgramData%` paths causing cross-platform and override-data-dir drift against `AppPaths.StatePath`, priority collision/inversion in `ProfileSourceFactory`, unescaped Spectre markup in exception handlers and process names, and an extensive test gap where command execution paths are only audited via AST source guards rather than executable tests.

# Exhaustive Code Inventory & Audit: CLI Commands & Program Entrypoint (Module L01 / Batch B066_L01)

## 1. SUMMARY & PURPOSE

The `VPNRouter.CLI` module provides the command-line interface, automated service installer, and diagnostic tooling for VPNRouter. It serves as an alternative to the Avalonia desktop application (`VPNRouter.App`) and provides automation capabilities for headless environments, scripts, CI integration, and Windows Service management.

### Architectural Role & Subsystem Boundaries
- **Decoupled CLI Execution**: Functions as an independent executable (`vpnrouter.exe`) interfacing directly with `VPNRouter.Core` (`VpnEngine`, `ProfileManager`, `SubscriptionResolver`, `HealthCheck`, `FirewallManager`, `LeakProtection`, `ProcessOwnership`) and `VPNRouter.Service` (`ServiceInstaller`).
- **Process Ownership & Anti-Spoofing Model**: Implements strict process-identity tracking (`OwnedProcessIdentity`, `ProcessOwnership`) combining PID, UTC process creation ticks, and verified image paths to prevent PID reuse attacks and uncontrolled kills across CLI, Service, and GUI boundaries.
- **Custom DI Integration for Spectre.Console**: Employs `SettingsAwareTypeRegistrar` to resolve dependency-injected command constructors (`ISettingsStore`) while working around Spectre.Console 0.49.1's default greediest-constructor activator limitation.
- **Safe Lifecycle & Teardown**: Provides synchronized shutdown via dual named `EventWaitHandle` capabilities (generation-qualified and legacy PID-qualified) and conditional atomic state persistence (`StateFile`).

- **Control Flow**:

  - `registrar`: Instance of `SettingsAwareTypeRegistrar`. Registers `typeof(ISettingsStore)` to `RealSettingsStore.Instance`.

  - Execution: `await app.RunAsync(args)`.
  - Global Exception Handling: `catch (Exception ex)` logs `Log.Fatal(ex, "Unhandled exception")` and returns 1. `finally` awaits `Log.CloseAndFlushAsync()`.

    - Validates parameters (non-empty generation, PID > 0, ticks > 0, non-empty path).
    - Under lock: reads `current`. Verifies `current.RunGeneration == generation` and monotonic ticks (`current.SingBoxStartedAtUtcTicks <= child.StartedAtUtcTicks`). Updates `SingBoxPid`, `SingBoxStartedAtUtcTicks`, `SingBoxExecutablePath`, and rewrites file.

### 2.12. `StopCommand.cs`

#### Class: `VPNRouter.CLI.Commands.StopCommand`
- **Modifiers**: `public`, inherits `Spectre.Console.Cli.Command`.
- **Constants & Enums**:
  - `internal const string StopEventPrefix = "VPNRouter_CLI_Stop_";`
  - `internal static readonly NamedWaitHandleOptions StopEventOptions = new() { CurrentUserOnly = true, CurrentSessionOnly = true };`
  - `private enum OwnerStopResult { Unavailable, Exited, TimedOut }`
  - `private enum ExactProcessState { DeadOrReplaced, Alive, Unknown }`
  - `private enum ChildStopResult { Stopped, AlreadyGone, Refused }`
- **Methods**:
  - `public override int Execute(CommandContext context)`:
    - Reads state via `StateFile.Read()`. If null, reports not running and returns 0.
    - Rejects legacy state (`RunGeneration == Guid.Empty`) with exit code 1.
    - Validates expected owner and child identities (`PersistedIdentity`).
    - Calls `TrySignalOwnerAndWait(expectedOwner.Value, generation)`.
    - If `TimedOut`: returns 1.
    - If `Unavailable`: probes owner via `ProbeExactProcess`. Refuses fallback if owner is alive or identity unverified.
    - Re-reads state file. If state cleared and owner exited, returns 0. If generation replaced, returns 1.
    - Verifies child against durable TUN owner record: `ProcessOwnership.IsCurrentRuntimeOwnerPair(expectedOwner.Value, expectedChild.Value)`. Refuses kill if mismatch.
    - Calls `TryStopExactChild(expectedChild.Value)`.
    - Conditionally clears state: `StateFile.ClearIfGeneration(generation)`.
    - Returns 0 on success, 1 on refusal/failure.
  - `internal static string BuildStopEventName(int ownerPid, Guid generation)`: Returns `${StopEventPrefix}{ownerPid}_{generation:N}`.
  - `private static OwnedProcessIdentity? PersistedIdentity(int pid, long startedAtUtcTicks, string executablePath)`
  - `private static OwnerStopResult TrySignalOwnerAndWait(OwnedProcessIdentity expectedOwner, Guid generation)`:

## 4. CONCURRENCY, LOCKS & LIFECYCLE

### 4.1. Inter-Process Synchronization: `StateFile` Named Mutex
- **Mutex Name**: `VPNRouter_CLI_State_v1`.
- **Options**: `NamedWaitHandleOptions { CurrentUserOnly = true, CurrentSessionOnly = false }`.
- **Scope**: User-wide across sessions on Windows; allows elevated CLI process to synchronize with non-elevated status queries running under the same user SID.
- **Timeout**: Strict 5-second timeout (`TimeSpan.FromSeconds(5)`).
- **Abandoned Mutex Handling**: Catches `AbandonedMutexException` and treats ownership as granted (`ownsMutex = true`), preventing deadlocks if a previous CLI instance was forcibly killed while writing.

### 4.2. In-Process Synchronization: `childStateGate`
- **Scope**: Private `object childStateGate` in `StartCommand.ExecuteAsync`.
- **Purpose**: Serializes `engine.SingBoxStarted` callback invocations with the main thread's initial state publication.
- **Invariants Maintained**:
  - Eliminates races where an asynchronous sing-box restart callback attempts to update `state.json` before the initial `StateFile.Write` completes.
  - Ensures child process start ticks are strictly monotonic (`latest.StartedAtUtcTicks <= identity.StartedAtUtcTicks`), discarding stale notifications.

### 4.3. Asynchronous IPC: Dual `EventWaitHandle` Architecture
- **Primary Handle**: `VPNRouter_CLI_Stop_{OwnerPid}_{Generation:N}`.
- **Legacy Bridge Handle**: `VPNRouter_CLI_Stop_{OwnerPid}`.
- **Wait Handle Scope**: `NamedWaitHandleOptions { CurrentUserOnly = true, CurrentSessionOnly = true }`.
- **Registration**: Uses `ThreadPool.RegisterWaitForSingleObject` with `executeOnlyOnce: true` and `timeout: Timeout.InfiniteTimeSpan`.
- **AutoReset Semantics**: The event retains an early signal even if signaled before the thread pool wait is registered, eliminating signal-loss races.

### 4.4. Teardown & Resource Safety
- **Pinned Process Handles**: In `StopCommand.TrySignalOwnerAndWait` and `TryStopExactChild`, process handles are pinned via `process.SafeHandle` and protected with `GC.KeepAlive` across `WaitForExit(5000)` calls to guarantee that the underlying OS handle is not recycled during the wait.
- **Atomic File Write**: `StateFile.WriteUnlocked` writes to `${path}.{Guid.NewGuid():N}.tmp`, sets private permissions (`AppPaths.CreatePrivateFile`), calls `stream.Flush(true)` to commit metadata and data, and executes `File.Move(tmp, path, overwrite: true)`.

## 5. SECURITY & PRIVILEGE BOUNDARIES

### 5.1. Privilege Elevation Matrix

| Command | Elevation Required? | Enforcement Mechanism | Rationale |
|---|---|---|---|
| `start` | **Yes** (unless `--dry-run`) | `AdminHelper.IsAdmin()` | Creation of TUN virtual network adapter (`wintun`), injection of Windows Firewall filtering rules (`netsh`), and ETW kernel session tracing. |
| `start --dry-run` | **No** | Explicit bypass in `StartCommand.cs` line 74 | In-memory config generation and schema validation only; no TUN or network mutation. |
| `stop` | **No** | Least privilege | Signals user-scoped `EventWaitHandle` of the running CLI process; fallback child termination requires matching durable runtime owner record. |
| `status` | **No** | Least privilege | Read-only inspection of `state.json` and process status; side-effect free. |
| `doctor` | **No** | Least privilege | Diagnostic probes check file existence, configuration syntax, and service status. |
| `profiles list/show/update`| **No** | Least privilege | Reads local config/cache files and performs outgoing HTTPS requests to GitHub. |
| `service install/uninstall`| **Yes** | `AdminHelper.IsAdmin()` | Invokes `sc.exe create/delete` targeting the Windows Service Control Manager. |
| `service start/stop` | **Yes** | `AdminHelper.IsAdmin()` | Interacts with SCM to start/stop the `VPNRouter` service. |
| `service status` | **No** | Least privilege | Queries SCM status via `ServiceControllerStatus`. |
| `test-update` | **No** (Gated by env) | `Environment.GetEnvironmentVariable("VPNROUTER_CI") == "1"` | CI integration test harness. |

### 5.2. PID Reuse & Process Spoofing Defenses
`StopCommand.cs` implements an adversarial-resistant verification sequence before attempting process termination:
1. **Identity Triad Validation**: Compares PID, UTC creation timestamp ticks, and executable image path (`OwnedProcessIdentity`).
2. **Durable Runtime Record Cross-Check**: Before fallback termination of the `sing-box` child process, `StopCommand` verifies `ProcessOwnership.IsCurrentRuntimeOwnerPair(expectedOwner, expectedChild)`. Even if `state.json` was tampered with by a malicious local process, `StopCommand` will refuse to kill any process that is not recorded in the internal runtime owner record.
3. **Sing-Box Executable Verification**: Enforces `ProcessOwnership.TryReadOwnedSingBoxIdentity` and `IsTrustedRuntimePath` to prevent killing an unrelated process that recycled the PID.

### 5.3. IPC Isolation & Namespace Protection
- All named mutexes and event wait handles utilize `NamedWaitHandleOptions`:
  - `CurrentUserOnly = true`: Prefixes Windows kernel object names with user SID, preventing cross-user hijacking or squatting in multi-user environments.
  - `CurrentSessionOnly = true`: Limits stop events to the active terminal/login session, preventing cross-session disruption on Remote Desktop / Terminal Services servers.

### 6.1. Defect Candidate 01: Hardcoded `%ProgramData%` vs `AppPaths.StatePath` (Path Discrepancy)
- **Location**:
  - `Program.cs` line 10: `Environment.ExpandEnvironmentVariables(@"%ProgramData%\VPNRouter\logs")`
  - `StateFile.cs` line 48: `Path.Combine(Environment.ExpandEnvironmentVariables(@"%ProgramData%\VPNRouter"), "state.json")`
  - `ProfileSourceFactory.cs` line 36: `Environment.ExpandEnvironmentVariables(@"%ProgramData%\VPNRouter\profiles\default.json")`
  - `StartCommand.cs` line 441: `Environment.ExpandEnvironmentVariables(@"%ProgramData%\VPNRouter\config")`
- **Contrast**:
  - `VPNRouter.Core.AppPaths` defines `DataDir`, `LogsDir`, `ConfigDir`, `ProfilesDir`, and `StatePath` with support for macOS (`~/Library/Application Support/VPNRouter`), Linux (`~/.config/vpnrouter`), and Android/testing data directory overrides (`AppPaths.OverrideDataDir`).
  - `StatusCommand.cs` line 140 explicitly calls `File.GetLastWriteTimeUtc(VPNRouter.Core.AppPaths.StatePath)`.
- **Consequence**:
  1. If `AppPaths.OverrideDataDir` is utilized (such as in integration testing, portable installations, or custom automation), `StateFile.Write` persists state to `%ProgramData%\VPNRouter\state.json`, whereas `StatusCommand` reads timestamp metadata from `AppPaths.StatePath`.
  2. On non-Windows platforms (Linux/macOS), `%ProgramData%` does not expand and results in a literal directory named `"%ProgramData%"` created in the current working directory.

### 6.2. Defect Candidate 02: Priority Collision and Inversion in `ProfileSourceFactory.Create`
- **Location**: `ProfileSourceFactory.cs` lines 12–27:
  ```csharp
  int priority = 10;
  foreach (var src in settings.ProfileSources)
  {
      switch (src.Type?.ToLowerInvariant())
      {
          case "github" when !string.IsNullOrEmpty(src.Url):
              sources.Add(new GitHubProfileSource(src.Url, priority));
              break;

          case "local" when !string.IsNullOrEmpty(src.Path):
              sources.Add(new LocalProfileSource(src.Path, priority + 10));
              break;
      }
      priority += 10;
  }
  ```
- **Analysis**:
  - For a local source at index 0, it receives `priority + 10` = 20. Then `priority` is incremented to 20.
  - If source at index 1 is a GitHub source, it receives `priority` = 20. Both sources share identical priority (20).
  - Furthermore, fallback profile sources are hardcoded at priorities 80 (`default.json` in app dir) and 85 (`default.json` in `%ProgramData%`). If a user configures $\ge 8$ profile sources, user-defined sources will receive priorities $\ge 80$, inverting precedence against the fallback sources.

### 6.3. Defect Candidate 03: Unescaped Spectre.Console Markup Injection
- **Locations**:

  - `ProfilesCommand.cs` line 117: `AnsiConsole.MarkupLine($"    Patterns: [grey]{string.Join(", ", proc.ScanPatterns)}[/]");`

### 6.4. Defect Candidate 04: Unhandled Early Directory Creation Exception in `Program.cs`
