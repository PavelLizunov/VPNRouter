# Exhaustive Code Inventory & Audit: Windows Service Subsystem (Module S01 / Batch B137_S01)

## 1. SUMMARY & PURPOSE

Module **S01** encapsulates the Windows Service subsystem for VPNRouter. Running under the privileged `LocalSystem` account at system boot before interactive user logon, this subsystem provides unattended background VPN routing, Zapret DPI circumvention, and Telegram MTProto proxy (`tg-ws-proxy`) services. It integrates tightly with the Service Control Manager (SCM), Windows Event Log, and the Core business logic layer (`VpnEngine`, `TunOwnershipLock`, `SettingsLoader`).

### Component Roles & Responsibilities

1. **Service Process Bootstrapper & Host (`VPNRouter.Service/Program.cs` - 221 SLOC)**
   - **Early Event Log Diagnostics**: Initializes the Windows Event Log source (`VPNRouter` in `Application` log) before file logging is available.
   - **Orphan sing-box Sweep**: Scans and terminates leftover `sing-box.exe` processes from abnormal prior shutdowns, guarded by atomic `TunOwnershipLock` acquisition and handle pinning (`SafeProcessHandle`).
   - **File Logging Configuration**: Configures Serilog with a daily rolling file sink at `%ProgramData%\VPNRouter\logs\vpnrouter.log` (retaining 7 days) and a safe fallback to a no-op logger on permission/locking failures.
   - **Firewall Orphan Reclamation**: Sweeps dangling kill-switch firewall block rules on startup and registers an `AppDomain.CurrentDomain.ProcessExit` hook, guarded by `TunOwnershipLock.IsOwnedByAnyone()`.
   - **Execution Mode Branching**: Detects the `--service` command-line switch; configures Microsoft Generic Host via `Host.CreateApplicationBuilder` with `AddWindowsService` (for SCM execution) or interactive console mode with graceful `Ctrl+C` handling.

2. **Programmatic Service Installer & SCM Manager (`VPNRouter.Service/ServiceInstaller.cs` - 262 SLOC)**
   - **SCM Service Lifecycle**: Provides programmatic installation (`Install`), removal (`Uninstall`), starting (`Start`), and stopping (`Stop`) of the Windows Service via `sc.exe` wrapper execution (`RunSc`).
   - **Dependency Hardening**: Enforces network stack boot ordering via `sc.exe depend= Tcpip/Dnscache/Dhcp`, preventing cold-boot race conditions where sing-box fails to initialize the TUN adapter before network drivers are loaded.
   - **Self-Healing & Upgrade Migration**: Supplies `UpdateDependencies` and `GetDependencies` to inspect and patch legacy pre-v2.14.12 installations lacking boot dependencies.
   - **Failure Recovery Policy**: Configures SCM failure actions (`sc failure reset= 86400 actions= restart/60000/restart/60000/restart/60000`) for automatic service restart after crashes.
   - **Status Inspection**: Wraps `System.ServiceProcess.ServiceController` to provide `IsInstalled`, `IsRunning`, `GetStatus`, and status polling (`WaitForStatus`).

3. **Background Hosted Service & Orchestration Engine (`VPNRouter.Service/VPNRouterService.cs` - 527 SLOC)**
   - **`BackgroundService` Lifecycle**: Implements `ExecuteAsync` and `StopAsync` to manage the lifecycle of background components.
   - **Network Readiness Gate**: Waits up to 30 seconds for network interfaces (`NetworkInterface.GetIsNetworkAvailable()`) on cold boot.
   - **Three-Engine Autostart**: Independently evaluates `AutostartVpn`, `AutostartZapret`, and `AutostartTgProxy` configuration flags.
   - **Watcher Mode & Deference**: Probes `TunOwnershipLock.IsOwnedByAnyone()` before starting sing-box. If the desktop App or CLI already holds the TUN interface, the service transitions immediately to passive "watcher mode" without contending for resources.
   - **Hot-Reload Reconciler**: Subscribes to `config.yaml` changes via `ISettingsStore.StartWatching`. When changes are detected, reloads settings and hot-reloads the active `VpnEngine` via `ApplyAsync` without restarting the service.
   - **Config Write Invariant**: Strictly adheres to invariant `v2.27 §4.6 C2`, acting as a pure reader of `config.yaml` to prevent write races with the desktop GUI.
   - **Cascading Teardown**: Performs orderly cancellation and resource disposal (`VpnEngine`, `ZapretManager`, `TgProxyManager`) with exception isolation and event log diagnostics.

### 3.2. Watcher Mode Transition Invariant
- **Trigger**: `TunOwnershipLock.IsOwnedByAnyone() == true` or `TunOwnershipException` during `VpnEngine.StartAsync`.
- **State Semantics**:
  - The Service relinquishes attempt to bind sing-box or create the Wintun adapter.
  - The Service marks `_startupComplete.TrySetResult()` immediately, unblocking shutdown or dependent flows.
  - The `config.yaml` file watcher remains active.
  - If the interactive owner (App / CLI) drops TUN ownership, the service does not auto-acquire mid-session; it will acquire on next boot or upon operator restart.

### 3.3. Configuration Hot-Reload Flow
- **Source**: External file change on `%ProgramData%\VPNRouter\config.yaml` (typically written by desktop GUI `VPNRouter.App`).
- **Pipeline**:
  1. `ISettingsStore` (`SettingsLoader`) detects file touch via `FileSystemWatcher` (2-second debounce).
  2. Invokes `OnConfigChanged(AppSettings newSettings)` on threadpool.
  3. Replaces `_currentSettings = newSettings`.
  4. If `_engine != null && _engine.IsRunning`, initiates `Task.Run(async () => await _engine.ApplyAsync(newSettings))`.
  5. `VpnEngine.ApplyAsync`:
     - Checks if server, mode, or rules changed.
     - Tries hot reload via sing-box Clash REST API (TUN stays up).
     - Falls back to sing-box process restart only if route mode or bypass-ru flipped.

### 3.4. Cascading Teardown Sequence (`StopAsync`)
1. **Unwatch Configuration**: `_store.StopWatching()` disarms `FileSystemWatcher` so last-second config writes cannot fire `ApplyAsync` against disposed engines.
2. **Startup Completion Synchronization**: `await Task.WhenAny(_startupComplete.Task, Task.Delay(15000, cancellationToken))` ensures service does not kill components that are in the middle of cold startup.
3. **Sequential Engine Teardown**:
   - `_engine?.Stop()` -> signals sing-box termination, stops ETW monitor, disengages split driver, tears down netsh firewall rules.
   - `_engine?.Dispose()` -> disposes process handles and cancellation tokens.
   - `_zapret?.Stop()` / `_zapret?.Dispose()` -> terminates `winws.exe` process tree.
   - `_tgProxy?.Stop()` / `_tgProxy?.Dispose()` -> terminates Python `tg-ws-proxy` process tree.
4. **Base Stop**: `await base.StopAsync(cancellationToken)`.
5. **Event Log Notice**: Emits "VPN Router service stopped".

## 4. CONCURRENCY, LOCKS & LIFECYCLE

### 4.1. System-Wide Synchronization Primitives
- **`TunOwnershipLock` (`Global\VPNRouter_TunOwnership_Semaphore`)**:
  - Global named Windows semaphore with maximum count 1.
  - Owned by whichever VPNRouter process is actively running sing-box with a TUN adapter.
  - **Program.cs Startup Sweep**: Reserves the lock via `using var cleanupLock = new TunOwnershipLock(); _ = cleanupLock.TryAcquire();`. If held by another process, orphan cleanup is skipped to avoid killing a legitimate sing-box owned by the desktop app.
  - **VPNRouterService Autostart**: Probes via static `TunOwnershipLock.IsOwnedByAnyone()` (which performs a zero-wait acquisition and immediate release). Prevents 30-second start retry loops when the desktop app is already connected.

### 4.2. Asynchronous Coordination & Startup Latch
- **`TaskCompletionSource _startupComplete`**:
  - Initialized with `TaskCreationOptions.RunContinuationsAsynchronously` to prevent continuations from running synchronously on the thread that calls `TrySetResult`.
  - Serves as a barrier in `StopAsync`: `await Task.WhenAny(_startupComplete.Task, Task.Delay(15000, cancellationToken));`.
  - Ensures graceful shutdown waits for in-flight startup without blocking indefinitely if startup hangs.

### 4.3. Process Handle Pinning & Lifetime
- **Handle Pinning in `Program.cs` (lines 65-80)**:
  - When scanning zombie `sing-box` candidates, `var pinnedHandle = z.SafeHandle;` obtains an explicit reference to the native kernel process object.
  - `GC.KeepAlive(pinnedHandle);` is called after `z.WaitForExit(3000)`.
  - **Guarantees**: Prevents the Windows kernel from recycling the Process ID (PID) between ownership verification (`ProcessOwnership.IsOwnedSingBox`) and `z.Kill(entireProcessTree: true)`.

### 4.4. Cancellation Token Propagation
- `stoppingToken` provided by `BackgroundService.ExecuteAsync` is threaded into:
  - `WaitForNetworkAsync(stoppingToken, ...)`
  - `SubscriptionResolver.ResolveAsync(..., ct)`
  - `ResilientStarter.StartWithBackoffAsync(..., ct)` for VPN, Zapret, and TgProxy
  - `Task.Delay(Timeout.Infinite, stoppingToken)`
- `StopAsync(cancellationToken)` receives SCM stop deadline token (typically 30s allotted by Windows SCM).

## 5. SECURITY & PRIVILEGE BOUNDARIES

### 5.1. Execution Identity & Elevation
- **`LocalSystem` (NT AUTHORITY\SYSTEM)**:
  - Configured by `WindowsServiceCommand.BuildCreateArguments` (`obj= LocalSystem`).
  - Grants necessary privileges: `SeTcbPrivilege`, `SeDebugPrivilege`, network configuration rights (creating Wintun adapter, modifying routing table, configuring Windows Defender Firewall via `netsh`).
  - Runs in non-interactive Session 0. Cannot display Avalonia UI, message boxes, or console windows.
- **Elevation Requirement for SCM Commands**:
  - `ServiceInstaller.Install`, `Uninstall`, `Start`, `Stop`, and `UpdateDependencies` invoke `sc.exe`.
  - These operations require an elevated Administrator token (`SeIncreaseQuotaPrivilege`, `SC_MANAGER_CREATE_SERVICE`, `SERVICE_CHANGE_CONFIG`).

### 5.2. Windows Event Log Access
- Service registers event source `VPNRouter` under the `Application` log.
- Registration creates registry key `HKLM\SYSTEM\CurrentControlSet\Services\EventLog\Application\VPNRouter`.
- Requires administrator rights; on unprivileged execution (e.g. CLI without admin), `Program.cs:15-20` and `VPNRouterService:512-520` safely catch and ignore security exceptions.

### 5.3. File System Access & Permissions
- **Log Directory**: `%ProgramData%\VPNRouter\logs\vpnrouter.log`.
  - `%ProgramData%` is writable by `LocalSystem` and Administrators.
- **Config Invariant (`v2.27 §4.6 C2`)**:
  - The Service is strictly a **reader** of `%ProgramData%\VPNRouter\config.yaml`.
  - Writing is prohibited to prevent file-lock contention and ACL distortion against non-elevated desktop users.
  - If service persistence is ever needed, it must use a dedicated `service-state.json`.

### 5.4. Command Line Injection Defense
- `ServiceInstaller.RunSc` uses `ProcessStartInfo.ArgumentList` instead of raw string concatenation.
- `WindowsServiceCommand.FormatImagePath` validates that the executable path does not contain quotation marks and wraps it in quotes: `$"\"{fullPath}\" --service"`.
- Prevents unquoted service path vulnerabilities (`C:\Program Files\...` being hijacked by `C:\Program.exe`).

### 5.5. Sensitive Data Redaction
- In `VPNRouterService.AutostartTgProxyAsync`:
  - `_logger.LogInformation("... secret configured (len {SecretLen}), port {Port} chosen...", secret.Length, port);`
  - Only the secret length is logged; raw MTProto secrets are never emitted to Serilog or Event Log.

## 6. SUSPICIOUS PATTERNS / DEFECT CANDIDATES

### Defect Candidate 1: Unshared File Logging Lock Contention (`vpnrouter.log`)
- **Location**: `VPNRouter.Service/Program.cs:124-129`
- **Code**:
  ```csharp
  Log.Logger = new LoggerConfiguration()
      .MinimumLevel.Information()
      .MinimumLevel.Override("Microsoft", LogEventLevel.Warning)
      .WriteTo.File(
          path: Path.Combine(logDir, "vpnrouter.log"),
          rollingInterval: RollingInterval.Day,
          retainedFileCountLimit: 7,
          outputTemplate: "[{Timestamp:yyyy-MM-dd HH:mm:ss}] [{Level:u5}] {Message:lj}{NewLine}{Exception}")
      .CreateLogger();
  ```
- **Finding**:
  `WriteTo.File` is called **without** `shared: true`. In Serilog, the file sink defaults to exclusive file locking (`FileShare.Read`). Both `VPNRouter.App` (`App/Program.cs:206` and `MainWindowViewModel.cs:2759`) and `VPNRouter.Service` point to the identical file `%ProgramData%\VPNRouter\logs\vpnrouter.log`.
- **Impact**:
  When `VPNRouter.Service` is running, it holds an open, exclusive file handle. When a user launches `VPNRouter.App`, `VPNRouter.App`'s logger fails to open `vpnrouter.log` with `IOException: The process cannot access the file because it is being used by another process`. The App falls back to a silent logger, dropping all subsequent GUI logs. Conversely, if App is launched first, Service file logging fails and falls back to a no-op logger.
- **Remediation**:
  Specify `shared: true` in `WriteTo.File` across all entry points (`Service/Program.cs`, `App/Program.cs`, and `MainWindowViewModel.cs`), or write Service logs to a dedicated file `vpnrouter-service.log`.

### Defect Candidate 2: `InvalidOperationException` on Timed-out `sc.exe` Execution
- **Location**: `VPNRouter.Service/ServiceInstaller.cs:228-230`
- **Code**:
  ```csharp
  var output = proc.StandardOutput.ReadToEnd()
             + proc.StandardError.ReadToEnd();
  proc.WaitForExit(10000);

  return (proc.ExitCode, output.Trim());
  ```
- **Finding**:
  `proc.WaitForExit(10000)` returns a `bool` indicating whether the process exited within 10 seconds. If `sc.exe` hangs or times out, `WaitForExit` returns `false`. The code ignores the return value, leaves the hanging process alive, and immediately attempts to read `proc.ExitCode`. In .NET, accessing `proc.ExitCode` when `HasExited` is `false` throws `InvalidOperationException: Process must exit before requested information can be determined`.
- **Remediation**:
  Check the return value of `proc.WaitForExit(10000)`. If false, call `proc.Kill()` and return `(-1, "sc.exe timed out after 10 seconds")`.

### Defect Candidate 3: Synchronous Stdout/Stderr Deadlock Hazard
- **Location**: `VPNRouter.Service/ServiceInstaller.cs:226-227`
- **Code**:
  ```csharp
  var output = proc.StandardOutput.ReadToEnd()
             + proc.StandardError.ReadToEnd();
  ```
- **Finding**:
  Calling `StandardOutput.ReadToEnd()` synchronously before `StandardError.ReadToEnd()` can cause a deadlock if the child process (`sc.exe`) produces enough output on stderr to fill the OS pipe buffer (typically 4096 bytes) while stdout is waiting for EOF.
- **Remediation**:
  Read streams asynchronously (`await Task.WhenAll(proc.StandardOutput.ReadToEndAsync(), proc.StandardError.ReadToEndAsync())`) or use `proc.BeginOutputReadLine()` / `proc.BeginErrorReadLine()`.

### Defect Candidate 4: Unhandled `Win32Exception` in `ServiceInstaller.IsInstalled()`
- **Location**: `VPNRouter.Service/ServiceInstaller.cs:166-178`
- **Code**:
  ```csharp
  public static bool IsInstalled()
  {
      try
      {
          using var sc = new ServiceController(ServiceName);
          _ = sc.Status; // throws if not installed
          return true;
      }
      catch (InvalidOperationException)
      {
          return false;
      }
  }
  ```
- **Finding**:
  `IsInstalled()` catches **only** `InvalidOperationException` (which is thrown when the service does not exist). If querying `sc.Status` fails due to `Win32Exception` (e.g. `ERROR_ACCESS_DENIED` when running under a restricted security token) or `PlatformNotSupportedException` (on non-Windows), the exception is uncaught and crashes the caller. In contrast, `IsRunning()` (lines 180-191) and `GetStatus()` (lines 193-205) use general `catch` blocks.
- **Remediation**:
  Update `IsInstalled()` to catch `Exception` or specifically `InvalidOperationException` and `Win32Exception`, returning `false`.

### Defect Candidate 5: Silent Ignored Failures in `ServiceInstaller.Install()`
- **Location**: `VPNRouter.Service/ServiceInstaller.cs:56-60`
- **Code**:
  ```csharp
  // Set description
  RunSc("description", ServiceName, Description);

  // Configure failure recovery: restart after 60s, 3 times, reset counter after 24h
  RunSc(WindowsServiceCommand.BuildFailureRecoveryArguments(ServiceName));

  return InstallResult.Ok(...);
  ```
- **Finding**:
  `Install()` verifies the exit code of `sc create`, but completely discards the exit codes of `sc description` and `sc failure`. If configuring the restart recovery actions fails (e.g. permission or syntax issue), the service is installed without recovery policy, yet `InstallResult.Ok` is returned.
- **Remediation**:
  Check `code != 0` for description and failure configuration, returning `InstallResult.Fail` or appending warnings to `InstallResult`.

### Defect Candidate 6: Teardown Race with Fire-and-Forget Zapret and TgProxy Startup
- **Location**: `VPNRouter.Service/VPNRouterService.cs:104-114, 483-506`
- **Code**:
  ```csharp
  if (settings.App.AutostartZapret)
      _ = AutostartZapretAsync(settings, stoppingToken);

  if (settings.App.AutostartTgProxy)
      _ = AutostartTgProxyAsync(settings, stoppingToken);
  ```
- **Finding**:
  `AutostartZapretAsync` and `AutostartTgProxyAsync` are launched as unawaited fire-and-forget tasks (`_ = ...`). `_startupComplete` is signaled as soon as the VPN autostart finishes (or is skipped). If SCM requests service stop while `AutostartZapretAsync` or `AutostartTgProxyAsync` is in its backoff retry loop:
  1. `StopAsync` awaits `_startupComplete.Task`, which completes immediately.
  2. `_zapret?.Stop()` runs when `_zapret` might still be null.
  3. The background task finishes backoff, instantiates `_zapret = new ZapretManager(...)`, and starts the process AFTER `StopAsync` has completed.
- **Impact**:
  A leftover `winws.exe` (Zapret) or `python.exe` (TgProxy) process is spawned as an orphan after the service terminates.
- **Remediation**:
  Track `Task` instances for `_zapretTask` and `_tgProxyTask`, await their completion or cancellation in `StopAsync`, and guard process spawn with a cancellation check.

### Defect Candidate 7: Unbounded Concurrent `ApplyAsync` Invocations in `OnConfigChanged`
- **Location**: `VPNRouter.Service/VPNRouterService.cs:451-465`
- **Code**:
  ```csharp
  if (_engine != null && _engine.IsRunning)
  {
      _ = Task.Run(async () =>
      {
          try
          {
              var ok = await _engine.ApplyAsync(newSettings);
              ...
          }
          catch (Exception ex)
          {
              _logger.LogWarning(ex, "[Service] ApplyAsync raised");
          }
      });
  }
  ```
- **Finding**:
  Each file change event triggers an unqueued `Task.Run(async () => await _engine.ApplyAsync(newSettings))`. Rapid successive writes to `config.yaml` can spawn concurrent hot-reload tasks. Because task scheduling is non-deterministic, a stale config reload could complete *after* a newer one.
- **Remediation**:
  Serialize hot reloads using a `SemaphoreSlim(1, 1)` or an asynchronous channel/worker loop.

### Defect Candidate 8: Rigid Dependency Migration Check
- **Location**: `VPNRouter.Service/VPNRouterService.cs:145-150`
- **Code**:
  ```csharp
  var current = ServiceInstaller.GetDependencies();
  if (current != null &&
      current.Any(d => string.Equals(d, "Tcpip", StringComparison.OrdinalIgnoreCase)))
  {
      return;  // Already migrated
  }
  ```
- **Finding**:
  `TryMigrateDependencies()` checks only whether `Tcpip` is present in dependencies. If a future version adds a 4th dependency (e.g. `BFE` or `NlaSvc`), an existing installation that has `Tcpip` will be considered "already migrated" and will never have its dependencies updated.
- **Remediation**:
  Verify that all entries in `ServiceInstaller.ServiceDependencies.Split('/')` are present in `current`.

### Defect Candidate 9: `StopAsync` Delay Timeout Disparity with `ServiceInstaller.Stop()`
- **Location**: `VPNRouterService.cs:485` vs `ServiceInstaller.cs:159`
- **Finding**:
  `VPNRouterService.StopAsync` allows up to 15 seconds for startup completion (`Task.Delay(15000, cancellationToken)`), followed by the time needed to stop sing-box, Zapret, and TgProxy. However, `ServiceInstaller.Stop()` waits exactly 15 seconds (`WaitForStatus(ServiceControllerStatus.Stopped, TimeSpan.FromSeconds(15))`). If the service takes 15.5 seconds to fully unwind, `ServiceInstaller.Stop()` reports failure to the caller even though the service stopped cleanly a moment later.
- **Remediation**:
  Increase `ServiceInstaller.Stop()` timeout to 25 or 30 seconds.
