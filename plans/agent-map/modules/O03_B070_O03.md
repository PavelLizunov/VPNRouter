> **TL;DR:** Module O03 encompasses the complete presentation and feature view suite of the Omarchy Quickshell VPNRouter plugin (`omarchy-vpnrouter`), providing 13 QML components spanning reusable controls (`Button`, `IconButton`, `Navigation`, `Header`, `HeroCard`) and advanced feature views (`ServersView`, `AppsView`, `CustomConfigView`, `DiagnosticsView`, `FreePoolView`, `ProfilesView`, `RulesView`, `SettingsView`). The audit uncovered multiple concrete defect candidates, including completely inert `tooltipText` properties in `IconButton`, broken QML reactive bindings on user input mutation in `SettingsView` and `RulesView`, unhandled asynchronous callbacks on component teardown, and unscrollable large-payload JSON inputs in `CustomConfigView`.

# Exhaustive Code Inventory & Audit: Omarchy Plugin UI Feature Views (Module O03 / Batch B070_O03)

## 1. SUMMARY & PURPOSE

Module **O03** provides the native presentation and user interaction layer for the `omarchy-vpnrouter` desktop shell plugin on the Omarchy Linux desktop (powered by the Quickshell QtQuick/QML runtime). The plugin serves as the graphical front-end communicating with the `VPNRouter` headless daemon via the Omarchy Protocol v1 NDJSON RPC interface.

### Component Roles & Responsibilities
- **`ui/Button.qml` (135 lines)**: Reusable primary action button supporting multiple visual variants (`normal`, `primary`, `danger`, `subtle`), loading/busy spinners with continuous rotation animation, keyboard accessibility (`Return`, `Enter`, `Space`), and state-driven color/border transitions.
- **`ui/IconButton.qml` (88 lines)**: Compact, fixed-dimension action button optimized for toolbars, list row actions (test, verify, delete, cancel, dismiss), and close buttons. Declares `tooltipText`, keyboard navigation, and busy spinner states.
- **`ui/Navigation.qml` (114 lines)**: Horizontally flickable navigation tab bar in Advanced mode. Renders 9 categorized tabs with dynamic locale binding and keyboard selection.
- **`ui/Header.qml` (149 lines)**: Main panel titlebar hosting the application identity, real-time connection status glyph, embedded `StatusBadge`, language toggle button (EN/RU), display mode switcher (`simple` vs. `advanced`), and panel close button.
- **`ui/HeroCard.qml` (253 lines)**: Central hero connection widget. Features a circular connection dial with state-driven pulsing/rotation, active server status, tunnel mode indicator ("FULL VPN" vs. "SPLIT"), in-flight operation progress/cancellation bar, and dismissible error alert banner.
- **`ui/AppsView.qml` (302 lines)**: Split-tunneling application policy editor. Manages routing modes (`split` vs. `full`), application filter policies (`include` vs. `exclude`), custom process addition, running process suggestions from backend inspection, and per-app removal.
- **`ui/ServersView.qml` (299 lines)**: Primary server browser. Features real-time search filtering across names and protocols, collapsible multi-line server import box, latency metrics with quality tier coloration, test/verify actions, server deletion, and selection with strict mouse hit-test isolation.
- **`ui/FreePoolView.qml` (171 lines)**: Community free server pool browser. Provides discovery refresh, latency testing, cryptographic verification, and one-click application to the active connection.
- **`ui/ProfilesView.qml` (135 lines)**: Profile selector view allowing users to switch between server profiles, trigger profile reloads, and inspect active profile selection.
- **`ui/RulesView.qml` (219 lines)**: Routing rule definitions and priority manager. Controls evaluation priority between system toggles and custom rules (`toggles_first` vs. `custom_first`), provides a multi-line rule definition editor, and supports multi-format rule import/export (`json`, `csv`, `singbox`).
- **`ui/CustomConfigView.qml` (236 lines)**: Raw JSON configuration manager for advanced protocols (Xray, sing-box). Includes collapsible import form, validation, activation, and removal of custom config profiles.
- **`ui/SettingsView.qml` (396 lines)**: Comprehensive network, routing, and engine preferences view. Manages TUN MTU validation, IPv6 toggle, Strict Routing, Strict DNS, Bypass Russian Traffic, Ad Blocking, DNS Leak Lockdown (capability-guarded), multi-mode DNS routing (`vpn_only`, `smart`, `direct`, default), and CIDR exclusion list management.
- **`ui/DiagnosticsView.qml` (197 lines)**: Built-in system health and diagnostics self-test viewer. Runs diagnostic checks, displays color-coded badges (`PASS`, `FAIL`, `WARN`), and allows exporting an off-line diagnostic bundle with interactive path reporting.

### 2.1. `ui/Button.qml`
- **Component Root**: `Item { id: root }`
- **Public Properties**:
  - `property string text: ""`: Label text displayed inside the button.
  - `property string icon: ""`: Icon character/glyph (Nerd Font or unicode).
  - `property string variant: "normal"`: Styling variant; accepts `"normal"`, `"primary"`, `"danger"`, or `"subtle"`.

- **Readonly / Computed Properties**:
  - `readonly property bool hot: mouseArea.containsMouse`: Tracks mouse hover state.
  - `readonly property bool pressed: mouseArea.pressed`: Tracks mouse down state.
  - `readonly property color baseColor`: Evaluates `Color.accent` (`primary`), `Color.urgent` (`danger`), or `Color.foreground`.
  - `readonly property color bgFill`: Resolves background color depending on `enabled`, `variant`, `pressed`, `hot`, and `activeFocus`.
  - `readonly property color textColor`: Resolves text color (`Color.muted` if disabled; `Color.background` if primary/danger; `Color.foreground` otherwise).
  - `readonly property color borderColor`: Resolves border color depending on focus, variant, and hover.
  - `readonly property int borderWidth`: Resolves border width (`Style.focusBorderWidth` when focused; 0 for subtle; `Style.normalBorderWidth` otherwise).
- **Public Signals**:
  - `signal clicked()`: Emitted on mouse release or keyboard activation when `enabled && !busy`.
- **Keyboard & Mouse Event Handlers**:
  - `Keys.onReturnPressed`: Triggers `root.clicked()` if `enabled && !busy`.
  - `Keys.onEnterPressed`: Triggers `root.clicked()` if `enabled && !busy`.
  - `Keys.onSpacePressed`: Triggers `root.clicked()` if `enabled && !busy`.
  - `MouseArea.onClicked`: Invokes `root.forceActiveFocus()` and emits `root.clicked()`.
- **Animations**:
  - `Behavior on color { ColorAnimation { duration: 150 } }`
  - `Behavior on border.color { ColorAnimation { duration: 150 } }`
  - `NumberAnimation on rotation { running: root.busy; from: 0; to: 360; loops: Animation.Infinite; duration: 1000 }`

## 3. DATA FLOWS & STATE MACHINES

### 3.1. Input Sources & UI Data Propagation
```
                       +---------------------------------------+
                       |    Quickshell / QtQuick Event Loop    |
                       +---------------------------------------+
                                           |
                   +-----------------------+-----------------------+
                   | User Clicks, Keys, Inputs                     | I18n Signal / Revision
                   v                                               v
        +---------------------+                        +------------------------+
        |  Interactive Views  | <--------------------- | I18n.js / i18nRevision |
        |  (Buttons/Toggles)  |                        +------------------------+
        +---------------------+
                   |
                   | Invocations via root.service.*
                   v
        +---------------------+                        +------------------------+
        |     Service.qml     | <--------------------- |  Headless Daemon RPC   |
        |  (Reactive State)   | ---------------------> | (NDJSON v1 Standard IO)|
        +---------------------+                        +------------------------+
                   |
                   | Property Updates (e.g. servers, state, busy)
                   v
        +---------------------+
        |  Declarative Views  |
        |  (Repeater/Bindings)|
        +---------------------+
```

1. **User Action Ingestion**:
   - Keyboard events (`Return`, `Enter`, `Space`) on focused items (`Button`, `IconButton`, `Navigation`, `Toggle`) or mouse clicks directly trigger UI signal handlers.
   - Text inputs (`TextField`, `TextEdit`) ingest raw strings from the user and either mutate draft properties (e.g. `SettingsView.mtuVal`, `ServersView.searchQuery`) or are read on submission (`CustomConfigView.customTextArea`).
2. **Transformations**:
   - `Model.filterServers(servers, query)`: Case-insensitive filtering matching either server name or protocol.
   - `Model.formatLatency(latencyMs)`: Numerical rounding with unit suffix (`"124 ms"`), or em-dash (`"—"`) for missing/negative latency.
   - `Model.latencyTier(latencyMs)`: Classification into `"good"` (<100ms), `"medium"` (<250ms), or `"poor"` (>=250ms).
   - `Model.protocolDisplay(protocol)`: Converts wire protocol tokens (`"vless"`, `"hy2"`, `"wg"`, `"ss"`) to branded display labels (`"VLESS"`, `"Hysteria 2"`, `"WireGuard"`, `"Shadowsocks"`).
   - `Model.validateMtu(val)`: Clamps input integer to `[576, 9000]` range with fallback to 1420.
   - `Model.cleanCidrList(raw)`: Splits multi-line/comma input, validates IPv4 octets `[0..255]` and subnet masks `[0..32]`, filtering out malformed entries.
3. **Reactive Translation Invalidation**:
   - Views declare `property int i18nRevision: service ? service.i18nRevision : 0`.
   - `function tr(key, args)` reads `var _ = i18nRevision` to create a dependency edge in Qt's property engine. Whenever `Service.setLocale()` or `Header.localeToggled()` fires, `i18nRevision` increments, invalidating all visible labels across all views simultaneously.

### 3.2. View State Machines

#### A. Connection State Machine (`HeroCard.qml`)
- **`disconnected`**: Hero dial shows `󱚤` (inactive icon), status label "Disconnected" in muted color. Button displays "Connect" (primary).
- **`connecting`**: Hero dial pulses red/urgent with rotating spinner `󰦞`, status label "Connecting…". Button displays "Connect" (busy disabled).
- **`connected`**: Hero dial turns `Color.accent` showing `󰖂` (shield/VPN icon), status label "Connected" in accent color. Button displays "Disconnect" (danger variant).
- **`disconnecting`**: Dial shows rotating spinner `󰦞`, status label "Disconnected" in urgent color. Button displays "Disconnect" (busy disabled).
- **In-flight / Busy**: If `service.activeOperation !== ""`, an operation bar expands with a cancel button that triggers `service.cancel()`.
- **Error State**: If `service.lastError !== ""`, a banner expands with error text and a dismiss button.

#### B. Display Mode State Machine (`Header.qml` & `Panel.qml`)
- **`simple`**: Displays `Header`, `HeroCard`, Quick Server List (top 6 servers), and Quick Routing Card.
- **`advanced`**: Displays `Header`, `HeroCard`, `Navigation` tab bar, and the selected dedicated subview (`ServersView`, `AppsView`, `SettingsView`, etc.).

## 4. CONCURRENCY, LOCKS & LIFECYCLE

### 4.1. Concurrency Architecture
- **Single-Threaded Main Loop**: All QML UI views, property bindings, and JavaScript functions execute within the single thread of the Quickshell QtQuick event loop. No multi-threaded synchronization primitives (mutexes, locks, semaphores) exist in this layer.
- **Asynchronous Protocol Operations**: Operations that mutate backend state (`connect`, `selectServer`, `setSettings`, `importCustom`) communicate asynchronously through `Service.qml`.
- **Busy State Protection**: UI controls prevent duplicate in-flight requests:
  - `Button.qml`: `Keys` and `MouseArea` click handlers explicitly check `if (root.enabled && !root.busy)`.
  - `HeroCard.qml`: Disables action buttons when `root.busy` is true.

### 4.2. Component Lifecycle & Teardown Guarantees
- **View Retention in Panel**: In `Panel.qml`, all 9 advanced subviews are instantiated simultaneously as children of the main column and toggled via `visible: root.currentTab === "<tab>"`.
  - *Implication*: Local view states (such as `SettingsView` draft fields, `ServersView` search query, and `CustomConfigView.showImportForm`) persist across tab switches while the panel remains open.
- **Lifecycle Teardown**: When the panel closes or Quickshell unloads:
  - In-flight anonymous callbacks passed to `Service.qml` (e.g. `service.exportRules(..., function(exported) { rulesTextEdit.text = exported })`) risk firing after the host component is destroyed or unmapped, risking `TypeError: Cannot set property 'text' of null` (see Section 6).

## 5. SECURITY & PRIVILEGE BOUNDARIES

### 5.1. Privilege Boundaries
- **Unprivileged Execution**: The UI layer runs entirely within the unprivileged user context. It does not invoke `sudo`, `pkexec`, or helper binaries directly. All operations are mediated through the standard-I/O NDJSON RPC channel managed by `Service.qml` connecting to `bin/vpnrouter-headless`.

### 5.2. Sensitive Input Sanitization & Memory Hygiene
- **Immediate Input Clearing**:
  - `ServersView.qml`: `importArea.text` is captured into local variable `txt` and immediately cleared (`importArea.text = ""`) before calling `service.importServers(txt)` (lines 110–113).
  - `CustomConfigView.qml`: `customTextArea.text` and `customNameInput.text` are captured and cleared (`customTextArea.text = ""` / `customNameInput.clear()`) before `service.importCustom(name, txt)` (lines 104–108).
  - `AppsView.qml`: `customAppInput.clear()` is called immediately upon accepting custom process names (lines 149, 159).
- **Capability Gating**:
  - `SettingsView.qml`: The dangerous/privileged `dnsLeakLockdown` parameter is explicitly omitted from the JSON payload unless `service.capabilities.dnsLockdown === true` (lines 77, 210–218). This prevents unauthorized attempts to toggle system-level firewall drops when the backend lacks capability.
- **Network Input Validation**:
  - `SettingsView.qml`: Subnets entered into `cidrEdit` are parsed and validated via `Model.cleanCidrList()` which drops invalid IPs, invalid subnet masks (>32), and non-IPv4 addresses before dispatching `setSettings`.

## 6. SUSPICIOUS PATTERNS / DEFECT CANDIDATES

During the line-by-line audit of the 13 assigned files, several defect candidates, architectural edge cases, and UI inconsistencies were identified:

### Finding 1: Completely Inert `tooltipText` Property in `IconButton.qml`
- **Location**: `ui/IconButton.qml`, lines 8, 50–74.
- **Issue**: `IconButton` declares `property string tooltipText: ""` and every consumer view (`ServersView`, `FreePoolView`, `CustomConfigView`, `AppsView`, `Header`, `HeroCard`) passes localized strings to `tooltipText`. However, `IconButton.qml` does not instantiate a `ToolTip` component, nor does it invoke any tooltip display method (e.g. `bar.showTooltip()`).
- **Impact**: All button tooltips across the entire user interface are completely silent and never rendered, degrading accessibility and user guidance.

### Finding 2: QML Property Binding Breakage on Draft Settings Mutation (`SettingsView.qml`)
- **Location**: `ui/SettingsView.qml`, lines 19–35, 173, 181, 187, 193, 199, 205, 216, 273.
- **Issue**: Draft properties (`mtuVal`, `ipv6Val`, `strictRouteVal`, `strictDnsVal`, `dnsModeVal`, `bypassRuVal`, `blockAdsVal`, `dnsLeakVal`) are initialized using dynamic binding expressions referencing `service.settingsData`. When a user toggles an option or types into `mtuInput`, the event handler imperatively assigns to the property (e.g. `root.mtuVal = Model.validateMtu(text)` or `root.ipv6Val = val`). In QML, imperative assignment permanently severs the declarative binding expression.
- **Impact**: If `service.settingsData` updates subsequently (e.g., from an external snapshot refresh, profile switch, or `refreshSnapshot()`), `SettingsView` will fail to update and will continue displaying stale local values.

### Finding 3: QML Binding Severing and Desynchronization in `RulesView.qml`
- **Location**: `ui/RulesView.qml`, lines 10, 97, 104, 137.
- **Issue**: `selectedPriority` is initialized as a binding to `service.rules.priority`. Toggling priority executes `root.selectedPriority = val ? "custom_first" : "toggles_first"`, permanently breaking the binding. Similarly, `rulesTextEdit.text` is initialized to `service.rules.text`. User keystrokes break the text binding.
- **Impact**: If backend rules update externally, `RulesView` will not reflect the changes unless the component is destroyed and recreated.

### Finding 4: Unhandled Asynchronous Callbacks on Destroyed Component (`RulesView.qml`, `SettingsView.qml`)
- **Location**:
  - `ui/RulesView.qml`, lines 174–177 (`root.service.exportRules(..., function(exported) { rulesTextEdit.text = exported; ... })`)
  - `ui/SettingsView.qml`, lines 387–389 (`root.service.setSettings(..., function() { root.saveNotice = root.tr("settings.saved") })`)
- **Issue**: When an asynchronous backend request is dispatched with an inline anonymous completion callback, the target elements (`rulesTextEdit`, `root`) are accessed upon completion. If the user navigates away, closes the panel, or Quickshell unloads before the backend returns, referencing `rulesTextEdit.text` or `root.saveNotice` can throw an unhandled `TypeError` in the QML engine.
- **Impact**: Spurious console runtime errors and possible engine warning noise.

### Finding 5: Direct Mutation of Injected Service Properties (`DiagnosticsView.qml`, `HeroCard.qml`)
- **Location**:
  - `ui/DiagnosticsView.qml`, line 81: `onClicked: if (root.service) root.service.diagnosticsExportPath = ""`
  - `ui/HeroCard.qml`, line 248: `onClicked: if (root.service) root.service.lastError = ""`
- **Issue**: Rather than invoking a service method (such as `service.clearLastError()`), views directly mutate fields on the `service` object.
- **Impact**: Violates unidirectional data flow. If `lastError` or `diagnosticsExportPath` were refactored into readonly or encapsulated properties, these click handlers would crash with property write errors.

### Finding 6: Cross-Sibling Grandchild Property Reference During Layout (`ServersView.qml`)
- **Location**: `ui/ServersView.qml`, line 184: `anchors.rightMargin: rowActions.width + Style.space(16)`.
- **Issue**: `rowMouse` is a child of `serverRowRect`. `rowActions` is a child of `rowContent`, which is a sibling of `rowMouse`. `rowMouse` binds its right margin to `rowActions.width`.
- **Impact**: During the initial QML layout pass, before `rowContent` and `rowActions` have calculated their children's implicit widths, `rowActions.width` evaluates to 0. This causes momentary layout twitching or warnings before settling.

### Finding 7: Unscrollable TextEdit for Large JSON Payloads (`CustomConfigView.qml`)
- **Location**: `ui/CustomConfigView.qml`, lines 65–92.
- **Issue**: `customTextArea` (`TextEdit`) is wrapped inside a `Rectangle` with fixed height `Style.space(90)`. It is NOT enclosed in a `Flickable` or `ScrollView`.
- **Impact**: When pasting complex sing-box or Xray configurations (typically 50–300 lines of JSON), the text overflows the 90px bounding box without a scrollbar, making editing or inspecting the pasted configuration impossible.

### Finding 8: Unused Dead Signal Declaration (`HeroCard.qml`)
- **Location**: `ui/HeroCard.qml`, line 20: `signal openServerPickerRequested()`.
- **Issue**: Declared in `HeroCard`, but never emitted anywhere within `HeroCard.qml`, nor handled in `Panel.qml`.
- **Impact**: Dead code / misleading API contract.

### Finding 9: Tab Repeater Re-instantiation on Locale Toggle (`Navigation.qml`)
- **Location**: `ui/Navigation.qml`, lines 22–35.
- **Issue**: `readonly property var tabs` binds to `i18nRevision`. Every time the locale is toggled between EN and RU, the entire array is reconstructed with new object instances.
- **Impact**: Causes `Repeater` to destroy and recreate all 9 tab delegate items on every language switch, resetting active focus and scroll positions.
