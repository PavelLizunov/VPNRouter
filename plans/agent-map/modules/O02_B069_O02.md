It enforces strict FIFO queuing (depth 8), deferred revision injection to prevent optimistic CAS concurrency conflicts, urgent out-of-band request bypass (bounded to 4), a 15-second request deadline watchdog, and an unprivileged, capability-gated security model.

## 1. SUMMARY & PURPOSE

`Service.qml` is the core architectural backbone of the `omarchy-vpnrouter` plugin for the Omarchy Quattro desktop shell (Quickshell). Declared in `manifest.json` as the plugin's primary service entrypoint (`entryPoints.service: "Service.qml"`), it acts as an unprivileged, singleton process manager, state store, and remote procedure call (RPC) client for the local `vpnrouter-headless` backend daemon.

### Component Roles & Responsibilities

1. **Subprocess Lifecycle & Transport Orchestrator**:
   Spawns, monitors, and terminates the headless backend daemon (`bin/vpnrouter-headless --stdio`) as a child process via `Quickshell.Io.Process`. Manages clean process teardown (SIGTERM 15), graceful backoff retry timers (exponential backoff capped at 30 seconds), and emergency state degradation (`unavailable`).

2. **Omarchy Protocol v1 Client Implementation**:
   Coordinates streaming newline-delimited JSON (NDJSON) over standard I/O streams using an incremental chunk accumulator (`_accumulator`) with a strict 256 KiB frame ceiling, JSON depth checks, and schema validation.

3. **Mutation Serializer & Optimistic Lock (CAS) Coordinator**:
   Serializes ordinary mutating and querying requests through a FIFO queue (`_requestQueue`, capacity 8) with single in-flight concurrency. To eliminate stale-revision conflicts (`RouterException("conflict", ...)`), it implements deferred revision injection, dynamically binding the current storage revision (`root.revision`) at dispatch time rather than enqueue time.

4. **Urgent Request Bypass & Preemption**:
   Allows time-critical control commands (`disconnect`, `cancel`) to bypass the ordinary request queue and write directly to standard input, while maintaining strict isolation so urgent responses never desynchronize or prematurely clear ordinary in-flight operations. Urgent concurrency is bounded to a maximum of 4 pending requests.

5. **Request Deadline & Timeout Watchdog**:
   Maintains a dedicated 1-second interval timer (`deadlineWatchdog`) that enforces a 15-second request deadline across all pending callbacks. Timed-out operations are safely rejected with `code: "timeout"`, releasing in-flight locks and unblocking the queue pump.

6. **Reactive State Store & Capability Gate**:
   Exposes high-level reactive properties (`state`, `activeServer`, `servers`, `subscriptions`, `settingsData`, etc.) to the UI hierarchy. Enforces fail-closed capability gating, preventing `connect()` calls until the backend explicitly confirms connection capabilities during the handshake snapshot.

7. **Localization Driver**:
   Drives dynamic i18n reactivity across Russian and English translation catalogs (`locales/en.json`, `locales/ru.json`), tracking system locale changes (`LANG`, `LC_MESSAGES`) and notifying child views via revision counter (`i18nRevision`).

## 4. CONCURRENCY, LOCKS & LIFECYCLE

### 4.1. Single-Threaded Event Loop & Queue Constraints

QML and JavaScript execute on a single event-driven UI thread in Quickshell. Concurrency is managed via asynchronous event callbacks and explicit state markers rather than OS threads, mutexes, or semaphores:

1. **Ordinary Operation Concurrency**:
   - Strictly serialized: At most **one** ordinary request can be active in flight (`_requestQueue.getActive() !== null`).
   - If an ordinary request is active, `pumpQueue()` returns `null` and leaves remaining requests in `_requestQueue`.
   - Maximum queue depth: **8 frames** (`Protocol.createRequestQueue(8)`). Exceeding this rejects calls immediately with `{ code: "queue_full", message: "Request queue is full (max 8)" }`.

2. **Urgent Operation Concurrency**:
   - Urgent commands (`disconnect`, `cancel`) execute out-of-band and bypass `_requestQueue`.
   - Concurrency is bounded by `maxUrgentPending: 4`. If `_pendingUrgentCount >= 4`, calls are rejected with `{ code: "queue_full", message: "Urgent request limit exceeded" }`.
   - Total pending callbacks in memory is bounded to at most $8 + 1 + 4 = 13$.

3. **Urgent Isolation Invariant**:
   - When an urgent response arrives, `handleResponse` verifies `isOrdinaryActive`. Since urgent requests are tagged `isUrgent: true`, it decrements `_pendingUrgentCount` but **does not** touch `activeRequestId`, **does not** touch `_requestQueue.clearActive()`, and **does not** call `pumpQueue()`. This guarantees ordinary operations are not corrupted or double-pumped.

---

### 4.2. Request Deadlines & Watchdog Timer

- **Watchdog Cadence**: `deadlineWatchdog` runs every `1000ms`.
- **Deadline Calculation**: When a request is dispatched (at `sendRequest` for urgent, or `pumpQueue` for ordinary), `deadline = Date.now() + (customTimeoutMs || 15000)`.
- **Timeout Handling**:
  When `now > cb.deadline`:
  1. Callback is removed from `_pendingCallbacks`.
  2. If urgent: `_pendingUrgentCount` is decremented.
  3. If ordinary: `root.activeRequestId = ""`, `root.activeOperation = ""`, `root.activeProgress = null`, and `_requestQueue.clearActive()`.
  4. Callback `onError({ code: "timeout", message: "Request deadline exceeded" })` is fired.
  5. `errorNotice("timeout", ...)` is emitted.
  6. `pumpQueue()` is invoked, allowing subsequent queued operations to proceed without permanently hanging the queue.

---

### 4.3. Teardown & Destruction Invariants

- **Component Destruction**:
  `Component.onDestruction` calls `I18n.removeListener(_i18nListener)` to prevent dangling JavaScript callbacks, and invokes `tearDown()`.
- **Subprocess Signaling**:
  `tearDown()` stops `retryTimer` and issues `backendProc.signal(15)` (`SIGTERM`).
- **Callback Eviction**:
  When `backendProc.onExited` fires during teardown or crash, all remaining entries in `_pendingCallbacks` and `_requestQueue` are evicted and completed with `{ code: "process_exited", message: "Backend process exited with code " + exitCode }`.

## 5. SECURITY & PRIVILEGE BOUNDARIES

### 5.1. Elevation & Privilege Model

- **Zero Privilege Elevation**:
  `Service.qml` runs strictly within the unprivileged user desktop session under the user's UID.
  - Contains **no** `sudo` calls.
  - Contains **no** `pkexec` or Polkit invocations.
  - Contains **no** shell command pipelines (`sh -c`).
- **Communication Channel**:
  Interacts with `bin/vpnrouter-headless` exclusively via file descriptors 0 (stdin) and 1 (stdout) created by `Quickshell.Io.Process`. Any system-level routing, TUN device configuration, or firewall rules are handled internally by the headless daemon (or its companion system service).

---

### 5.2. Path Resolution & Sandboxing

- **Binary Resolution**:
  ```qml
  readonly property string helperPath: {
    var raw = Qt.resolvedUrl("bin/vpnrouter-headless").toString()
    return raw.replace("file://", "")
  }
  ```
  The helper binary is pinned relative to the plugin's own QML root directory (`Qt.resolvedUrl`). It does not search `$PATH` or accept arbitrary user-controlled binary paths.
- **Locale File Resolution**:
  Catalog paths (`locales/en.json`, `locales/ru.json`) are hardcoded relative URLs passed to `FileView`.

---

### 5.3. Environment Variables & Information Exposure

- **Environment Access**:
  Accesses only `LANG` and `LC_MESSAGES` via `Quickshell.env()` to resolve UI locale.
- **Redaction & Secrets**:
  - `Service.qml` does not log request payloads or responses to `console.log` in production.
  - Subscription URLs and server credentials passed into `addSubscription` or `importServers` flow directly into JSON frames written to stdin.
  - Diagnostic bundle exports are written to a backend-determined path (`diagnosticsExportPath`) without exposing raw system logs in QML properties.

---

### 5.4. Memory & Buffer Overflow Defense

- **Frame Size Guard**:
  `Protocol.createChunkAccumulator` enforces a hard 256 KiB limit (`MAX_FRAME_BYTES = 262144`). If the incoming un-delimited byte stream exceeds 256 KiB before finding `\n`, the buffer is immediately discarded, a `buffer_overflow` error is raised, and all pending requests are aborted via `flushAllQueued`.
- **JSON Depth & Schema Defense**:
  Incoming frames are parsed by `Protocol.parseFrame`, which enforces JSON nesting depth $\le 32$, rejects malformed or duplicate keys, and verifies the protocol version (`v === 1`).

## 6. SUSPICIOUS PATTERNS / DEFECT CANDIDATES

Line-by-line scrutiny of `Service.qml` revealed eight concrete defect candidates and subtle edge-case risks:

### Defect Candidate 1: Missing URL Decoding on `helperPath`
- **Location**: `Service.qml:15–18`
- **Pattern**:
  ```qml
  readonly property string helperPath: {
    var raw = Qt.resolvedUrl("bin/vpnrouter-headless").toString()
    return raw.replace("file://", "")
  }
  ```
- **Vulnerability / Risk**:
  `Qt.resolvedUrl(...).toString()` returns a percent-encoded URI string (e.g. spaces become `%20`, Cyrillic characters become `%D0%...`). Simply replacing `"file://"` does not decode percent-encoded sequences. If the plugin or user home directory contains spaces or special characters (e.g. `/home/user name/.local/...`), `helperPath` will be `/home/user%20name/...`, causing `Process` to fail with `ENOENT` (executable not found).
- **Remediation**:
  Wrap with `decodeURIComponent`:
  ```qml
  return decodeURIComponent(raw.replace(/^file:\/\//, ""))
  ```

---

### Defect Candidate 2: Cascading Mutation Failure on Revision Conflict
- **Location**: `Service.qml:404–406, 418–420`
- **Pattern**:
  ```qml
  if (errCode === "conflict") {
    root.refreshSnapshot()
  }
  ...
  if (isOrdinaryActive) {
    root.pumpQueue()
  }
  ```
- **Vulnerability / Risk**:
  Suppose two mutations are queued in sequence: Request A (`servers.select`) and Request B (`settings.set`).
  1. Request A fails on the backend with `code: "conflict"` because the backend revision moved.
  2. In `handleResponse`, `errCode === "conflict"` triggers `root.refreshSnapshot()`, which enqueues a `snapshot` request to the tail of `_requestQueue` (Queue: `[Request B, Snapshot]`).
  3. `handleResponse` then calls `root.pumpQueue()`.
  4. `pumpQueue()` immediately dequeues and dispatches **Request B**, injecting `root.revision`.
  5. However, `root.revision` **has not updated yet** because the `snapshot` request is still queued behind Request B!
  6. Request B is dispatched with the stale revision and fails with `conflict` as well.
- **Remediation**:
  When a conflict occurs, pause the queue or prioritize `snapshot` at the front of `_requestQueue` before pumping subsequent mutations, or flush dependent queued mutations upon conflict.

---

### Defect Candidate 3: Silent Drop of Follow-up Queries on Queue Saturation
- **Location**: `Service.qml:608–614, 663–669, 756–762, 897–906`
- **Pattern**:
  ```qml
  function selectServer(id, onDone, onError) {
    return sendRequest("servers.select", { revision: root.revision, id: id }, function(res) {
      applySnapshot(res)
      listServers() // <--- Queues servers.list without onError callback!
      if (onDone) onDone(res)
    }, onError)
  }
  ```
- **Vulnerability / Risk**:
  When a mutation like `selectServer` succeeds, its callback fires follow-up query requests (e.g. `listServers()`, `listSubscriptions()`, `getApps()`). If `_requestQueue` is saturated (depth 8) due to rapid user operations, `sendRequest` fails with `queue_full`. Because `listServers()` is called without an `onError` parameter, the failure is silently dropped. The UI model (`root.servers`) remains stale and out of sync with the backend.
- **Remediation**:
  Forward the outer `onError` callback or log a warning if follow-up refresh queries fail to enqueue.

---

### Defect Candidate 4: Swallowed Syntax Errors in Locale Loaders
- **Location**: `Service.qml:123–128, 136–141`
- **Pattern**:
  ```qml
  try {
    var obj = JSON.parse(text())
    I18n.setCatalogs(obj, null)
    root.i18nRevision++
  } catch (e) {}
  ```
- **Vulnerability / Risk**:
  If a developer or translator introduces a trailing comma or syntax error into `locales/en.json` or `locales/ru.json`, `JSON.parse` throws a `SyntaxError`. The empty `catch (e) {}` swallows the error completely without logging. The catalog is left empty, and the UI silently renders fallback translation keys (`key.name`) with no diagnosis available.
- **Remediation**:
  Log a console warning or notify `lastError` when catalog parsing fails:
  ```qml
  console.warn("Failed to parse locale JSON:", e)
  ```

---

### Defect Candidate 5: Permanent Unavailability on Clean Exit (`exitCode === 0`)
- **Location**: `Service.qml:328–336`
- **Pattern**:
  ```qml
  if (exitCode !== 0) {
    root.lastError = "Backend exited (code " + exitCode + "). Retrying…"
    ...
    retryTimer.restart()
  }
  ```
- **Vulnerability / Risk**:
  If the backend daemon terminates cleanly with exit code 0 (for example, if killed by an external systemd service restart, an EOF on stdin, or an internal maintenance exit), `exitCode !== 0` evaluates to `false`. `retryTimer` is never scheduled. The service remains permanently in `state: "unavailable"` and `helperPresent: false` until the user manually restarts the desktop shell.
- **Remediation**:
  Differentiate between intentional plugin teardown (`root.starting === false` during `tearDown()`) and unexpected daemon exit. Restart on exit code 0 if not shutting down.

---

### Defect Candidate 6: Absence of SIGKILL Escalation on Teardown
- **Location**: `Service.qml:273–278`
- **Pattern**:
  ```qml
  function tearDown() {
    retryTimer.stop()
    if (backendProc.running) {
      backendProc.signal(15) // SIGTERM
    }
  }
  ```
- **Vulnerability / Risk**:
  If the daemon encounters an uncooperative driver, deadlocked async task, or blocking I/O call in sing-box, `SIGTERM` may not terminate the process. `Service.qml` has no fallback timer to escalate to `SIGKILL` (`signal(9)`). The orphaned backend process can continue running in the background, holding network interfaces and preventing new instances from binding ports.
- **Remediation**:
  Introduce a 2-second fallback timer that issues `backendProc.signal(9)` if `backendProc.running` remains true after `SIGTERM`.

---

### Defect Candidate 7: Default `settingsData` Property Incompleteness
- **Location**: `Service.qml:72–82` vs `Service.qml:879–892`
- **Pattern**:
  Line 72 initializes:
  ```qml
  property var settingsData: ({
    mtu: 1420,
    ipv6Enabled: false,
    strictRoute: false,
    strictDns: false,
    dnsMode: "vpn_only",
    bypassRussianTraffic: true,
    blockAds: false,
    dnsLeakLockdown: false,
    routeExcludeAddress: []
  })
  ```
  While `getSettings` populates:
  ```qml
  dnsModeOverride: res.dnsModeOverride !== undefined ? res.dnsModeOverride : (res.dnsMode || "vpn_only"),
  dnsModeSemantics: res.dnsModeSemantics || null,
  ```
- **Vulnerability / Risk**:
  Prior to the first successful execution of `getSettings()`, `settingsData.dnsModeOverride` and `settingsData.dnsModeSemantics` are `undefined`. If UI bindings in `SettingsView.qml` read these properties immediately upon plugin load, they evaluate to `undefined` rather than their default semantics, causing flickering or misrendered DNS mode radio buttons.
- **Remediation**:
  Include `dnsModeOverride: "vpn_only"` and `dnsModeSemantics: null` directly in the default `settingsData` property definition.

---

### Defect Candidate 8: Queued Requests Delay Timeout Clock
- **Location**: `Service.qml:493–502, 547`
- **Pattern**:
  ```qml
  // sendRequest:
  var item = { id: reqId, ..., timeoutMs: timeoutDuration }
  root._requestQueue.enqueue(item)
  ...
  // pumpQueue:
  root._pendingCallbacks[next.id] = {
    ...
    deadline: Date.now() + (next.timeoutMs || root.requestDeadlineMs)
  }
  ```
- **Vulnerability / Risk**:
  The deadline clock for an ordinary request is not initialized when the user invokes the method (`sendRequest`), but only when the item is dequeued and pumped to the wire (`pumpQueue`). If 7 slow requests are queued ahead of request 8, request 8 could sit in `_requestQueue` for minutes without timing out. The calling UI component will not receive a timeout error until 15 seconds *after* it reaches the head of the queue.
- **Remediation**:
  Track `enqueueTime` on queued items and enforce an overall queue residence timeout in `checkDeadlines`.

## 8. AUDIT CONCLUSION & SUMMARY TABLE

`Service.qml` is a robust, well-architected client transport for the Omarchy Quattro desktop environment. Its queue management, deferred revision injection, and urgent bypass designs effectively resolve past concurrency defects. Addressing the URL decoding on `helperPath` and the cascading conflict handling will further solidify its enterprise reliability.

|---|---|---|
