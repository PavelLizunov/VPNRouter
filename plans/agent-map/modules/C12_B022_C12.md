> **TL;DR:** Module C12 (`ConfigPipeline` and `ConfigGenerator` multi-file partial class) forms the single source of truth for generating, hardening, and validating sing-box 1.12+ configuration JSON across all connection modes (split include, split exclude, full tunnel) and proxy protocols (VLESS Reality/TLS, AmneziaWG, Hysteria2, TUIC, Shadowsocks, NaiveProxy, and DNS-Tunnel). The audit identified critical invariants (fail-closed IPv6 leak prevention, in-place server mutation, MTU clamping, and DNS detour bindings), thread-safety hazards from un-synchronized shared settings mutation, and subtle behavioral edge cases in Hy2/TUIC multi-server auto-selection and port-range truncation.

# Exhaustive Code Inventory & Architecture Audit: Core Config Generation Subsystem (Module C12 / Batch B022_C12)

## 1. SUMMARY & PURPOSE

Module C12 (`VPNRouter.Core.Services`) provides the canonical configuration compilation and validation pipeline that transforms VPNRouter's high-level domain models (`AppSettings`, `Profile`, `VlessServerEntry`, `CustomRule`) into wire-compatible sing-box 1.12+ JSON configurations.

### 1.1 Architectural Role
The module serves as the authoritative boundary between application intent and the sing-box data-plane engine. It is consumed by:
1. **`VpnEngine.StartAsync`**: Initial VPN connection establishment (runs in strict validation mode).
2. **`VpnEngine.Apply` / `ApplyAsync`**: Live profile or settings hot-reloading.
3. **`HealthMonitor`**: Background auto-restart and recovery path (runs in advisory validation mode with deterministic IPv6 leak guards).

Prior to the Phase 2F unification (`ConfigPipeline`), separate hand-rolled generation pipelines in `VpnEngine` and `HealthMonitor` caused silent traffic leaks (such as the v2.28.2 incident where subscription aggregation was missing in the hot-reload path). Module C12 centralizes subscription resolution, server health filtering, outbound group assembly, DNS architecture, route rule composition, and anti-leak validation into a single, unified pipeline.

### 1.2 Component Responsibilities

| File | Primary Role & Responsibilities |
|---|---|
| **`ConfigPipeline.cs`** | Orchestrates the end-to-end generation lifecycle: subscription resolution via `VlessServersResolver`, empty server safety guards, sing-box model generation, leak validation via `LeakProtection`, warning dispatch, and JSON serialization. |
| **`ConfigGenerator.cs`** | Core orchestrator for the `ConfigGenerator` static partial class. Normalizes TUN MTU, selects OS-specific TUN network stack (`system` vs `gvisor`), resolves effective routed processes, computes deterministic routing fingerprints, builds inbounds (`tun-in`), configures Clash API telemetry with authentication secrets, and serializes configs using `System.Text.Json` source generation. |
| **`ConfigGenerator.Dns.cs`** | Generates the sing-box DNS subsystem: remote DoH (`vpn-dns`), direct DoH (`local-dns`), LAN/system resolvers (`dns-system`), ECH/SVCB suppression rules (anti-censorship for RU TSPU), LAN TLD leak guards, and per-process DNS detours. |
| **`ConfigGenerator.Outbounds.cs`** | Orchestrates outbound topologies: protocol filtering (gating fork-only AmneziaWG/XHTTP and platform-dependent NaiveProxy), auto-select health hygiene (verdict-driven dropping of handshake-blocked nodes and high-risk ASNs), capability-gated chained detours (`chain-entry` -> `proxy`), UDP split auto-detection (`proxy` vs `proxy-udp`), and fallback outbounds (`direct`, `dns-direct`). |
| **`ConfigGenerator.OutboundBuilders.cs`** | Implements protocol-specific builders: VLESS+Reality/TLS, Hysteria2 (QUIC + Brutal CC), TUIC v5 (QUIC + BBR), Shadowsocks 2022 (+ ShadowTLS), NaiveProxy (HTTP/2 / HTTP/3 over QUIC), Slipstream DNS-Tunnel, and AmneziaWG 1.0/2.0/3.0 endpoints. Manages MTU, TCP keepalive (30s), ALPN parsing, and `prefer_ipv4` domain resolution. |
| **`ConfigGenerator.Route.cs`** | Compiles sing-box action-based routing rules: protocol sniffing (`sniff`), DNS hijacking (`hijack-dns`), DNS-tunnel infrastructure self-exclusions, private IP bypass (`ip_is_private`), QUIC head-of-line blocking mitigation (`blockQuicOnTcpProxy`), per-app process routing, and final route determination (`direct` vs `proxy`). |
| **`ConfigGenerator.Rules.cs`** | Manages rule-sets and advanced routing features: AdBlock (`.srs` local caching), Russian geo-bypass (`geosite-ru` domain-only bypass), custom rules engine (direct/proxy/block actions, port range expansion, DNS reject generation), rule-ordering priority toggles (`toggles_first` vs `custom_first`), and macOS Chromium/WebKit helper process expansion. |

### 2.1 `ConfigPipeline.cs`

```csharp
namespace VPNRouter.Core.Services;

internal static class ConfigPipeline
```

#### Enums

##### `ConfigPipeline.ValidationMode`
```csharp
public enum ValidationMode
{
    Strict,
    Advisory
}
```
- **`Strict`**: Initial-connect semantics. Any validation error reported by `LeakProtection.ValidateConfig` throws `InvalidOperationException`, aborting connection startup.
- **`Advisory`**: Recovery / auto-restart semantics. Validation warnings and transient errors are logged at `WARN` level rather than throwing, allowing recovery across minor glitches. However, static IPv6 leak violations (`ipv4_only` or `dns.strategy`) remain fatal.

#### Methods

##### `ConfigPipeline.Generate`
```csharp
public static string Generate(
    Profile profile,
    IEnumerable<string> resolvedProcessNames,
    AppSettings settings,
    ValidationMode validationMode = ValidationMode.Strict,
    Action<string>? warningSink = null,
    ILogger? logger = null,
    bool? strictDnsOverride = null,
    Func<VlessServerEntry, bool>? isServerAlive = null)
```
- **Parameters**:
  - `profile`: The active profile specifying `DnsMode` and process rules.
  - `resolvedProcessNames`: Pre-scanned process names from `IProcessScanner`.
  - `settings`: Application settings (mutated in-place by `VlessServersResolver`).
  - `validationMode`: `Strict` (fail-closed) or `Advisory` (fail-open for recovery).
  - `warningSink`: Optional callback delegate receiving non-fatal configuration warnings.
  - `logger`: Optional Serilog `ILogger` for diagnostic tracing.
  - `strictDnsOverride`: Optional runtime override for Strict DNS failover.
  - `isServerAlive`: Optional predicate for live health checking during outbound selection.
- **Return Type**: `string` (formatted sing-box JSON).
- **Exceptions**:
  - `InvalidOperationException`:
    - Thrown when `VlessServersResolver.Resolve` yields 0 usable servers (actionable message from `VlessServersResolver.DescribeEmptyReason`).
    - Thrown when `LeakProtection.ValidateConfig` fails in `Strict` mode.
    - Thrown when `LeakProtection.ValidateConfig` detects non-transient IPv6-leak invariants in `Advisory` mode.
- **Side Effects**: Mutates `settings.Vless.Servers` in-place.

```csharp
    string routingMode = "split",

    bool isExcludeMode = false,
```

    - Split include: routes processes to `proxy` (or TCP->`proxy` + UDP->`proxy-udp`).
    - Split exclude: routes processes to `direct`.
    - Full tunnel with UDP split: routes UDP to `proxy-udp`.
  - Final Outbound: `"proxy"` for full tunnel or exclude split mode; `"direct"` for include split mode.
  - Interface Auto-Detection: `AutoDetectInterface = true`, `DefaultDomainResolver = "local-dns"`.

```
       ┌───────────────────────────┐
       │ ConfigGenerator.Serialize │ ──► Wire-ready sing-box JSON string
       └───────────────────────────┘
```

### 3.2 State Matrix: Routing & DNS Modes

| RoutingMode | RoutingAppsMode | StrictDns | Process List Empty? | Final Route | DNS Final | Per-Process DNS |
|---|---|---|---|---|---|---|
| `split` | `include` | `false` | No | `direct` | `local-dns` | `vpn-dns` (unless smart -> `local-dns`) |
| `split` | `include` | `true` | No | `direct` | `vpn-dns` | `vpn-dns` |
| `split` | `include` | `false` | Yes | `direct` | `local-dns` | None |
| `split` | `exclude` | `false` | No (Apps excluded) | `proxy` | `vpn-dns` | `local-dns` (for excluded apps) |
| `split` | `exclude` | `true` | No (Apps excluded) | `proxy` | `vpn-dns` | `vpn-dns` (all via tunnel) |
| `full` | *any* | `false` | *ignored* | `proxy` | `vpn-dns` | None (all handled by DNS Final) |
| `full` | *any* | `true` | *ignored* | `proxy` | `vpn-dns` | None (all handled by DNS Final) |

### 3.3 Rule Insertion Priority Stack

In sing-box, routing rules are evaluated sequentially (first match wins). The compiled order in `route.rules` is strictly maintained as:

1. **Protocol Sniffing**: `{ action: "sniff", timeout: "300ms" }` (Must be rule #0 so domain matchers have SNI).
2. **DNS-Tunnel Infrastructure (Conditional)**: Direct routing for slipstream resolver CIDRs and `slipstream-client` process.
3. **DNS Hijacking**: `{ protocol: "dns", action: "hijack-dns" }`.
4. **Private IP Direct**: `{ ip_is_private: true, action: "route", outbound: "direct" }`.
5. **High-Priority Toggles or Custom Rules** (Configured via `CustomRulesPriority`):
   - **Under `toggles_first` (Default)**:
     1. `BypassRussianTraffic` (`vpnrouter-geosite-ru` -> `direct`)
     2. `BlockAds` (`vpnrouter-adblock` -> `reject`)
     3. User `CustomRules` (in user-defined order)
   - **Under `custom_first` (Opt-in)**:
     1. User `CustomRules` (in user-defined order)
     2. `BypassRussianTraffic` (`vpnrouter-geosite-ru` -> `direct`)
     3. `BlockAds` (`vpnrouter-adblock` -> `reject`)
6. **QUIC Suppression (Conditional)**: `{ protocol: "quic" / udp:443, action: "reject" }`.
7. **Per-App Process Rules**: `{ process_name: [...], action: "route", outbound: "proxy" / "direct" }`.
8. **Final Default**: Handled by `route.final` (`"direct"` or `"proxy"`).

## 4. CONCURRENCY, LOCKS & LIFECYCLE

### 4.1 Concurrency Model & Synchronization
- **No Internal Locks**: Neither `ConfigPipeline` nor `ConfigGenerator` contains locks, semaphores, or mutexes. All methods are `static` and pure with respect to internal class state.
- **Caller Synchronization Requirement**: Callers MUST synchronize access when invoking `ConfigPipeline.Generate`. Specifically, `VlessServersResolver.Resolve` mutates `settings.Vless.Servers` in-place. If two threads (e.g. `VpnEngine.StartAsync` on the main thread and `HealthMonitor` on a thread-pool timer) call `ConfigPipeline.Generate` concurrently on the same `AppSettings` instance, race conditions will occur on the list collections.
- **Async & Cancellation**: Config generation is entirely synchronous and CPU-bound (involving string formatting, collection filtering, and JSON serialization). It takes no `CancellationToken`. Any I/O (such as RuleSet downloads in `RuleSetCacheManager`) occurs within bounded synchronous timeouts.

### 4.2 Lifecycle Guarantees & Side Effects
- **In-Place Mutation**: `settings.Vless.Servers` is modified to contain aggregated subscription endpoints and active server markers.
- **Persistence Warning**: Callers must NOT persist `settings` to disk immediately following `ConfigPipeline.Generate` without reloading, as transient subscription servers would leak into the permanent configuration file.
- **Failover / Teardown**: Generated configurations configure Clash API controllers (`127.0.0.1:9090`) with randomized bearer secrets, ensuring teardown and live telemetry inspection can be controlled securely by `SingBoxManager`.

## 5. SECURITY & PRIVILEGE BOUNDARIES

### 5.1 Leak Protection & Fail-Closed Invariants
1. **Empty Servers Guard**: If `servers.Count == 0`, generation immediately throws `InvalidOperationException`. Emitting route rules pointing to a non-existent `"proxy"` outbound causes sing-box to silently fall through to `route.final ("direct")`, creating an undetectable plaintext data leak.
2. **Deterministic IPv6 Leak Invariant**: In `ValidationMode.Advisory` (used by `HealthMonitor`), most validation errors are treated as warnings to prevent restart-loops. However, `ConfigPipeline.Generate` strictly enforces that any violation containing `"ipv4_only"` or `"dns.strategy"` remains fatal (`throw new InvalidOperationException`). This prevents crash-recovery cycles from silently re-enabling IPv6 AAAA lookups on an IPv4-only TUN, which would leak IPv6 packets to the ISP.
3. **Public TLD Deny List**: `ConfigGenerator.Dns.cs` enforces `PublicTldDenyList` against user-supplied LAN DNS suffixes. Registering a bare public TLD (e.g. `com` or `ru`) as a LAN suffix would route all lookups under that TLD to the local system/ISP plaintext resolver, completely defeating encrypted DoH privacy.
4. **Censorship ECH Suppression**: Sing-box DNS rules explicitly reject DNS `HTTPS` (type 65) and `SVCB` (type 64) queries. Under Russian TSPU DPI, Encrypted Client Hello (ECH) trigger packet drops and connection resets on Cloudflare domains; rejecting these query types forces browsers to fall back to standard TLS 1.3 SNI, preserving connectivity.

### 5.2 Secrets & Credential Handling
- **Credentials in Output**: Generated configs serialize plaintext VLESS UUIDs, Hysteria2 passwords, TUIC passwords, Shadowsocks keys, and AmneziaWG private keys into sing-box JSON.
- **Memory Redaction**: Config models themselves do not perform memory zeroing. Redaction of sensitive fields during diagnostic log export is handled upstream by `DiagnosticsRedactor`.
- **Clash API Protection**: `SingBoxConfig.Experimental.ClashApi.Secret` binds a bearer secret to the external controller (`127.0.0.1:9090`), preventing unauthorized local processes or browser tabs from accessing connection telemetry or hijacking sing-box routes.

## 6. SUSPICIOUS PATTERNS / DEFECT CANDIDATES

### 6.1 Defect Candidate 1: Hy2 / TUIC Sole Proxy Bypasses Multi-Server Auto-Selection Pool
- **Location**: `VPNRouter.Core/Services/ConfigGenerator.Outbounds.cs`, lines 297–315.
- **Pattern**:
  ```csharp
  var udpNativeActiveName = settings.Vless.ActiveServer;
  var udpNativeActiveEntry = !string.IsNullOrEmpty(udpNativeActiveName)
      ? servers.FirstOrDefault(s => string.Equals(s.Name, udpNativeActiveName, StringComparison.OrdinalIgnoreCase))
      : servers.FirstOrDefault();
  var udpNativeActive = (udpNativeActiveEntry != null
      && ("hysteria2".Equals(udpNativeActiveEntry.Protocol, StringComparison.OrdinalIgnoreCase)
          || "tuic".Equals(udpNativeActiveEntry.Protocol, StringComparison.OrdinalIgnoreCase)))
      ? udpNativeActiveEntry : null;

  if (udpNativeActive != null)
  {
      AddOutboundGroup(outbounds, new List<VlessServerEntry> { udpNativeActive }, "proxy", "vless");
      hasUdpProxy = false;
      proxyIsUdpNativeOutbound = true;
  }
  ```
- **Issue**: If a user has `AutoSelectBestServer = true` and their active subscription provides multiple Hysteria2 or TUIC servers, the generator detects that `udpNativeActiveEntry` is UDP-native and immediately creates a single outbound containing only `udpNativeActive`. It completely bypasses `AddOutboundGroup` multi-server handling and never generates a `urltest` outbound for UDP-native pools.
- **Impact**: Automatic latency testing and failover does not function for pools consisting exclusively of Hysteria2 or TUIC servers; the active server remains pinned to the first entry.

### 6.2 Defect Candidate 2: Incomplete Dead Server Filtering in Flow Split Fallback
- **Location**: `VPNRouter.Core/Services/ConfigGenerator.Outbounds.cs`, lines 324–344.
- **Pattern**:
  ```csharp
  var flowServers = servers.Where(s => !string.IsNullOrEmpty(s.Flow)).ToList();
  var noFlowServers = servers.Where(s => string.IsNullOrEmpty(s.Flow)).ToList();
  if (isServerAlive != null)
      noFlowServers = noFlowServers.Where(isServerAlive).ToList();
  hasUdpProxy = flowServers.Count > 0 && noFlowServers.Count > 0;

  if (hasUdpProxy)
  {
      AddOutboundGroup(outbounds, flowServers, "proxy", "vless");
      AddOutboundGroup(outbounds, noFlowServers, "proxy-udp", "vless-udp");
  }
  else
  {
      // Single outbound: all traffic → proxy
      AddOutboundGroup(outbounds, servers, "proxy", "vless");
  }
  ```
- **Issue**: When `isServerAlive` filters out all dead `noFlowServers`, `hasUdpProxy` evaluates to `false`. Execution falls into the `else` block, which invokes `AddOutboundGroup(outbounds, servers, "proxy", "vless")`. However, `servers` was never filtered by `isServerAlive`!
- **Impact**: The dead `noFlowServers` that were explicitly eliminated from `noFlowServers` are reintroduced into the single `"proxy"` outbound group and can win latency probes or receive traffic if urltest is generated.

### 6.3 Defect Candidate 3: Port Range Expansion Truncation
- **Location**: `VPNRouter.Core/Services/ConfigGenerator.Rules.cs`, lines 253–266.
- **Pattern**:
  ```csharp
  var rangePorts = new List<int>();
  foreach (var v in values)
  {
      if (TryParsePortRange(v, out var min, out var max))
      {
          var step = Math.Max(1, (max - min) / 50);
          for (int p = min; p <= max; p += step) rangePorts.Add(p);
          if (!rangePorts.Contains(max)) rangePorts.Add(max);
      }
  }
  if (rangePorts.Count == 0) return null;
  route.Port = rangePorts.Distinct().Take(64).ToList();
  ```
- **Issue**: Sing-box supports a native `port_range` field in rules, but `RouteRule` models encode this into discrete `Port` integers. The generator samples a range across at most 50 steps, but if multiple ranges are specified, `Take(64)` silently discards all remaining ports.
- **Impact**: Traffic on un-sampled or truncated ports in a custom port-range rule will not match the rule and falls through to default routing without any error or warning surfacing to the user.

### 6.4 Defect Candidate 4: Unhandled Generic Exception Swallowing in Advisory Validation
- **Location**: `VPNRouter.Core/Services/ConfigPipeline.cs`, lines 186–197.
- **Pattern**:
  ```csharp
  catch (Exception ex)
  {
      if (validationMode == ValidationMode.Strict) throw;
      logger?.Warning(ex, "[ConfigPipeline] LeakProtection.ValidateConfig threw (non-fatal in advisory mode)");
  }
  ```
- **Issue**: If `LeakProtection.ValidateConfig` throws an unexpected runtime exception (e.g. `NullReferenceException` or `ArgumentOutOfRangeException` due to a malformed outbound), advisory mode catches and swallows it entirely. Recovery continues, and `ConfigPipeline.Generate` serializes and deploys an unvalidated configuration.
