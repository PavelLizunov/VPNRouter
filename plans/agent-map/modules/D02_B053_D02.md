# Exhaustive Code Inventory & Audit: Android Native / JNI Bridge (Module D02 / Batch B053_D02)

## 1. SUMMARY & PURPOSE

Module **D02** constitutes the mission-critical Android OS integration and native runtime bridge layer of VPNRouter on Android (`net10.0-android36.0`). It encapsulates the core OS networking primitives, JNI communication boundaries with external Go and Rust shared libraries, process lifecycle management, background automation, and the UI-side lifecycle state machine.

### Core Architectural Functions:
1. **OS VPN Service & Datapath Orchestration (`VpnRouterService.java`)**:
   - Manages the native Android `VpnService` lifecycle, allocating and configuring the virtual network interface (`tun0`) through `VpnService.Builder`.
   - Directly hosts and drives `libbox` (SingBox Go runtime via gomobile/JNI) using `Libbox.newService` without the historical `CommandServer` intermediary.
   - Enforces kernel-level self-exclusion via `addDisallowedApplication(getPackageName())` and `protect(fd)` so outbound proxy and resolver sockets bypass the local tunnel to prevent infinite routing loops.
   - Hosts the `SlipstreamNative` sidecar (`libslipstream_jni.so`) for QUIC-over-DNS tunneling, binding a local loopback TCP front (`127.0.0.1:<port>`) before sing-box dials it.
   - Implements Android resilience patterns: `START_STICKY`, `PARTIAL_WAKE_LOCK` for connect-init, swipe-away recovery via `AlarmManager` (`ACTION_RESTART`), Always-on VPN boot restoration (`last_good_config_json`), and live traffic polling via a protected loopback socket against the Clash API.
2. **Free-Configs In-Process Deep Verification (`AndroidDeepVerifyBox.java`)**:
   - Provides an isolated, transient SingBox engine (`BoxService`) that binds only a local SOCKS5 inbound (no TUN) to verify raw HTTP egress through candidate VLESS proxy outbounds against `https://www.cloudflare.com/cdn-cgi/trace`.
   - Validates status codes, latency, and ensures the egress IP does not match private or CGNAT ranges (guarding against transparent ISP interception).
3. **Rust DNS-Tunnel Client JNI Interface (`SlipstreamNative.java`)**:
   - Manages dynamic loading of `libslipstream_jni.so` and exposes static native entrypoints (`nativeStart`, `nativeStop`) to orchestrate the picoquic QUIC-over-DNS client.
4. **External Intent Automation Gate (`VpnControlReceiver.cs`)**:
   - An exported `BroadcastReceiver` exposing standard automation hooks (`EXT_START`, `EXT_STOP`, `EXT_TOGGLE`) for Tasker, Termux, widgets, and ADB.
   - Enforces a strict default-OFF user opt-in security model (`AndroidStorage.GetExternalControlEnabled()`), routing start operations through the service's `ACTION_RESTART` last-good config restoration path.
5. **UI Lifecycle & Diagnostics Pump (`AndroidApp.VpnLifecycle.cs`)**:
   - Avalonia UI partial class managing the visual state machine for connection status, chip breathing animations (VPN and Zapret DPI bypass pills), and a 1 Hz `DispatcherTimer` diagnostics pump.
   - Tracks session uptime, drives file-based sing-box log freshness and transport probes every 30 seconds, and visualizes live traffic throughput and connection counts.

  - Updates `_statusCard` properties (`IsOn`, `IsWarn`, `IsOff`, `Title`, `Subtitle`), CTA visibility (`_ctaConnect`, `_ctaConnecting`, `_ctaDisconnect`), VPN chip state (`SetVpnChipState`), Zapret chip state (`UpdateZapretChipFromState`), diagnostics timer (`StartDiagnosticsTimer` / `StopDiagnosticsTimer`), battery optimization exemption checks, and Advanced shell footer status.
- `private void SetVpnChipState(ChipState state, bool force = false)`:
  - Cancels and disposes existing `_vpnPulseCts`, sets chip brushes via `BindToken`, updates `_vpnChipState`, and initiates `StartChipPulse` when in `Connecting` state. Mirrors brushes onto `_advVpnChip`.
- `private void SetZapretChipState(ChipState state, bool force = false)`:
  - Mirrors `SetVpnChipState` logic for `_zapretChip`, `_zapretPulseCts`, and `_advZapretChip`.
- `private void UpdateZapretChipFromState()`:
  - Evaluates `AndroidStorage.GetDpiBypassMode()`. If enabled, mirrors `_vpnChipState`; if off, sets `ChipState.Off`.
- `private System.Threading.CancellationTokenSource StartChipPulse(Visual target)`:
  - Launches infinite breathing opacity animation (1.0 $\leftrightarrow$ 0.55 over 1.2s) via `anim.RunAsync(target, cts.Token)`. Returns owning `CancellationTokenSource`.
- `private void OnTunnelErrorReported(string message)`:
  - UI-thread dispatcher setting `_lastError`, updating `_lastErrorAt`, invoking `ApplyErrorOneLinerDisplay()`, and starting diagnostics timer for auto-clear.
- `private void StartDiagnosticsTimer()`:
  - Starts 1 Hz `DispatcherTimer` at `DispatcherPriority.Background` and fires an immediate tick.
- `private void StopDiagnosticsTimer()`:
  - Stops diagnostics timer and hides `_statusHealthCheck`.
- `private void OnDiagnosticsTick()`:
  - 1 Hz tick handler. If `MainActivity.IsActivityPaused` is true, returns. Updates uptime string change-only on `_statusCard.Title` and `_advFooterStatusText`, runs health probe every 30s (`RunHealthProbe()`), and auto-clears `_lastError` after 30s.
- `private void RunHealthProbe()`:
  - Reads `filesDir/singbox.log` size and `LastWriteTimeUtc`. Evaluates `grew || recent || vpnUp` (using `MainActivity.IsVpnTransportActive`) to prevent idle false alarms. Updates `_lastHealthOk`.
- `private void ApplyHealthCheckDisplay()`:
  - Formats and displays health status (`DiagHealthCheckPending`, `DiagHealthCheckOk`, `DiagHealthCheckStale`).
- `private void ApplyErrorOneLinerDisplay()`:
  - Displays or hides `_statusErrorOneLiner`.
- `private static string FormatUptime(TimeSpan elapsed)`:
  - Formats `TimeSpan` into `"M:SS"` or `"H:MM:SS"`.

### 3.2. Data Transformations & Side-Effects
- **Config JSON Parsing & Enrichment**:
  - `VpnRouterService` extracts `experimental.clash_api.secret` from incoming JSON via `org.json.JSONObject`.
  - In `openTun()`, SingBox's `TunOptions` are parsed: MTU is assigned, addresses/routes are translated into OS kernel routes via `VpnService.Builder`, and per-app include/exclude package filters are populated.
- **Log Sanitation**:
  - Uncaught Java exceptions and tunnel initialization failures are passed through `scrubSecrets()`, which scrubs proxy URLs (`vless://[redacted]`), web URLs (`https://host/[redacted]`), UUIDs (`<uuid>`), and base64 strings (`<key>`) before persisting to `<filesDir>/crashes/` or broadcasting via `ACTION_TUNNEL_ERROR`.
- **Live Stats Polling**:
  - `pollStatsOnce()` issues a raw HTTP/1.0 request to `127.0.0.1:9090/connections` using a VpnService-protected socket. It extracts `downloadTotal`, `uploadTotal`, and connection array length, then broadcasts `ACTION_STATS`. `AndroidApp.OnStatsReported` computes instantaneous rates ($\Delta \text{bytes} / \Delta t$) and updates the status card subtitle.
- **Deep Verify Verification**:
  - `AndroidDeepVerifyBox.verifyConfigSync` accepts raw config JSON, starts transient `BoxService`, waits for SOCKS port binding, sends HTTP GET to Cloudflare trace endpoint, validates 2xx response and non-private IP, and returns serialized JSON to C#.

## 4. CONCURRENCY, LOCKS & LIFECYCLE

### 4.1. Threading Architecture

```
Thread / Pool                 Responsibilities
─────────────────────────────────────────────────────────────────────────────
Android Main Thread           Service lifecycle events (onCreate, onStartCommand,
                              onDestroy), immediate startForeground() FGS contract,
                              BroadcastReceiver deliveries.
lifecycleExecutor             Dedicated single-thread ThreadPoolExecutor ("vpn-lifecycle").
                              Serializes all startTunnel, stopTunnel, and config restoration.
                              30s core thread timeout prevents thread leaks.
netCallbackThread             Dedicated HandlerThread ("vpn-net-monitor").
                              Handles NetworkCallback events and JNI interface updates.
statsPoller                   ScheduledExecutorService ("vpnrouter-stats").
                              Polls Clash API every 2s via protected socket.
runBounded Daemon Threads     Throwaway threads ("vpn-bounded-<name>") running blocking native
                              calls (boxService.close, nativeStop) with 4s timeouts.
Avalonia UI Thread            Dispatcher.UIThread drives all Avalonia property setters,
                              chip animations, and 1 Hz diagnostics timer.
```

### 4.2. Concurrency Primitives & Synchronization Mechanisms
- **`lifecycleExecutor` Serialization**:
  - Configured with `corePoolSize = 1`, `maximumPoolSize = 1`, and `LinkedBlockingQueue`. All `startTunnel()` and `stopTunnel()` calls execute sequentially.
  - Implements `exec.allowCoreThreadTimeOut(true)` with a 30-second keep-alive. If the service is recreated or idling, the daemon worker reaps itself.
- **Bounded Native Teardown (`runBounded`)**:
  - `runBounded(name, timeoutMs, action)` spawns a daemon thread and joins with a 4,000ms timeout. This guarantees that uncooperative Go runtime or picoquic threads (e.g. stalled in QUIC reconnect backoff) cannot hang the `lifecycleExecutor`.
- **Process-Wide Libbox Initialization**:
  - `VpnRouterService.ensureLibboxSetup()` uses method-level synchronization (`private synchronized void ensureLibboxSetup()`).
  - `AndroidDeepVerifyBox.ensureLibboxSetup()` uses double-checked locking on an `AtomicBoolean`:
    ```java
    if (libboxSetupDone.get()) return;
    synchronized (libboxSetupDone) {
        if (libboxSetupDone.get()) return;
        // setup...
        libboxSetupDone.set(true);
    }
    ```
- **HandlerThread Management**:
  - `ensureNetCallbackHandler()` and `quitNetCallbackThread()` are `synchronized` on the service instance to prevent race conditions during service shutdown and restart.
- **WakeLock Management**:
  - `connectWakeLock` is initialized with `setReferenceCounted(false)` and acquired with a 60,000ms hard ceiling. It is acquired before tunnel startup and released in the `startTunnel()` `finally` block or during `teardownTunnelResources()`.
- **CancellationTokenSource Animation Disposal**:
  - In `AndroidApp.VpnLifecycle.cs`, `SetVpnChipState` and `SetZapretChipState` strictly enforce atomic cancellation and disposal to prevent timer/event leaks:
    ```csharp
    var prevCts = _vpnPulseCts;
    _vpnPulseCts = null;
    try { prevCts?.Cancel(); } catch { }
    prevCts?.Dispose();
    ```

## 5. SECURITY & PRIVILEGE BOUNDARIES

### 5.1. Android Permissions & Elevation
- **`android.permission.BIND_VPN_SERVICE`**:
  - Guarding `VpnRouterService` in `AndroidManifest.xml` with `android:exported="false"`. Prevents arbitrary third-party applications from binding or manipulating the VPN service.
- **`android.permission.FOREGROUND_SERVICE` & `FOREGROUND_SERVICE_TYPE_SYSTEM_EXEMPTED`**:
  - Declared for Android 14+ (API 34+) compatibility. Required to run continuous background network routing.
- **`android.permission.WAKE_LOCK`**:
  - Used strictly for 60-second partial CPU wake-locks during connection handshakes.
- **External Receiver Security Boundary (`VpnControlReceiver.cs`)**:
  - The receiver is exported (`android:exported="true"`) to allow automation from Tasker or ADB.
  - **Zero-Trust Default**: Gated behind `AndroidStorage.GetExternalControlEnabled()`, which defaults to `false`. Without explicit user enablement in Settings, all incoming broadcasts are dropped and logged.
  - **Start Restriction**: Uses `ACTION_RESTART` instead of `ACTION_START`, preventing external callers from injecting arbitrary config JSON. It reuses the previously verified `last_good_config_json`.

### 5.2. Network Isolation & Loop Avoidance
- **Self-Disallow Application**:
  - `VpnRouterService.openTun` calls `builder.addDisallowedApplication(getPackageName())`. All traffic originating from VPNRouter (including sing-box outbound dials and Slipstream UDP queries) completely bypasses `tun0` at the Linux kernel routing layer.
- **Protected Sockets**:
  - Sockets created for Clash API polling and platform auto-detect invoke `protect(fd)`, binding them directly to the underlying physical network interfaces.
- **Deep Verify Egress Isolation**:
  - `AndroidDeepVerifyBox` creates a SOCKS-only instance with no TUN. Because the app UID is disallowed from the main VPN tunnel, Deep Verify's outbound dials bypass the active VPN and test the raw underlying network.

### 5.3. Secret Redaction & Sandbox Isolation
- **Filesystem Sandbox**:
  - Stderr redirects (`singbox.stderr.log`), logs (`singbox.log`), certificates (`slipstream-cert.pem`), and crash dumps (`crashes/java-crash-*.txt`) are strictly stored in `Context.getFilesDir()` (`/data/data/com.ninitux.vpnrouter/files/`). External storage (`getExternalFilesDir()`) is forbidden.
- **Regex Scrubbing**:
  - `scrubSecrets` scrubs VLESS/VMess/Trojan/Shadowsocks/Hysteria/TUIC URLs, HTTP authorization/path components, UUIDs, and base64 strings before writing crash reports or emitting `ACTION_TUNNEL_ERROR` broadcasts.

## 6. SUSPICIOUS PATTERNS / DEFECT CANDIDATES

### 6.1. Defect Candidates & Risks

1. **Async Void Exception Unhandled Crash Hazard (`AndroidApp.VpnLifecycle.cs:57`)**:
   - `private async void OnConnectClicked(object? sender, RoutedEventArgs e)`:
   - *Risk*: `OnConnectClicked` calls `await ApplyScannedSubscriptionUrlAsync(subscriptionUrl)`. If `ApplyScannedSubscriptionUrlAsync` throws an unhandled exception, `async void` will bubble the exception directly to the synchronization context and terminate the application process.
   - *Recommendation*: Wrap the awaitable call in a `try ... catch` block with user-facing error reporting.

2. **False Positive Tunnel Health on Multi-VPN Environments (`AndroidApp.VpnLifecycle.cs:672`)**:
   - `RunHealthProbe()` incorporates `MainActivity.IsVpnTransportActive(ctx)`.
   - *Risk*: `NetworkCapabilities.TRANSPORT_VPN` checks if *any* VPN transport is currently active on the device. If another VPN service is running or if the OS takes time to tear down a stale transport, `_lastHealthOk` remains `true` even if VPNRouter's internal sing-box engine has halted or deadlocked.

3. **Missing InterruptedException Restoration (`AndroidDeepVerifyBox.java:243`)**:
   - In `waitForPortBound`:
     ```java
     try { Thread.sleep(100); } catch (InterruptedException ignored) { return false; }
     ```
   - *Risk*: Catches `InterruptedException` and exits without re-interrupting the thread (`Thread.currentThread().interrupt()`), suppressing the interruption state for caller threads.

4. **Background FGS Launch Exception on Android 12+ (`VpnControlReceiver.cs:93`)**:
   - `context.StartForegroundService(svc)` is executed from `OnReceive`.
   - *Risk*: On Android 12+ (API 31+), initiating a foreground service from a broadcast receiver when the app is in the background will throw `ForegroundServiceStartNotAllowedException` unless the app is battery-opt exempt. While `VpnControlReceiver` catches the exception and `VpnRouterService.ensureForegroundStarted()` catches it internally, external automation triggers will fail unless battery optimization is disabled.

5. **Loopback Egress Hazard in Per-App Include Mode (`VpnRouterService.java:1548`)**:
   - In `openTun()`, when `isInclude` is active:
     ```java
     if (isInclude) {
         addPackages(builder, options.getIncludePackage(), true);
         // adds pendingPerAppPackages...
     }
     ```
   - *Risk*: In `include` mode, `addDisallowedApplication(getPackageName())` is *not* called (Android's `VpnService.Builder` throws `IllegalArgumentException` if both allowed and disallowed methods are called). If the include package list ever contains `com.ninitux.vpnrouter`, outbound traffic will route into `tun0`, causing an immediate routing loop. (While `AppListLoader.cs` filters our package, crafted configuration intents could bypass this).

6. **Network Callback Handler Head-of-Line Blocking (`VpnRouterService.java:2014`)**:
   - Inside `fireUpdate`:
     ```java
     for (int attempt = 0; attempt < 10 && index < 0; attempt++) {
         // ...
         try { Thread.sleep(50); } catch (InterruptedException ignored) {}
     }
     ```
   - *Risk*: Retrying up to 10 times with `Thread.sleep(50)` blocks `netCallbackThread` for up to 500ms. Because `netCallbackThread` is a single-threaded looper, subsequent network capability changes or interface drops are delayed during this window.

7. **JSON Parse Vulnerability to Whitespace in Clash API Secret (`VpnRouterService.java:1174`)**:
   - `extractClashApiSecret` extracts `secret` via `ca.optString("secret", "")` without `.trim()`.
   - *Risk*: If a configuration contains trailing newlines or spaces in `secret`, the raw HTTP request header `Authorization: Bearer <secret>\r\n` can result in HTTP header injection or authentication failure.
