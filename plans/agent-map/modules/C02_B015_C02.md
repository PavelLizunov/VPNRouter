# Exhaustive Code Inventory & Audit: Core Models Subsystem (Module C02 / Batch B015_C02)

## 1. SUMMARY & PURPOSE

Module **C02** encompasses the foundational data models, configuration schemas, runtime transfer objects (DTOs), and serialization ASTs for VPNRouter. These models represent the single source of truth for application configuration, sing-box daemon generation, routing decisions, DNS policies, profile structures, and external protocol integration (VLESS+Reality, Hysteria2, TUIC, Shadowsocks, NaiveProxy, AmneziaWG, and DNS-tunnel/slipstream).

### Component Roles & Responsibilities

1. **Top-Level Application Settings (`AppSettings.cs`, `AppConfig.cs`, `AppSettingsSane.cs`)**
   - **`AppSettings.cs`**: Root configuration container persisted to `%ProgramData%\VPNRouter\config.yaml`. Owns the persistent schema version (`CurrentSchemaVersion = 8`), application settings (`AppConfig`), server configurations (`VlessConfig`), network settings (`TunSettings`, `DnsSettings`), engine settings (`SingBoxSettings`, `MonitoringSettings`, `UpdateSettings`), and user profile definitions.
   - **`AppConfig.cs`**: Controls routing behavior (`RoutingMode`: "split" vs "full"; `RoutingAppsMode`: "include" vs "exclude"), UI preferences (theme, language, UI complexity mode), feature toggles (Russian traffic bypass, ad blocking, QUIC blocking, DNS leak lockdown), and external integration state (Zapret DPI bypass, MTProto proxy).
   - **`AppSettingsSane.cs`**: Post-deserialization null-safety sweep and canonicalization engine (`EnsureSane`). Ensures that missing or null YAML nodes do not trigger `NullReferenceException` in downstream view models or core services. Generates cryptographically secure Clash API bearer secrets on first load.

2. **Network & TUN Settings (`TunSettings.cs`, `EngineSettings.cs`)**
   - **`TunSettings.cs`**: Encapsulates TUN adapter interface parameters (MTU, IPv4 address, IPv6 enablement, auto-routing). Computes effective route-exclusion subnets (`GetEffectiveRouteExcludeAddress`), merging user-configured exclusions, mandatory RFC 1918/link-local networks, and transient auto-detected WireGuard/AmneziaWG subnets without persisting runtime state to disk.
   - **`EngineSettings.cs`**: Defines DNS strategy (`DnsSettings`), sing-box executable paths and Clash API settings (`SingBoxSettings`), health monitoring intervals and restart backoff thresholds (`MonitoringSettings`), and update channels (`UpdateSettings`).

3. **Proxy & Server Configuration (`VlessConfig.cs`, `VlessServerEntry.cs`, `SubscriptionEntry.cs`, `UserFreeSource.cs`)**
   - **`VlessConfig.cs`**: Manages manual and aggregated proxy servers. Implements server resolution logic (`GetEffectiveServers`, `GetActiveServers`), automatic failover pooling (`BuildAutoSelectPool`), and outbound detour chaining.
   - **`VlessServerEntry.cs`**: Universal proxy server model representing VLESS+Reality, Hysteria2 (Brutal CC & Salamander obfs), TUIC v5, Shadowsocks 2022 / ShadowTLS, NaiveProxy (HTTP/2 & HTTP/3), AmneziaWG (AWG2 / AWG3.1 obfuscation via `AwgConfig`), and DNS-tunnel slipstream transports.
   - **`SubscriptionEntry.cs`**: Holds subscription metadata (URL, update interval, tokenized user info) and cached offline server endpoints.
   - **`UserFreeSource.cs`**: Represents user-provided community subscription sources.

4. **Routing Rules & Profiles (`CustomRule.cs`, `CustomDirectRule.cs`, `Profile.cs`, `ProfileSource.cs`, `ProcessRule.cs`, `CustomCategory.cs`, `PerAppFilterMode.cs`, `ConnectionIntent.cs`)**
   - **`CustomRule.cs`**: Defines user-authored routing rules with explicit actions (`direct`, `proxy`, `block`) across domain, IP CIDR, port, process name, and geosite/geoip match criteria.
   - **`CustomDirectRule.cs`**: Legacy v2.29 direct-routing rule model preserved for schema migration.
   - **`Profile.cs` & `ProcessRule.cs`**: Defines application groups and process-matching criteria for split tunneling, including Android package support (`AndroidPackages`).
   - **`ProfileSource.cs`**: Specifies remote or local profile update sources.
   - **`CustomCategory.cs`**: Represents custom UI groupings of application executables.
   - **`PerAppFilterMode.cs`**: Pure helper class for 2-way projection between desktop routing modes ("split"/"full") and Android VpnService per-app filter tri-state ("off", "include", "exclude").
   - **`ConnectionIntent.cs`**: Categorizes user intent ("general", "gaming", "privacy", "compatibility") for automated server scoring.

5. **sing-box Configuration AST (`VPNConfig.cs`)**
   - **`VPNConfig.cs`**: Comprehensive strongly typed object graph mapping directly to sing-box 1.12+ JSON configuration schemas (`SingBoxConfig`, `SingBoxInbound`, `SingBoxOutbound`, `SingBoxRoute`, `SingBoxDns`, `SingBoxEndpoint`, `SingBoxExperimental`). Implements custom JSON conversion for `DomainResolverValue` to support legacy string and 1.13+ object dial formats.

6. **Diagnostics & Telemetry DTOs (`HealthAdvice.cs`, `CustomConfigEntry.cs`, `UpdateInfo.cs`)**
   - **`HealthAdvice.cs`**: Severity-rated troubleshooting advice records generated during health monitoring.
   - **`CustomConfigEntry.cs`**: Metadata pointing to user-imported custom sing-box JSON configurations.
   - **`UpdateInfo.cs`**: DTO conveying release metadata, checksums, and update package URLs.

## 4. CONCURRENCY, LOCKS & LIFECYCLE

### 4.1. Thread Safety Analysis of POCO Models
- All models across `VPNRouter.Core.Models` are plain C# objects (POCOs) with public mutable getters and setters.
- **No Internal Synchronization**: None of the models (`AppSettings`, `AppConfig`, `TunSettings`, `VlessConfig`, `VlessServerEntry`, etc.) encapsulate `lock`, `Monitor`, `SemaphoreSlim`, or `ReaderWriterLockSlim`.
- **Collection Race Risks**: Properties such as `VlessConfig.Servers`, `AppConfig.CustomRules`, `AppSettings.CustomGroupApps`, and `TunSettings.RouteExcludeAddress` expose mutable `List<T>` and `Dictionary<K,V>` instances. Modifying these collections from background telemetry or UI threads while `ConfigGenerator` or `LeakProtection` reads them causes `InvalidOperationException` ("Collection was modified; enumeration operation may not execute").
- **Synchronization Boundaries**: Concurrency control is entirely the responsibility of calling services (`SettingsLoader`, `VpnEngine`, `HealthMonitor`).

### 4.2. Model Immutability vs Mutability
- `HealthAdvice` is defined as an immutable `sealed record` with `init` properties, ensuring thread-safe publication across UI view models.
- `UpdateInfo` uses C# 9 `init` accessors, making instances immutable post-construction.
- `DomainResolverValue` is immutable in typical usage via the implicit string operator, though its properties retain public setters.
- All other configuration classes are fully mutable to support YamlDotNet and System.Text.Json property-based deserialization.

### 4.3. Lifecycle of Cryptographic Secrets
- `SingBoxSettings.ClashApiSecret` is generated lazily by `AppSettingsSane.EnsureSane()` using `RandomNumberGenerator`. Its lifecycle is tied to the persistent `AppSettings` instance and written to `config.yaml`.
- Ephemeral runtime collections (`TunSettings.AutoDetectedExcludeAddress`) are populated during network adapter discovery and cleared upon disconnection; they are explicitly excluded from serialization via `[YamlIgnore]` and `[JsonIgnore]`.

### 5.2. Privilege Boundaries & Path Expansion
- **Environment Variable Expansion**: Paths such as `AppConfig.LogFile` (`@"%ProgramData%\VPNRouter\logs\vpnrouter.log"`), `SingBoxSettings.ExecutablePath` (`@"%ProgramData%\VPNRouter\bin\sing-box.exe"`), and `CustomConfigEntry.Path` contain Windows environment variable placeholders (`%ProgramData%`). These models store unexpanded strings; expansion must occur at invocation boundaries via `Environment.ExpandEnvironmentVariables` to avoid path traversal or access denials.
- **Firewall & TUN Elevation**: `AppConfig.DnsLeakLockdown`, `TunSettings.Mtu`, and `TunSettings.InterfaceName` directly configure OS-level network stack objects requiring administrator (Windows) or root / `CAP_NET_ADMIN` (Linux) privileges.

### 5.3. Process Name Casing & sing-box Compatibility Invariant
- sing-box Go core performs exact map lookups on process names extracted from kernel sockets using `filepath.Base`.
- On Windows, `QueryFullProcessImageName` returns filesystem casing (e.g. `Discord.exe`).
- **Critical Invariant**: Models storing process names (`AppConfig.RoutingAppsInclude`, `AppConfig.RoutingAppsExclude`, `AppSettings.CustomApps`, `AppSettings.ExcludedApps`, `ProcessRule.Name`) must **preserve original casing**. Case normalization (e.g., `ToLowerInvariant()`) is strictly prohibited, as it breaks sing-box rule matching.

## 6. SUSPICIOUS PATTERNS & DEFECT CANDIDATES

### 6.1. Defect Candidate: Incomplete Null Sanitization in `EnsureSaneServerEntry` for DNS-Tunnel Lists
- **File**: `VPNRouter.Core/Models/AppSettingsSane.cs`
- **Lines**: 150–156
- **Evidence**:
  ```csharp
  private static void EnsureSaneServerEntry(VlessServerEntry s)
  {
      s.Reality   ??= new VlessRealityConfig();
      s.Tls       ??= new VlessTlsConfig();
      s.Transport ??= new VlessTransportConfig();
      s.Transport.Headers ??= new Dictionary<string, string>();
  }
  ```
- **Vulnerability / Impact**: While `Reality`, `Tls`, `Transport`, and `Headers` are protected against null, the DNS-tunnel collections on `VlessServerEntry` (`DnsResolvers` and `DnsAuthoritative`) are **not** checked. If a YAML file contains `dns_resolvers:` with no children or bare `-` items, YamlDotNet deserializes them as null or containing null items. Downstream code iterating over `server.DnsResolvers` will encounter a `NullReferenceException`.
- **Recommendation**: Add `s.DnsResolvers ??= new List<string>(); s.DnsResolvers.RemoveAll(x => x == null!);` and equivalent for `DnsAuthoritative`.

---

### 6.2. Defect Candidate: Case-Sensitive Ordinal Equality in Server Sibling Matching
- **File**: `VPNRouter.Core/Models/VlessConfig.cs`
- **Lines**: 142–143
- **Evidence**:
  ```csharp
  var activeIp = active.Server;
  return all.Where(s => s.Server == activeIp && string.IsNullOrEmpty(s.DetourVia)).ToList();
  ```
- **Vulnerability / Impact**: The equality comparison `s.Server == activeIp` is an ordinal, case-sensitive string comparison. If a subscription publishes mixed-case hostnames (e.g., `Node1.Example.com` vs `node1.example.com`), TCP/UDP sibling pairing fails silently, resulting in UDP traffic not being paired or the sibling being omitted. Furthermore, if two unrelated servers in a large subscription share an IP address on different ports or different UUIDs, `GetActiveServers()` unintentionally groups both into the active configuration.
- **Recommendation**: Use `string.Equals(s.Server, activeIp, StringComparison.OrdinalIgnoreCase)`.

---

### 6.3. Defect Candidate: Untrimmed String Retention in `GetEffectiveRouteExcludeAddress`
- **File**: `VPNRouter.Core/Models/TunSettings.cs`
- **Lines**: 100–107
- **Evidence**:
  ```csharp
  if (RouteExcludeAddress != null)
  {
      foreach (var s in RouteExcludeAddress)
      {
          if (string.IsNullOrWhiteSpace(s)) continue;
          if (seen.Add(s.Trim())) result.Add(s);
      }
  }
  ```
- **Vulnerability / Impact**: `seen.Add(s.Trim())` correctly records the trimmed subnet in the deduplication set, but `result.Add(s)` appends the original untrimmed string `s`. If the user has leading or trailing spaces in `config.yaml` (e.g. `" 192.168.1.0/24 "`), the un-sanitized string with spaces is emitted into `SingBoxInbound.RouteExcludeAddress`. sing-box's CIDR parser rejects subnets with whitespace on startup with fatal parse errors.
- **Recommendation**: Append `s.Trim()` to `result`.

---

### 6.4. Defect Candidate: Ephemeral Clash API Secret Desynchronization Across Processes
- **File**: `VPNRouter.Core/Models/AppSettingsSane.cs`
- **Lines**: 43–44
- **Evidence**:
  ```csharp
  if (string.IsNullOrEmpty(settings.SingBox.ClashApiSecret))
      settings.SingBox.ClashApiSecret = GenerateClashApiSecret();
  ```
- **Vulnerability / Impact**: If `config.yaml` is located in a read-only directory or if saving fails due to file-lock contention during first startup, `App` (GUI) and `Service` (Windows Service) each execute `EnsureSane` independently and generate different ephemeral 32-hex tokens. The GUI becomes permanently unable to authenticate with sing-box's Clash REST API (`HTTP 401 Unauthorized`), causing health checks and hot-reloads to fail.
- **Recommendation**: Surface secret persistence failures as a logged warning or explicitly verify file-write roundtripping.

### 6.5. Defect Candidate: Missing `[JsonPropertyName]` on Legacy `CustomDirectRule`
- **File**: `VPNRouter.Core/Models/CustomDirectRule.cs`

- **Evidence**:

### 7.2. Identified Test Gaps

1. **Untrimmed Whitespace in `TunSettings.RouteExcludeAddress`**:
   - No test currently asserts that subnets with leading/trailing spaces in `TunSettings.RouteExcludeAddress` do not propagate raw whitespace into the generated sing-box inbound configuration.
2. **Null DNS-Tunnel Collections in `AppSettingsSane`**:
   - Existing `EnsureSane` tests do not test an input `VlessServerEntry` with null `DnsResolvers` or null `DnsAuthoritative`.
3. **Casing Discrepancies in `VlessConfig.GetActiveServers`**:
   - No test verifies behavior when server hostnames share identical letters with differing casing (e.g. uppercase vs lowercase).
4. **Duplicate IP Servers with Different Ports in `VlessConfig`**:
   - No test pins whether multiple distinct proxy endpoints sharing an IP address (e.g., ports 443, 8443, 2083) are erroneously co-selected by `GetActiveServers()` when `AutoSelectBestServer == false`.
5. **System.Text.Json Deserialization of `DomainResolverValue` Object Form**:
   - `DomainResolverValueConverter` has unit tests for string round-tripping, but lacks test coverage for parsing unexpected JSON token types (e.g. integer or boolean inputs) to verify fallback and reader skipping safety.

## 8. CONCLUSION

Module C02 represents a robust, highly evolved configuration and model foundation that has successfully navigated eight schema versions (`CurrentSchemaVersion = 8`). The adoption of build-time source generation (`YamlStaticContext` and `AppJsonContext`) provides excellent NativeAOT compatibility, low-allocation parsing, and strong compile-time type safety.
