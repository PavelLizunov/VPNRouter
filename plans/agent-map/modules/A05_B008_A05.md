> **TL;DR:** Module A05 encompasses the application shell, startup bootstrap, cross-platform lifecycle, XAML value converters, simple-mode input classification, and view resolution for `VPNRouter.App`. Critical findings include argument injection vulnerability during Windows UAC self-elevation due to naive string formatting, dynamic theme invalidation failure in token brush converters (`ActionToTokenBrushConverter`, `BoolToBrushConverter`), a complete naming-convention mismatch rendering `ViewLocator` ineffective for all application views, ThreadPool thread starvation during snapshot cleanup sleep, and unmanaged `WindowIcon` handle leaks on theme switching in the system tray.

## 1. SUMMARY & PURPOSE

Module A05 provides the primary execution entry point, process bootstrap orchestration, application lifecycle management, desktop shell integration (system tray, window visibility, shell verb queuing), XAML data-binding converters, input format classification, and dynamic view template location for the `VPNRouter.App` desktop client.

### Component Roles & Responsibilities

1. **`Program.cs` (Process Entry Point & Startup Pipeline Orchestrator)**
   - Acts as the Win32/POSIX `Main` entry point with `[STAThread]`.
   - Intercepts Unix-owned root helper dispatch (`UnixOwnedProcessSignal.TryHandleHelper`).
   - Installs the emergency global crash reporter (`CrashReporter.Install`).
   - Parses top-level CLI flags (`--minimized`, `--safe`, `--reset`, `--route-app`, `--unroute-app`, `--category`).
   - Enforces administrative privilege elevation on Windows via `runas` ProcessStartInfo.
   - Manages startup recovery tiers driven by `LaunchFailureCounter` (web self-repair, config reset, safe-mode prompt).
   - Coordinates single-instance lifecycle (`SingleInstance`), pre-update rollback verification, DLL version consistency checks (`InstallHealthCheck`), service path self-healing (`WindowsServiceHelper`), shortcut repairs, and firewall orphan rule sweeps on launch and process termination.
   - Configures the Avalonia application builder with font rendering (`WithInterFont`), platform detection, and trace logging.

2. **`App.axaml.cs` & `App.axaml` (Avalonia Application & Desktop Shell Coordinator)**
   - Subclasses Avalonia's `Application`, loading XAML resources and theme styles (`Tokens.axaml`, Twemoji COLR/CPAL flags, `FluentTheme`, `TabStripPill` styles).
   - Manages `IClassicDesktopStyleApplicationLifetime`, setting `ShutdownMode.OnExplicitShutdown`.
   - Constrains SkiaSharp's native font cache (4 MB byte limit, 64 entry limit) to avoid unbounded process memory growth.
   - Instantiates root ViewModel (`MainWindowViewModel`) and `MainWindow`, establishing the root `DataContext`.
   - Hooks window lifecycle events (`Closing` cancelled to hide to tray; `ShutdownRequested` to execute teardown).
   - Manages the OS system tray (`TrayIcon`, `NativeMenu`), handling dynamic theme variant icon swaps (white vs black lineart across Windows/macOS/Linux) and connection state reflecting.
   - Registers Windows Explorer shell verbs (`ShellMenuRegistrar`) with user-defined application categories.
   - Connects IPC single-instance events (`ShowWindowRequested`, `RouteAppRequested`, `UnrouteAppRequested`) to the UI thread and drains pending startup verbs.

3. **`Converters.cs` (XAML Data-Binding Value Converters)**
   - Houses 8 implementations of Avalonia's `IValueConverter`:
     - `BoolToStatusColorConverter`: Maps connection status boolean to hardcoded green/zinc `SolidColorBrush`.
     - `BoolToLangConverter`: Maps boolean to `"EN"` or `"RU"`.
     - `BoolToFontWeightConverter`: Maps boolean to `FontWeight.Bold` or `FontWeight.Normal`.
     - `BoolToChevronConverter`: Configurable chevron glyph alternator (`"▲|▼"` or `"▽|›"`).
     - `BoolTo10or05Converter`: Maps boolean to opacity `1.0` or `0.5` for full-tunnel visual dimming.
     - `FullTunnelCursorConverter`: Maps boolean to `StandardCursorType.No` or `StandardCursorType.Arrow`.
     - `ActionToTokenBrushConverter`: Maps routing action (`direct`/`proxy`/`block`) and role (`Bg`/`Fg`/`Border`) to active theme resource brushes.
     - `BoolToBrushConverter`: Maps boolean to paired resource brushes (`"ActiveKey|InactiveKey"` or `"Transparent"`).

4. **`SimpleInputDetector.cs` (Input Classifier for Simple Mode)**
   - Provides zero-allocation, prefix-based, network-free classification of raw user-pasted input strings into the `SmpInputKind` enum (`Invalid`, `ServerUri`, `SubscriptionUrl`).
   - Recognizes multi-protocol share-link URI schemes: `vless://`, `hysteria2://`, `hy2://`, `tuic://`, `ss://`, `naive://`, `naive+https://`, `naive+quic://`, `dns-tunnel://`, `awg://`, `amneziawg://`, and HTTP/HTTPS subscription endpoints.

5. **`ViewLocator.cs` (Convention-Based DataTemplate Locator)**
   - Standard Avalonia template resolver implementing `IDataTemplate`.
   - Inspects bound ViewModel types, attempts reflection-based string replacement (`"ViewModel"` → `"View"`), and dynamically instantiates matching controls.

## 4. CONCURRENCY, LOCKS & LIFECYCLE

### 4.1. Single-Instance & Cross-Process Synchronization
- **Global Mutex (`SingleInstance`)**:
  - `Program.cs` invokes `SingleInstance.TryAcquireOrSignal(Log.Logger)`. If ownership cannot be claimed, the current process immediately terminates.
  - Lifecycle guarantee: `desktop.Exit += (_, _) => SingleInstance.Release();` guarantees the mutex is freed on clean Avalonia application exit.
- **LockFile Crash Sentinel (`LockFile`)**:
  - `App.axaml.cs` calls `LockFile.DetectPreviousCrash()` on startup, then immediately invokes `LockFile.Acquire()`.
  - On `desktop.ShutdownRequested`, `LockFile.Release()` removes the sentinel. Abnormal termination (SIGKILL, BSOD, power loss) leaves the sentinel on disk to alert the user on the next run.

### 4.2. Threading Model & UI Dispatcher Handoffs
- **Thread Boundary Handoff**:
  - Named pipe IPC events in `SingleInstance` (`ShowWindowRequested`, `RouteAppRequested`, `UnrouteAppRequested`) dispatch onto Avalonia's UI thread via `Dispatcher.UIThread.Post`.
  - In `App.axaml.cs`, the event handlers directly manipulate UI controls (`WindowForegroundHelper.BringToFront(desktop.MainWindow)`) and ViewModel collections (`RouteAppFromShell`), safely residing on the UI thread.
- **Background Task Thread Starvation (`Program.cs:357-368`)**:
  - When cleaning up the pre-update backup snapshot:
    ```csharp
    System.Threading.Tasks.Task.Run(() =>
    {
        try
        {
            System.Threading.Thread.Sleep(TimeSpan.FromSeconds(30));
            VPNRouter.Core.Services.UpdateBackup.DeleteSnapshot(...);
        }
        catch { }
    });
    ```
  - **Defect:** Synchronously blocks a ThreadPool worker thread with `Thread.Sleep(30000)` instead of using non-blocking asynchronous delay (`await Task.Delay(30000)`).

### 4.3. Window & Tray Teardown Guarantees
- **`ShutdownMode.OnExplicitShutdown`**:
  - Windows closing is intercepted: `mainWindow.Closing += (_, e) => { e.Cancel = true; mainWindow.Hide(); };`.
  - The application process never exits upon closing the main window; it remains resident in the notification area / system tray.
  - Process exit only occurs when `QuitCommand` or `desktop.Shutdown()` is explicitly dispatched.
- **ProcessExit Firewall Rule Sweep (`Program.cs:466-478`)**:
  - `AppDomain.CurrentDomain.ProcessExit` registers a hook to sweep orphaned firewall block rules (`FirewallManager.TryCleanupOrphanedRulesSafe`), preventing network lockups if the process is terminated while holding WFP rules.
  - Guarded by `!TunOwnershipLock.IsOwnedByAnyone()` to ensure GUI closing in Windows Service mode does not destroy the active background service's rules.

## 5. SECURITY & PRIVILEGE BOUNDARIES

### 5.1. Privilege Elevation & Injection Vulnerabilities
1. **Windows Self-Elevation (`Program.cs:134-171`)**:
   - Executes when `OperatingSystem.IsWindows() && !IsAdmin()`.
   - Spawns the current process path with `Verb = "runas"`, prompting the Windows UAC consent/credential dialog.
   - **Vulnerability:** Arguments are formatted via:
     ```csharp
     Arguments = string.Join(" ", args.Select(a => $"\"{a}\""))
     ```
     This naive quoting does not escape internal double quotes (`"`) or trailing backslashes preceding quotes (`\"`). An unprivileged local caller or shell shortcut invoking `VPNRouter.App.exe` with crafted parameters can inject arbitrary command-line switches into the elevated process token.
   - **Failure Logging:** If elevation is rejected by the user or policy, error details are appended to `%CommonApplicationData%\VPNRouter\logs\vpnrouter-launch-error.log` (accessible machine-wide).

2. **Safe Mode Enforcement (`Program.cs:76-103`)**:
   - Setting `--safe` triggers `SafeMode.Enabled = true`.
   - Before executing configuration parsing, snapshots `config.yaml` to `config.yaml.backup-before-safemode-<stamp>`.
   - Bypasses untrusted or corrupted external YAML profile sources, preventing malformed routing scripts or crash loops from locking the user out.

### 5.2. Input Sanitization & Classification Attack Surface
1. **Simple Input Classification (`SimpleInputDetector.cs`)**:
   - Zero regex engine usage protects against Regular Expression Denial of Service (ReDoS) from maliciously crafted inputs.
   - Restricts classification purely to invariant ordinal prefix checks (`StringComparison.OrdinalIgnoreCase`).
   - Delegates complex URI parameter parsing to downstream domain parsers (`ServerUriParser`), isolating intake from semantic parsing.

2. **Shell Verbs & Named Pipe Routing Paths (`Program.cs`, `App.axaml.cs`)**:
   - Shell verb targets passed via `--route-app "<path>"` or `--unroute-app "<path>"` are checked against `TryGetArgValue`.
   - Passed via IPC named pipe to running instance or stashed in `PendingRouteAppPath`.
   - Paths are resolved inside `RouteAppFromShell` which sanitizes executable paths and filters invalid binaries.

### 6.2. Detailed Defect Analysis

#### DEF-A05-01: Insecure Argument Quoting in Windows Admin Self-Elevation
- **Location:** `VPNRouter.App/Program.cs:142`
- **Mechanism:**
  ```csharp
  var psi = new ProcessStartInfo
  {
      FileName = Environment.ProcessPath!,
      Arguments = string.Join(" ", args.Select(a => $"\"{a}\"")),
      UseShellExecute = true,
      Verb = "runas"
  };
  Process.Start(psi);
  ```
  When the application detects it is not running under an elevated token on Windows, it re-spawns itself with `Verb = "runas"`. The command-line string is constructed by wrapping each argument in quotes: `$"\"{a}\""`. If an argument contains an embedded double-quote (e.g. `--route-app "C:\Games \"Test\"\game.exe"`), or ends with a backslash before the closing quote (`C:\Path\`), the Windows command-line parser unescapes the quotes, corrupts the token boundary, and permits injection of additional CLI flags (e.g. injecting `--reset` or custom paths into the elevated instance).
- **Remediation:** Escape embedded double quotes and backslashes properly, or use Windows API `CommandLineToArgvW` escaping conventions:
  ```csharp
  static string EscapeArg(string arg) =>
      "\"" + arg.Replace("\\", "\\\\").Replace("\"", "\\\"") + "\"";
  ```

#### DEF-A05-02: Stale Brushes on Theme Variant Change in Token Brush Converters
- **Location:** `VPNRouter.App/Converters.cs:143-148, 180-185`
- **Mechanism:**
  ```csharp
  var app = Avalonia.Application.Current;
  if (app != null
      && app.TryGetResource(key, app.ActualThemeVariant, out var res)
      && res is IBrush brush)
      return brush;
  ```
  `ActionToTokenBrushConverter` and `BoolToBrushConverter` inspect `app.ActualThemeVariant` at the moment `Convert` is called. However, Avalonia bindings using `IValueConverter` do not establish dynamic resource listeners on the visual tree. When the user changes the system or app theme between Light and Dark, `ActualThemeVariantChanged` is raised, but already-rendered controls (such as the action chips in Network → Rules) will not re-trigger `Convert`. The brushes remain frozen in the previous theme's color until the view model property changes or visual items are recycled.
- **Remediation:** In XAML, bind controls using dynamic resource references or `ThemeVariantScope`, or implement an `IMultiValueConverter` that accepts `ActualThemeVariant` as a binding source.

#### DEF-A05-03: ViewLocator Naming Convention Mismatch & Trimming Vulnerability
- **Location:** `VPNRouter.App/ViewLocator.cs:22-28`
- **Mechanism:**
  ```csharp
  var name = param.GetType().FullName!.Replace("ViewModel", "View", StringComparison.Ordinal);
  var type = Type.GetType(name);
  if (type != null)
      return (Control)Activator.CreateInstance(type)!;
  return new TextBlock { Text = "Not Found: " + name };
  ```
  `ViewLocator` is registered as the default application data template in `App.axaml`. However:
  1. Across the entire `VPNRouter.App` project, not a single View ends in `"View"`. All views are named `<Name>Page` (`SimplePage`, `ServersPage`, `NetworkPage`, etc.) or `<Name>Window` (`MainWindow`, `AboutWindow`, `SetupWizardWindow`).
  2. If any ViewModel is bound to a `ContentControl` relying on `ViewLocator`, `Type.GetType(name)` will return `null` every time, rendering an error `TextBlock` `"Not Found: VPNRouter.App.ViewModels.XxxView"`.
  3. `[RequiresUnreferencedCode]` indicates that under single-file trimmed publishing, reflection-based instantiation is unsafe.
- **Remediation:** Update `ViewLocator` to support the actual project conventions (`ViewModel` → `Page` / `Window`), or remove it from `App.axaml` since pages and dialogs are already instantiated explicitly or templated inline.

#### DEF-A05-04: ThreadPool Worker Thread Block in Snapshot Cleanup
- **Location:** `VPNRouter.App/Program.cs:363`
- **Mechanism:**
  ```csharp
  System.Threading.Tasks.Task.Run(() =>
  {
      try
      {
          System.Threading.Thread.Sleep(TimeSpan.FromSeconds(30));
          VPNRouter.Core.Services.UpdateBackup.DeleteSnapshot(installDir, cleanupGeneration);
      }
      catch { }
  });
  ```
  `Task.Run` queues work onto the .NET ThreadPool. Calling synchronous `Thread.Sleep(TimeSpan.FromSeconds(30))` holds a thread hostage for 30 seconds during application launch.
- **Remediation:** Replace with non-blocking async delay:
  ```csharp
  System.Threading.Tasks.Task.Run(async () =>
  {
      try
      {
          await System.Threading.Tasks.Task.Delay(TimeSpan.FromSeconds(30));
          VPNRouter.Core.Services.UpdateBackup.DeleteSnapshot(installDir, cleanupGeneration);
      }
      catch { }
  });
  ```

#### DEF-A05-05: WindowIcon Handle Leak on Theme Change in `SetupTrayIcon`
- **Location:** `VPNRouter.App/App.axaml.cs:266`
- **Mechanism:**
  ```csharp
  ActualThemeVariantChanged += (_, _) =>
  {
      try
      {
          if (_trayIcon != null)
          {
              _trayIcon.Icon = new WindowIcon(AssetLoader.Open(new System.Uri(GetTrayIconUri(ActualThemeVariant))));
          }
      }
      catch { }
  };
  ```
  Each time the desktop theme variant switches, `AssetLoader.Open()` returns a new unmanaged resource stream, which is passed to `new WindowIcon(...)`. The previously assigned `WindowIcon` and its underlying native icon handle / stream are never disposed, leaking unmanaged resources over long-running sessions with repeated theme toggles.
- **Remediation:** Cache the two `WindowIcon` instances (`penguin_mascot.ico` and `penguin_mascot_white.ico`) statically or dispose the old icon.
