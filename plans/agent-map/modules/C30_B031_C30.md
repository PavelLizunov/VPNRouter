> **TL;DR:** Module C30 audits the Core Slipstream, TgProxy, and Zapret supporting service tier in `VPNRouter.Core`. It encapsulates transport-layer DNS-tunnel sidecar management (`SlipstreamManager`), MTProto WebSocket proxy lifecycle and background execution (`TgProxyManager`, `TgProxyPortConflictException`), pinned integrity runtime installation (`TgProxyUpdater`), and Flowseal Zapret utility/diagnostic actions (`ZapretActions`). The audit identified multiple concrete defect candidates: sync-over-async thread pool starvation (`.GetAwaiter().GetResult()` in `SlipstreamManager`, `TgProxyManager`, and `ZapretActions`), missing lifecycle concurrency synchronization in `SlipstreamManager`, flawed ANSI escape sequence stripping regex in `SlipstreamManager`, CLI secret exposure in process tables (`TgProxyManager`), unpinned floating-branch downloads in `ZapretActions`, potential file-locking failures during in-place TgProxy updates, and mutable static test seams across `ZapretActions` and `TgProxyManager`.

# Exhaustive Code Inventory & Audit: Core Slipstream, TgProxy, Zapret Supporting Services (Module C30 / Batch B031_C30)

## 1. SUMMARY & PURPOSE

Module C30 delivers specialized sidecar process management, runtime binary provisioning, integrity validation, diagnostic tooling, and helper actions for three distinct circumvention and proxy subsystems within VPNRouter:
1. **Slipstream DNS-Tunnel Subsystem**: Covert transport dependency enabling sing-box VLESS connections over heavily restricted networks (such as Russian mobile whitelists).
2. **TgProxy Subsystem**: Standalone, headless MTProto WebSocket proxy daemon (`tg-ws-proxy`) powered by an embedded Python distribution, providing censorship bypass for Telegram Desktop without requiring full VPN tunnel engagement.
3. **Zapret Actions Subsystem**: Diagnostic inspection, cache maintenance, service configuration, and hosts/IPSet updates supporting Flowseal's DPI bypass toolkit (`winws.exe`).

### Component Roles & Responsibilities

1. **`SlipstreamManager.cs` (`VPNRouter.Core.Services.SlipstreamManager`)**
   - **Role**: Manages the lifecycle of `slipstream-client`, a high-performance Rust daemon implementing covert DNS-tunneling (encapsulating QUIC/VLESS streams within standard DNS queries).
   - **System Criticality**: Unlike independent sidecars (TgProxy or Zapret), Slipstream is a **strict transport dependency** of the VPN connection. sing-box's VLESS outbound dials the local loopback front (default `127.0.0.1:7001`). `VpnEngine` starts `SlipstreamManager` *before* launching `sing-box` and stops it *after*. If `SlipstreamManager` fails to spawn, bind, or stay alive, it throws, causing `VpnEngine` to **fail closed** and abort VPN startup.
   - **Certificate & Cryptography**: Extracts the leaf PEM certificate from `VlessServerEntry.DnsLeafCertPem`, writes it to disk at `AppPaths.SlipstreamActiveCertPath`, passes `--cert` to the client, and verifies the optional SHA-256 fingerprint (`DnsLeafFingerprint`) against the decoded DER bytes.
   - **Resolver Resolution**: Implements operator-agnostic whitelist bypass (`DnsUseSystemResolver`). Probes physical OS NIC DNS resolvers before the sing-box TUN interface comes up, falling back to profile literals if system resolvers cannot be discovered.
   - **Binary Provisioning**: Auto-promotes installer-bundled binaries from `AppPaths.SlipstreamBundledExePath` (`app/`) to the runtime directory in `ProgramData` upon launch if missing or if binary file size mismatches (version-aware update mechanism).
   - **Logging & Diagnostics**: Captures both stdout and stderr to a dedicated, rotated, 8 MB-capped log file (`AppPaths.SlipstreamLogPath`), while feeding a 16 KB ring-buffer for early-exit error attribution.

2. **`TgProxyManager.cs` (`VPNRouter.Core.Services.TgProxyManager`)**
   - **Role**: Manages the headless process lifecycle of `tg-ws-proxy` running under an embedded Python 3.12 interpreter (`python.exe -m proxy.tg_ws_proxy --port <port> --secret <secret>`).
   - **Process Model**: Fully headless daemon with no GUI, no system tray icon, and no user-interactive prompts. Controlled via `Start()`, `Stop()`, and `Dispose()`.
   - **Telemetry & State**: Subscribes to child process stdout/stderr streams to parse live throughput and connection metrics (`stats: total=X active=Y ws=Z`), exposing them via the `StatsUpdated` event.
   - **Safety & Pre-flight**: Probes loopback port availability before spawn (`IsPortAvailable`), resolving conflicting process ownership hints via `netstat` on Windows. Redacts secret tokens from logs and ProcessStartInfo diagnostic strings. Provides Telegram Desktop URI scheme registration checks and deep-link generation (`tg://proxy?...`).

3. **`TgProxyPortConflictException.cs` (`VPNRouter.Core.Services.TgProxyPortConflictException`)**
   - **Role**: Specialized typed exception thrown when `TgProxyManager.Start` detects that the target TCP port (default 1443) is already bound by another process.
   - **UI Decoupling**: Encapsulates the conflicting port number and an optional process owner hint (e.g., `"python.exe (PID 1234)"`), allowing presentation layers (`VPNRouter.App`) to catch the specific exception and display user-friendly, localized toast notifications rather than generic crash dialogs.

4. **`TgProxyUpdater.cs` (`VPNRouter.Core.Services.TgProxyUpdater`)**
   - **Role**: Automated provisioning and update pipeline for the complete Python runtime, third-party Python dependencies, and `tg-ws-proxy` source code.
   - **Cryptographic Pinning**: Downloads Python 3.12.7 embeddable zip from `python.org` and verifies against a hardcoded SHA-256 digest (`0d57bb6...`). Downloads wheels (`pycparser`, `cffi`, `cryptography`, `certifi`) from PyPI and verifies against hardcoded digests. Downloads proxy source from GitHub tag `v1.10.0` and verifies against a hardcoded SHA-256 digest (`62193af...`).
   - **Atomic Activation & Smoke Testing**: Extracts dependencies to staging directories, executes an in-process Python probe (`import ...`) via `_processRunner` to verify interpreter health, and performs atomic folder swaps (`Directory.Move`) with rollback capabilities.

5. **`ZapretActions.cs` (`VPNRouter.Core.Services.ZapretActions`)**
   - **Role**: Pure C# reimplementation of Flowseal's batch/shell utilities for Zapret DPI circumvention (`winws.exe`).
   - **Capabilities**:
     - Discord process tree termination and cache deletion (`Cache`, `Code Cache`, `GPUCache`).
     - System diagnostics: checks Base Filtering Engine (BFE), Windows proxy settings, TCP timestamps via `netsh`, conflicting background services (`AdguardSvc`, `SmartByte`, `GoodbyeDPI`, etc.), and hosts file health.
     - Hosts file and IPSet list updates from Flowseal's GitHub repository.
     - Zapret configuration flags: Game filter mode (`game_filter.enabled`) and IPSet filtering mode (`ipset-all.txt`).
     - Network diagnostics via PowerShell script execution (`test zapret.ps1`) and service menu elevation via UAC (`service.bat`).
     - Service teardown: removal of `zapret`, `WinDivert`, and `WinDivert14` Windows services via `sc.exe`.

### 3.1. Slipstream DNS-Tunnel Lifecycle & Data Flow

```
[VlessServerEntry]
       │
       ├─► Validation (Protocol == "dns-tunnel", DnsDomain, DnsLeafCertPem)
```

## 4. CONCURRENCY, LOCKS & LIFECYCLE

### Synchronization Mechanisms Matrix

| Class | Synchronization Object | Scope | Protected Resources | Potential Hazards |
|---|---|---|---|---|
| `SlipstreamManager` | `_stderrGate` (instance object) | Instance methods (`Start`, `OnErrorLineHandler`) | `_capturedStderr` (`StringBuilder`) | Threadpool event callbacks race with `Start()` reading stderr buffer. |
| `SlipstreamManager` | `_transportLogGate` (static object) | Static methods (`AppendTransportLog`, `RotateTransportLog`) | `AppPaths.SlipstreamLogPath` file access | File locking contention across multiple instances or concurrent line writes. |
| `SlipstreamManager` | **None** (Missing Lifecycle Lock!) | Instance methods (`Start`, `Stop`, `Dispose`) | `_handle`, `LocalPort`, active certificate file | **Race Condition**: Concurrent `Start()` and `Stop()` can leave stranded processes or throw `NullReferenceException`. |
| `TgProxyManager` | `_lifecycleGate` (instance object) | Instance methods (`Start`, `Stop`, `Dispose`) | Process spawn, termination, handle disposal, `_activeSecret` | Locks calling thread during 2s startup watchdog or 3s stop wait barrier. |
| `TgProxyManager` | `_stderrGate` (instance object) | Instance methods (`Start`, `OnErrorLineHandler`) | `_capturedStderr` (`StringBuilder`) | Synchronizes threadpool stderr lines into the 16 KB ring-buffer. |
| `ZapretActions` | **None** (Static mutable seams!) | Static properties (`Http`, `ProcessRunner`, `ScExecutablePath`) | Static test seams | Data races if parallel test fixtures mutate `ProcessRunner` concurrently. |

### Async/Await & Sync-Over-Async Hazards

1. **`SlipstreamManager.Start`**:
   - Line 330: `earlyExitCode = startedHandle.WaitForExitAsync(probeCts.Token).GetAwaiter().GetResult();`
   - **Hazard**: Synchronously blocks the calling thread during VPN startup. If executed on the UI thread or under synchronization contexts, risks thread pool starvation.
2. **`SlipstreamManager.Stop`**:
   - Line 455: `handle.WaitForExitAsync(stopCts.Token).GetAwaiter().GetResult();`
   - **Hazard**: Blocks for up to 3000 ms waiting for the child process to exit.
3. **`SlipstreamManager.IsPortListening`**:
   - Line 663: `client.ConnectAsync(IPAddress.Loopback, port).Wait(300)`
   - **Hazard**: Synchronous wait on `ConnectAsync`. If connection does not complete within 300ms, the underlying socket remains active until garbage collected, potentially leaking socket handles or throwing unobserved task exceptions upon disposal.
4. **`TgProxyManager.Start`**:
   - Line 212: `var exitCode = startedHandle.WaitForExitAsync(probeCts.Token).GetAwaiter().GetResult();`
   - **Hazard**: Synchronously blocks the thread for up to 2 seconds under `_lifecycleGate`.
5. **`TgProxyManager.Stop`**:
   - Line 539: `handle.WaitForExitAsync(stopCts.Token).GetAwaiter().GetResult();`
   - **Hazard**: Synchronously blocks for up to 3 seconds under `_lifecycleGate`.
6. **`ZapretActions` Service Queries**:
   - Lines 552, 615, 639, 663: `ServiceExists`, `IsServiceRunning`, `IsAnyServiceMatching`, and `RunNetsh` all call `_processRunner.RunAsync(...).GetAwaiter().GetResult()`.
   - **Hazard**: Completely synchronous execution model wrapping async process runner tasks.

### Teardown & Process Cleanup Guarantees

- **`SlipstreamManager`**:
  - `handle.SuppressExitedEvent()` is invoked prior to `handle.Kill(entireProcessTree: true)`. This prevents false-positive crash logging during intentional stops.
  - Active certificate file (`AppPaths.SlipstreamActiveCertPath`) is deleted unconditionally in `CleanActiveCert()`.
  - Disposes `_handle` in `finally` blocks.
- **`TgProxyManager`**:
  - `handle.SuppressExitedEvent()` is called before `handle.Kill(entireProcessTree: true)`.
  - If process fails to exit within 3s, the handle is **retained** rather than disposed, and `_disposed` remains `false`. This prevents orphaned zombies from being silently lost from tracking.
  - Legacy methods `KillAll` and `KillByPort` are converted to safe no-ops to prevent accidental kills of unrelated processes binding on port 1443.
- **`ZapretActions`**:
  - `ClearDiscordCacheAsync`: Captures all `Process.GetProcessesByName("Discord")` handles in an array and disposes the entire array inside a `finally` block on enumerator completion, preventing OS handle leaks even on early termination.

## 5. SECURITY & PRIVILEGE BOUNDARIES

### Elevation & UAC Requirements
1. **Flowseal Service Menu (`ZapretActions.OpenServiceMenu`)**:
   - Explicitly requests elevated privileges via `ProcessStartInfo.Verb = "runas"`.
   - Invokes `cmd.exe /k ""service.bat""` to preserve terminal output for the administrator.
2. **Zapret Service Removal (`ZapretActions.RemoveZapretServiceAsync`)**:
   - Executes `sc stop` and `sc delete` on Windows services. Requires local administrator privileges. If executed by an unprivileged user, `sc` fails with error code 5 (`Access is denied`), which is caught and surfaced in the diagnostic stream.
3. **PowerShell Execution (`ZapretActions.RunTests`)**:
   - Executes `powershell.exe -NoProfile -ExecutionPolicy Bypass -File "test zapret.ps1"`. Note that `ExecutionPolicy Bypass` circumvents standard Windows PowerShell script execution restrictions for the current user.

### Input Sanitization & Command Injection Defenses
1. **Metacharacter Blacklisting (`ZapretActions`)**:
   - `RunTests` and `OpenServiceMenu` inspect file paths before launching processes, throwing `ArgumentException` if the path contains any of: `\r`, `\n`, `&`, `|`, `^`, `<`, `>`, `%`, `"`.
2. **Process Argument Passing**:
   - `SlipstreamManager` and `TgProxyManager` pass arguments as typed lists (`List<string>`) via `ProcessRequest.Arguments`, relying on .NET's argument escaping rather than raw shell concatenation.
   - `ZapretActions.RunSc` and `RunNetsh` split strings on whitespace (`args.Split(' ', StringSplitOptions.RemoveEmptyEntries)`). While safe for fixed single-word arguments, it does not support quoted strings with spaces.

### Cryptographic Pinning & Supply Chain Defenses (`TgProxyUpdater`)
- **Python Runtime**: Pinned to SHA-256 `0d57bb6cb078b74d23dbfe91f77d6780d45bed328911609f1f7ee2ba1606bf44`.
- **PyPI Wheels**: Hardcoded SHA-256 verification before extraction for:
  - `pycparser 3.0`: `b727414169a36b7d524c1c3e31839a521725078d7b2ff038656844266160a992`
  - `cffi 2.1.1`: `f53e442b08449d42821fa4a4fba000095af9f62742a500f978a9f557ec44339a`
  - `cryptography 46.0.5`: `38946c54b16c885c72c4f59846be9743d699eee2b69b6988e0a00a01f46a61a4`
  - `certifi 2026.7.22`: `62f22742b58a1a33014a2b6b706588a8d7e2a88ae7bd1a6ebe8c992928483775`
- **Proxy Source**: GitHub tag `v1.10.0` pinned to SHA-256 `62193af82c97d494264a0c6b744b37a7670c458cd1492e5e9ef0235298156327`.
- **Integrity Enforcement**: `VerifyPinnedSha256Static` computes SHA-256 and throws `InvalidOperationException` on mismatch, failing closed before unpacking untrusted code.

### Redaction & Secret Sanitization
1. **TgProxy Secret Redaction (`TgProxyManager`)**:
   - `RedactSecretInArgs`: Scans argument strings and replaces `--secret <token>` with `--secret REDACTED` prior to logging `ProcessStartInfo`.
   - `RedactSensitiveOutput`: Replaces occurrences of the active secret in child process stderr with `REDACTED` and applies regex `(?i)(secret(?:=|:\s*))[^\s&]+` to catch alternate formatting.
2. **Process List Exposure**:
   - While arguments in logs are redacted, `python.exe` is launched with `--secret <secret>` in its command line. On Windows systems, any process running in the same user session can view command line arguments via WMI (`Win32_Process.CommandLine`) or `Process Explorer`.

## 6. SUSPICIOUS PATTERNS / DEFECT CANDIDATES

### Finding 1: Missing Lifecycle Lock in `SlipstreamManager` (Concurrency / Race Hazard)
- **Location**: `VPNRouter.Core/Services/SlipstreamManager.cs`, lines 92–104, 434–473
- **Description**: Unlike `TgProxyManager` which serializes all state transitions with `_lifecycleGate`, `SlipstreamManager` has no lock guarding `Start()`, `Stop()`, or `Dispose()`.
- **Impact**: If a user cancels VPN connection startup while `SlipstreamManager.Start()` is in the middle of its 2000 ms watchdog probe or file copying, and `VpnEngine.TeardownInternal` invokes `SlipstreamManager.Dispose()`, `Stop()` runs concurrently on another thread. `_handle` may be nulled or disposed out from under `Start()`, or a newly created process handle from `Start()` may overwrite the nulled field, leaving a stranded `slipstream-client.exe` process running in the background.

### Finding 2: Flawed ANSI Escape Stripping Regular Expression in `SlipstreamManager` (Bug)
- **Location**: `VPNRouter.Core/Services/SlipstreamManager.cs`, line 432
- **Code**:
  ```csharp
  private static string StripAnsi(string s)
      => System.Text.RegularExpressions.Regex.Replace(s, " \\[[0-9;]*m", "");
  ```
- **Description**: The regex pattern starts with a literal space followed by `\[` (`" \\[[0-9;]*m"`). Real ANSI terminal escape sequences generated by Rust `tracing_subscriber` start with the ASCII ESC character (`\x1b` or `\u001b`), not a space character!
- **Impact**: ANSI color escape codes (e.g. `\x1b[33m`, `\x1b[0m`) emitted by `slipstream-client` are **not** stripped from log files or console output unless they happen to be preceded by a space. This pollutes `slipstream.log` and the application log with raw escape characters.
- **Correction**: Should match `\x1b\[[0-9;]*m`.

### Finding 3: Unhandled Socket Lifetime in `SlipstreamManager.IsPortListening` (Resource / Exception Leak)
- **Location**: `VPNRouter.Core/Services/SlipstreamManager.cs`, lines 658–669
- **Code**:
  ```csharp
  internal static bool IsPortListening(int port)
  {
      try
      {
          using var client = new TcpClient();
          return client.ConnectAsync(IPAddress.Loopback, port).Wait(300) && client.Connected;
      }
      catch
      {
          return false;
      }
  }
  ```
- **Description**: `client.ConnectAsync(IPAddress.Loopback, port).Wait(300)` returns `false` if the connection attempt takes longer than 300 ms. However, exiting the `using` block immediately disposes `client` while the background `ConnectAsync` task is still active. On certain .NET runtime configurations, disposing a `Socket`/`TcpClient` with an in-flight asynchronous connect operation can trigger unobserved socket exceptions on the thread pool.
- **Impact**: Potential unobserved task exceptions or socket resource lingering during rapid port probing.

### Finding 4: Sync-Over-Async Thread Pool Starvation Across Service Layer (Performance / Scalability)
- **Locations**:
  - `SlipstreamManager.cs`: line 330 (`WaitForExitAsync(...).GetAwaiter().GetResult()`) and line 455.
  - `TgProxyManager.cs`: line 213 (`WaitForExitAsync(...).GetAwaiter().GetResult()`) and line 539.
  - `ZapretActions.cs`: lines 552, 615, 639, 663 (`_processRunner.RunAsync(...).GetAwaiter().GetResult()`).
- **Description**: Synchronous blocking on asynchronous tasks via `.GetAwaiter().GetResult()` or `.Wait()` blocks thread pool worker threads. In `ZapretActions`, simple diagnostic checks perform multiple sequential sync-over-async process executions (`sc query`), stalling the caller for hundreds of milliseconds.
- **Impact**: Degrades UI responsiveness if invoked on UI threads, increases latency, and risks thread pool starvation under load.

### Finding 5: Live File Locking During In-Place Update in `TgProxyUpdater` (Reliability Defect)
- **Location**: `VPNRouter.Core/Services/TgProxyUpdater.cs`, lines 389–432, 582–630
- **Description**: `TgProxyUpdater.DownloadAsync` performs dependency and source directory updates using `Directory.Move(currentLibDir, backupDir)` and `Directory.Move(currentProxyDir, backupDir)`. If `tg-ws-proxy` is currently running (either started by `TgProxyManager` or orphaned), Windows locks files in `PythonDir` (e.g., DLLs, `.pyd` extensions, `python.exe`).
- **Impact**: `Directory.Move` throws an `IOException` or `UnauthorizedAccessException`. While `TgProxyUpdater` has rollback logic, rollback also requires moving directories back, which may similarly fail, resulting in a corrupted installation where neither new nor old runtime is functional. `TgProxyUpdater` does not assert that the proxy process is stopped before attempting updates.

### Finding 6: Unpinned Floating Upstream Dependencies in `ZapretActions` (Security / Integrity Gap)
- **Location**: `VPNRouter.Core/Services/ZapretActions.cs`, lines 215, 423
- **Code**:
  ```csharp
  const string url = "https://raw.githubusercontent.com/Flowseal/zapret-discord-youtube/refs/heads/main/.service/hosts";
  ...
  const string url = "https://raw.githubusercontent.com/Flowseal/zapret-discord-youtube/refs/heads/main/.service/ipset-service.txt";
  ```
- **Description**: Unlike `TgProxyUpdater` (which strictly pins release tags and verifies SHA-256 hashes), `ZapretActions` fetches hosts and IPSet files directly from the floating `main` branch of `Flowseal/zapret-discord-youtube` without cryptographic hash verification.
- **Impact**: If the upstream repository is compromised, malicious DNS redirects or corrupted IPSet routing entries could be injected directly into the user's workflow without detection.

### Finding 7: UI Thread Dispatch Vulnerability in `TgProxyManager.StatsUpdated` (UI Stability)
- **Location**: `VPNRouter.Core/Services/TgProxyManager.cs`, lines 277, 308
- **Description**: `StatsUpdated?.Invoke(line)` is fired directly from `OnOutputLineHandler` and `OnErrorLineHandler`, which execute on thread pool threads managed by `IProcessHandle`.
- **Impact**: If presentation layer consumers (e.g. Avalonia ViewModels) bind directly to this event without dispatching through `Dispatcher.UIThread.Post(...)`, cross-thread UI mutations occur, leading to intermittent Avalonia visual crashes or property notification anomalies.

### Finding 8: Mutable Static Test Seams in `ZapretActions` (Test Concurrency Hazard)
- **Location**: `VPNRouter.Core/Services/ZapretActions.cs`, lines 19, 34, 540
- **Code**:
  ```csharp
  public static IHttpClient Http { get; set; } = PolicyHttpClient.Shared;
  internal static IProcessRunner ProcessRunner { get => _processRunner; set => ...; }
  internal static string ScExecutablePath { get; set; } = ...;
  ```
- **Description**: `Http`, `ProcessRunner`, and `ScExecutablePath` are mutable static properties with no lock synchronization.
- **Impact**: In xUnit, tests across different test classes run concurrently by default. If one test swaps `ZapretActions.ProcessRunner` to a `FakeProcessRunner` while another test executes a diagnostic method, non-deterministic test flakiness or cross-contamination occurs.
