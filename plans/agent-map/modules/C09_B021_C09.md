> **TL;DR:** Module C09 (`VPNRouter.Core/Services`: `LinuxTunOwnership`, `TunOwnershipLock`, `ProcessOwnership`, `UnixOwnedProcessSignal`) provides cross-platform mutual exclusion and multi-tier cryptographic/OS identity verification for the sing-box TUN tunnel. # Exhaustive Code Inventory & Audit: Core Process & TUN Ownership (Module C09 / Batch B021_C09)

## 1. SUMMARY & PURPOSE

Module C09 delivers the core synchronization, process identity tracking, and privileged process termination boundaries for the VPNRouter core runtime. It ensures that across multiple processes (`VPNRouter.App`, `VPNRouter.Service`, `VPNRouter.CLI`, and `VPNRouter.Headless`) and operating systems (Windows, Linux, macOS), exactly **one** process controls the virtual TUN interface and sing-box engine at any given time.

### Component Roles & Responsibilities

- **`LinuxTunOwnership.cs`**:
  - Implements Linux-specific interprocess mutual exclusion for host TUN device access using Linux advisory kernel file locks (`flock(LOCK_EX | LOCK_NB)`).
  - Enforces strict directory isolation to `/run/user/<euid>` (systemd `XDG_RUNTIME_DIR`), explicitly prohibiting fallback to overrideable application data directories (`AppPaths.DataDir`) to eliminate split-domain lock divergence.
  - Implements robust defense-in-depth against TOCTOU, symlink traversal, FIFO blocking, and unauthorized file tampering by combining non-blocking flags (`O_NONBLOCK | O_NOFOLLOW | O_CLOEXEC`) with kernel descriptor stat validation (`fstatx` / `statx` with `AT_EMPTY_PATH`).
  - Provides a non-destructive probe mechanism (`ProbeOwnership`) to observe global lock state without allocating or mutating filesystem entries.

- **`TunOwnershipLock.cs`**:
  - Serves as the cross-platform frontend and singleton manager for TUN mutual exclusion.
  - On Windows, controls a system-wide named semaphore (`Global\VPNRouter-SingBox-Owner`), coordinating unprivileged user sessions and the elevated `LocalSystem` Windows Service (`VPNRouter.Service`).
  - On Linux, encapsulates and delegates lifecycle management to `LinuxTunOwnership`.
  - Implements asynchronous child-process observation (`StartOwnerRecordMonitor`): when a process acquires TUN ownership, it continuously scans for the launched child executable and writes an authoritative v2 `runtime-owner.json` record, linking the TUN owner to its child process.
  - Implements non-intrusive lock peering (`ProbeOwnership` and `IsOwnedByAnyone`) enabling secondary instances to detect active tunnels and park in passive watcher mode.

- **`ProcessOwnership.cs`**:
  - Authoritative authority for sing-box process identification, tracking, and takeover/kill gating.
  - Implements schema v2 durable records (`runtime-owner.json`) binding owner PID, owner UTC start time ticks, child PID, child UTC start time ticks, and exact executable path.
  - Completely divorces static configuration (`config.yaml`) discovery from execution trust: configuration files serve solely as candidate hints; destructive operations (process termination, stop fallback) require strict validation against trusted binary directories (`AppPaths.BinDir`) or exact matching against the live, proven v2 runtime owner record.
  - Implements Windows-specific parentage validation (`NtQueryInformationProcess` / `ProcessBasicInformation`) and Linux `/proc/<pid>/stat` inspection to ensure child processes are bona-fide descendants of the tunnel owner.

- **`UnixOwnedProcessSignal.cs`**:
  - Implements race-free, PID-recycling-immune Linux process termination using modern kernel process file descriptors (`pidfd_open` syscall 434 and `pidfd_send_signal` syscall 424).
  - Binds the process descriptor *before* verifying process identity (`ProcessOwnership.TryReadOwnedSingBoxIdentity`), guaranteeing that the subsequent signal (SIGTERM 15 or SIGKILL 9) reaches the proven process even if the OS PID is recycled concurrently.
  - Exposes the internal helper entry point (`--vpnrouter-internal-signal-owned-v1`) utilized by elevated `sudo` or `pkexec` escalation chains to cleanly stop root-owned tunnel processes without granting general shell execution rights.

- `internal static UnixOwnedSignalResult SignalLinux(OwnedProcessIdentity expected, int signal)`:
  - *Contract*: Linux-only. Rejects non-Linux and signals other than 9 and 15 (`Unsupported`).
  - Step 1: Issues `PidFdOpen(434, expected.Pid, 0)`.
  - Step 2: Wraps handle in `SafePidFd`.
  - Step 3: Re-queries process identity via `Process.GetProcessById(expected.Pid)` and `ProcessOwnership.TryReadOwnedSingBoxIdentity(process)`.
  - Step 4: Compares `ProcessOwnership.IsSameProcessIdentity(expected, current.Value)`. Returns `IdentityMismatch` or `IdentityUnavailable` if identity changed.
  - Step 5: Issues `PidFdSendSignal(424, pidFd, signal, IntPtr.Zero, 0)`.
- `private static UnixOwnedSignalResult MapError(int errno)`:
  - *Contract*: Maps errno values `ESRCH` -> `TargetGone`, `EPERM` -> `AccessDenied`, `ENOSYS` -> `Unsupported`, default -> `Failed`.

#### Helper Types & P/Invokes
- `private sealed class SafePidFd : SafeHandleMinusOneIsInvalid`:
  - Wraps file descriptor; overrides `ReleaseHandle` calling `CloseFd(handle.ToInt32()) == 0`.
- Native P/Invokes (`libc`):
  - `int CloseFd(int fd)` (`EntryPoint = "close"`, `SetLastError = true`)
  - `long PidFdOpen(long number, int pid, uint flags)` (`EntryPoint = "syscall"`, `SetLastError = true`)

## 3. DATA FLOWS & STATE MACHINES

### 3.1. TUN Adapter Ownership & Mutual Exclusion State Machine

```
[Start / TryAcquire]
        │
        ├── Windows ──> Create Named Semaphore ("Global\VPNRouter-SingBox-Owner")
        │                     │
        │                     ├── WaitOne(0) == true ───> [OWNED] (Trigger Monitor)
        │                     ├── WaitOne(0) == false ──> [HELD_BY_ANOTHER] (Fail)
        │                     └── Exception ─────────────> [FAIL_OPEN] (Acquire assumed)
        │
        └── Linux ────> Validate /run/user/<euid> (statx: mode 0700, UID match, no symlinks)
                              │
                              ├── Invalid/Missing ───────> [UNAVAILABLE] (Fail Closed)
                              └── Valid ─────────────────> Open lockfile (O_RDWR|O_CREAT|O_NONBLOCK|O_NOFOLLOW|O_CLOEXEC, 0600)
                                                                │
                                                                ├── fstatx check (S_IFREG, UID match, mode 0600)
                                                                │         │
                                                                │         ├── Non-regular/symlink/lax ─> Close & [REJECT]
                                                                │         └── Valid ───────────────────> flock(LOCK_EX|LOCK_NB)
                                                                │                                             │
                                                                │                                             ├── flock == 0 ─────────> [OWNED]
                                                                │                                             ├── EWOULDBLOCK/EAGAIN ─> [HELD_BY_ANOTHER]
                                                                │                                             └── Errno ──────────────> [FAIL]
```

### 3.3. Safe Process Signaling & Termination Flow (Linux)

```
[SingBoxManager.Stop / Update / CLI Stop]
        │
        ├── Query Target Identity: ProcessOwnership.FindOwnedSingBox(...)
        │         │
        │         ├── Target null ──> Target already gone (No-op)
        │         └── Target Found (Pid, StartedAtUtcTicks, ExecutablePath)
        │
        ▼
UnixOwnedProcessSignal.SignalLinux(target, signal: 15)
        │
        ├─> 1. syscall(SYS_pidfd_open, target.Pid, 0)
        │         │
        │         ├── Fails (ESRCH) ────> TargetGone (0)
        │         └── Returns rawFd ───> Wrap in SafePidFd
        │
        ├─> 2. Read live process by target.Pid
        │         │
        │         ├── Process gone ─────> TargetGone (0)
        │         └── Re-read identity ─> ProcessOwnership.TryReadOwnedSingBoxIdentity(proc)
        │
        ├─> 3. Verify Identity: IsSameProcessIdentity(expected, current)
        │         │
        │         ├── Mismatch ─────────> IdentityMismatch (PID reused! Refuse signal)
        │         └── Match ────────────> Proceed to step 4
        │
```

### 4.2. Asynchronous Lifecycles & Cancellation Guarantees

1. **Owner Record Monitor Lifecycle (`TunOwnershipLock`)**:
   - Spawns un-awaited background task via `Task.Run` with dedicated `CancellationTokenSource`.
   - Polling loop delay is cancellable (`Task.Delay(200, cts.Token)`).
   - Handled `OperationCanceledException` breaks loop cleanly.
   - Task `finally` block guarantees `cts.Dispose()`.
   - `StopOwnerRecordMonitor()` safely swallows `ObjectDisposedException` if cancellation races with task exit.

2. **File Descriptor Teardown Guarantees (`LinuxTunOwnership` & `UnixOwnedProcessSignal`)**:

3. **Singleton Disposal & Re-Arming**:
   - When `TunOwnershipLock.Dispose()` is called, `_instance` is set to `null` if reference matches (`ReferenceEquals(_instance, this)`).
   - `TunOwnershipLock.Instance()` creates a new instance if `_instance is null || _instance._disposed`.
   - Calling `TryAcquire()` on an already-disposed instance throws `ObjectDisposedException`, preventing re-arming of dead instances.

## 5. SECURITY & PRIVILEGE BOUNDARIES

### 5.1. Filesystem & Path Traversal Hardening

1. **Strict Production Directory Anchor**:
   - In `LinuxTunOwnership`, production runtime directory is strictly `/run/user/<euid>`.
   - Fallback to `AppPaths.DataDir` or user configuration directories is explicitly disallowed to prevent path switching and `--data-dir` divergence (where two separate processes run with different data directories and fail to detect each other's lock on the single host TUN adapter).
   - The directory must be owned by the current effective UID (`stx_uid == currentUid`) and have private permissions (`mode 0700`, verified via `(statxBuf.stx_mode & 0077) == 0`). Group or world permissions are rejected.

2. **Descriptor Verification & Anti-TOCTOU**:
   - Open operations specify `O_NOFOLLOW` (rejects symlinks), `O_CLOEXEC` (prevents leaking file descriptors to child processes across `fork`/`exec`), and `O_NONBLOCK` (prevents hangs if the target file was maliciously replaced by a FIFO or device node).
   - After `open()`, `fstatx` (`statx` with `AT_EMPTY_PATH`) is performed on the returned file descriptor, validating:
     - Regular file type: `(stx_mode & S_IFMT) == S_IFREG` (rejects sockets, FIFOs, device nodes).
     - Ownership: `stx_uid == currentUid`.
     - File mode: `(stx_mode & 0077) == 0` (rejects files writable or readable by group/other).

3. **Atomic File Publication**:
   - `ProcessOwnership.WriteRuntimeOwnerRecord` writes `runtime-owner.json` via a process-specific temporary file (`runtime-owner.json.<pid>.tmp`), followed by an atomic `File.Move(..., overwrite: true)`. This guarantees concurrent readers never encounter truncated or half-written JSON documents.

### 5.2. Privilege Escalation & Execution Boundaries

1. **Elevation Escalation Chain (`UnixOwnedProcessSignal`)**:
   - The helper flag `--vpnrouter-internal-signal-owned-v1` allows unprivileged processes to request elevated termination of root-owned sing-box instances via `sudo -n` or `pkexec`.
   - Strict argument constraints: requires exactly 5 arguments; validates numeric PID and UTC start ticks; validates executable path; restricts signals to `SIGTERM` (15) and `SIGKILL` (9). Arbitrary signal injection (e.g. `SIGHUP`, `SIGUSR1`) is refused.
   - The elevated helper verifies that the process at PID matches the recorded identity *before* issuing `pidfd_send_signal`.

2. **Gated Trust Model for Destructive Operations (`ProcessOwnership`)**:
   - Configuration files (`config.yaml`) are treated as untrusted discovery candidates. A process cannot be terminated simply because it is mentioned in `config.yaml`.
   - Destructive operations (`IsOwnedSingBox`, `IsCurrentRuntimeOwnerPair`, `PersistedCliStateMatches`) require the process executable path to either reside strictly within the trusted VPNRouter binary directory (`AppPaths.BinDir`) or match the exact path recorded in an authoritative v2 `runtime-owner.json` record that is corroborated by an active owner process.

## 6. SUSPICIOUS PATTERNS / DEFECT CANDIDATES

### 6.1. Defect Candidate 1: Windows `TunOwnershipLock.TryAcquire()` Fails Open on Exceptions
- **Location**: `VPNRouter.Core/Services/TunOwnershipLock.cs:111-125`
- **Code**:
  ```csharp
  try
  {
      _semaphore ??= new Semaphore(1, 1, MutexName, out _);
  }
  catch (Exception ex)
  {
      _logger.Warning(ex, "[TunLock] Failed to create semaphore (continuing without lock)");
      return true; // fail-open
  }
  ```
- **Risk / Mechanism**:
  If a security policy, sandbox, or `UnauthorizedAccessException` prevents creation or opening of `Global\VPNRouter-SingBox-Owner`, the method catches the exception and returns `true` (`_owned = false`).
  Both `VPNRouter.App` and `VPNRouter.Service` would encounter the exception, both would believe they acquired ownership, and both would concurrently launch sing-box. The second process will crash with `Cannot create a file when that file already exists` on the Wintun adapter.
- **Severity**: Low/Medium (mitigated by admin requirement for TUN adapters, but violates fail-closed security invariants).

### 6.2. Defect Candidate 2: Inconsistency Between `IsOwnedByAnyone()` and `ProbeOwnership()`
- **Location**: `VPNRouter.Core/Services/TunOwnershipLock.cs:327-358`
- **Code**:
  ```csharp
  public static bool IsOwnedByAnyone()
      => ProbeOwnership() == TunOwnershipStatus.Owned;
  ```
- **Risk / Mechanism**:
  `ProbeOwnership()` returns tri-state: `Free`, `Owned`, `Unavailable`.
  If `ProbeOwnership()` encounters an exception or cannot inspect the semaphore/directory, it returns `Unavailable`.
  However, `IsOwnedByAnyone()` evaluates `Unavailable == Owned` as `false` ("assume free").
  Callers relying on `IsOwnedByAnyone()` (such as `OrphanCleanup.KillOrphans`) will conclude the TUN adapter is free when it is actually unverified, and proceed to terminate candidate processes.
- **Severity**: Medium.

### 6.3. Defect Candidate 3: Ordinal Equality Comparer in `EnumerateCandidateProcesses` (OPEN-DEFECTS: OMARCHY-RUNTIME-CANDIDATE-COMPARER)
- **Location**: `VPNRouter.Core/Services/ProcessOwnership.cs:510-520`
- **Code**:
  ```csharp
  var names = new HashSet<string>(CandidateProcessNames(
      AppPaths.SingBoxExePath,
      durablePath,
      configuredCandidate ?? ConfiguredExePath));
  if (!string.IsNullOrEmpty(policyPath))
  {
      names.UnionWith(CandidateProcessNames(policyPath, null, null));
  }
  ```
- **Risk / Mechanism**:
  `CandidateProcessNames` internally constructs a `HashSet<string>(comparer)` with OS-specific comparer (`OrdinalIgnoreCase` on Windows) and returns an array.
  However, `new HashSet<string>(IEnumerable<string>)` at line 512 does NOT pass a comparer; it defaults to `StringComparer.Ordinal`.
  On Windows, if `policyPath` contributes a candidate with different casing (e.g. `SING-BOX.EXE`), `names.UnionWith` will retain both casings. While `seenPids` prevents duplicate identities, `Process.GetProcessesByName` executes redundant system queries.
- **Severity**: Low (tracked in `OPEN-DEFECTS.md` as P2).

### 6.4. Defect Candidate 4: TOCTOU Inherent in Non-Atomic Probe-Then-Acquire
- **Location**: `TunOwnershipLock.ProbeOwnership()` & `LinuxTunOwnership.ProbeOwnership()`
- **Risk / Mechanism**:
  Both Windows and Linux probe mechanisms momentarily test and release the lock. On Linux, if the lock file is free, `ProbeOwnership()` acquires `flock` and immediately releases it (`Flock(fd, LOCK_UN)`).
  A caller calling `if (TunOwnershipLock.ProbeOwnership() == Free) { lock.TryAcquire(); }` is subject to a race window where another process can acquire the lock between probe and acquire.
  Callers must be disciplined to rely directly on `TryAcquire()` rather than checking `ProbeOwnership()` first.
