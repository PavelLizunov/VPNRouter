> **TL;DR:** Module H07 (`VPNRouter.Headless/Features/*`) implements the 9 core Linux headless domain feature endpoints for the Omarchy Quattro shell plugin, strictly isolating application routing, custom sing-box configs, diagnostics, free configs, profiles, rules DSL, server management, settings, and subscriptions. All mutations execute under strict parameter allowlists, CAS revision checks, 256 KiB size limits, write-only secret policies (redacting subscription URLs, UUIDs, and credentials), and fail-closed Linux runtime policy containment.

# Exhaustive Code Inventory & Audit: Headless Features Layer (Module H07 / Batch B064_H07)

## 1. SUMMARY & PURPOSE

Module **H07** encompasses the domain-specific feature service layer of the headless daemon (`VPNRouter.Headless/Features/*`). Situated between the RPC dispatcher (`VPNRouter.Headless.Protocol.ProtocolDispatcher` and `VPNRouter.Headless.RouterBackend`) and the core domain/storage engines (`VPNRouter.Core` and `VPNRouter.Headless.Storage`), this module provides decoupled, stateless or scoped handlers for all 34 feature-level protocol v1 methods.

### Component Roles & Responsibilities

| File | Primary Responsibility | Protocol v1 Methods Handled |
|---|---|---|
| **`AppRoutingFeature.cs`** | Enumerates host processes and manages split-tunnel process include/exclude lists and global routing modes (`split`/`full`). | `apps.list`, `apps.set`, `routing.set` |
| **`CustomConfigFeature.cs`** | Manages import, activation, selection, removal, and private atomic filesystem storage of raw custom sing-box JSON configs. | `custom.list`, `custom.import`, `custom.select`, `custom.remove` |
| **`DiagnosticsFeature.cs`** | Executes non-leaking health checks and exports sanitized diagnostic zip bundles containing log tails, active configuration, and environment status. | `diagnostics.check`, `diagnostics.export` |
| **`FreeConfigFeature.cs`** | Manages cached free proxy pools, background pool aggregation, TCP reachability testing, deep verification, and promotion into active VLESS servers. | `free.list`, `free.refresh`, `free.test`, `free.verify`, `free.apply` |
| **`ProfileFeature.cs`** | Provides offline/cached profile listing, active profile selection with strictest DNS resolution, and remote profile source synchronization. | `profiles.list`, `profiles.select`, `profiles.refresh` |
| **`RulesFeature.cs`** | Implements domain routing rules manipulation, DSL serialization/parsing, line-numbered validation, and multi-format import/export (`json`, `csv`, `singbox`). | `rules.get`, `rules.set`, `rules.import`, `rules.export` |
| **`ServerFeature.cs`** | Manages direct VLESS / WireGuard server entries, unified server indexing across direct and subscription sources, TCP/TLS probing, and deep verification. | `servers.list`, `servers.import`, `servers.select`, `servers.remove`, `servers.test`, `servers.verify` |
| **`SettingsFeature.cs`** | Provides strictly allowlisted read/write access to tunnel configuration (MTU, IPv6, StrictRoute, StrictDNS, DNS mode override, Russian traffic bypass, ad blocking, DNS leak lockdown, route exclusion CIDRs). | `settings.get`, `settings.set` |
| **`SubscriptionFeature.cs`** | Handles subscription lifecycle, write-only subscription URL security, remote pool refreshes, enable/disable toggling, and automatic fallback of active subscription servers. | `subscriptions.list`, `subscriptions.add`, `subscriptions.remove`, `subscriptions.refresh`, `subscriptions.enable` |

### Architectural Invariants & Guarantees
1. **Strict Input Allowlisting**: Parameter JSON elements are strictly validated against explicit field allowlists (`RouterBackend.EnsureAllowedProperties` or `RouterBackend.EnsureEmptyParameters`). Unexpected properties trigger immediate fail-closed `RouterException("invalid_argument", ...)`.
2. **Revision-Guarded Mutations (CAS)**: All modifying operations require a string `revision` parameter matching the current configuration revision (`_storage.ValidateRevision(revision)`). Stale or mismatched revisions throw `RouterException("conflict", ...)`.
3. **Payload & Depth Bounds**: Input text fields (raw rules, custom configs, server import text) are hard-capped at 256 KiB (`262,144` bytes). Maximum JSON parsing depth is strictly capped at 32. List collections enforce hard item count caps (e.g. max 10,000 process names, max 256 CIDR exclusions, max 100 profile IDs).
4. **No Secret Leaks**: Raw subscription URLs, server UUIDs, credentials, and raw exception messages are omitted from read responses (`List`, `Get`) and error messages.
5. **Runtime Policy Containment**: Sensitive operations (`ServerFeature`, `FreeConfigFeature`, `CustomConfigFeature`, `DiagnosticsFeature`, `SubscriptionFeature`) execute within `SingBoxRuntimePolicy.EnterScope(...)`, ensuring Linux unprivileged daemon constraints and fail-closed readiness checks.

    - *Preconditions*: `storage != null` (throws `ArgumentNullException(nameof(storage))`). Defaults `_logger` to `Log.Logger`.
- **Methods**:
  - `public object List(JsonElement parameters = default)`
    - *Contract*: Enforces empty parameters (`RouterBackend.EnsureEmptyParameters`). Reads settings from `_storage.GetSettings()`. Discovers running host processes safely via `GetRunningProcessNamesSafe()`.
    - *Return Shape*:
      ```json
      {
        "include": ["string"],
        "exclude": ["string"],
        "running": ["string"]
      }
      ```
    - *Exceptions*: `RouterException("invalid_argument" | "invalid_request")` if parameters are non-empty.
  - `public void SetApps(JsonElement parameters)`
    - *Contract*: Validates allowed properties `["revision", "mode", "names"]`.
    - *Validation*:
      - `revision`: must be string.
      - `mode`: must be string, trimmed, normalized to lower-case; must be `"include"` or `"exclude"`.
      - `names`: must be JSON array of strings. Each element must be a non-empty string <= 256 characters. Deduplicated case-insensitively while preserving original casing. Maximum array count <= 10,000.
    - *State Mutations*:
      - Validates revision (`_storage.ValidateRevision(revision)`).
      - `settings.App.RoutingAppsMode = mode`.
      - If `mode == "include"`: sets `RoutingAppsInclude = cleanNames`, sets `RoutingAppsIncludeInitialized = true`.
      - If `mode == "exclude"`: sets `RoutingAppsExclude = cleanNames`.
      - Persists atomically via `_storage.SaveSettings(settings, revision)`.
    - *Exceptions*: `RouterException("invalid_argument", ...)` on malformed input or length/count violations; `RouterException("conflict", ...)` on revision mismatch.
  - `public void SetRouting(JsonElement parameters)`
    - *Contract*: Validates allowed properties `["revision", "routingMode", "routingAppsMode"]`.
    - *Validation*:
      - `revision`: must be string.
      - `routingMode`: must be `"split"` or `"full"` (case-insensitive).
      - `routingAppsMode`: must be `"include"` or `"exclude"` (case-insensitive).
    - *State Mutations*:
      - Validates revision (`_storage.ValidateRevision(revision)`).
      - Updates `settings.App.RoutingMode` and `settings.App.RoutingAppsMode`.
      - Persists via `_storage.SaveSettings(settings, revision)`.
    - *Exceptions*: `RouterException("invalid_argument", ...)` on invalid modes; `RouterException("conflict", ...)`.
  - `private static List<string> GetRunningProcessNamesSafe()`
    - *Contract*: Invokes `Process.GetProcesses()`. Iterates across processes, extracts `p.ProcessName`, deduplicates into case-insensitive `HashSet<string>`, and disposes every `Process` instance in a `finally` block. Catches and swallows exceptions per process (process exit races) and globally (OS security/permission denial). Returns sorted `List<string>`.

    - *Contract*: Validates allowed properties `["revision", "id"]`.
    - *Validation*: `revision`, `id` strings.
    - *State Mutations*:
      - Validates revision.
      - Finds matching config by `ComputeCustomConfigId(c.Name) == id`. If missing -> throws `RouterException("not_found", "Custom config not found")`.

      - Saves settings via `_storage.SaveSettings(settings, revision)`.
  - `public void Remove(JsonElement parameters)`
    - *Contract*: Validates allowed properties `["revision", "id"]`.
    - *Validation*: `revision`, `id` strings.
    - *State Mutations*:
      - Validates revision.
      - Matches config by ID; throws `RouterException("not_found", ...)` if missing.
      - Removes entry from `settings.App.CustomConfigs`.
      - Deletes config file from disk via `_customStorage.DeleteCustomConfig(match.Name)`.
      - Reconciles active configuration: if removed config was active:
        - If other custom configs remain: switches `ActiveCustomConfig` to `configs[0].Name`.
        - If no custom configs remain: sets `ActiveCustomConfig = string.Empty` and switches `ConfigMode = "generated"`.
      - Saves settings via `_storage.SaveSettings(settings, revision)`.
  - `private static string ComputeCustomConfigId(string name)`

      {
        "items": [
          {
            "id": "srv_0123456789abcdef",

    - *Execution*: Calls `TcpTlsProbe.ProbeServerAsync(server, ct)`.

    - *Return Shape*: `{ id = "...", ok = true|false, latencyMs = 35|null, error = "..."|null }`.

### 3.1. End-to-End Request/Mutation Pipeline

```
NDJSON Stdin 
  │
  ▼
ProtocolLineReader (enforces <= 256 KiB before accumulation)
  │
  ▼
ProtocolParser (validates v:1, max depth 32, duplicate key rejection)
  │
  ▼
ProtocolDispatcher (at most 1 ordinary operation; urgent cancel/disconnect bypass)
  │
  ▼
RouterBackend.ExecuteAsync
  │
  ├── Ordinary Dispatch -> DispatchOrdinaryMethodAsync(method, params, ct)
  │     │
  │     ├── RouterBackend.EnsureAllowedProperties(params, ...) / EnsureEmptyParameters
  │     │
  │     └── ExecuteMutationAsync(Func<Task>, ct)
  │           │
  │           ├── Snapshot previous settings
  │           ├── ct.ThrowIfCancellationRequested()
  │           ├── Execute Feature Action (Detached validation -> _storage.SaveSettings CAS)
  │           │
  │           └── If session is Connected:

  │
  ▼

```

### 3.2. ConfigMode State Machine

The daemon manages three distinct configuration modes (`ConfigMode` in `AppSettings.App`):

```
                        ┌───────────────────┐
                        │     generated     │ <───────────────────┐
                        │ (Direct VLESS/AWG)│                     │
                        └─────────┬─────────┘                     │
                                  │                               │
            custom.import /       │          servers.select(sub)  │
            custom.select         │                 │             │
                  │               │                 │             │
                  ▼               │                 ▼             │
        ┌───────────────────┐     │       ┌───────────────────┐   │
        │      custom       │     │       │     subscribe     │   │
        │ (Raw sing-box JSON│     │       │(Subscription pool)│   │
        └─────────┬─────────┘     │       └─────────┬─────────┘   │
                  │               │                 │             │
  custom.remove   │               │                 │  subs.remove│
  (last config)   │               │                 │  (0 servers)│
                  └───────────────┼─────────────────┴─────────────┘
                                  │
                                  ▼
                        ┌───────────────────┐
                        │ Free config apply │ -> Forces ConfigMode = "generated"
                        └───────────────────┘
```

#### State Transition Rules:
1. **`generated -> custom`**:
   - Triggered by `custom.import` (when 1st config added or `ActiveCustomConfig` empty) or `custom.select`.
   - Side effects: `ActiveCustomConfig` set to config name. Custom sing-box JSON at `AppPaths.ConfigDir/{name}.json` is used. DNS mode cannot be overridden (`settings.set` for `dnsMode` fails).
2. **`custom -> generated`**:
   - Triggered by `custom.remove` when the active custom config is deleted and no other custom configs remain in storage.
   - Side effects: `ActiveCustomConfig` reset to `""`, `ConfigMode` reset to `"generated"`.
3. **`generated -> subscribe`**:
   - Triggered by `servers.select` when selecting a server originating from a subscription (`IsSubscription == true`).
   - Side effects: `ActiveSubscriptionServer` and `Vless.ActiveServer` updated to the subscription server name.
4. **`subscribe -> generated`**:
   - Triggered by:
     - Selecting a direct server (`servers.select` on non-subscription server).
     - Applying a free config (`free.apply`).
     - Removing or refreshing subscriptions (`subscriptions.remove`, `subscriptions.enable`, `subscriptions.refresh`) when 0 servers remain across all enabled subscriptions (`ReconcileActiveSubscriptionServer`).
5. **`* -> generated` (Free Config Apply)**:
   - Triggered by `free.apply(id)`.
   - Verification gate: free config must have `Status == FreeConfigStatus.Verified`.
   - Side effects: Converts free config to `VlessServerEntry`, adds to `settings.Vless.Servers`, sets as active server, and forces `ConfigMode = "generated"`.

## 4. CONCURRENCY, LOCKS & LIFECYCLE

### 4.1. Concurrency Controls
1. **Single-Writer Daemon Invariant**:
   - `RouterBackend` guards all ordinary operations with atomic CAS concurrency control:
     ```csharp
     if (Interlocked.CompareExchange(ref _busyState, 1, 0) != 0)
         throw new RouterException("busy", "Another operation is currently in progress");
     ```
   - Only one ordinary request executes across all features at any moment. Concurrent requests fail immediately with protocol error `"busy"`.
   - Urgent operations (`cancel`, `disconnect`, `snapshot`) bypass `_busyState` and execute concurrently with bounded concurrency (up to 4 urgent tasks via `ProtocolConstants.MaxUrgentOperations`).
2. **Cancellation Token Propagation**:
   - Requests registered in `_inFlightRequests` can be cancelled out-of-band via `cancel(id)`.
   - Cancellation tokens are propagated through:
     - `FreeConfigFeature.RefreshAsync` (re-throws `OperationCanceledException` without pool corruption).
     - `FreeConfigFeature.TestAsync` and `VerifyAsync`.
     - `ServerFeature.TestAsync` and `VerifyAsync`.
     - `SubscriptionFeature.RefreshAsync` (checks `ct.ThrowIfCancellationRequested()` between items).
3. **CAS Storage Synchronization**:
   - Persistence operations go through `ConfigStorage.SaveSettings(settings, revision)`.
   - Compares the caller-provided `revision` against `_currentRevision` in memory and disk state. If an external process modified `config.yaml`, the CAS check rejects the mutation with `RouterException("conflict", ...)`.

### 4.2. Resource Lifecycle & Teardown Guarantees
1. **Process Handles**:
   - `AppRoutingFeature.GetRunningProcessNamesSafe()` obtains `Process[]` from `Process.GetProcesses()`. Every process handle is explicitly disposed in a `finally` block to prevent OS handle leaks:
     ```csharp
     finally
     {
         foreach (var p in processes)
         {
             try { p.Dispose(); } catch { }
         }
     }
     ```
2. **File Streams & Atomic Temp Files**:
   - `CustomConfigStorage.SaveCustomConfig` creates a temporary file `destPath.tmp.{Guid}` using `FileMode.CreateNew`. The `FileStream` and `StreamWriter` are flushed and synced to disk (`stream.Flush(flushToDisk: true)`) before calling atomic `File.Move(..., overwrite: true)`. The temp file is cleaned up in a `finally` block if an error occurs.
   - `OfflineProfileHelper.TryLoadLocalProfileBounded` opens files with `FileShare.ReadWrite`, reads into bounded in-memory byte buffers, and disposes streams deterministically.
3. **Stall & Teardown Deadlines**:
   - Handled at protocol boundary: 3-second handler disposal timeout, 3-second output drain timeout, 2-second in-flight task drain timeout.

## 5. SECURITY & PRIVILEGE BOUNDARIES

### 5.1. Privilege Boundary & Execution Model
- `VPNRouter.Headless` operates entirely as the unprivileged desktop user (`UID 1000`). It does not run setuid, does not invoke `sudo`, and does not invoke `pkexec`.
- Elevated capabilities (`cap_net_admin,cap_net_bind_service=+eip`) are attached strictly to the external `sing-box` binary.
- Features that interface with runtime probes (`CustomConfigFeature`, `DiagnosticsFeature`, `FreeConfigFeature`, `ServerFeature`, `SubscriptionFeature`) execute within `SingBoxRuntimePolicy.EnterScope(EffectivePolicy)`. Under default production policy without an authorized binary hash, any execution or probe immediately throws `SingBoxRuntimePolicyException` which translates to `RouterException("unavailable", "VPN runtime is unavailable")`.

### 5.2. Secret Isolation & Write-Only Invariants
1. **Write-Only Subscription URLs**:
   - Subscription URLs may contain embedded private tokens, API keys, or user IDs.
   - `SubscriptionFeature.List` projects `s.Id`, `s.Name`, `s.Enabled`, and `s.serverCount`. `s.Url` is **strictly excluded** from all responses.
2. **Server Credentials & Share URIs**:
   - Server UUIDs, passwords, and private keys are never returned in `ServerFeature.List` or `FreeConfigFeature.List`. Only public metadata (`id`, `name`, `protocol`, `selected`, `latencyMs`) is emitted.
3. **Log & Message Redaction**:
   - `DiagnosticsFeature.Check` passes all health check output through `DiagnosticsRedactor.RedactLogText`.
   - `RouterException` maps errors to pre-defined safe messages (`SafeMessage`), preventing sensitive input values from echoing back to the client.
   - `SettingsFeature.Set` rejects unknown setting keys with fixed message `"Unknown setting"` without echoing the unrecognized property name.

### 5.3. Filesystem Hardening & Path Traversal Prevention
1. **No-Symlink Hierarchy Enforcement**:
   - `CustomConfigStorage.AssertNoSymlinksInPath` inspects the entire directory hierarchy up to filesystem root (`LinkTarget != null` and `ReparsePoint` flags). Fails closed if any path component is a symlink.
   - `DiagnosticsFeature.AssertNoSymlink` verifies the diagnostics directory is not a symlink/reparse point.
2. **POSIX Permissions**:
   - Private storage directories are configured with `0700` (`UnixFileMode.UserRead | UserWrite | UserExecute`).
   - Configuration files are created with `0600` (`UnixFileMode.UserRead | UserWrite`).

## 6. SUSPICIOUS PATTERNS / DEFECT CANDIDATES

During this line-by-line audit of the 9 feature files, the following subtle bugs, race conditions, and architectural smells were identified:

### Finding 1: Stale `_profileManager` Caching in `ProfileFeature`
- **Location**: `VPNRouter.Headless/Features/ProfileFeature.cs:113-122`
- **Pattern**:
  ```csharp
  private ProfileManager GetOrCreateProfileManager()
  {
      if (_profileManager != null)
          return _profileManager;

      var settings = _storage.GetSettings();
      var sources = VpnEngine.BuildProfileSources(settings, _storage.DataDir);
      _profileManager = new ProfileManager(sources, _logger);
      return _profileManager;
  }
  ```
- **Defect Impact**: `_profileManager` is cached permanently on the feature instance upon the first call to `RefreshAsync`. If settings are subsequently modified (e.g. user adds or updates `ProfileSources` in `config.yaml`), `_profileManager` is **never updated or invalidated**. Furthermore, `ListAsync` checks `_profileManager?.Loaded`: once loaded, `ListAsync` perpetually reads from this cached, stale profile manager rather than reloading updated local/cached profiles.
- **Remediation**: `GetOrCreateProfileManager()` should compare current `settings.ProfileSources` or re-create the manager, or `RouterBackend` should invalidate feature caches on settings change.

---

### Finding 2: Sync-Over-Async Blocking in `OfflineProfileHelper`
- **Location**: `VPNRouter.Headless/Features/ProfileFeature.cs:148-150`, `155-157`
- **Pattern**:
  ```csharp
  public static ProfileCollection GetOfflineProfileCollection(AppSettings settings, string? dataDir, ILogger? logger = null)
  {
      var manager = CreateOfflineProfileManager(settings, dataDir, logger);
      var loadTask = manager.LoadAsync(CancellationToken.None);
      return loadTask.GetAwaiter().GetResult();
  }
  ```
- **Defect Impact**: Calling `.GetAwaiter().GetResult()` synchronously blocks the executing thread on an asynchronous task (`manager.LoadAsync`). While `MemoryProfileSource` returns completed tasks, `ProfileManager` may perform asynchronous task scheduling internally. In constrained thread pool environments or synchronization contexts, sync-over-async causes thread pool starvation and potential deadlocks.
- **Remediation**: Make `GetOfflineProfileCollection` asynchronous (`GetOfflineProfileCollectionAsync`) and `await` it inside `ProfileFeature.ListAsync`.

---

### Finding 3: Non-Atomic Loop Failure in `SubscriptionFeature.RefreshAsync`
- **Location**: `VPNRouter.Headless/Features/SubscriptionFeature.cs:229-236`
- **Pattern**:
  ```csharp
  foreach (var sub in targets)
  {
      ct.ThrowIfCancellationRequested();
      progress?.Invoke(new { stage = "refresh_subscription", completed = done, total });
      await SubscriptionFetcher.RefreshEntryAsync(sub, _logger, ct);
      done++;
      progress?.Invoke(new { stage = "refresh_subscription", completed = done, total });
  }

  ReconcileActiveSubscriptionServer(settings);
  _storage.SaveSettings(settings, revision);
  ```
- **Defect Impact**: Target subscriptions are fetched sequentially without per-item exception handling. If subscription #1 fails with a network timeout, HTTP error, or DNS failure, an exception is thrown out of the loop. Consequently:
  1. Subscriptions #2..N are never attempted.
  2. `ReconcileActiveSubscriptionServer` is never executed.
  3. `_storage.SaveSettings` is skipped, losing any successfully refreshed servers from prior items in the batch.
- **Remediation**: Wrap each `RefreshEntryAsync` in a try/catch block, log failures per subscription, and proceed to refresh remaining subscriptions before reconciling and saving.

---

### Finding 4: Error Ambiguity in `ServerFeature.Remove` for Subscription Servers
- **Location**: `VPNRouter.Headless/Features/ServerFeature.cs:220-224`
- **Pattern**:
  ```csharp
  var settings = _storage.GetSettings();
  var servers = settings.Vless?.Servers ?? new List<VlessServerEntry>();
  var server = FindServerById(servers, id);
  if (server == null)
      throw new RouterException("not_found", "Server not found");
  ```
- **Defect Impact**: `servers.list` generates unified `srv_` IDs for both direct servers AND enabled subscription servers. When a client issues `servers.remove` targeting a subscription server ID, `FindServerById` searches only `settings.Vless.Servers`. It returns `RouterException("not_found", "Server not found")`. To the client, this appears as an invalid or nonexistent ID rather than clarifying that subscription-managed servers are read-only and must be managed via `subscriptions.*`.
- **Remediation**: Check `BuildUnifiedServerIdMap(settings)` first; if the ID matches a subscription server, throw `RouterException("invalid_argument", "Subscription servers cannot be deleted individually")`.

---

### Finding 5: Potential `NullReferenceException` in `ServerFeature.Select`
- **Location**: `VPNRouter.Headless/Features/ServerFeature.cs:188-198`
- **Pattern**:
  ```csharp
  settings.Vless ??= new VlessConfig();

  if (match.IsSubscription)
  {
      settings.App.ConfigMode = "subscribe";
      settings.App.ActiveSubscriptionServer = serverName;
      settings.Vless.ActiveServer = serverName;
  }
  else
  {
      settings.App.ConfigMode = "generated";
      settings.Vless.ActiveServer = serverName;
  }
  ```
- **Defect Impact**: While `settings.Vless` is null-coalesced (`settings.Vless ??= new VlessConfig()`), `settings.App` is not null-coalesced. If `settings.App` is null (e.g. deserialized from minimal or malformed YAML), accessing `settings.App.ConfigMode` throws a raw `NullReferenceException`. In contrast, `SettingsFeature.cs:268` correctly performs `settings.App ??= new AppConfig()`.
- **Remediation**: Add `settings.App ??= new AppConfig();` before mutating app settings.

---

### Finding 6: Unhandled Exceptions in `ServerFeature.Import` for WireGuard Conf
- **Location**: `VPNRouter.Headless/Features/ServerFeature.cs:118-129`
- **Pattern**:
  ```csharp
  if (ServerUriParser.IsWireGuardConf(text))
  {
      try
      {
          var wgServer = ServerUriParser.ParseWireGuardConf(text);
          parsedServers = new List<VlessServerEntry> { wgServer };
      }
      catch (FormatException)
      {
          throw new RouterException("invalid_argument", "Invalid WireGuard configuration");
      }
  }
  ```
- **Defect Impact**: Only `FormatException` is caught. If `ParseWireGuardConf` encounters malformed keys or unexpected input resulting in `ArgumentException` or `IndexOutOfRangeException`, the exception bubbles unhandled to the protocol layer, turning what should be a user-friendly `invalid_argument` error into an `internal_error`.
- **Remediation**: Catch `Exception ex when (ex is FormatException or ArgumentException)` to ensure all parser syntax failures return `invalid_argument`.

---

### Finding 7: Case-Sensitive Path Comparisons in `OfflineProfileHelper`
- **Location**: `VPNRouter.Headless/Features/ProfileFeature.cs:246, 264`
- **Pattern**:
  ```csharp
  if (File.Exists(defaultJson) && !defaultJson.Equals(platformBundled, StringComparison.Ordinal))
  ...
  if (File.Exists(userDefault) && !userDefault.Equals(platformProfiles, StringComparison.Ordinal))
  ```
- **Defect Impact**: `StringComparison.Ordinal` is used to verify that the fallback `default.json` is not the exact same file path as the platform-specific default. On case-insensitive file systems (Windows / macOS) or when path normalization differs (e.g. directory separators), `defaultJson.Equals(...)` evaluates to false even if referencing the same file, resulting in redundant profile loading and priority shadowing.
- **Remediation**: Use `string.Equals(Path.GetFullPath(defaultJson), Path.GetFullPath(platformBundled), StringComparison.OrdinalIgnoreCase)` on case-insensitive OSes.

### 7.2. Test Gaps & Untested Paths

Despite the strong existing coverage, the following paths remain untested:

1. **`ProfileFeature` Stale Manager Invalidation**:
   - No test verifies that modifying profile sources in settings updates the `ProfileManager` returned by `GetOrCreateProfileManager()`.
2. **`SubscriptionFeature.RefreshAsync` Mid-Loop Partial Failures**:
   - No test verifies what happens when one of several subscriptions throws a network error during multi-subscription refresh.
3. **`AppRoutingFeature.GetRunningProcessNamesSafe` Process Access Denials**:
   - The exception catch block handling individual process inspection (`catch { /* Process exited */ }`) and container permission denial (`Process.GetProcesses()` failure) is not exercised under synthetic security denial conditions.
4. **`ServerFeature.Import` WireGuard Parser Non-`FormatException` Exceptions**:
   - Malformed WireGuard configuration strings throwing non-`FormatException` errors are untested.
5. **CIDR Boundary Edge Cases in `SettingsFeature.ValidateCidr`**:
   - No tests assert IPv6 prefix lengths between 129 and 255 or malformed prefix formats (e.g. non-numeric `/abc`).
6. **Concurrent Deletion / Selection Race on Custom Configs**:
   - Race conditions where a custom config file is deleted externally between `List` and `Select` are not covered.
