## 1. SUMMARY & PURPOSE

Module A01 encompasses the core desktop application services for `VPNRouter.App`. Operating underneath Avalonia UI Views and ViewModels, these services provide OS-level desktop integration, lifecycle control, installation health self-healing, automated testing hooks, and shell extensions.

### Component Roles & Responsibilities

1. **`AppAutomationDriver.cs` (Localhost HTTP Automation & Telemetry Seam)**
   - Implements an embedded localhost HTTP server (`HttpListener`) conditionally activated via `--automation-port <port>` or `VPNROUTER_AUTOMATION_PORT`.
   - Exposes REST endpoints (`/metrics`, `/ui/tree`, `/ui/action`, `/ui/screenshot`) for black-box testing and continuous telemetry (RAM, CPU, GC generations, UI dispatcher latency).
   - Translates remote HTTP JSON requests into UI thread operations (`Dispatcher.UIThread.InvokeAsync`) to manipulate controls, switch tabs, toggle modes, and capture Avalonia window bitmaps without native OS accessibility hooks.

2. **`FileManagerHelper.cs` (Cross-Platform OS Shell File Reveal)**
   - Builds safe `ProcessStartInfo` instances to open the native OS file explorer and highlight/reveal a specific file.
   - Distinguishes Windows (`explorer.exe /select,"<path>"`), macOS (`/usr/bin/open "<dir>"`), and Linux (`xdg-open "<dir>"`), enforcing argument separation via `ProcessStartInfo.ArgumentList` to defeat shell injection.

3. **`InstallHealthCheck.cs` (Mixed-Version DLL Consistency Verifier)**
   - Detects partial, corrupted, or locked auto-update deployments resulting from kernel file locks held by the running `VPNRouter` Windows Service.
   - Employs a dual-layer check:
     - **Primary:** Compares compile-time constant inlining (`VPNRouter.Core.AppVersion.Version`) against runtime metadata reflection (`GetRawConstantValue()`) to detect mismatched `Core.dll` loads.
     - **Secondary:** Validates Git commit-hash equality extracted from `FileVersionInfo.ProductVersion` across tracked DLLs (`VPNRouter.App.dll`, `VPNRouter.Core.dll`, `VPNRouter.Service.dll`).

4. **`SelfRepair.cs` (Automated Web Installer Self-Healing)**
   - Remediates corrupted or broken installations by orchestrating execution of the canonical remote `install.ps1` (`https://vpn.ninitux.com/install.ps1`).
   - Implements a 10-minute rate-limiting loop prevention gate using an on-disk timestamped marker file (`self-repair-marker`).
   - Generates a temporary bootstrap PowerShell script in `%TEMP%` and spawns a detached, hidden `powershell.exe -ExecutionPolicy Bypass` process to execute repair and replace locked binaries while the host process terminates.

5. **`ShellMenuRegistrar.cs` (Windows Explorer Context Menu Integration)**
   - Manages per-user registry entries (`HKCU\Software\Classes\exefile` and `lnkfile`) for the "Route through VPN" and "Remove from VPN" shell context verbs.
   - Dynamically constructs either a flat single verb or a cascading submenu (`MUIVerb`, `SubCommands = ""`) based on configured application routing categories.
   - Emits `SHChangeNotify(SHCNE_ASSOCCHANGED)` to immediately flush Explorer's shell association and verb MUI cache without requiring user logout or system reboot.

6. **`ShortcutResolver.cs` (Windows Shell Verb Path & Shortcut Resolver)**
   - Resolves incoming shell context-menu path tokens (`%1`) to target executable process names.
   - Late-binds to Windows Script Host COM object (`WScript.Shell`) to inspect `.lnk` shortcut `TargetPath` attributes.
   - Preserves exact filesystem casing required for case-sensitive sing-box `process_name` rule matching, with deterministic COM object reclamation via `Marshal.FinalReleaseComObject`.

7. **`ShortcutSelfHeal.cs` (Start Menu Trampoline Migration)**
   - Inspects the per-machine Start Menu shortcut (`C:\ProgramData\Microsoft\Windows\Start Menu\Programs\VPNRouter.lnk`) to migrate legacy targets pointing directly at `VPNRouter.App.exe` to the Go trampoline stub `VPNRouter.GUI.exe`.
   - Guarantees trampoline integrity verification triggers on daily user launches while retaining the Win32 application icon resource (`App.exe,0`).

8. **`SingleInstance.cs` (Cross-Process Mutex & Named Pipe IPC Hub)**
   - Guarantees single-instance execution via a named global system mutex (`Global\VPNRouter.App.SingleInstance.v2`).
   - Operates a background `NamedPipeServerStream` (`VPNRouter.App.ShowWindow.v2`) secured with current-user DACL on Windows.
   - Handles multi-instance rendezvous: subsequent launches transmit command verbs (`0x01` Show Window, `0x02` Route App with optional Category, `0x03` Unroute App) to the primary instance, then exit cleanly.

9. **`SteamLibraryScanner.cs` (Steam VDF & ACF Game Library Scanner)**
   - Scans Steam libraries across Windows registry paths (`HKCU\Software\Valve\Steam\SteamPath`) and default filesystem locations.
   - Parses KeyValue VDF formats (`libraryfolders.vdf`, `appmanifest_*.acf`) using regex pattern matching.
   - Enumerates candidate game executables while filtering out utility binaries (uninstallers, crash reporters, redistributables, setups) to populate process split-tunneling lists.

10. **`WindowForegroundHelper.cs` (Win32 Focus-Stealing Policy Bypass)**
    - Overcomes Windows `ForegroundLockTimeout` focus-stealing restrictions when activating existing minimized or background application windows.
    - Temporarily binds the application's thread message queue to the active foreground thread (`AttachThreadInput`), applies a topmost z-order flicker (`HWND_TOPMOST` / `HWND_NOTOPMOST`), restores iconic windows (`ShowWindow(SW_RESTORE)`), and calls `SetForegroundWindow`.

11. **`WindowsServiceHelper.cs` (Admin Service Management via `sc.exe`)**
    - Wraps Windows Service Control Manager operations (`query`, `create`, `delete`, `start`, `stop`, `config binPath=`) through native `sc.exe` execution without requiring `System.ServiceProcess` dependencies.
    - Provides automatic self-healing of registered service binary image paths (`EnsureCurrentBinPath`) to prevent ghost-path service failures following directory moves or re-installations.

## 4. CONCURRENCY, LOCKS & LIFECYCLE

### 4.1. Synchronization Primitives & Cross-Process Mutexes
- **`SingleInstance` Mutex (`Global\VPNRouter.App.SingleInstance.v2`)**:
  - Instantiated with `initiallyOwned: false`.
  - Acquisition is strictly atomic via `_mutex.WaitOne(0)`.
  - Implements explicit `AbandonedMutexException` catching: if a prior instance crashed or terminated abnormally without releasing the mutex, the runtime transfers ownership to the current instance, allowing startup to proceed.
  - Teardown: `Release()` calls `_mutex.ReleaseMutex()` and `_mutex.Dispose()`.

### 4.2. Named Pipe Server Concurrency & Threading Model
- **`SingleInstance` Pipe Server Loop (`RunPipeServerLoop`)**:
  - Runs in a background thread via `Task.Run(...)`.
  - Governed by `CancellationTokenSource _serverCts`.
  - **Sync-over-Async Antipattern:** Uses `var connectTask = server.WaitForConnectionAsync(ct); connectTask.GetAwaiter().GetResult();` blocking a ThreadPool thread rather than using native `async/await`.
  - **Thread Handoff:** IPC payloads are read on the ThreadPool thread, then dispatched to Avalonia's UI thread via `Dispatcher.UIThread.Post(...)` to prevent cross-thread exceptions when modifying UI collections (`RoutingAppsInclude`) or manipulating Avalonia controls.

### 4.3. HTTP Automation Driver Concurrency
- **`AppAutomationDriver.AcceptLoopAsync`**:
  - Bound to `HttpListener`. Uses `await listener.GetContextAsync().ConfigureAwait(false)` in an asynchronous loop.
  - Spawns concurrent background request handlers via `Task.Run(() => HandleRequestAsync(context))` allowing concurrent handling of incoming HTTP connections.
  - UI State Inspection: `HandleMetricsAsync`, `HandleUiTreeAsync`, `HandleUiActionAsync`, and `HandleScreenshotAsync` synchronize with Avalonia by scheduling tasks on the UI thread via `await Dispatcher.UIThread.InvokeAsync(...)`.

### 4.4. Synchronous UI Thread Freezing in Service Polling
- **`WindowsServiceHelper.Start()` and `Stop()`**:
  - Implement polling loops with `System.Threading.Thread.Sleep(500)`.
  - `Start()` sleeps up to 20 iterations (10,000 ms).
  - `Stop()` sleeps up to 30 iterations (15,000 ms).
  - When invoked directly from synchronous UI event handlers (e.g. `MainWindowViewModel.Connection.cs`), this completely starves the Avalonia dispatcher thread, causing the window to become unresponsive and trigger OS "Application Not Responding" warnings. (In `ServiceViewModel.cs`, calls are correctly wrapped in `Task.Run(() => WindowsServiceHelper.Start())`, but the underlying helper API remains blocking and synchronous).

## 5. SECURITY & PRIVILEGE BOUNDARIES

### 5.1. Privilege Elevation & Identity Boundaries
1. **Windows Service Management (`WindowsServiceHelper.cs`)**:
   - Interacts with Windows Service Control Manager via `sc.exe`.
   - Modifying services (`create`, `delete`, `start`, `stop`, `config binPath=`) strictly requires elevated administrative privileges (`SeLoadDriverPrivilege` / High Integrity Token). `Program.cs` enforces application self-elevation on Windows at launch.
2. **Start Menu Shortcut Migration (`ShortcutSelfHeal.cs`)**:
   - Targets `Environment.SpecialFolder.CommonStartMenu` (`C:\ProgramData\Microsoft\Windows\Start Menu\Programs\VPNRouter.lnk`).
   - `ProgramData` is writable only by Administrators. Standard user executions will fail with access denied.
3. **Explorer Shell Context Menu (`ShellMenuRegistrar.cs`)**:
   - Targets `HKCU\Software\Classes` (User-specific class store).
   - Operates entirely in unprivileged medium-integrity contexts without administrative prompts.

### 5.2. Inter-Process Communication (IPC) Trust Boundary
- **`SingleInstance` Named Pipe DACL**:
  - `CreateServerStream` on Windows configures a custom `PipeSecurity` object restricted exclusively to the active user's SID (`WindowsIdentity.GetCurrent().User` with `PipeAccessRights.FullControl`).
  - Defends against local cross-user privilege escalation: other standard user accounts on a multi-user machine cannot connect to the pipe to trigger unauthorized window activation or inject split-tunnel routes.
  - Enforces payload bounds: input streams are limited to `MaxRouteAppPayloadBytes = 64 * 1024` (64 KB) to prevent memory exhaustion DoS attacks.

### 5.3. Process Spawning & Injection Defenses
- **`FileManagerHelper.cs`**:
  - Configures `UseShellExecute = false` and uses `ProcessStartInfo.ArgumentList` instead of raw string concatenation.
  - Prevents argument injection when passing paths containing quotes, semicolons, or shell metacharacters (`/select,<path>`).
- **`ShellMenuRegistrar.cs`**:
  - Enforces strict input validation on category names prior to registry embedding:
    ```csharp
    !c.Contains('"') && !c.Contains('%') && !c.Contains('\\')
    ```
  - Defends against command-line argument breaking, quote escaping, and Explorer environment variable token expansion (`%TEMP%`, `%COMSPEC%`).

### 5.4. HTTP Automation Attack Surface (`AppAutomationDriver.cs`)
- Binds strictly to loopback (`127.0.0.1`).
- Implements Bearer token validation via `Authorization: Bearer <token>` or `?token=<token>`.
- **Caution:** If launched without `--automation-token` or `VPNROUTER_AUTOMATION_TOKEN`, authentication is completely disabled (`_token == null`). Any local unprivileged process on the host can inspect the full Avalonia visual tree, trigger UI clicks, alter routing configurations, and capture real-time desktop window screenshots.

### 6.2. Detailed Defect Analysis

#### DEF-A01-01: Synchronous Unbounded Pipe Read Deadlock in `SingleInstance`
- **Location:** `VPNRouter.App/Services/SingleInstance.cs:350, 367, 380, 408`
- **Mechanism:**
  ```csharp
  var verb = server.ReadByte();
  // ...
  if (ReadExact(server, lenBuf, 4)) { ... }
  ```
  `server.ReadByte()` and `Stream.Read()` inside `ReadExact` are synchronous blocking calls without read timeouts. Furthermore, the cancellation token `ct` is not passed to the read operations.
- **Impact:** If a rogue client, misbehaved launcher, or security scanner connects to the named pipe and transmits 0 bytes or halts mid-transmission, the pipe server loop hangs permanently inside `ReadByte()` or `ReadExact()`. Subsequent legitimate second-instance launches will fail to connect or time out, and calling `SingleInstance.Release()` cannot terminate the thread because `_serverCts.Cancel()` cannot unblock synchronous native I/O.
- **Remediation:** Replace synchronous stream operations with `await server.ReadAsync(buf, ct)` or configure `PipeStream.ReadTimeout = 2000`.

#### DEF-A01-02: Missing Process Kill & `InvalidOperationException` on `sc.exe` Timeout
- **Location:** `VPNRouter.App/Services/WindowsServiceHelper.cs:253-255`
- **Mechanism:**
  ```csharp
  proc.WaitForExit(10000);
  return (proc.ExitCode, (stdout + stderr).Trim());
  ```
  `proc.WaitForExit(10000)` returns `false` if `sc.exe` is blocked or hung. However, `WindowsServiceHelper` does not check the boolean return value and does not call `proc.Kill()`. On the very next line, evaluating `proc.ExitCode` on a running process immediately throws `System.InvalidOperationException: Process has not exited`.
- **Impact:** While caught by the outer `catch (Exception ex)` block, the hanging `sc.exe` process is leaked and remains running indefinitely in the background, locking SCM handles.
- **Remediation:** Check `if (!proc.WaitForExit(10000)) { proc.Kill(); return (-1, "sc.exe timed out"); }`.

#### DEF-A01-03: Missing OS Check in `SelfRepair` Causes Crash on Linux and macOS
- **Location:** `VPNRouter.App/Services/SelfRepair.cs:151-165`
- **Mechanism:**
  `SelfRepair.Run()` configures a `ProcessStartInfo` with `FileName = "powershell.exe"` and executes `Process.Start(psi)` without verifying `OperatingSystem.IsWindows()`.
- **Impact:** While `InstallHealthCheck` is primarily designed for Windows DLL lockup recovery, if an unhandled startup crash or health check anomaly triggers `SelfRepair.Run()` on Linux or macOS, `Process.Start` will throw `System.ComponentModel.Win32Exception` ("No such file or directory"), causing an unhandled crash if unhandled by the caller.
- **Remediation:** Add `if (!OperatingSystem.IsWindows()) { logger?.Warning("[SelfRepair] Self-repair is supported only on Windows"); return; }` at the beginning of `Plan()` and `Run()`.

#### DEF-A01-04: Unmanaged COM RCW Memory Leak in `ShortcutSelfHeal`
- **Location:** `VPNRouter.App/Services/ShortcutSelfHeal.cs:50-91`
- **Mechanism:**
  In `ShortcutResolver.cs:84-85`, COM objects are strictly reclaimed:
  ```csharp
  finally
  {
      try { if (lnk != null) Marshal.FinalReleaseComObject(lnk); } catch { }
      try { if (shell != null) Marshal.FinalReleaseComObject(shell); } catch { }
  }
  ```
  In contrast, `ShortcutSelfHeal.cs` instantiates `WScript.Shell` and `IWshShortcut` COM wrappers via reflection but lacks any `finally` block and never calls `Marshal.FinalReleaseComObject()`.
- **Impact:** Leaves COM Runtime Callable Wrappers (RCWs) dangling in memory until finalizer execution, keeping Windows Shell COM server handles open longer than necessary.
- **Remediation:** Mirror the `finally { Marshal.FinalReleaseComObject(...) }` pattern from `ShortcutResolver.cs`.

#### DEF-A01-05: Insecure Temporary Script Paths and Disk Leak in `SelfRepair`
- **Location:** `VPNRouter.App/Services/SelfRepair.cs:134, 140`
- **Mechanism:**
  1. Temporary bootstrap script is written to `%TEMP%\vpnr-self-repair-{timestamp}.ps1`. This file is never deleted after execution.
  2. Inside the script, the downloaded payload is saved to a fixed path: `$tmp = Join-Path $env:TEMP 'vpnr-repair.ps1'`.
- **Impact:** On shared multi-user systems, predictable filenames in the shared temp directory can lead to symlink attacks or pre-creation denial-of-service. Furthermore, repeated repairs pollute `%TEMP%` indefinitely.
- **Remediation:** Generate secure random filenames via `Path.GetRandomFileName()` and ensure self-deletion (`Remove-Item -Force $tmp`) upon script completion.
