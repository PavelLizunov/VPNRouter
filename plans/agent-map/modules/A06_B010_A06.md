> **TL;DR:** Module A06 (Batch B010_A06) audits the core Desktop App Views of `VPNRouter.App` (Avalonia 12.x on .NET 10), centering on `MainWindow.axaml.cs`, `ApplicationsPage.axaml.cs` (assigned as `ApplicationsView`), `FreeConfigsPage.axaml.cs`, and their companion views (`AboutWindow`, `NetworkPage` reconciling `CustomRulesView`, `ServersPage`). The audit establishes the architectural consolidation of historical/mockup standalone views (`AdvancedWindow`, `CustomRulesView`) into `MainWindow`'s unified `DeferredPage` tab model and `NetworkPage`'s responsive sub-section. Key findings include `async void` crash risks in UI event handlers (`OnBrowseExeClicked`, `OnSelectRunningProcessClicked`), synchronous child-process execution on the UI thread in `AboutWindow.GetSingBoxVersion()`, unthrottled process table enumeration under UI flyouts, and critical lifecycle contracts including `LaunchFailureCounter.MarkStable()` on `Opened` and defensive `vm.Dispose()` on `Closed`.

```csharp
private async void OnBrowseExeClicked(object? sender, RoutedEventArgs e)
```
- **Signature**: `async void (object? sender, RoutedEventArgs e)`
- **Purpose**: Opens OS native file picker for executable selection (`.exe`, `.app`, `*.*`).
- **Data Flow & Side Effects**:
  1. Resolves `TopLevel.GetTopLevel(this)`.
  2. Awaits `topLevel.StorageProvider.OpenFilePickerAsync(new FilePickerOpenOptions { ... })`.
  3. Extracts absolute path via `files[0].TryGetLocalPath() ?? files[0].Path.LocalPath`.
  4. Extracts process filename via `Path.GetFileName(localPath)`.
  5. Updates `CustomAppInput.Text` control with process name.
  6. Dispatches command: `vm.AddCustomAppCommand.Execute(procName)`.
- **Exception Contract**: `async void` handler. Unhandled exceptions bubble directly to UI thread / `AppDomain.UnhandledException`.

```csharp
private async void OnSelectRunningProcessClicked(object? sender, RoutedEventArgs e)
```
- **Signature**: `async void (object? sender, RoutedEventArgs e)`
- **Purpose**: Populates and opens a `MenuFlyout` containing currently executing desktop processes.
- **Data Flow & Side Effects**:
  1. Resolves `btn.Flyout as MenuFlyout`.
  2. Sets temporary loading placeholder: `MenuItem { Header = Strings.LoadingProcesses, IsEnabled = false }`.
  3. Offloads process scanning to worker thread via `await Task.Run(...)`:
     - Calls `Process.GetProcesses()`.
     - Iterates through processes, reading `p.ProcessName` inside try/catch.
     - Filters out nulls, empty strings, and entries in `ExcludedSystemProcesses`.
     - On Windows (`OperatingSystem.IsWindows()`), ensures name ends in `.exe`.
     - Calls `p.Dispose()` in `finally`.
     - Applies `Distinct(StringComparer.OrdinalIgnoreCase)`, sorts alphabetically, and limits to top 60 (`Take(60)`).
  4. Returns to UI thread: clears menu items, creates `MenuItem` per process with click handler triggering `AddCustomAppCommand.Execute(name)`, and invokes `flyout.ShowAt(btn)`.
- **Exception Contract**: Process scan errors in `Process.GetProcesses()` return empty list. Control lookups and flyout calls assume non-null controls.

```csharp
private static string GetSingBoxVersion()
```

- **Modifiers**: `private static`
- **Purpose**: Spawns bundled `sing-box` binary to retrieve version string.
- **Implementation Details**:
  - Resolves executable from `AppPaths.SingBoxExePath`. Returns `"not installed"` if missing.

  - Catch handler writes diagnostic entry to `AppPaths.LogsDir/about-probe.log` and returns `"err: {ex.GetType().Name}"`.

## 3. DATA FLOWS & STATE MACHINES

### 3.1. Main Window Mode Switch & Page Activation

`MainWindow` orchestrates two high-level presentation modes (Simple Mode and Advanced Mode) driven by `MainWindowViewModel.IsSimpleMode`:

```
                           [ User Toggles Mode ]
                                     │
                        MainWindowViewModel.IsSimpleMode
                                     │
                  ┌──────────────────┴──────────────────┐
                  ▼                                     ▼
         IsSimpleMode == true                  IsSimpleMode == false
                  │                                     │
           [ SimplePage ]                         [ Tab Strip ]
                  │                          (Manual, Sub, Net, Apps,
           One-card UI                       Tools, FreeConfigs)
           Big Connect CTA                              │
                                                        ▼
                                                [ DeferredPage ]
                                                (Lazily instantiated on
                                                 first tab selection)
```

1. **Deferred Instantiation**: In Advanced Mode, pages (`ServersPage`, `SubscribePage`, `NetworkPage`, `ApplicationsPage`, `ToolsPage`, `FreeConfigsPage`) are wrapped in `<ctrl:DeferredPage>`. The actual `UserControl` instance is created only when its tab is first selected (`IsActive="{Binding IsXxxTabSelected}"`), optimizing startup memory and XAML visual tree footprint.
2. **Context Menu Flyout (⋯)**: Renders a naked Avalonia `Flyout` containing three-state theme selection (`System` / `Light` / `Dark`), language toggle (`RU` / `EN`), diagnostic links (Logs, Leak Check, Updates), troubleshooting actions (Setup Wizard, Health Check, Safe Mode, armed Reset Config), and the About modal trigger.

### 3.2. Applications Split-Tunneling Workflow

```
[ User Action: Browse EXE ]                    [ User Action: Running Apps ]
            │                                                │
OpenFilePickerAsync (*.exe, *.app)             Task.Run -> Process.GetProcesses()
            │                                                │
   Extract Process Name                         Filter System / Sanitize / Cap 60
            │                                                │
            └──────────────────────┬─────────────────────────┘
                                   ▼
                         Set CustomAppInput.Text
                                   │
                     AddCustomAppCommand.Execute(name)
                                   │
              MainWindowViewModel.ActiveAppGroups Updated
                                   │
                       HasPendingAppChanges = true
                                   │
                     ApplyPendingChangesCommand.Execute()
                                   │
                     Hot-Reload sing-box / Core Engine
```

1. **Input Transformation**: Path traversal and directory components are stripped using `Path.GetFileName(localPath)`, ensuring only clean executable filenames (e.g., `discord.exe`, `Telegram`) enter the routing rule pipeline.
2. **Process Deduplication**: Running processes are filtered against `ExcludedSystemProcesses`, appended with `.exe` on Windows if missing, deduplicated case-insensitively, and capped at 60 items.
3. **Pending State Propagation**: Adding an application triggers `HasPendingAppChanges`, exposing the visual warning banner and enabling `ApplyPendingChangesCommand`.

### 3.3. Responsive Container Queries

Because Avalonia 12 lacks native CSS container queries, responsive layout breakpoints are managed through code-behind size monitoring:

- **`FreeConfigsPage`**: Width `< 420px` sets `Classes.Set("narrow", true)`. XAML style selectors hide `col-aux` TextBlocks to prevent horizontal clipping.
- **`NetworkPage`**: Width `< 700px` updates `MainWindowViewModel.IsRulesNarrow`. Switches custom rules controls from horizontal column grids to stacked layout panels.

## 4. CONCURRENCY, LOCKS & LIFECYCLE

### 4.1. Threading Model & UI Dispatcher Marshalling

1. **Process Scanning Offload**: In `ApplicationsPage.OnSelectRunningProcessClicked`, `Process.GetProcesses()` and property access are dispatched onto the thread pool via `await Task.Run(...)`. Process handles are disposed on the background thread. Once complete, control returns to the Avalonia UI thread to populate `MenuFlyout.Items` and display the popup.
2. **Deferred UI Operations**: In `ServersPage.OnActiveServerChanged` and `NetworkPage.OnBulkItemClick`, operations are marshaled to the UI event loop via `Avalonia.Threading.Dispatcher.UIThread.Post(...)`:
   - Prevents re-entrancy during visual layout passes.
   - Ensures Button `Command` execution and INPC notifications settle before flyout teardown (`Hide()`).

### 4.2. Memory & Event Subscription Lifecycle

1. **DataContextChanged Teardown**: `ApplicationsPage`, `ServersPage`, and `SubscribePage` maintain private fields (`_subscribedVm`) tracking the bound ViewModel. When `DataContextChanged` fires, existing event handlers (`PropertyChanged`, `ActiveServerChanged`) are explicitly unsubscribed before attaching to the new VM instance. This prevents memory leaks and stale event firing during window recreation, localization swaps, or headless test execution.
2. **Root VM Disposal Contract**: `MainWindow.axaml.cs` binds `Closed += (_, _) => vm.Dispose()`. When the window is closed via the OS frame, `MainWindowViewModel.Dispose()` is invoked deterministically, terminating background polling loops, cancelling pending token sources, and unhooking core engine events.
3. **Advisory Startup Counter Reset**: `MainWindow.Opened` triggers `LaunchFailureCounter.MarkStable()`. Wires to `Opened` rather than the constructor because XAML parsing, styles, and template binding execute between `ctor` and `Opened`; crashes during template realization correctly register as startup failures.

## 5. SECURITY & PRIVILEGE BOUNDARIES

### 5.1. Operating System Trust Boundaries & Process Execution

1. **Hyperlink Invocation (`AboutWindow.OnOpenRepoClick`)**:
   - Validates URI scheme strictly: `uri.Scheme == Uri.UriSchemeHttp || uri.Scheme == Uri.UriSchemeHttps`.
   - Uses `ProcessStartInfo { FileName = uri.AbsoluteUri, UseShellExecute = true }`.
   - Prevents arbitrary command injection or execution of malicious protocol handlers (e.g. `file://`, `cmd://`).
2. **Binary Probe Execution (`AboutWindow.GetSingBoxVersion`)**:
   - Executes `AppPaths.SingBoxExePath` directly without shell wrapping (`UseShellExecute = false`).
   - Restricts arguments to constant string `"version"`.
   - Sets `CreateNoWindow = true`.
   - Reads within a bounded 3000 ms timeout to prevent hung processes from freezing resources.

### 5.2. Process Name Sanitization & Split-Tunnel Invariants

1. **Path Stripping**: In `ApplicationsPage.OnBrowseExeClicked`, full file paths provided by `OpenFilePickerAsync` are normalized with `Path.GetFileName(localPath)`. Prevents relative path manipulation (`../../`) from being stored in configuration rules.
2. **System Process Denylist**: `ExcludedSystemProcesses` enforces a strict denylist preventing users from accidentally routing core Windows kernel binaries (`smss.exe`, `csrss.exe`, `lsass.exe`, `services.exe`) through VPN tunnels, which would induce kernel deadlocks or Windows security subsystem failures.

## 6. SUSPICIOUS PATTERNS / DEFECT CANDIDATES

### 6.1. `async void` Event Handlers Crash Risk (P2 / High)

**Locations**:
- `VPNRouter.App/Views/Pages/ApplicationsPage.axaml.cs:83` (`OnBrowseExeClicked`)
- `VPNRouter.App/Views/Pages/ApplicationsPage.axaml.cs:124` (`OnSelectRunningProcessClicked`)

**Mechanism**: Both methods are declared `private async void`. In .NET, unhandled exceptions inside `async void` methods cannot be caught by callers and bubble directly to the synchronization context / `AppDomain.UnhandledException`, terminating the application process. While `OpenFilePickerAsync` and `Process.GetProcesses()` contain inner try/catch blocks, unexpected exceptions thrown by Avalonia's storage provider or control resolution (e.g. if `TopLevel` or `Flyout` is unexpectedly detached or null during rapid window close) will crash the application.

**Remediation**: Wrap the entirety of both method bodies in a top-level `try { ... } catch (Exception ex) { ... }` block with defensive logging.

---

### 6.2. UI Thread Blocking in `AboutWindow` Constructor (P3 / Medium)

**Location**:
- `VPNRouter.App/Views/AboutWindow.axaml.cs:38` (`SingBoxTextBlock.Text = GetSingBoxVersion();`)

**Mechanism**: `GetSingBoxVersion()` is called synchronously inside `AboutWindow`'s parameterless constructor. It executes an external child process (`sing-box version`), reads two stream buffers to end, and calls `proc.WaitForExit(3000)`. If `sing-box.exe` is being locked, scanned by antivirus software, or experiencing I/O latency, the UI thread freezes for up to 3 seconds before the About window can open.

**Remediation**: Populate `SingBoxTextBlock.Text` asynchronously upon `Opened` or `Loaded`, or reuse the cached version string from `MainWindowViewModel.GetSingBoxVersion()`.

---

### 6.3. Concurrent Process Scan / Flyout Re-entrancy (P3 / Medium)

**Location**:
- `VPNRouter.App/Views/Pages/ApplicationsPage.axaml.cs:124-202` (`OnSelectRunningProcessClicked`)

**Mechanism**: If the user repeatedly clicks `RunningProcessesButton` while `await Task.Run(...)` is scanning processes in the background, multiple concurrent background scans are queued. The subsequent UI updates race to mutate `items.Clear()` and add `MenuItem` elements to the same `flyout.Items` collection, potentially resulting in duplicated or malformed flyout lists.

**Remediation**: Disable the button or check an `_isScanningProcesses` boolean flag at the start of `OnSelectRunningProcessClicked`.

---

### 6.4. Double-Click Selection Mutation Race in `FreeConfigsPage` (P4 / Low)

**Location**:
- `VPNRouter.App/Views/Pages/FreeConfigsPage.axaml.cs:28-39` (`ConfigsList_DoubleTapped`)

**Mechanism**:
```csharp
if (fcVm.SelectedItem != null && !fcVm.IsBusy)
{
    if (fcVm.ApplySelectedCommand.CanExecute(null))
        fcVm.ApplySelectedCommand.Execute(null);
}
```
If the user double-clicks while the list is actively updating or clearing (e.g. during an automated verification batch), `fcVm.SelectedItem` could theoretically be reset or replaced between the null-check and command execution.

**Remediation**: Capture `var item = fcVm.SelectedItem;` into a local variable or pass the tapped item directly via command parameter.
