> **TL;DR:** Core Windows Platform (Module C35) encapsulates low-level Windows OS integration across DNS leak prevention (`WindowsDnsHardening`), legacy PnP adapter cleanup (`WindowsPnpDeviceManager`), and Service Control Manager command hardening (`WindowsServiceCommand`). Key findings include synchronous blocking over process execution in `WindowsDnsHardening` (`.GetAwaiter().GetResult()`), non-atomic state file writes risking registry state corruption, an uncoordinated netsh execution race between fire-and-forget lockdown enable/disable tasks, un-timeout-guarded SetupAPI device uninstallation, and strict security validation against unquoted service path vulnerabilities (CWE-428) and foreign PnP adapter deletion.

# Exhaustive Code Inventory & Audit: Core Windows Platform (Module C35 / Batch B034_C35)

## 1. SUMMARY & PURPOSE

Module C35 (`Core Windows Platform`) encompasses low-level Windows operating system integration primitives in `VPNRouter.Core`. It directly controls system-wide networking configuration, device node hardware lifecycle, and Windows Service Control Manager (`sc.exe`) interactions.

### Component Roles & Responsibilities

1. **`WindowsDnsHardening.cs` (`VPNRouter.Core.Services.WindowsDnsHardening`)**
   - **Role**: Closes operating-system-level DNS leak vectors where Windows queries bypass the sing-box TUN interface (`VPNRouter-TUN`).
   - **Vectors Closed**:
     1. *Smart Multi-Homed Name Resolution (SMHNR)*: Windows 8+ sends DNS queries across all active adapters simultaneously and accepts the fastest response. In multi-homed or multi-VPN configurations, DNS queries leak through physical adapters without reaching sing-box. Mitigated via registry key `HKLM\SOFTWARE\Policies\Microsoft\Windows NT\DNSClient\DisableSmartNameResolution = 1`.
     2. *Parallel A and AAAA Queries*: Windows DNS client emits IPv4 (A) and IPv6 (AAAA) lookups in parallel across adapters. Mitigated via registry key `HKLM\SYSTEM\CurrentControlSet\Services\Dnscache\Parameters\DisableParallelAandAAAA = 1`.
     3. *TUN Interface Metric Prioritization*: When SMHNR is disabled, Windows resolves DNS using the adapter with the lowest interface metric. Pins `VPNRouter-TUN` interface metric to `1` (highest priority) via `netsh.exe interface ipv4 set interface "VPNRouter-TUN" metric=1`.
     4. *Wave 39 / BR-7 / BR-8 Firewall DNS-Port Lockdown*: Coordinates background firewall rules (UDP/53, TCP/53, TCP/853 blocks off-tunnel while permitting loopback `127.0.0.1:53` and the sing-box TUN endpoint `172.19.0.2:53`) via `FirewallManager`. Implements the "Auto" fail-open policy (`DnsLockdownPolicy`), arming only after the warm-up probe confirms the TUN interface is actively routing, and immediately lifting blocks upon tunnel outage or crash.
   - **Lifecycle & Recovery**: Saves original registry values and metric alteration flags to `%ProgramData%\VPNRouter\dns-hardening-state.json`. If a stale state file is detected during startup (indicating an unclean previous shutdown or crash), restores original settings before reapplying to prevent permanently baking modified values into the baseline.

2. **`WindowsPnpDeviceManager.cs` (`VPNRouter.Core.Services.WindowsPnpDeviceManager`)**
   - **Role**: Provides direct SetupAPI, NewDev, and Configuration Manager P/Invoke device management for Windows builds where `pnputil.exe` predates `/remove-device` and `/enum-devices` switches (specifically Windows 10 LTSC 2019 / build 17763, where Windows build < 19041).
   - **Problem Solved**: When Wintun crashes or terminates abruptly, orphaned phantom network device nodes remain registered in the PnP manager. Wintun fails on subsequent startup with `ERROR_FILE_EXISTS`. Because older Windows 10 builds lack modern `pnputil` device management commands, low-level Win32 P/Invoke is necessary to remove the stranded device node.
   - **Security Whitelist & Ownership Boundaries**: To prevent accidental corruption or deletion of host physical network adapters, Hyper-V switches, or third-party VPN interfaces (such as Tailscale or WireGuard), strictly enforces adapter name whitelisting (`VPNRouter-TUN`, `sing-box-tun`, `sing-box-tun-*`) and validates that PnP instance IDs conform strictly to `SWD\Wintun\{GUID}` format.

3. **`WindowsServiceCommand.cs` (`VPNRouter.Core.Services.WindowsServiceCommand`)**
   - **Role**: Pure contract helper and command-line builder for the Windows Service Control Manager (`sc.exe`).
   - **Vulnerabilities Mitigated**:
     1. *Unquoted Service Path (CWE-428)*: Enforces strict quote boundaries around the executable image path (`"C:\Program Files\VPNRouter\VPNRouter.Service.exe" --service`), preventing whitespace path hijacking during service launch.
     2. *Service Command Injection*: Validates that image paths do not contain extraneous quotation marks and splits arguments into discrete array tokens (`ArgumentList`) rather than concatenated shell strings.
     3. *Binary Hijacking / PATH Interception*: Resolves absolute inbox path to `%SystemRoot%\System32\sc.exe` via `GetSystemScPath()`, eliminating vulnerability to malicious `sc.exe` binaries planted in application or current working directories.
     4. *Foreign Service Guard*: Inspects installed service configurations to verify whether an existing service belongs to VPNRouter or is a foreign binary masquerading under the same service name.

## 4. CONCURRENCY, LOCKS & LIFECYCLE

### Concurrency Mechanisms & Thread Boundaries
1. **`WindowsDnsHardening._lockdownEffective`**:
   - Declared as `private static volatile bool _lockdownEffective`.
   - Access points:
     - HealthMonitor background timer thread (calling `ReconcileLockdownForHealth`).
     - StartupPipeline background task (calling `EnableLockdownIfConfigured`).
     - Crash/exit callback on sing-box process handle (calling `ReconcileLockdownForHealth(false)`).
     - UI or lifecycle thread invoking `VpnEngine.Stop` -> `WindowsDnsHardening.Restore`.
   - **Observation**: `volatile` guarantees read/write visibility across processor cores, but does *not* provide atomicity for check-then-act transitions.

2. **Fire-and-Forget Asynchronous Tasks**:
   - `WindowsDnsHardening.ReconcileLockdownForHealth` and `Restore` spawn detached background tasks using `_ = Task.Run(async () => { ... })`.
   - **Rationale**: Prevents synchronous netsh execution (which may take 1-5 seconds) from blocking critical paths such as `HealthMonitor` timer ticks, startup pipelines, or `VpnEngine.Stop`.
   - **Teardown Impact**: If the application process terminates immediately after `Restore()` is called, these detached tasks may be aborted before the netsh commands complete execution.

3. **Synchronous Blocking via `GetAwaiter().GetResult()`**:
   - In `WindowsDnsHardening.TrySetTunMetricViaRunner`, the process execution is invoked via:
     ```csharp
     var result = runner.RunAsync(req).GetAwaiter().GetResult();
     ```
   - This performs synchronous waiting on an asynchronous `Task<ProcessResult>` on whatever thread invokes `Apply` or `Restore`.

4. **Resource Management in P/Invoke (`WindowsPnpDeviceManager`)**:
   - `RemoveDevice` allocates an unmanaged device info set handle via `SetupDiCreateDeviceInfoList`.
   - Handle cleanup is strictly enclosed in a `try...finally` block calling `SetupDiDestroyDeviceInfoList(deviceInfoSet)`.

5. **Thread Safety in Tests (`_runnerOverride`)**:
   - `WindowsDnsHardening._runnerOverride` is a mutable static field. Tests rely on `IDisposable` in `WindowsDnsHardeningTests` to set it back to `null`. It is not thread-safe and assumes serial test execution within that fixture.

## 5. SECURITY & PRIVILEGE BOUNDARIES

### 1. Privilege & Elevation Requirements
- **Registry Modification (`WindowsDnsHardening`)**:
  - Writing to `HKLM\SOFTWARE\Policies\Microsoft\Windows NT\DNSClient` and `HKLM\SYSTEM\CurrentControlSet\Services\Dnscache\Parameters` requires administrative privileges (`BUILTIN\Administrators` or `NT AUTHORITY\SYSTEM`).
  - Standard user accounts lack permission to modify these keys. The operations fail, catch the `SecurityException`/`UnauthorizedAccessException`, and log a warning ("Apply failed (non-fatal)").
- **Network Interface Metric (`netsh.exe`)**:
  - Modifying adapter metrics via `netsh interface ipv4 set interface` requires administrative elevation. Without elevation, netsh exits with code 1.
- **PnP Device Uninstallation (`WindowsPnpDeviceManager`)**:
  - `DiUninstallDevice` in `newdev.dll` requires `SeLoadDriverPrivilege` / local administrator privileges.
- **Service Creation / Configuration (`WindowsServiceCommand`)**:
  - Executing `sc.exe create` or `sc.exe config` requires `SC_MANAGER_CREATE_SERVICE` access on the Service Control Manager database (Admin/LocalSystem).

### 2. Path Traversal & Injection Protections
- **Executable Path Quoting (`WindowsServiceCommand.FormatImagePath`)**:
  - Specifically protects against CWE-428 (Unquoted Search Path or Element). If an application installs into `C:\Program Files\VPNRouter`, an unquoted service path could allow an unprivileged attacker to drop `C:\Program.exe` or `C:\Program Files\VPNRouter\VPNRouter.exe` to achieve privilege escalation to `LocalSystem`.
  - Rejects any executable path containing an embedded quotation mark (`"`).
  - Formats image path with quotes strictly encapsulating the executable path, leaving `--service` unquoted outside.
- **Inbox Tool Path Pinning (`WindowsServiceCommand.GetSystemScPath`)**:
  - Eliminates reliance on the `PATH` environment variable or current working directory by resolving directly to `%SystemRoot%\System32\sc.exe`.
- **PnP Adapter Whitelist (`WindowsPnpDeviceManager.IsOwnedAdapterName`)**:
  - Blocks any attempt to remove unowned adapters.
  - Whitelist: Exact match on `"VPNRouter-TUN"` or `"sing-box-tun"`, or starting with `"sing-box-tun-"` followed strictly by alphanumeric, hyphen, or underscore characters.
  - Fails closed on any foreign adapter names (such as physical NICs or competitor VPNs).
- **Wintun PnP ID Structure Validation (`TryValidateOwnedWintunMapping`)**:
  - Validates that the Connection ID is a valid braced GUID.
  - Validates that the PnP Instance ID strictly matches the format `SWD\Wintun\{GUID}` where the suffix is a valid braced GUID.

### 3. State & Logging Redaction
- No sensitive user credentials, tokens, or private keys are processed or stored by any of these three components.
- State file `%ProgramData%\VPNRouter\dns-hardening-state.json` contains only boolean and integer flags:
  ```json
  {
    "Smhnr": { "HadValue": true, "OldValue": 0 },
    "ParallelAAAA": { "HadValue": false, "OldValue": 0 },
    "TunMetricChanged": true
  }
  ```

## 6. SUSPICIOUS PATTERNS / DEFECT CANDIDATES

### Finding 1: Sync-Over-Async Blocking in `TrySetTunMetricViaRunner`
- **Location**: `VPNRouter.Core/Services/WindowsDnsHardening.cs:400`
- **Pattern**:
  ```csharp
  var result = runner.RunAsync(req).GetAwaiter().GetResult();
  ```
- **Risk**: Calling `.GetAwaiter().GetResult()` synchronously blocks the calling thread while awaiting an asynchronous process invocation. If `Apply()` or `Restore()` is called on a UI thread or under heavy thread pool contention, this risks thread pool exhaustion or deadlock.
- **Recommendation**: Provide async overloads `ApplyAsync()` and `RestoreAsync()`, or route the synchronous path through a dedicated background execution boundary.

### Finding 2: Non-Atomic State File Persistence in `SaveState`
- **Location**: `VPNRouter.Core/Services/WindowsDnsHardening.cs:446`
- **Pattern**:
  ```csharp
  var json = JsonSerializer.Serialize(state, WindowsDnsHardeningJsonContext.Default.HardeningState);
  File.WriteAllText(StatePath, json);
  ```
- **Risk**: Direct write to `StatePath` without writing to a temporary file and atomically replacing/moving (`File.Replace` / `File.Move`) means an unexpected power cut, crash, or kill signal during `File.WriteAllText` can result in a truncated or 0-byte file.
- **Impact**: On subsequent startup, `File.Exists(StatePath)` evaluates to true, but `LoadState()` throws a JSON deserialization exception and returns `null`. Consequently, the crash recovery mechanism fails to restore the user's true baseline settings, and newly applied settings permanently overwrite the original state!

### Finding 3: Race Condition on Background Lockdown Transitions
- **Location**: `VPNRouter.Core/Services/WindowsDnsHardening.cs:181-221`
- **Pattern**:
  `ReconcileLockdownForHealth` updates `_lockdownEffective` and immediately fires an unawaited background task `_ = Task.Run(async () => { await FirewallManager.EnableDnsLockdownAsync(...); })` or `DisableDnsLockdownAsync(...)`.
- **Risk**: If the HealthMonitor tick, warm-up probe completion, and a crash callback occur in rapid succession (e.g. during tunnel flap), multiple background tasks can execute concurrently. Because `netsh.exe` execution takes multiple seconds, `EnableDnsLockdownAsync` and `DisableDnsLockdownAsync` can run out of order or interleave, leaving the firewall in an inconsistent state (e.g., DNS port blocks remaining enabled when the tunnel is down).
- **Recommendation**: Guard firewall lockdown mutations with an asynchronous queue, channel, or semaphore to ensure strict sequential execution.

### Finding 4: Absence of Cancellation Support and Teardown Wait in `Restore`
- **Location**: `VPNRouter.Core/Services/WindowsDnsHardening.cs:276-286`
- **Pattern**:
  ```csharp
  _ = Task.Run(async () =>
  {
      try { await FirewallManager.DisableDnsLockdownAsync(log); }
      catch (Exception ex) { ... }
  });
  ```
- **Risk**: When shutting down the application (`VpnEngine.Stop`), `Restore()` returns immediately while `DisableDnsLockdownAsync` is still running in the background. If the process terminates, the task is killed before netsh can delete the firewall rules. The user is then left with orphaned firewall block rules on port 53/853 without sing-box running, breaking general internet connectivity!

### Finding 5: Missing OS Platform Guard on Native SetupAPI P/Invoke Methods
- **Location**: `VPNRouter.Core/Services/WindowsPnpDeviceManager.cs:164-208`
- **Pattern**:
  `RemoveDevice(string instanceId)` and `QueryPresence(string instanceId)` do not contain `#if PLATFORM_WINDOWS` or `OperatingSystem.IsWindows()` runtime checks before invoking native SetupAPI and Configuration Manager DLLs.
- **Risk**: Although `FindNetworkAdapterInstanceIds` checks `#if PLATFORM_WINDOWS`, `RemoveDevice` and `QueryPresence` are `internal static` and could be called directly on non-Windows platforms (e.g., in unit tests or cross-platform callers), resulting in an immediate `DllNotFoundException` (`setupapi.dll` / `cfgmgr32.dll`).

### Finding 6: Indefinite Hang Risk in `DiUninstallDevice`
- **Location**: `VPNRouter.Core/Services/WindowsPnpDeviceManager.cs:182`
- **Pattern**:
  ```csharp
  DiUninstallDevice(IntPtr.Zero, deviceInfoSet, ref deviceInfo, 0, out var restartRequired);
  ```
- **Risk**: `DiUninstallDevice` in `newdev.dll` is a synchronous Win32 API that waits on the Windows PnP manager and device driver stacks. If a corrupt Wintun driver instance hangs in kernel mode during `IRP_MN_REMOVE_DEVICE`, `DiUninstallDevice` blocks indefinitely without any timeout mechanism.
