> **TL;DR:** Module C19 implements Windows true-split tunneling via the Mullvad kernel driver (`mullvad-split-tunnel.sys`), Windows Filtering Platform (WFP) sublayer management, and real-time process monitoring via Windows Event Tracing (ETW). The subsystem strictly adheres to a fail-open architecture (degrading to sing-box post-capture routing rather than failing closed or breaking connectivity), provides collision avoidance against foreign split-tunnel drivers (e.g. Amnezia/Mullvad), enforces deterministic overlapped I/O and pump lifecycle management, and isolates pure protocol encoding/decoding for cross-platform unit testing.

# Exhaustive Code Inventory & Audit: Core SplitTunnelDriver (Interop, Manager, Protocol) & EtwProcessMonitor (Module C19 / Batch B025_C19)

## 1. SUMMARY & PURPOSE

Module C19 contains the Windows-specific kernel interfacing, split-tunnel routing redirection, and real-time process lifecycle monitoring for `VPNRouter`. It comprises four source files:
- `VPNRouter.Core/Services/EtwProcessMonitor.cs` (212 lines)
- `VPNRouter.Core/Services/SplitTunnelDriverInterop.cs` (291 lines)
- `VPNRouter.Core/Services/SplitTunnelDriverManager.cs` (1,190 lines)
- `VPNRouter.Core/Services/SplitTunnelDriverProtocol.cs` (702 lines)

### Subsystem Roles & Responsibilities
1. **`EtwProcessMonitor`**:
   - Subscribes to the Windows Kernel Event Tracing (`Microsoft.Diagnostics.Tracing`) `KernelTraceEventParser.Keywords.Process` provider.
   - Detects process creation and termination events in real time (<10ms latency vs. 500ms+ for WMI polling).
   - Translates raw kernel events into cross-platform `ProcessEventArgs` payloads and fires `ProcessStarted` / `ProcessStopped` events.
   - Enables dynamic split-tunnel process binding and reactive route recalculation.

2. **`SplitTunnelDriverInterop`**:
   - The native P/Invoke boundary (`[SupportedOSPlatform("windows")]`) wrapping Win32 subsystem APIs:
     - `kernel32.dll`: Device handle management (`CreateFileW`), synchronous and asynchronous/overlapped device I/O (`DeviceIoControl`, `DeviceIoControlOverlapped`, `GetOverlappedResult`, `CancelIoEx`), synchronization events (`CreateEventW`, `ResetEvent`), process inspection (`CreateToolhelp32Snapshot`, `Process32First`, `Process32Next`, `OpenProcess`, `QueryFullProcessImageNameW`, `GetProcessTimes`), and DOS device name queries (`QueryDosDeviceW`).
     - `advapi32.dll`: Windows Service Control Manager (SCM) interactions (`OpenSCManager`, `CreateService`, `OpenService`, `StartService`, `ChangeServiceConfig`, `QueryServiceConfig`, `QueryServiceStatus`, `CloseServiceHandle`).
     - `fwpuclnt.dll`: Windows Filtering Platform (WFP) Base Filtering Engine (BFE) sublayer configuration (`FwpmEngineOpen0`, `FwpmEngineClose0`, `FwpmSubLayerAdd0`, `FwpmSubLayerDeleteByKey0`).
   - Declares the custom `SafeDeviceHandle` type derived from `SafeHandleZeroOrMinusOneIsInvalid`.

3. **`SplitTunnelDriverProtocol` & `SplitTunnelPolicy`**:
   - Pure C#, platform-agnostic specification of the Mullvad split-tunnel driver ABI (`win-split-tunnel` / `mullvadvpn-app`).
   - Contains zero P/Invoke dependencies and no OS platform attributes, allowing 100% test execution on Linux and macOS CI runners.
   - Encodes hand-packed little-endian binary buffers for:
     - WFP Sublayer GUIDs (32 bytes).
     - Bound IP addresses (40 bytes; tunnel IPv4/IPv6 vs. physical internet IPv4/IPv6).
     - Process discovery registry buffers (headers, HANDLEs, offsets, and UTF-16LE image paths).
     - Excluded process configurations (headers, offsets, lengths, and concatenated UTF-16LE NT device paths).
   - Implements zero-allocation span-based parsing of the `DEQUEUE_EVENT` kernel ring buffer.
   - Houses pure decision logic: `SplitTunnelPolicy` for engage evaluation, log event severity classification, address change detection, SCM binary collision classification, sidecar SHA256 parsing, and path normalization.

4. **`SplitTunnelDriverManager`**:
   - Implements the cross-platform `ISplitTunnelDriver` interface.
   - Orchestrates the full lifecycle of the `mullvad-split-tunnel` kernel driver service:
     - Dynamic discovery, installation, and relocation self-healing (`AdoptMovedInstall`).
     - Collision prevention: strictly forbids stopping, modifying, or deleting foreign kernel services (e.g. Amnezia or Mullvad VPN).
     - WFP baseline and DNS sublayer creation and teardown.
     - Device handle acquisition and overlapped control-plane IOCTL execution.
     - Live process hierarchy snapshotting with process-creation-time PID recycling protection.
     - Background inverted-call event pump (`DEQUEUE_EVENT`) running on a dedicated thread to observe kernel split events.
     - Debounced dynamic network interface change monitoring (`NetworkChange.NetworkAddressChanged`) with retry logic.
     - Deterministic teardown and stale-state crash sweeping.
   - **Fail-Open Invariant**: Public methods never throw exceptions. Failures gracefully degrade to user-space sing-box post-capture process rules (`process_name → direct`).

## 3. DATA FLOWS & STATE MACHINES

### 3.1. ETW Process Discovery & Monitoring Flow

```
[Windows Kernel Process Manager]
               │ (Kernel Events)
               ▼
[TraceEventSession("VPNRouterETW")]
   ├── EnableKernelProvider(Process)
   │
   ├── Kernel.ProcessStart
   │     │
   │     ▼
   │   EtwProcessMonitor.TranslateProcessEvent(PID, ImageFileName, ParentPID)
   │     │ (ImageFileName ?? "")
   │     ▼
   │   ProcessStarted?.Invoke(this, ProcessEventArgs)
   │
   └── Kernel.ProcessStop
         │
         ▼
       EtwProcessMonitor.TranslateProcessEvent(PID, ImageFileName, ParentPID)
         │
         ▼
       ProcessStopped?.Invoke(this, ProcessEventArgs)
```

1. `EtwProcessMonitor.Start()` checks active sessions via `TraceEventSession.GetActiveSessionNames()`. If a dangling `"VPNRouterETW"` session exists, it stops and disposes it.
2. Creates a fresh `TraceEventSession` and background thread `"VPNRouter-ETW"`.
3. Signals `_sessionReady` to release any pending `Stop()` invocations.
4. Kernel events arrive on the worker thread via `session.Source.Process()`.
5. Event data is converted via `TranslateProcessEvent`, handling edge cases:
   - Null `ImageFileName` becomes `""`.
   - PID 0 / negative PIDs are passed through.
6. Handlers for `ProcessStarted` and `ProcessStopped` are dispatched synchronously on the ETW thread.

```
                          └─────────────────────────────┘
```

#### Engage Sequence (`EngageLocked`):
1. **Validation**: Checks `File.Exists(mullvad-split-tunnel.sys)`.
2. **Diagnostic Integrity**: Compares SHA256 of `.sys` against `checksums.sha256` sidecar (warn-only, fail-open).
3. **Foreign Driver Check**: Queries WMI `Win32_SystemDriver`. If a foreign driver is running, sets `LastFailureReason` and aborts.
4. **SCM Service Assurance**: Opens SCM; if missing, creates `mullvad-split-tunnel` (`SERVICE_DEMAND_START`, `SERVICE_KERNEL_DRIVER`). If existing, evaluates `ClassifyServiceBinPath`. Adopts moved install or starts existing.
5. **WFP Sublayer Provisioning**: Opens BFE via `FwpmEngineOpen0`, creates `SublayerBaseline` (weight `0xFFFF`) and `SublayerDns` (weight `0xFFFE`).
6. **Device Handle**: Opens exclusive overlapped handle to `\\.\MULLVADSPLITTUNNEL` via `CreateFileW`. Creates manual-reset control event.
7. **Address Resolution**: Auto-picks physical internet interface via `NetworkInterfaceDetector`. If IPv4 is missing, aborts.
8. **State Reset**: If driver is not in `Started` state, issues `IOCTL_RESET`.
9. **Four-Stage IOCTL Pipeline**:
   - `IOCTL_INITIALIZE` (0x80000004): 32 bytes of Sublayer GUIDs.
   - `IOCTL_REGISTER_PROCESSES` (0x8000000C): Process tree snapshot with PID recycle guard.
   - `IOCTL_REGISTER_IP_ADDRESSES` (0x80000010): 40 bytes of tunnel and internet IPs.
   - `IOCTL_SET_CONFIGURATION` (0x80000018): Excluded NT device paths.
10. **State Verification**: Calls `IOCTL_GET_STATE` (0x80000024); verifies state is `Engaged`.
11. **Post-Engage**: Subscribes to `NetworkChange.NetworkAddressChanged` and starts event pump thread.

#### Disengage Sequence (`DisengageLocked`):
1. Stops event pump via `CancelIoEx` and joins pump thread.
2. Unsubscribes from `NetworkChange` and cancels debounce CTS.
3. Issues `IOCTL_RESET` (leaves kernel service in `Started` state; never stops SCM service).
4. Closes device handle and control event.
5. Deletes WFP sublayers (`FwpmSubLayerDeleteByKey0`).
6. Sets `_engaged = false`.

### 3.4. Process & Configuration Memory Buffer Assembly Pipeline

#### Process Discovery (`BuildProcessSnapshotBuffer`):
1. `CreateToolhelp32Snapshot(TH32CS_SNAPPROCESS, 0)` enumerates all running processes.
2. For each process (excluding PID 0 and PID 4):
   - Opens process with `PROCESS_QUERY_LIMITED_INFORMATION`.
   - Reads native device image path via `QueryFullProcessImageNameW(PROCESS_NAME_NATIVE)`.
   - Reads process creation timestamp via `GetProcessTimes`.
   - Stores `ProcInfo(PID, ParentPID, CreationTime, NTPath)` in `Dictionary<uint, ProcInfo>`.
3. `ApplyPidRecycleGuard`: If `Parent.CreationTime > Child.CreationTime`, sets `Child.ParentPID = 0`.
4. Hand-packs binary layout:
   - Header (16 bytes): `NumEntries` (u64 LE), `TotalLength` (u64 LE).
   - Stride Array (32 bytes per entry): `PID` (u64 LE), `ParentPID` (u64 LE), `ImageNameOffset` (u64 LE, relative to string table), `ImageNameLength` (u16 LE, byte count), 6 bytes padding.
   - String Table: Concatenated UTF-16LE characters (no null terminators).

#### Configuration Buffer (`BuildConfigBuffer`):
1. Converts each DOS path (e.g. `C:\Program Files\App\app.exe`) to NT path (e.g. `\Device\HarddiskVolume3\Program Files\App\app.exe`) via `QueryDosDeviceW`.
2. Encodes paths as UTF-16LE byte arrays. Validates length $\le 65,535$.
3. Hand-packs binary layout:
   - Header (16 bytes): `NumEntries` (u64 LE), `TotalLength` (u64 LE).
   - Stride Array (16 bytes per entry): `ImageNameOffset` (u64 LE, relative to string table), `ImageNameLength` (u16 LE, byte count), 6 bytes padding.
   - String Table: Concatenated UTF-16LE bytes.

### 3.5. Inverted-Call Event Pump (`DEQUEUE_EVENT`) & Lifecycle

1. **Initialization**: Dedicated background thread `"split-tunnel-events"`. Allocates 65,600-byte buffer pinned via `GCHandle.Alloc(..., GCHandleType.Pinned)`. Creates manual-reset event `_pumpEvent`.
2. **Loop Iteration**:
   - Resets `_pumpEvent`.
   - Prepares `NativeOverlapped` holding `_pumpEvent` handle, pinned via `GCHandle`.
   - Calls `DeviceIoControlOverlapped` with `IOCTL_DEQUEUE_EVENT` (0x80000008).
   - If returned `false`, expects `Marshal.GetLastWin32Error() == ERROR_IO_PENDING`.
   - Waits synchronously for completion via `GetOverlappedResult(..., bWait: true)`.
   - Parses payload via `Proto.ParseEventBuffer` and logs event (Information for splitting, Warning for errors, Debug for malformed/unknown).
3. **Error Handling & Degradation**:
   - `ERROR_OPERATION_ABORTED` or `_pumpStop == true`: Clean exit.
   - Up to 3 consecutive errors: Tracked via `_pumpErrorStreak`. At 3 errors, logs warning, sets `_pumpHealthy = false`, and terminates thread. In-kernel splitting remains active.
4. **Shutdown**:
   - `StopPumpLocked()` sets `_pumpStop = true`.
   - Calls `CancelIoEx(_device, IntPtr.Zero)`.
   - Waits up to 2 seconds for thread join. If timed out, abandons thread safely without unpinning memory until thread exits.

### 3.6. Collision Guard & Foreign Driver Arbitration Flow

When checking service configuration via `EnsureServiceLocked()`:
1. Opens service `mullvad-split-tunnel`.
2. Queries current binary path via `QueryServiceConfig`.
3. Normalizes path (stripping `\??\`, quotes, whitespace, and lowercasing).
4. `SplitTunnelPolicy.ClassifyServiceBinPath`:
   - Exact match with current executable's driver path $\rightarrow$ `StartExisting`.
   - Contains path segment `\vpnrouter\` AND ends with `\driver\mullvad-split-tunnel.sys` $\rightarrow$ `AdoptMovedInstall` (updates path via `ChangeServiceConfig` and starts).
   - Any other path (e.g. `\Mullvad VPN\resources\...` or unknown squatter) $\rightarrow$ `BailForeign`.
5. If `BailForeign`, aborts startup, records owner in `LastFailureReason`, and leaves existing service untouched.
6. Before SCM operations, inspects `Win32_SystemDriver` for running drivers matching `*\mullvad-split-tunnel.sys` under a foreign service name (e.g. `AmneziaVPNSplitTunnel`). If found, refuses to start.

## 4. CONCURRENCY, LOCKS & LIFECYCLE

### 4.1. Synchronization Primitives Matrix

| Component | Primitive | Purpose | Scope / Guarded State | Timeout / Granularity |
|---|---|---|---|---|
| `SplitTunnelDriverManager` | `SemaphoreSlim _gate` (1, 1) | Serializes control plane | `EngageLocked`, `DisengageLocked`, `ReRegisterIfChangedAsync`, `SweepStaleStateAsync` | `WaitAsync(ct)`, 5s on Dispose |
| `SplitTunnelDriverManager` | `SafeWaitHandle _controlEvent` | Synchronous overlapped IOCTL completion | Blocks caller thread in `GetOverlappedResult(bWait: true)` | Kernel wait per IOCTL |
| `SplitTunnelDriverManager` | `SafeWaitHandle _pumpEvent` | Inverted-call event pump completion | Blocks `_pumpThread` in `GetOverlappedResult(bWait: true)` | Kernel wait per event |
| `SplitTunnelDriverManager` | `Interlocked.Exchange` | Thread-safe replacement of debounce CTS | `_debounceCts` | Atomic |
| `SplitTunnelDriverManager` | `volatile bool _engaged` | Lock-free query of engaged status | `IsEngaged` property | Atomic read/write |
| `SplitTunnelDriverManager` | `volatile bool _pumpHealthy` | Lock-free query of pump health | `IsPumpHealthy` property | Atomic read/write |
| `SplitTunnelDriverManager` | `volatile bool _pumpStop` | Signal pump thread shutdown | `PumpLoop` termination | Atomic read/write |
| `EtwProcessMonitor` | `ManualResetEventSlim _sessionReady` | Signals assignment of `_session` | Prevents race between `Start()` and `Stop()` | 1s timeout in `Stop()` |
| `EtwProcessMonitor` | Background `Thread` | ETW kernel trace processing | `RunSession()` / `session.Source.Process()` | Dedicated OS thread |

### 4.2. Control-Plane vs Event-Pump Concurrency Isolation

- `SplitTunnelDriverManager` separates the control plane and event pump over the same kernel device handle:
  - Both open the same `SafeDeviceHandle` created with `FILE_FLAG_OVERLAPPED`.
  - The control plane executes under `_gate` using `_controlEvent` and dedicated pinned `NativeOverlapped` structures.
  - The event pump runs continuously on `_pumpThread` using `_pumpEvent` and a separate `NativeOverlapped` structure.
  - Windows kernel drivers support concurrent overlapped requests on the same device handle when distinct `OVERLAPPED` instances and event handles are used.
  - Pump degradation or crash does not affect the control plane or kernel-level routing.

### 4.3. Async/Await Patterns, Thread Boundaries & Blocking Calls

- **`EngageAsync` / `DisengageAsync`**: Asynchronous entry points (`await _gate.WaitAsync(ct)`). Once the gate is acquired, internal work (`EngageLocked`, `DisengageLocked`) is performed synchronously. Control IOCTLs take $<10$ms and are reaped synchronously with `GetOverlappedResult(bWait: true)`.
- **`ReRegisterIfChangedAsync`**: Releases `_gate` before initiating a 5-second retry delay (`Task.Delay(ReRegisterRetryDelay, ct)`). This prevents blocking concurrent calls to `DisengageAsync` or engine shutdown while waiting for network stabilization.
- **`EtwProcessMonitor.Start()`**: Non-blocking; delegates blocking `TraceEventSession.Source.Process()` to `_sessionThread`.

### 4.4. Cancellation Token Propagation & Teardown Guarantees

- **Cancellation Handling**:
  - `EngageAsync(ct)`: If canceled during `_gate.WaitAsync(ct)`, catches `OperationCanceledException` and returns `false` (fail-open).
  - `DisengageAsync(ct)`: If canceled during `_gate.WaitAsync(ct)`, catches `OperationCanceledException` and returns cleanly.
  - `SweepStaleStateAsync(ct)`: If canceled during `_gate.WaitAsync(ct)`, returns cleanly.
- **Teardown Guarantees (`DisengageLocked`)**:
  - Orders shutdown deliberately:
    1. `StopPumpLocked()` cancels pending I/O and joins pump thread.
    2. `UnsubscribeNetworkChangeLocked()` unhooks network events and cancels debounce CTS.
    3. `TryResetLocked()` issues `IOCTL_RESET` to return driver to inert state.
    4. `CloseDeviceLocked()` closes device handle.
    5. `DeleteSublayersLocked()` cleans up WFP sublayers.
    6. `_engaged = false`.

### 4.5. Superseded CTS Lifetime Management (The r2 Crash Fix)

In `SplitTunnelDriverManager.OnNetworkAddressChanged`:
- Bursts of network address changes occur during adapter initialization or reconnects.
- `fresh = new CancellationTokenSource()` is atomically swapped into `_debounceCts` via `Interlocked.Exchange`.
- The prior CTS is canceled and disposed immediately by the caller:
  ```csharp
  var prior = Interlocked.Exchange(ref _debounceCts, fresh);
  if (prior is not null)
  {
      try { prior.Cancel(); }
      catch (ObjectDisposedException) { }
      finally { prior.Dispose(); }
  }
  ```
- The background task spawned to run `ReRegisterIfChangedAsync` **never disposes its own CTS** in a finally block.
- This eliminates the use-after-dispose race where `Interlocked.Exchange` could return a CTS already disposed by its own completing task, which previously resulted in an unhandled `ObjectDisposedException` crashing the process.

## 5. SECURITY & PRIVILEGE BOUNDARIES

### 5.1. Privilege & Elevation Prerequisites
- **Administrator Elevation**:
  - `EtwProcessMonitor`: Opening kernel ETW trace sessions (`TraceEventSession` with `KernelTraceEventParser.Keywords.Process`) strictly requires Administrator privileges. Running under a standard user token causes `TraceEventSession` creation to throw an `UnauthorizedAccessException`.
  - `SplitTunnelDriverManager`: Creating, modifying, and starting Windows Services via SCM (`OpenSCManager` with `SC_MANAGER_ALL_ACCESS`) and modifying WFP sublayers via BFE (`FwpmEngineOpen0`) strictly require Administrator privileges.
- **Fail-Open Behavior under Reduced Privileges**:
  - If `OpenSCManager` fails with `ERROR_ACCESS_DENIED` (5), `EnsureServiceLocked` logs an administrative warning, populates `LastFailureReason`, and returns `false`.
  - If `CreateFileW` on `\\.\MULLVADSPLITTUNNEL` fails with `ERROR_ACCESS_DENIED`, `EnsureDeviceOpenLocked` logs a warning and returns `false`.
  - Under all elevation failures, VPNRouter continues operating using standard user-space sing-box routing.

### 5.2. Device & Driver Path Sanitization / Verification
- **Fixed Device Path**: `\\.\MULLVADSPLITTUNNEL` is hardcoded; no user-supplied device strings are accepted.
- **Driver Location**: Default path is anchored to `AppContext.BaseDirectory/driver/mullvad-split-tunnel.sys`.
- **Sidecar SHA256 Integrity Verification**:
  - `VerifySysIntegrityLocked` reads `driver/checksums.sha256`.
  - Parses expected hash via `SplitTunnelPolicy.ParseSidecarHashFor`.
  - Computes `SHA256.HashData` over the driver binary.
  - Emits a warning on mismatch to diagnose stale or ABI-mismatched files while relying on Windows kernel driver signature verification (WHQL / driver signature enforcement) as the authoritative execution gate.

### 5.3. Collision & Foreign Driver Protection (No Service Deletion Invariant)
- **Coexistence Invariant**: VPNRouter strictly forbids stopping, deleting, or altering split-tunnel kernel services owned by other applications (such as official Mullvad VPN or Amnezia VPN). Stopping another provider's kernel driver at runtime can cause OS blue-screens (BSOD).
- **Collision Rules (`SplitTunnelPolicy.ClassifyServiceBinPath`)**:
  - Only paths containing a `\vpnrouter\` path segment AND ending with `\driver\mullvad-split-tunnel.sys` are recognized as relocations of VPNRouter's driver.
  - Substring-only matches (e.g. `\NotVpnRouterApp\...`) or wrong directory structures trigger `ServiceCollisionAction.BailForeign`.
  - VPNRouter never calls `DeleteService` or `ControlService(..., SERVICE_CONTROL_STOP)` on kernel services.

### 5.4. Diagnostic Redaction & Integrity Verification
- Event pump payloads and process tracking logs record process names (e.g. `Discord.exe`), PIDs, and NT device paths.
- Paths and process arguments are not logged to diagnostics exports without passing through `DiagnosticsRedactor`.
- Driver error statuses (`NTSTATUS` and Win32 error codes) are formatted as hex/decimal integers without exposing sensitive user environment variables.

### 5.5. Fail-Open Security Architecture
- The entire split-tunnel subsystem is built on a fail-open security model:
  - If driver files are missing, WFP fails, SCM fails, or foreign drivers conflict, `EngageAsync` returns `false`.
  - Generated sing-box configurations always retain fallback user-space rules (`process_name → direct`).
  - Kernel driver binding is an optimization to prevent socket leaks before sing-box captures them; failure to engage never severs internet connectivity.

## 6. SUSPICIOUS PATTERNS / DEFECT CANDIDATES

### 6.1. `EtwProcessMonitor`: Concurrency Races in `Start()` / `Stop()` without Mutex
- **Location**: `EtwProcessMonitor.cs`, lines 51–64 (`Start()`) and 66–111 (`Stop()`).
- **Observation**: Neither `Start()` nor `Stop()` uses a locking primitive (`lock` or `SemaphoreSlim`).
- **Vulnerability**:
  - If `Start()` is invoked concurrently from two threads, both can observe `_session == null` before `RunSession` assigns `_session`. This creates two distinct worker threads running `RunSession()`. Both threads will attempt to open `TraceEventSession("VPNRouterETW")`, causing session conflicts or thread leakage.
  - If `Stop()` is called concurrently with `Start()`, `_sessionThread` can be overwritten or set to `null` while the thread is still being spawned.
- **Recommendation**: Introduce a `private readonly object _syncLock = new();` to synchronize `Start()`, `Stop()`, and `Dispose()`.

### 6.2. `EtwProcessMonitor`: Thread-Join Deadlock Hazard on Event Callbacks
- **Location**: `EtwProcessMonitor.cs`, lines 101–110 and 132–156.
- **Observation**: `RunSession()` invokes `ProcessStarted` and `ProcessStopped` directly on `_sessionThread`.
- **Vulnerability**: If an event subscriber directly or indirectly calls `EtwProcessMonitor.Stop()` or `Dispose()` from within their event handler callback, `Stop()` calls `thread.Join(TimeSpan.FromSeconds(2))` where `thread` is the *current calling thread* (`_sessionThread`).
- **Impact**: The calling thread deadlocks itself waiting for its own termination until the 2-second timeout expires, degrading shutdown performance.
- **Recommendation**: Add a check `if (Thread.CurrentThread != thread) thread.Join(...)` in `Stop()`, or dispatch event invocations to `ThreadPool.QueueUserWorkItem`.

### 6.3. `EtwProcessMonitor`: Synchronous Dispatch Blocking ETW Kernel Buffers
- **Location**: `EtwProcessMonitor.cs`, lines 132–156.
- **Observation**: Event callbacks (`ProcessStarted?.Invoke`, `ProcessStopped?.Invoke`) execute synchronously inside the TraceEvent event processing callback.
- **Vulnerability**: If a subscriber performs blocking work (e.g. disk I/O, lock contention, or process scanning), the ETW worker thread is blocked from calling `session.Source.Process()`.
- **Impact**: Windows kernel ETW circular buffers can overflow, causing silent kernel event drops.
- **Recommendation**: Enqueue process start/stop events into a lightweight channel (`Channel<ProcessEventArgs>`) consumed by a worker, keeping the ETW callback non-blocking.

### 6.4. `SplitTunnelDriverManager`: `EngagedChanged` Event Lock Inconsistency
- **Location**: `SplitTunnelDriverManager.cs`, lines 56–58, 203, 218, and 998.
- **Observation**:
  - The XML documentation on `ISplitTunnelDriver.EngagedChanged` states:
    `"Handlers run under the manager lock — keep them trivial and non-reentrant."`
  - In `EngageAsync` (line 203) and `DisengageAsync` (line 218), `RaiseEngagedChanged` is called **outside** `_gate` (after `_gate.Release()`).
  - In `ReRegisterIfChangedAsync` (line 998), `RaiseEngagedChanged` is called **inside** `_gate`.
- **Vulnerability**:
  - If Thread A completes `EngageAsync` and releases `_gate`, Thread B can enter `DisengageAsync`, complete `DisengageLocked()`, release `_gate`, and fire `EngagedChanged(false)`. If Thread A then fires `EngagedChanged(true)`, listeners receive an out-of-order state update (`false` followed by `true`), leaving UI badges out of sync with actual driver state.
- **Recommendation**: Ensure `EngagedChanged` firing order is strictly serialized or state transitions are stamped with a monotonic revision counter.

### 6.5. `SplitTunnelDriverManager`: Synchronous WMI Query Overhead during Startup
- **Location**: `SplitTunnelDriverManager.cs`, lines 599–624 (`FindRunningForeignSplitDrivers`).
- **Observation**:
  ```csharp
  using var searcher = new ManagementObjectSearcher(
      "SELECT Name, DisplayName, State, PathName FROM Win32_SystemDriver WHERE State = 'Running'");
  foreach (ManagementObject driver in searcher.Get()) ...
  ```
- **Vulnerability**: Executing WMI queries synchronously inside `EngageLocked` (which runs on the critical startup path under `_gate`) can introduce 300ms–2000ms of latency, or hang if the Windows Management Instrumentation service (`winmgmt`) repository is corrupted.
- **Recommendation**: Cache the foreign driver check result, or query service status directly via `EnumServicesStatusEx` in `advapi32.dll` instead of WMI.

### 6.6. `SplitTunnelDriverManager`: High Allocation Churn in `PumpLoop`
- **Location**: `SplitTunnelDriverManager.cs`, lines 1105–1128.
- **Observation**: Inside the `while (!_pumpStop)` loop:
  ```csharp
  var overlapped = new NativeOverlapped { EventHandle = evt.DangerousGetHandle() };
  var ovH = GCHandle.Alloc(overlapped, GCHandleType.Pinned);
  try { ... }
  finally { if (ovH.IsAllocated) ovH.Free(); }
  ```
- **Vulnerability**: For every received driver event, a `NativeOverlapped` struct is boxed, pinned with `GCHandle.Alloc`, and unpinned. Under high socket or process activity, this creates unnecessary GC handle churn and memory fragmentation.
- **Recommendation**: Allocate a single reusable `NativeOverlapped` struct (or pin a single field on the manager) across the lifetime of the pump thread.

### 6.7. `SplitTunnelDriverManager`: Race Window during Address Re-Registration Retry Delay
- **Location**: `SplitTunnelDriverManager.cs`, lines 980–988.
- **Observation**: In `ReRegisterIfChangedAsync`, `_gate` is released before awaiting `Task.Delay(ReRegisterRetryDelay, ct)`.
- **Vulnerability**: While `_gate` is released for 5 seconds, an external call to `EngageAsync` can re-engage the driver with a completely new configuration request (`_lastRequest`). When the delay completes and `_gate` is re-acquired, `ReRegisterIfChangedAsync` calls `ResolveAddresses(_lastRequest)` and re-registers the driver using the new request, potentially overwriting a state change made during the wait.
- **Recommendation**: Capture the target `_lastRequest` reference before releasing the gate and verify `_lastRequest` has not mutated upon re-acquiring the gate.

### 6.8. `SplitTunnelDriverInterop`: Documentation vs. Kernel Behavior of `CancelIoEx`
- **Location**: `SplitTunnelDriverInterop.cs`, line 112.
- **Observation**: The doc-comment states: `"Pass the address of the same OVERLAPPED to cancel just that request, or IntPtr.Zero to cancel all I/O this thread issued."`
- **Correction**: Win32 `CancelIoEx(hDevice, NULL)` cancels all outstanding I/O requests for the specified file handle issued by **any thread**, unlike `CancelIo` which only cancels requests issued by the calling thread. The code functions correctly because cross-thread cancellation is exactly what `StopPumpLocked` requires, but the comment incorrectly characterizes it as calling-thread-scoped.
