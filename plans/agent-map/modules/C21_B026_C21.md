> **TL;DR:** Module C21 (`ProfileApplication`, `ProfileManager`, `SettingsLoader`, `SettingsMigrator`, `SettingsValidator`) forms the configuration lifecycle and profile management backbone of VPNRouter. It provides atomic YAML settings persistence with disaster-recovery backups (`.unloadable` / `.invalid`), deterministic forward schema migrations (v0–v8), strict semantic and port validation, multi-source profile aggregation (GitHub, Local, Built-in) with JSON-DoS depth capping (MaxDepth=32), and pure functional Android/desktop profile application planning. Critical defect candidates identified include silent loss of `AndroidPackages` during profile merges, `ArgumentNullException` in `ResolveDnsMode` if `dns_mode` is null, unpruned `ActiveSubscriptionServer` references during placeholder cleanup, and unsynchronized concurrency in the `FileSystemWatcher` reload timer.

# Exhaustive Code Inventory & Audit: Core ProfileManager, SettingsLoader, SettingsMigrator, SettingsValidator, ProfileApplication (Module C21 / Batch B026_C21)

## 1. SUMMARY & PURPOSE

Module C21 resides in `VPNRouter.Core/Services/` and serves as the single source of truth for loading, migrating, validating, persisting, and applying user configuration and routing profiles. It contains five core source files:
- `VPNRouter.Core/Services/ProfileApplication.cs` (81 lines)
- `VPNRouter.Core/Services/ProfileManager.cs` (477 lines)
- `VPNRouter.Core/Services/SettingsLoader.cs` (786 lines)
- `VPNRouter.Core/Services/SettingsMigrator.cs` (662 lines)
- `VPNRouter.Core/Services/SettingsValidator.cs` (325 lines)

### Subsystem Roles & Responsibilities

1. **`ProfileApplication` & `ProfileApplyPlan`**:
   - Provides a pure, side-effect-free functional bridge between high-level routing profiles (`Profile`) and platform-specific storage writes.
   - Used by the Android profiles overlay (`AND-PROFILES` in `AndroidApp`) to translate catalog selections into `AndroidStorage` updates without depending on the Android runtime.
   - Enforces the invariant that applying a profile switches routing to split-tunnel mode (`"split"`) with specified package filters and leak protection, whereas clearing a profile (`profile is null`) transitions to full-tunnel mode (`"full"`) without clobbering the user's manual per-app picks.

2. **`ProfileManager` & Profile Sources**:
   - Manages an ordered pipeline of profile sources sorted by priority: remote GitHub URL (priority 10) $\rightarrow$ local JSON file (priority 20) $\rightarrow$ compiled built-in fallback profiles (priority 99).
   - Enforces JSON DoS protection via `SafeJsonOptions.MaxDepth = 32` across all profile deserialization to neutralize deeply-nested adversarial payloads.
   - Supports single profile lookups, case-insensitive tolerant lookups, and multi-profile merging (`MergeProfiles` / `MergeProfilesTolerant`) with conflict resolution (union of processes, strictest DNS mode, boolean OR for leak protection).
   - Includes schema-versioned caching (`ProfileCacheFile`, v1) with automatic offline recovery via `CacheRecovery.LoadOrRecover` when remote endpoints are unreachable.

3. **`SettingsLoader`**:
   - Manages the persistence and loading of the primary `config.yaml` configuration file.
   - Implements fail-safe loading (`Load` never throws): I/O errors, malformed syntax, or schema coercion failures fall back to sane defaults while creating timestamped forensic backups (`config.yaml.unloadable-{timestamp}`).
   - Implements atomic file writes (DATA-1 / P05): serializes via source-generated `YamlStaticContext`, writes to a temporary file (`.tmp`) with Unix file-permission hardening (0600), forces an fsync (`Flush(flushToDisk: true)`), and performs an atomic filesystem replace (`File.Move(..., overwrite: true)`).
   - Provides live configuration reloading via `FileSystemWatcher` with a 2-second debounce timer for daemon/service host scenarios.
   - Houses the `SafeMode` write gate (`SafeMode.Enabled` makes persistence strictly read-only to avoid clobbering user settings).

4. **`SettingsMigrator`**:
   - Performs deterministic, step-wise forward schema migrations (from schema v0 up to `AppSettings.CurrentSchemaVersion = 8`).
   - Implements data-repair passes: AM-1 (seeds `RoutingAppsInclude` from legacy `CustomApps`), F-B (`CleanupOrphanVlessServers` removes legacy shadow-override entries), and MTU corrections (lowering legacy 9000/1500 jumbo MTUs to 1280 and then to standard 1420).
   - Hosts `PruneKnownPlaceholders` to scrub leaked smoke-test Reality public keys, short IDs, and placeholder servers from scalar configs, manual server lists, and subscription lists.

5. **`SettingsValidator` & `SettingsValidationResult`**:
   - Enforces semantic and structural invariants on post-migration `AppSettings` before runtime execution.
   - Classifies errors into **Fatal** (which trigger an automatic reset to defaults and rename the file to `config.yaml.invalid-{timestamp}`) and **Warnings** (soft observations logged for operator visibility, such as missing custom config files on disk or risky MTU boundaries).
   - Validates allowed enumerations for `config_mode`, `routing_mode`, `theme`, `dns.strategy`, `update.channel`, valid TCP/UDP port ranges (1..65535), URI schemas, and TUN MTU constraints.

## 4. CONCURRENCY, LOCKS & LIFECYCLE

### 4.1. Threading Model & Shared State
- **`SettingsLoader` Static State**:
  - `LastRecoveryNotice`: Unsynchronized static string property. Written by `LoadCore` on the loading thread; read and cleared by `ConsumeRecoveryNotice`. Because settings load occurs sequentially during startup before UI/worker dispatch, data races are rare but unprotected.
  - `_watcher`, `_debounceTimer`, `_reloadCallback`: Static references controlling the live reload mechanism. Modified in `StartWatching`, `StopWatching`, and `ScheduleReload` without locks.
- **`ProfileManager` Instance State**:
  - `_cache`: Stored as a single private reference (`ProfileCollection? _cache`). It is read-only after `LoadAsync` completes during normal startup. However, concurrent calls to `LoadAsync` across multiple threads would race on updating `_cache` without synchronization.

### 4.2. Atomic File Persistence & IO Guarantees
- **Write-Flush-Rename Pattern (`SettingsLoader.Save`)**:
  - Temp file creation: `var tmp = configPath + ".tmp";`
  - Stream creation: `using var stream = AppPaths.CreatePrivateFile(tmp)`
  - Explicit flush: `writer.Flush(); stream.Flush(flushToDisk: true);`
  - Atomic swap: `File.Move(tmp, configPath, overwrite: true);`
  - Cleanup: `finally { try { if (File.Exists(tmp)) File.Delete(tmp); } catch {} }`
  - **Guarantee**: Prevents zero-byte truncated configurations if power fails or the process is killed mid-write. Same-directory temp file guarantees same-filesystem volume, ensuring `File.Move` is an atomic inode/MFT pointer swap on POSIX and NTFS.

### 4.3. Async/Await & Cancellation Token Propagation
- `ProfileManager.LoadAsync(CancellationToken ct)` passes `ct` to `source.LoadAsync(ct)`.
- `GitHubProfileSource.LoadAsync(CancellationToken ct)` passes `ct` to `_http.SendAsync` and `File.WriteAllTextAsync`.
- `LocalProfileSource.LoadAsync(CancellationToken ct)` performs **synchronous blocking I/O** (`File.ReadAllText`) wrapped in `Task.FromResult`, completely ignoring the cancellation token.
- `SettingsLoader.Save` and `SettingsLoader.Load` are entirely synchronous APIs.

## 5. SECURITY & PRIVILEGE BOUNDARIES

### 5.1. Filesystem & OS Privilege Hardening
- **Private Unix Directory (0700)**:
  - On Linux and macOS, `SettingsLoader.Save` checks if `configPath` matches `AppPaths.ConfigYamlPath` and calls `AppPaths.EnsurePrivateUnixDirectory(AppPaths.DataDir)`.
  - Enforces `POSIX 0700` (`rwx------`) on the configuration root directory, ensuring unprivileged local processes cannot inspect configuration files containing VLESS credentials, Reality public keys, or Clash API secrets.
- **Private File Permissions (0600)**:
  - `AppPaths.CreatePrivateFile(tmp)` sets `POSIX 0600` (`rw-------`) on Unix systems during the creation of `.tmp` configuration files prior to atomic renaming.

### 5.2. Defense-in-Depth Against Denial of Service (DoS)
- **JSON Nesting Cap (CO-4 / SafeJsonOptions)**:
  - `ProfileManager.SafeJsonOptions` explicitly configures `MaxDepth = 32`.
  - Profiles are shallow structures ($\le 4$ levels: `collection` $\rightarrow$ `profile` $\rightarrow$ `processes` $\rightarrow$ `rule`). Deeply nested arrays or objects (e.g. 100+ brackets) injected via malicious GitHub URLs or local files throw `JsonException` immediately, preventing stack overflow crashes and unconstrained allocations.
  - Pinned by `ProfileManagerJsonDosGuardTests`.
- **YAML Mapping & Known Key Constraints**:
  - `SettingsLoader.Parse` parses the raw YAML into a `YamlStream` prior to object mapping.
  - Rejects documents whose root is not a mapping node (`YamlMappingNode`).
  - Requires at least one recognized top-level configuration key (`schema_version`, `app`, `profile_sources`, `vless`, `tun`, etc.), preventing empty mappings or arbitrary YAML payloads from silently overwriting user settings.

### 5.3. Secret & Credential Handling
- **Clash API Bearer Token (P1)**:
  - When `SingBox.ClashApiSecret` is generated by `EnsureSane()`, `SettingsLoader.LoadCore` automatically persists it to disk so independent processes (`VPNRouter.App` and `VPNRouter.Service`) share the same bearer token.
- **Placeholder Fingerprint Scrubbing (v2.32.3)**:
  - `SettingsMigrator.PruneKnownPlaceholders` scrubs known leaked credentials:
    - Reality public key: `DnT9hIvt5QEx07unHUeXbWxN4Qo1gnecN4p0s62nckU`
    - Short ID: `78ca7952`
    - Endpoint IP: `195.135.255.216`
  - Atomically zeroes `Server`, `Port`, `Uuid`, and `Reality` on scalar hits.
  - Logs redacted fingerprints (`TruncateForLog` emits `v[..8]…v[^4..]`) to prevent credential leakage into diagnostic logs.

## 6. SUSPICIOUS PATTERNS / DEFECT CANDIDATES

### Defect Candidate 1: `MergeProfiles` and `MergeProfilesTolerant` Silently Drop `AndroidPackages`
- **Location**: `VPNRouter.Core/Services/ProfileManager.cs:178-185` and `ProfileManager.cs:205-212`
- **Severity**: High (Functional Regression / Leak Vulnerability on Android)
- **Mechanism**:
  When merging multiple profiles in `MergeProfiles` or `MergeProfilesTolerant`, the constructor for the merged `Profile` only populates `Name`, `Description`, `Processes`, `DnsMode`, and `BlockOnVpnFail`:
  ```csharp
  var merged = new Profile
  {
      Name = string.Join("+", resolved.Select(p => p.Name)),
      Description = $"Merged: {string.Join(", ", resolved.Select(p => p.Name))}",
      Processes = resolved.SelectMany(p => p.Processes).ToList(),
      DnsMode = ResolveDnsMode(resolved.Select(p => p.DnsMode)),
      BlockOnVpnFail = resolved.Any(p => p.BlockOnVpnFail)
  };
  ```
  `AndroidPackages` is omitted and defaults to an empty list `new()`.
- **Impact**: If an Android user selects a composite/merged profile (e.g. "Messengers+Browsers"), `ProfileApplication.Plan(merged)` produces an empty package list. Split-tunneling on Android routes zero applications through the VPN tunnel, causing all traffic to bypass the tunnel and leak directly onto the physical network interface.
- **Remediation**: Populate `AndroidPackages` in the merged profile by unioning package names:
  ```csharp
  AndroidPackages = resolved.SelectMany(p => p.AndroidPackages ?? Enumerable.Empty<string>())
                            .Distinct(StringComparer.OrdinalIgnoreCase).ToList(),
  ```

### Defect Candidate 2: `ResolveDnsMode` Crashes with `ArgumentNullException` on Null `DnsMode` and `InvalidOperationException` on Empty Collection
- **Location**: `VPNRouter.Core/Services/ProfileManager.cs:224-237`
- **Severity**: Medium
- **Mechanism**:
  ```csharp
  private static string ResolveDnsMode(IEnumerable<string> modes)
  {
      var priority = new Dictionary<string, int>(StringComparer.OrdinalIgnoreCase)
      {
          ["vpn_only"] = 3,
          ["smart"]    = 2,
          ["direct"]   = 1
      };

      return modes
          .OrderByDescending(m => priority.GetValueOrDefault(m, 0))
          .First();
  }
  ```
  1. In .NET, `Dictionary<TKey, TValue>.GetValueOrDefault(key, defaultValue)` calls `TryGetValue(key, out var val)`. If `key` is `null`, it throws `ArgumentNullException: Value cannot be null. (Parameter 'key')`. If an imported JSON profile contains `"dns_mode": null`, `p.DnsMode` is null, causing `MergeProfiles` to throw an unhandled `ArgumentNullException`.
  2. If `MergeProfiles(new string[0])` is called with an empty list, `modes` is empty, causing `.First()` to throw `InvalidOperationException: Sequence contains no elements`.
- **Remediation**: Guard against null and empty sequences:
  ```csharp
  private static string ResolveDnsMode(IEnumerable<string?> modes)
  {
      var priority = new Dictionary<string, int>(StringComparer.OrdinalIgnoreCase)
      {
          ["vpn_only"] = 3,
          ["smart"]    = 2,
          ["direct"]   = 1
      };

      return modes
          .Where(m => !string.IsNullOrWhiteSpace(m))
          .OrderByDescending(m => priority.GetValueOrDefault(m!, 0))
          .FirstOrDefault() ?? "vpn_only";
  }
  ```

### Defect Candidate 3: `SettingsMigrator.PruneKnownPlaceholders` Does Not Clear `ActiveSubscriptionServer`
- **Location**: `VPNRouter.Core/Services/SettingsMigrator.cs:165-181`
- **Severity**: Medium (Stale Configuration State)
- **Mechanism**:
  When known placeholder servers are scrubbed from `App.Subscriptions[*].Servers`, the migrator checks if `vless.ActiveServer` was affected and clears it if pruned. However, it completely ignores `settings.App.ActiveSubscriptionServer`:
  ```csharp
  // (d) ActiveServer pointed at something we removed → clear it.
  if (vless != null && !string.IsNullOrEmpty(vless.ActiveServer))
  {
      var effective = vless.GetEffectiveServers();
      var stillPresent = effective.Any(s =>
          string.Equals(s.Name, vless.ActiveServer, StringComparison.OrdinalIgnoreCase));
      if (!stillPresent)
      {
          vless.ActiveServer = string.Empty;
      }
  }
  // Missing: check for settings.App.ActiveSubscriptionServer!
  ```
- **Impact**: If the pruned server was the active server under `App.ActiveSubscriptionServer`, that setting remains populated with the name of a deleted server. Downstream resolvers (`VlessServersResolver`) will fail to find the active server and fall back to arbitrary default selection or fail to connect.
- **Remediation**: Verify whether `settings.App.ActiveSubscriptionServer` still exists in any enabled subscription; if not, reset it to `string.Empty`.

### Defect Candidate 4: Unsynchronized Concurrency in `SettingsLoader.ScheduleReload`
- **Location**: `VPNRouter.Core/Services/SettingsLoader.cs:642-660`
- **Severity**: Low / Race Condition
- **Mechanism**:
  `ScheduleReload` is triggered by `FileSystemWatcher` events (`Changed`, `Created`, `Renamed`), which dispatch concurrently on thread pool threads:
  ```csharp
  private static void ScheduleReload(string configPath)
  {
      try { _debounceTimer?.Stop(); _debounceTimer?.Dispose(); } catch { }

      _debounceTimer = new System.Timers.Timer(2000) { AutoReset = false };
      _debounceTimer.Elapsed += (_, _) =>
      {
          try
          {
              var settings = Load(configPath);
              _reloadCallback?.Invoke(settings);
          }
          catch { }
      };
      _debounceTimer.Start();
  }
  ```
  Without a synchronization lock, rapid successive events can interleave between disposing the old timer and creating the new timer. Two timers can run concurrently, firing duplicate `Load` calls and duplicate `_reloadCallback` invocations.
- **Remediation**: Wrap timer creation and cancellation in a `lock (_watcherLock)` block.

### Defect Candidate 5: `GitHubProfileSource.LoadAsync` Bypasses Offline Cache on Malformed JSON
- **Location**: `VPNRouter.Core/Services/ProfileManager.cs:370-395`
- **Severity**: Medium
- **Mechanism**:
  `GitHubProfileSource.LoadAsync` attempts to fall back to `cache/profiles.json` via `CacheRecovery.LoadOrRecover` only inside:
  ```csharp
  catch (Exception ex) when (ex is HttpRequestException or TaskCanceledException)
  ```
  If GitHub returns HTTP 200 with an HTML page (e.g. Wi-Fi captive portal, CDN error, proxy injection), `JsonSerializer.Deserialize` throws `JsonException`.
- **Impact**: `JsonException` escapes unhandled to `ProfileManager.LoadAsync`, which marks the entire GitHub source as failed and falls back directly to `LocalProfileSource` or `BuiltInProfiles`, completely bypassing the valid on-disk offline cache.
- **Remediation**: Include `JsonException` in the catch filter:
  ```csharp
  catch (Exception ex) when (ex is HttpRequestException or TaskCanceledException or JsonException)
  ```

### Defect Candidate 6: Non-Atomic Serialization of `cache/profiles.json` in `GitHubProfileSource`
- **Location**: `VPNRouter.Core/Services/ProfileManager.cs:365`
- **Severity**: Low
- **Mechanism**:
  `GitHubProfileSource.LoadAsync` persists cache files using direct `File.WriteAllTextAsync`:
  ```csharp
  await File.WriteAllTextAsync(cacheFile, wrapperJson, ct);
  ```
  Unlike `SettingsLoader.Save`, this operation is not atomic. If the process terminates abruptly during write, `profiles.json` is truncated to 0 bytes or left in a corrupt state.
- **Remediation**: Use the `.tmp` + atomic rename pattern identical to `SettingsLoader.Save`.

### Defect Candidate 7: Case-Sensitive Known Key Checking in `SettingsLoader.Parse`
- **Location**: `VPNRouter.Core/Services/SettingsLoader.cs:331-348`
- **Severity**: Low / Usability Defect
- **Mechanism**:
  In `SettingsLoader.Parse`, the pre-parse structural check uses:
  ```csharp
  var knownKeys = new HashSet<string>(StringComparer.Ordinal)
  {
      "schema_version", "app", "profile_sources", "active_profile",
      "vless", "tun", "dns", "singbox", "monitoring",
      "custom_apps", "custom_group_apps", "custom_categories", "update",
      "emergency_channel"
  };
  ```
  Because `StringComparer.Ordinal` is used instead of `StringComparer.OrdinalIgnoreCase`, a hand-edited `config.yaml` with PascalCase keys (e.g. `App:` or `Vless:`) will match zero keys.
- **Impact**: The file is flagged as corrupted, renamed to `.unloadable-{timestamp}`, and replaced with default settings.
- **Remediation**: Use `StringComparer.OrdinalIgnoreCase` for `knownKeys`.

### Defect Candidate 8: Synchronous Blocking I/O in `LocalProfileSource.LoadAsync`
- **Location**: `VPNRouter.Core/Services/ProfileManager.cs:256-264`
- **Severity**: Low
- **Mechanism**:
  `LocalProfileSource.LoadAsync` calls `File.ReadAllText(_path)` synchronously on the calling thread and wraps the result in `Task.FromResult`. The `CancellationToken ct` is discarded. If the file is on a slow network share or locked, this blocks the calling thread synchronously.
- **Remediation**: Use `await File.ReadAllTextAsync(_path, ct)`.
