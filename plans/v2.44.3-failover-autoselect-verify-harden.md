# v2.44.3 — Verify, Test & Harden Auto-Failover + Auto-Select-Best-Server

Composed 2026-06-25 from a 6-mapper code/test/defect/UX audit + the OPEN-DEFECTS
ledger. This is the spec for the "does fallback + auto-select work correctly?"
goal. Verification context cross-refs: `OPEN-DEFECTS.md`,
`server-health-failover-backlog-2026-06-19.md`,
`independent-review-server-health-mtu-2026-06-19.md`.

## 1. Goal

Bring VPNRouter's two server-resilience features to a state we can *trust*:
(a) **auto-failover** (`AutoFailoverEngine` + the post-start `ConfigSanityCheck`
probe + the v2.44.2 `_warmupConfirmed` gate) and (b) **auto-select best server**
(`VlessConfig.BuildAutoSelectPool` -> sing-box `urltest` group). Investigate and
reproduce the known/suspected breakages first, fix each only behind a pinning
test, fill the concrete unit-coverage gaps, and live-verify end-to-end on the
Windows test VM + Android phone against the user's real subscription — without
ever regressing the warmup false-positive gate. Headline: kill the active node
mid-session and watch the client recover on a healthy node within a bounded time
with no leak, and confirm `urltest` genuinely re-picks the fastest reachable node.

## 2. Current state (what the audit found)

- **Live but broken on genuine outage (P0).** Detection works, recovery does not:
  `WireFailoverWithStop`'s restart delegate calls `_engine.Stop()`, which cancels
  `_probeCts` — the same token (`innerCt`) the re-entrant `StartAsync` runs under,
  so the restart **self-cancels** (`VpnEngine.cs:1165-1177`, diag `20260624-235243`).
  On a real dead node the tunnel is torn down and no replacement comes up.
- **Gated, not root-fixed.** v2.44.2 `ShouldAutoFailoverAfterProbe(...) => probeIsDead
  && !probeCancelled && !warmupConfirmed` (`VpnEngine.cs:248`) only suppresses the
  transient-503 false positive *after* a confirmed TUN warmup. The probe still treats
  a transient Clash 503 as `IsDead` (`ConfigSanityCheck.cs:249-322`); a 503 *without*
  a prior warmup would still false-teardown. Safety net, not cure — must not regress.
- **Two latent failover defects (P1).** `ResetCycle()` has **no production caller**
  (`AutoFailoverEngine.cs:352`) — after 3 lifetime switches failover gives up
  permanently ("Все серверы недоступны") until app restart. `PickNextCandidate`
  **ignores protocol** — can swap VLESS+Reality -> Hysteria2/TUIC and waste a capped
  attempt. `_store.Save(_settings)` on swap serializes the resolver aggregate into
  `vless.servers` YAML (subscription-leak class, `AutoFailoverEngine.cs:202`).
- **Auto-select live but thinly tested + asymmetric.** Pool logic (`VlessConfig.cs:106-150`)
  + `urltest` emission (`ConfigGenerator.AddOutboundGroup:1195-1232`: `interval=3m`,
  `tolerance=150`, `interrupt_exist_connections=false`) work, but the only
  generator-level urltest tests are `[Fact(Skip)]` (`ConfigGeneratorTests.cs:173,189`)
  and nothing wires pool->generator->re-selection. Desktop resolves the live member
  via Clash `/proxies/proxy -> "now"` (`ConnStats.cs:159-191`); **Android shows
  nothing** (no "now" readback, no active-member highlight).
- **B0 conn-health telemetry is code-complete but dormant.** `_connHealth` is
  write-only (`VpnEngine.cs:645,652`), gated off by `VPNROUTER_CONN_HEALTH` (default
  OFF). Task-ledger #34/#35 ("calibrated warning"/"auto-switch") are marked done but
  are NOT wired to B0 — they reflect the older probe path. Out-of-scope sensor work
  here; do not mistake its labels for delivered failover behaviour.

## 3. Protocol

- **Investigate-and-reproduce first.** For every P0/P1, reproduce (or prove current
  behaviour) before touching code — drive the live `SchedulePostStartProbe` /
  `HandleDeadConfigAsync` paths, not just the pure predicates. Capture the diag/log
  lines that demonstrate it.
- **Fix only behind a pinning test** (fails before, passes after). Prefer a
  deterministic verifier (xUnit + fakes: `FakeSingBoxApi`, `InMemorySettingsStore`,
  fake probe) over manual judgement.
- **Live-verify on real infra.** Windows test VM `windows-brat` (192.168.0.106) via
  `mcp__vpnrouter-test__*` + `post-ship-mcp-verify`; Android phone via the existing
  device/MCP path; both against the user's real subscription. Mid-session node-kill
  must be exercised LIVE — the self-cancelling restart + resurrection race only show
  up end-to-end.
- **Never regress the v2.44.2 warmup gate.** Pin the `_warmupConfirmed` set/reset
  lifecycle (`VpnEngine.cs:260/475/1044`) + the suppress-after-warmup branch.
- **Baseline noise.** The ~18 `SingBoxManager` + ~2 `Wgturn` ProgramData
  `UnauthorizedAccess` failures are the documented env baseline (green on CI).
- **Mode:** autonomous to a verified `-rN` candidate; stable cut stays an explicit
  user-command gate.

## 4. Acceptance / DoD

**Auto-failover ("fallback works"):**
1. **Genuine-outage recovery (the P0):** connected session on a real subscription,
   kill/blackhole the active node mid-session -> client detects dead, **brings up a
   replacement node, traffic flows again within a bounded budget** (target ~<=30 s,
   given 15 s probe delay + 2x3 s attempts). Restart must NOT self-cancel. Live on
   windows-brat.
2. **No tunnel resurrection** after user Disconnect racing a failover restart.
3. **Survives >3 lifetime switches** within a session (no permanent brick).
4. **Protocol-compatible candidate** — a swap never lands on an incompatible protocol.
5. **No subscription leak** into `vless.servers` YAML on a failover persist.
6. **Warmup gate pinned both ways:** 503 *after* warmup -> no teardown; never-connected
   start (no warmup) -> still fails over.

**Auto-select ("auto-select works"):**
7. `AutoSelectBestServer=true` + 3 same-protocol servers -> config has a `type=urltest`
   `proxy` outbound, 3 child tags, `url=.../generate_204`, `interval=3m`,
   `tolerance=150`, `interrupt_exist_connections=false` (un-skip
   `ConfigGeneratorTests.cs:173/189`).
8. **urltest re-picks on death** — active member dies -> sing-box routes to a live
   sibling (live-verified; lowest-latency reachable node wins).
9. Desktop status line + list highlight resolve to the **real** live member
   (`/proxies/proxy -> "now"`), not the stored first-in-list — no "says Germany,
   exits Iceland."
10. **Composition with failover tested:** auto-select ON + whole pool dead +
    warmup-confirmed -> no spurious teardown; pool dead + no warmup -> app failover fires.

**Coverage DoD:** gaps below have passing tests; `dotnet build -c Release` clean;
Mac/Linux CI green; `post-ship-mcp-verify` PASS on the candidate.

## 5. Work-list (prioritized)

**P0 — verify-and-fix (pinning test, then live):**
1. **Self-cancelling restart** (`VpnEngine.cs:1165-1177`) — re-entrant `StartAsync`
   must not run under the `Stop()`-cancelled token. v2.44.3 headline.
2. **Start/stop/failover synchronization** — `SemaphoreSlim` + `_isStopping` so a
   `CancellationToken.None` restart can't resurrect the tunnel after Disconnect.

**P1 — verify-and-fix:**
3. **`ResetCycle()` unreachable** (`AutoFailoverEngine.cs:352`) — wire a caller on
   successful connect (or per-attempt scoping); pin it.
4. **`PickNextCandidate` ignores protocol** (`AutoFailoverEngine.cs:274-330`) — filter
   to compatible protocol (or handle the switch without wasting a capped attempt).
5. **Subscription-leak persist** (`AutoFailoverEngine.cs:202`) — `_store.Save` on
   failover must not serialize the resolver aggregate into `vless.servers`.

**Test-coverage gaps:**
6. Live `SchedulePostStartProbe` test w/ fake probe + warmup flag: dead+no-warmup ->
   `HandleDeadConfigAsync` + `AutoFailoverTriggered`; dead+warmup -> no failover;
   `_warmupConfirmed` lifecycle pinned. (Highest value — exact v2.44.2 surface.)
7. Un-skip/rewrite `ConfigGeneratorTests.cs:173/189` (full urltest shape) + a urltest
   re-selection test (dead child -> live sibling).
8. Real restart-delegate e2e: failover restart re-runs Resolve->Generate and the
   regenerated proxy outbound points at the NEW server's IP/uuid.
9. `HandleDeadConfigAsync` persistence-failure path (throwing store -> still
   `Switched=true`); `IsCandidateUsable` bad-port / `your.server.com` / structural guards.
10. Auto-select pool composed with failover (dead urltest member rotates group or
    member?); auto-select ON + warmup-confirmed asserts no teardown.

**Refinements (UX parity — after correctness):**
11. **Localize failover messages** — `AutoFailoverEngine.cs:91-234` emits RU-only
    literals while bilingual `App/Strings.cs:826-837` strings sit unused.
12. **Android parity** — failover is silent on Android (`AndroidApp.VpnLifecycle.cs`
    has no dead-config handler); auto-select shows no active member. Add a minimal
    surfaced signal + "now" readback.
13. **Failover notification + stale suspect line** — failover only overwrites
    `StatusText` (no toast, clobbered by next "Connected" tick); `SimpleActiveOutbound*`
    goes stale after a mid-session swap. Hook `RefreshActiveIndicator` /
    `OnAutoFailoverMessage`; reuse existing toast infra.
