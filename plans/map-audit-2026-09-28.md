# Agent map audit (MAP_AUDIT), 2026-09-28

Snapshot-bound accounting evidence for the agent map published on draft PR #296.
The map remains a navigation aid, not a source of truth for current behavior,
defect status or release readiness. Task record:
[phase-map-00-2026-09-28.md](phase-map-00-2026-09-28.md). Reproduce the figures
below with [map-audit-2026-09-28-verify.py](map-audit-2026-09-28-verify.py).

Method: serial self-review and source cross-check by one agent. No independent
review, product build, test run or runtime check is part of this audit. The
map was read from pinned Git objects; PR #296 was not checked out or merged.

## 5. Imported findings and NEW-1

The PR #296 ledger holds 11 findings labelled P1 there. On main they are not
confirmed and must not gate a cut until source revalidation:

- Main-applicable, recorded in `plans/OPEN-DEFECTS.md` as UNVERIFIED IMPORTED
  HYPOTHESIS: WIN-DNS-RESTORE-ORPHAN, WIN-DNS-LOCKDOWN-TOCTOU,
  LINUX-NFT-TAILSCALE-LOCKOUT, WIN-DNS-NETSH-TIMEOUT-DEADLINE and
  WIN-BINDIR-ACL-FAIL-OPEN cite files that are byte-identical from map baseline
  to target, so the premise may still apply. FAILOVER-WARMUP-RACE cites
  `StartupPipeline.cs` and `VpnEngine.cs`, which changed; its line references
  are stale.
- Out-of-target, not imported: HEADLESS-GATE-DISPOSE-RACE,
  HEADLESS-SERILOG-RAW-EXCEPTION, HEADLESS-CUSTOM-CONFIG-TRANSACTION,
  OMARCHY-QML-CLEAN-EXIT-STALL, OMARCHY-QML-CONFLICT-CASCADE. The companion
  head `bf1446b0` subject suggests the two QML items were addressed there; not
  verified.

NEW-1, Android "Block on VPN fail" (hypothesis, no runtime verification): the
setting is stored (`AndroidStorage`), shown, exported and copied into
`Profile.BlockOnVpnFail` by `AndroidConfigBuilder`, which calls
`ConfigGenerator.Generate` directly. `ConfigGenerator` does not read the field.
In Core, `ProfileApplication` and `ProfileManager` only propagate it;
`StartupPipeline` and `VpnEngine` use it for the desktop firewall. Android
sources do not reference `VpnEngine`, `StartupPipeline` or `FirewallManager`
(Core is source-linked, so these types compile into the APK but have no static
Android caller). The Android hint text promises `VpnService.Builder.setBlocking(true)`,
which is not called and which, per the Android API, selects blocking mode for
the VPN file descriptor rather than blocking traffic. Possible outcomes range
from a no-op toggle with misleading copy to an enforcement path this source
reading missed (reflection, Java-side preference read, OS lockdown). No traffic
leak or broken kill switch is claimed.

Correction during MAP-00: the earlier MAP_AUDIT draft said `StartupPipeline` was
the only Core reader of the field. The verifier found `ProfileApplication`,
`ProfileManager` and `VpnEngine` as well; the conclusion above reflects that.
