# v2.32.0 — Android subscription parity with desktop SubscribePage

## Триггер

Android port (v3.0 alpha) поддерживает только одну subscription URL
через `AndroidStorage.GetSubscriptionUrl()` (Phase 1.H, 2026-05-04).
Desktop SubscribePage всегда был multi-subscription через
`app.subscriptions[]` YAML список и UI с per-card refresh / delete /
edit. Mobile отставал — нужен полноценный port.

## Симптом

User на Android может только хранить одну подписку в
`SharedPreferences/subscription_url`. Чтобы поменять — overwrite в
paste-box. Нет:
- per-source server count history
- last-refreshed timestamp
- enabled toggle для temporarily disable одной подписки без потери URL
- bulk Refresh all
- inline URL edit без полного re-paste
- 2-tap delete confirm

## Root cause

Phase 1.H (commit `cd36f34`) shipped с
`KeySubscriptionUrl = "subscription_url"` (single string). Это был
deliberate MVP shortcut для Phase 1 smoke-test'а — параметр был "хватит
ли libbox.aar в принципе обработать subscription через
`SubscriptionFetcher.FetchAsync`". Multi-sub откладывалось до
"когда UI parity'ом займёмся". Сейчас занимаемся.

## Fix strategy

Использовать desktop'овский `VPNRouter.Core.Models.SubscriptionEntry`
verbatim — он уже в Core, Android уже линкует Core sources напрямую
(`<Compile Include="..\VPNRouter.Core\**\*.cs">` в .csproj). Никакого
Android-specific схемы — просто JSON-сериализуем
`List<SubscriptionEntry>` в новый `KeySubscriptions = "subscriptions_json"`
SharedPreferences ключ.

UI — fullscreen overlay по примеру `BuildAppPickerOverlay`
(handbook §1.3 «mirror existing patterns»). Триггер — tap по
"Расширенные настройки" advanced-card на SimplePage (pre-2.32.0 был
no-op placeholder, что и обещало "Серверы · Подписки · Маршрутизация ·
Логи" в сабтайтле).

## Storage migration

Pre-2.32.0 install reads `subscription_url` (legacy single string).
On first call to `GetSubscriptions()` we synthesize a one-entry list:

```csharp
new SubscriptionEntry {
    Name = "Default",
    Url = legacy,
    Enabled = true,
    Servers = GetServers(),  // pre-existing aggregated list
}
```

That entry is presented in the new UI; first edit / refresh / add
persists the new schema via `SetSubscriptions()` which writes
`subscriptions_json` and rebuilds the aggregated server pool. Old key
(`subscription_url`) is **not** auto-deleted — kept as fallback in case
user downgrades. (Will sweep in v2.33 once enough usage time has
passed.)

## Connect-path compatibility

`MainActivity.StartTunnelService()` calls
`AndroidStorage.GetActiveServer()` (line 316), which reads
`KeyServersJson` (the aggregated pool). `SetSubscriptions` deduplicates
all enabled entries' Servers into that same pool using the
`Server:Port:Uuid:Flow` key shape — matches desktop's
`VlessServersResolver.Resolve` semantics. So existing connect logic
keeps working without any change in `MainActivity` / `AndroidConfigBuilder`.

## Why the per-app picker pattern, not nav stack

Avalonia на Android умеет navigation stack (`SingleViewApplicationLifetime.MainView` swap), но в текущей кодовой базе мы выбрали overlay pattern для log viewer + per-app picker. Subscribe overlay следует тому же выбору для:
- Consistency со существующим UX (user уже знает, что × вверху-справа закрывает overlay)
- Простоты state management (нет navigation history → нет проблем с back-button + state restore)
- Performance (нет MainView teardown/rebuild при каждом open/close)

Trade-off: overlay не поддерживает Android system back button gesture out-of-box. Можно потом добавить через `MainActivity.OnBackPressed` if user feedback требует. Pre-r1 же — × button работает, того хватит.

## Не сделано / future work

- **Test all / Deep verify**: требует TCP+TLS probe infra на Android (`FreeConfigTester` сейчас завязан на `System.Net.Sockets.TcpClient` + `SslStream` — должно работать на Android, но не проверял). Defer to v2.33.
- **Per-server selection**: desktop SubscribePage позволяет radio-select один server из агрегированного пула. Android уже это поддерживает в SimplePage's inline ListBox через `KeySelectedServerName`. Не дублируем в overlay — overlay про подписки, не про server picker.
- **Headless Android UI tests**: пока нет infra. Когда появится — пара тестов на `AndroidStorage.SetSubscriptions` round-trip + legacy migration.
