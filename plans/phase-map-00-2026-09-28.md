# MAP-00: agent map accounting and navigation receipts

## Why

The full agent map exists only on draft PR #296 and claims complete coverage.
The MAP_AUDIT pass on 2026-09-28 found that its receipts, coverage figures and
several platform/concurrency claims do not hold against its own artifacts or
current source. Main has no record of that result, so a later AUDIT could treat
the map as a source of truth. The owner accepted MAP-00 with corrections.

## What

Scope is limited to four paths:

- `plans/map-audit-2026-09-28.md`: audit report with snapshot identities,
  recounted receipts, two-way coverage, claim register, build/test matrix,
  ready/blocked scope, unknowns and proposed follow-ups.
- `plans/map-audit-2026-09-28-verify.py`: read-only verifier over pinned SHAs.
- `plans/phase-map-00-2026-09-28.md`: this brief and its Outcome.
- `plans/OPEN-DEFECTS.md`: map/accounting entries only, plus imported and new
  hypotheses marked so that they cannot trip the P0/P1 cut gate.

## Invariants

- No change to product code, tests, AGENTS files, `docs/agent-contract.md`,
  skills, CI/workflows, hooks, build/release behavior, Headless/Omarchy code,
  or the historical map files on PR #296.
- The map stays a snapshot-bound navigation aid, not a source of truth.
- Findings copied from the PR #296 ledger are recorded as
  UNVERIFIED IMPORTED HYPOTHESIS without a bold P0/P1 marker. They do not gate
  a stable cut until source revalidation assigns a severity.
- NEW-1 (Android Block on VPN fail) is a source-level hypothesis only. No claim
  of a traffic leak or broken kill switch; no runtime verification was done.
- The verifier reads Git objects only. It never fetches, checks out, writes
  files, or runs `supervisor.py` or `generate_manifest.py`. Any mismatch exits
  non-zero.
- Missing owners, CI coverage documentation, `VPNRouter.GUI.exe`,
  `opendesign/`, `profiles/`, `samples/` and the release build graph are
  proposed as a separate MAP-01/DOC-01 follow-up, not edited here.

## Risk and rollback

Risk: a ledger line accidentally matches the cut gate regex
(`- [ ]` plus a bold marker starting with P0/P1) and blocks a stable cut, or
wording promotes the historical map or old findings to current facts.
Mitigation: gate-regex check over the changed ledger; explicit status labels.
Rollback: revert the documentation commit. No runtime state is touched.

## Six gates

1. Build: N/A. No product, project or build file changes.
2. Tests: verifier exits 0 on pinned SHAs; negative control with one altered
   expectation exits non-zero; gate regex finds no new open P0/P1 line;
   exact-head PR CI green.
3. Documentation: links in changed Markdown resolve; diff limited to the four
   paths; ASCII punctuation in new files.
4. Independent review: only if actually available under Harness rules;
   otherwise recorded as NOT RUN. Self-review is not counted as independent.
5. UI/runtime: N/A. No behavior change; NEW-1 runtime check belongs to AUDIT.
6. Integration: merge only on explicit owner command.
