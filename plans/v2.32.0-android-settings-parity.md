# v2.32.0 — Android Settings parity (4 sub-sections vs desktop NetworkPage)

**Date**: 2026-05-07
**Branch**: `claude/goofy-nobel-45a1ed`
**Status**: code shipped, live phone test deferred (Mac SSH timed out at session start)

## Триггер

Handbook §1.1 (`plans/vpnrouter-android-handbook.md`) требует one-to-one
parity Android UI с desktop equivalent. Pre-2.32.0 Android port имел
только routing-mode toggle внутри collapsed формы — четыре desktop
NetworkPage sub-sections (Routing / Leak / Updates / Autostart) не были
отражены. Задача брифа: добавить полноценный Settings overlay,
покрывающий все 4 sub-section'а с persistence, без android-only options
и без drop'а desktop options.

## Архитектурные решения

### Доступ через kebab menu, не через bottom-nav

Desktop держит NetworkPage как одну из tabs в left-nav. Android kebab
menu Phase 7.2 уже имеет 4 секции (Вид / Диагностика / Устранение
неполадок / О приложении). Добавил «Настройки» / «Settings» первым
item'ом в Diagnostics (most-used → top of section). Альтернатива
(bottom-nav как у Material Design Android apps) была отброшена — выпадает
из существующего design language Android-порта (single-page SimplePage
+ kebab + overlays).

### Fullscreen Border-overlay, не отдельная Activity

Mirror Phase 7.4 in-app log viewer + Phase 7.5 per-app picker — Border
layered поверх main ScrollViewer через root Grid. Это значит:

- одно `Application.Current.MainView` без navigation stack
- back-button (handled в `MainActivity.OnBackPressed` если будет
  добавлено) или close-X кнопка
- никаких Activity transitions, persists через configuration changes
  (theme switch, locale switch, rotation)

Все 4 секции — collapsible нет; используем простой stacked layout с
Border-картами, как desktop.

### Auto-save вместо Apply

Desktop NetworkPage показывает «Auto-saved» footer + Apply кнопку
(только для applying к работающему VPN). Android Settings overlay
использует только auto-save (persistence через AndroidStorage в момент
изменения toggle / radio / combo). Apply на работающий туннель пока
не нужен — Android tunnel restart требует нового VpnService.Builder
flow что отдельная задача.

### AndroidStorage — 8 новых keys

Все persisted в SharedPreferences:

| Key | Type | Default | Mapped from |
|---|---|---|---|
| `routing_mode` | string | `"split"` | `AppSettings.App.RoutingMode` |
| `bypass_ru` | bool | `true` | `AppSettings.App.BypassRussianTraffic` |
| `block_on_vpn_fail` | bool | `false` | `Profile.BlockOnVpnFail` (per profile on desktop, single global on Android) |
| `dns_strategy` | string | `"ipv4_only"` | `AppSettings.App.ForceIpv4Only` (true→ipv4_only) + extension (prefer_ipv4/prefer_ipv6) |
| `update_channel` | string | `"stable"` | `AppSettings.Update.Channel` |
| `autostart_vpn` | bool | `false` | `AppSettings.App.AutostartVpn` |
| `autostart_zapret` | bool | `false` | `AppSettings.App.AutostartZapret` |
| `autostart_tgproxy` | bool | `false` | `AppSettings.App.AutostartTgProxy` |

`bypass_ru` и `dns_strategy` дополнительно прокидываются в
`AndroidConfigBuilder.BuildConfigJson` → `settings.App.BypassRussianTraffic` /
`settings.App.ForceIpv4Only` так что generated sing-box JSON реально
учитывает выбор пользователя. Остальные (Autostart*, BlockOnVpnFail,
update_channel) живут только в SharedPreferences (см. «Автостарт tier
discovery» ниже).

## Autostart status badge tier

DBG-3 logic (`MainWindowViewModel.ComputeAutostartStatus`) на desktop:

```csharp
if (isServiceInstalled) return Strings.AutostartStatusBoot;       // ✓ Service-at-boot
return hasAppBootstrap                                              // ⚠ App-only fallback
    ? Strings.AutostartStatusLoginFallback
    : Strings.AutostartStatusNoBoot;                                // ⛔ Will not fire
```

На Android текущий tier для всех 3 toggles: **⛔ Will not fire**.

Investigation подтвердила:

- **Нет BOOT_COMPLETED receiver** в `AndroidManifest.xml` (grep
  `BOOT_COMPLETED|BootReceiver|RECEIVE_BOOT` → 0 hits)
- **Нет foreground Service-mode** аналога `VPNRouterService.exe` — наш
  `VpnRouterService` это только `android.net.VpnService` который
  активируется по user-Connect intent
- **Нет app-side login bootstrap** в `AndroidApp.OnFrameworkInitializationCompleted`
  или `MainActivity.OnCreate` который автоматически запускал бы туннель

Соответственно, status badges:

- **VPN toggle** → `AutostartStatusNoBoot` (⛔ "Не сработает: нужен BOOT_COMPLETED + Service")
- **Zapret toggle** → `AutostartZapretNotPorted` (⛔ "Zapret пока не портирован на Android")
- **TgProxy toggle** → `AutostartTgProxyNotPorted` (⛔ "TgProxy пока не портирован на Android")

Все 3 — самый строгий ⛔ tier. Когда у нас появится Phase 8 BootCompletedReceiver
+ AutoStartIntent для VPN, status badge для VPN-toggle переключится в
`AutostartStatusBoot` (✓) automatically (logic already in place). Pre-port
Zapret/TgProxy остаются в ⛔ независимо.
