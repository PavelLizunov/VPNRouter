# v2.32.0 — Android per-server testing UI inside subscription drill-down

## Триггер

AND-1 (`v2.32.0-android-subscription-parity.md`) добавил multi-subscription
UI на Android, но per-server breakdown остался необработанным:

> Test all / Deep verify buttons (l.210-225) — not on Android — test
> infrastructure (TLS probe, HTTP trace) is desktop-only currently
> ⊘ deferred to v2.33+

Однако TCP+TLS probe **уже** в Core (`TcpTlsProbe.ProbeServerAsync`,
v2.31.6-r16). Никакой platform barrier нет — `System.Net.Sockets` +
`System.Net.Security.SslStream` доступны на android-arm64 .NET 8 без
modifications. Можно сразу сделать parity.

User-pain pre-AND-2 (Android): tap на subscription card открывал inline
URL editor (только edit-метаданные). Не было способа узнать какой из 25
серверов в подписке самый быстрый или вообще живой — приходилось пробовать
поочерёдно через Connect button на SimplePage.

## Симптом

```
[Subscriptions] → tap card → "edit URL" overlay (метаданные only)
                            ↓ no server list
                            ↓ no per-server status
                            ↓ no "test fastest"
```

vs desktop ServersPage (`VPNRouter.App/Views/Pages/ServersPage.axaml`):

```
[Servers tab] → list of all VLESS entries → per-row Test button + ms latency
                                            + Test all button
                                            + Deep verify button (proxy round-trip)
                                            + sort by latency
```

## Root cause

Architectural: AND-1 explicitly excluded "Sub-tab strip / Tabs nav" because
Android UX is single-screen overlay. Server-list лежал на desktop отдельным
tab'ом (`ServersPage`), у Android'а отдельного tab'а нет — нужен drill-down
overlay поверх `_subsOverlay`.

Test infrastructure: desktop `MainWindowViewModel.TestServerCommand` →
`TcpTlsProbe.ProbeServerAsync(server, ct)` → `ServerProbeResult`. Эта
chain — Core, без UI deps. Можно вызывать прямо из Android-side handler.

Persistence: AND-1 persists `SubscriptionEntry.Servers` через
`AndroidStorage.SetSubscriptions` → JSON в SharedPreferences. Test results
**не** в Core schema (desktop держит их в memory только, на ServerViewModel,
теряются при app restart). Android выбирает другой trade-off — persist test
history так чтобы badge показывал "last known latency" после reopen.

## Fix strategy

### UI delta — server-list drill-down overlay

Новый fullscreen `_srvOverlay` (Border, IsVisible toggle, тот же pattern
что Phase 7.4 log viewer / AND-2 Settings / AND-3 Free Configs). Triggered
по tap на `BuildSubCard`'s name area (NOT кнопки `✎/↻/✕` — те остаются на
edit/refresh/delete).

Layout сверху-вниз:

```
┌────────────────────────────────────────┐
│ ✕  <Subscription Name>                  │  ← title bar
├────────────────────────────────────────┤
│ [Test all]  ⇅ Sort: latency↓  · "5/12"  │  ← action row
├────────────────────────────────────────┤
│ ◯  is-01-grpc-test                      │
│    93.95.226.167:8444    [142 ms]  ⟳    │  ← per-row
│ ◯  is-02-vless-tcp                      │
│    de-server.example.com:443  [×]   ⟳   │
│ ●  is-03-hy2 ← (active)                 │
│    eu-host.example:9443  [— ✓✓]  ⟳     │
│   …                                      │
└────────────────────────────────────────┘
```

Per-row layout (mirrors desktop `Border.srv-row` from `ServersPage.axaml`
lines 178-238):

| Column | Content |
|---|---|
| Radio dot (12×12) | Active server marker (filled+ring vs hollow) |
| Name + host:port | Two-line stack — name 11px SemiBold, host 9px monospace muted |
| Latency badge | Colored Border by `ServerProbeStatus` (mirrors desktop `StatusDotBrush` mapping) |
| `⟳` Test button | Per-row test, disabled while `IsTesting` |

**Не порт** на Android (deferred):

- Deep Verify button — нужен sing-box spawn, на Android sing-box идёт
  in-process через libbox, нет detached spawn API. Phase v2.33+
- Server URI editor (right-click context menu desktop) — на Android
  servers иммутабельны (приходят из subscription fetch, не вручную
  добавляются). Edit subscription URL уже есть в AND-1.
- Per-row delete — same reason, серверы синхронятся с subscription
  fetch result, ручное удаление одной строки переписалось бы.

### Latency badge color mapping

Mirrors desktop `ServerViewModel.StatusDotBrush` (lines 107-124) +
`PingDisplay` (lines 80-88). For text only (no colored dot — that's a
desktop-specific design element):

| Status | Text | Background hex | Notes |
|---|---|---|---|
| `Unknown` | "—" | `#9CA3AF` muted | Never tested |
| `Ok` <100ms | "{N} ms" | `#22C55E` green | Reachable, fast |
| `Ok` 100-300ms | "{N} ms" | `#65A30D` lime | Reachable, normal |
| `Ok` 300-800ms | "{N} ms" | `#F59E0B` amber | Reachable, slow-ish |
| `Slow` (≥800ms) | "{N} ms" | `#EF4444` red | Reachable but high latency |
| `TlsFailed` | "TLS×" | `#F97316` orange | TCP ok but TLS bad |
| `Timeout` / `Unreachable` | "×" | `#DC2626` red | Connect failed |
| `Implausible` | "<5ms?" | `#DC2626` red | Local intercept (active VPN?) |
| `SkippedNotApplicable` | "—" | `#9CA3AF` muted | Hysteria2/TUIC quick-probe skip |

(Desktop uses semantic token brushes — Success/Warning/Danger Solid. На
Android код-behind мы snapshot'им брашы один раз; ради простоты и parity
с FreeConfigs row pattern (`AndroidApp.FreeConfigs.cs:716-727`) — использую
прямые hex. В theme switch фон цвета остаются те же что и desktop'а в
light / dark theme — это semantic colors, не theme-variant colors.)

### Test all flow + concurrency

**Concurrency = 4.** Rationale:

1. Desktop `FreeConfigTester.MaxConcurrency = 80`. Это для bulk free-config
   pool (1000+ entries). Subscription size типично 5-50 серверов — большой
   parallelism не даёт заметного speedup но платит throughput.
2. Mobile constraints:
   - Cellular networks NAT-thrashing: 80 parallel TCP SYN burst может
     trigger middlebox rate-limiting, false unreachable
   - Battery: 80 SslStream handshakes одновременно — большая CPU spike
   - Connection-tracking: некоторые IPv4 NATs ограничены ~16-32 conntrack
     entries per device
3. Avoid serial: serial = 50 серверов × 1.5s TCP + 3s TLS = ~225s.
   Parallel=4 = ~57s. ~4x speedup, единственный signfificant gain.
4. Mirrors `FreeConfigGeoIp.MaxConcurrency = 4` precedent в Core (network
   I/O bursts on mobile-shaped CPU).

```csharp
var sem = new SemaphoreSlim(4);
var tasks = sub.Servers.Select(async srv => {
    await sem.WaitAsync(ct);
    try {
        var result = await TcpTlsProbe.ProbeServerAsync(srv, ct);
        ApplyResult(srv, result);  // mutate side-table + mark IsTesting=false
    } finally { sem.Release(); }
});
await Task.WhenAll(tasks);
```

Progress: status text "tested {done}/{total}", обновляется через
`Interlocked.Increment` + `Dispatcher.UIThread.Post`.

### Sort-by-latency toggle

Single button toggles `_srvSortByLatency` (false → original order, true →
ascending by `LatencyMs`, untested servers at the end). On toggle: rebuild
`_srvListStack.Children` from sorted view.

Keying: untested (`Unknown` status) sort to the end with `int.MaxValue`
fallback. Failed (`Timeout` / `Unreachable` / `TlsFailed`) sort after Ok+Slow
but before untested via secondary key (`status priority` — Ok=0, Slow=1,
Failed=2, Unknown=3).

### Storage schema delta

New SharedPreferences key:

```
KeyServerTestResults = "server_test_results"   ← v2.32.0
```

Value shape: `Dictionary<string, ServerTestResultDto>` JSON-serialized,
where:

```csharp
class ServerTestResultDto {
    int    Status;          // ServerProbeStatus enum int
    int    LatencyMs;
    DateTimeOffset LastTestedAt;
    string? Error;
}
```

Key: `"{server}:{port}:{uuid}:{flow}"` (matches `VlessServersResolver.Resolve`
dedup key — Core).

Why side-table not embedded in `SubscriptionEntry.Servers`:

- `VlessServerEntry` is a Core model shared with desktop YAML schema.
  Adding `LatencyMs` would either pollute desktop YAML or require
  Android-specific subclass (worse).
- Test results survive subscription refresh (which replaces the Servers
  list wholesale). Lookup by stable identity key matches desktop's
  in-memory `ServerViewModel.PingMs` semantics.
- Pruning: opportunistic — на каждом `SetServerTestResults()` дропаем
  записи которым >7 дней / для серверов которые уже не в active pool.
  Не блокирующий cleanup, просто bookkeeping.

Migration: pre-v2.32.0 ключа нет, `GetServerTestResults` возвращает пустой
dict (untested by default). Никакого explicit migration.

### Connect-from-server-list

Tap на per-server row (NOT на Test button) → `AndroidStorage.SetSelectedServerName(srv.Name)`
+ закрытие overlay + `ReloadServerList` + `UpdateConfigSummary`. Без
автоматического Connect — user сам нажмёт Connect на SimplePage.

Это matches desktop semantics (selecting row в `ServersPage` НЕ запускает
auto-reconnect когда VPN off; запускает только когда VPN running — но на
Android user должен сам сделать flow Save→Connect, поэтому keep simple).
