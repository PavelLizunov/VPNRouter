# v2.32.0-r2 — Android per-app picker: real icons + exclude-mode UI

## Триггер

Phase 7.5 (commit 3a6e9d6) shipped the per-app filter overlay with three
backing modes (`off` / `include` / `exclude`) wired through to
`VpnRouterService.java` (`addAllowedApplication` / `addDisallowedApplication`),
but the UI surfaced only two of them:

1. **No icons** — picker rows showed text-only label + package name.
   Browsing 100+ installed apps to find Discord vs Telegram became a
   reading exercise. Desktop equivalent (`ApplicationsPage.axaml`) does
   show real app icons via `AppIcon` resolver, so the gap is purely an
   Android-port omission.
2. **Exclude mode unreachable from UI** — handbook §6 explicitly tagged
   it as a "known gap, no longer blocking, power-user mode, can edit
   SharedPreferences directly". That's not a real product surface.
   Users wanting "everything goes via VPN except my banking app" had to
   `adb shell run-as com.ninitux.vpnrouter` and hand-edit SharedPrefs.

## Симптом

- User opens picker, scrolls past 80 system apps trying to find their
  one user-installed messenger because every row reads `com.foo.bar`
  in muted gray.
- User wants per-app exclude (banking app should not VPN), can't find
  the option, gives up and uses split-include with all-other-apps
  toggled — fragile + tedious.

## Root cause

`VPNRouter.Android/AppListLoader.cs` already loads `Drawable Icon` via
`pm.GetApplicationIcon(info)` (Phase 7.5 carried it but never used it).
The Drawable→Avalonia.Media.Imaging.Bitmap conversion was filed as
"Phase 8.1 cosmetic" and not done.

The exclude-mode UI was filed as a power-user feature; the form's split
radio always wrote `mode = "include"` (not `mode = "exclude"`),
the picker overlay had no surface to refine include vs exclude, and
`AndroidStorage.GetPerAppLastMode` didn't exist so toggling
split-tunnel off+on lost any non-default mode intent.

## Fix strategy

Six-file delta + one new helper, no behavioural change to the routing
layer (the Service wiring was already correct).

### 1. New `VPNRouter.Android/AppIconCache.cs`

Drawable → Avalonia Bitmap pipeline + LRU cache.

- Cap incoming Drawables at 96×96 (AdaptiveIconDrawables can intrinsically
  report 1024² which is wasteful for a 24px UI slot).
- Render Drawable into ARGB_8888 Android Bitmap via Canvas, PNG-encode
  to MemoryStream, hand to Avalonia's stream-based Bitmap constructor.
- LRU: 200-entry cap, dictionary + LinkedList for O(1) touch/evict.
- Thread-safe (locked); the AppListLoader background `Task.Run` populates
  while the UI thread reads on warm cache.

### 2. `VPNRouter.Android/AppListLoader.cs`

- Add `IconBitmap` field to `AppEntry`.
- Inside `Load()`'s per-app loop, call `AppIconCache.GetOrConvert` after
  `pm.GetApplicationIcon`. Conversion happens on the same background
  thread that already enumerates packages — no extra dispatcher hops.

### 3. `VPNRouter.Android/AndroidApp.axaml.cs`

- `BuildAppRow`: add a 24×24 `Image` element between checkbox and label
  (3-column grid `Auto,Auto,*`). `Image.Source = app.IconBitmap` reads
  synchronously; null → blank slot (no placeholder glyph).
- `BuildAppPickerOverlay`: add include/exclude segment row above the
  search box, plus a hint TextBlock below it that explains the active
  mode in plain language.
- `ShowAppPicker`: seed `_appPickerMode` from storage; default to
  `GetPerAppLastMode()` when the saved mode is currently `"off"`.
- `OnAppPickerSaveClicked`: persist both `SetPerAppMode` and
  `SetPerAppLastMode` so toggling split-off → split-on later restores
  the same mode.
- `OnTunnelModeRadioChanged`: when split toggles ON and current mode is
  `"off"`, restore the last active non-off mode instead of hardcoding
  `"include"`.
- `_perAppCountLabel` text formatting routed through new
  `UpdatePerAppFormCountLabel()` helper that picks include vs exclude
  format string.
- Form-side seeds (split radio `IsChecked`, full radio `IsChecked`,
  perAppStack `IsVisible`) updated to use `mode != "off"` predicate
  instead of `== "include"` so exclude doesn't mistakenly select full
  tunnel.

### 4. `VPNRouter.Android/AndroidStorage.cs`

- Add `KeyPerAppLastMode = "per_app_last_mode"` SharedPreferences key.
- `GetPerAppLastMode()` delegates to
  `VPNRouter.Core.Models.PerAppFilterMode.ResolveLastMode` for net8.0
  testability (returns "include" by default, "exclude" only if persisted
  exactly).
- `GetPerAppMode()` runs through `PerAppFilterMode.Normalize` so
  corrupted preferences fall through to `"off"` instead of leaking an
  unknown token to the routing layer.

### 5. `VPNRouter.Core/Models/PerAppFilterMode.cs` (new)

Pure-parse helpers (Normalize / ResolveLastMode / IsSplit) so the
testable rules live in `VPNRouter.Core` (consumable from net8.0 tests)
rather than in the Android-only project.

### 6. `VPNRouter.Android/Localization.cs`

Five new strings (RU+EN):
- `PerAppPickerModeLabel` — section label "Mode"
- `PerAppHintInclude` / `PerAppHintExclude` — mode-specific hint text
- `PerAppCountInclude` / `PerAppCountExclude` — form-side count label
  formats with mode suffix

## Cache eviction strategy chosen

LRU at 200 entries. Reasoning: typical user has 80-150 user-installed
apps, plus 100-300 system apps when the system-apps toggle flips. 200
covers a recently-toggled session without unbounded heap growth (each
Avalonia Bitmap holds the decoded pixel buffer ~96×96×4=37 KB → 200 ×
37 KB = ~7 MB worst case). Eviction by tail-removal on insert.

## Risk

- Pure UI / metadata-read change. Reads installed-app metadata via
  `PackageManager` (no network). Safe.
- Drawable → PNG conversion on cold cache adds ~1 s to the first
  picker open (per the existing background `Task.Run`). Acceptable
  because there's already a "Loading…" placeholder.
- Toggle restore semantics intentionally preserve last mode across
  split-off → split-on transitions. Documented in `PerAppFilterMode`
  comments.
- WFP / network: untouched. Service-side `addAllowedApplication` /
  `addDisallowedApplication` branches were already correct in
  `VpnRouterService.java` lines 357-377 (Phase 7.5 commit 3a6e9d6).
  Only the UI surface changed.
