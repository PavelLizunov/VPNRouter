# v2.32.0 — Android libbox API migration

## Триггер

После AND-1..AND-4 merges (subscription multi-card + Settings parity +
Free Configs port + theme live-switch) и pull'а текущего libbox.aar
(sing-box 1.13.x upstream gomobile binding, ~11.7 MB, 2026-05-07)
Android Java build падал. Партial fix `901a079` дотянул
`PlatformInterface` (writeLog/packageNameByUid/uidByPackageName) +
`CommandServerHandler` (serviceStop → postServiceClose) но оставил два
core compile errors:

- `OverrideOptions` тип удалён из libbox.
- `ConnectionOwner` тип удалён, `findConnectionOwner` возвращает
  теперь `int`.

## Симптом

```
VpnRouterService.java:77: error: cannot find symbol — io.nekohasekai.libbox.OverrideOptions
VpnRouterService.java:216: error: cannot find symbol — OverrideOptions
VpnRouterService.java:802: error: cannot find symbol — io.nekohasekai.libbox.ConnectionOwner
```

протестировать AND-* features на устройстве.

## Root cause

**OverrideOptions** обслуживал старый
`commandServer.startOrReloadService(json, overrides)` API. В новой
libbox-AAR этого метода больше нет — service создаётся через
`Libbox.newService(json, platformInterface) → BoxService`.

**ConnectionOwner** был struct с полем uid (для per-app rules в
sing-box). Текущий API возвращает raw `int` (`-1` = unknown).

`javap` over `Lib/libbox.aar/classes.jar`:

```
public abstract class io.nekohasekai.libbox.Libbox {
  public static native io.nekohasekai.libbox.BoxService newService(
      java.lang.String, io.nekohasekai.libbox.PlatformInterface) throws java.lang.Exception;
  public static native io.nekohasekai.libbox.CommandServer newCommandServer(
      io.nekohasekai.libbox.CommandServerHandler, int);  // (handler, port) — без PI!
  ...
}

public final class io.nekohasekai.libbox.BoxService {
  public native void start() throws java.lang.Exception;
  public native void close() throws java.lang.Exception;
  public native void pause();
  public native void wake();
  public native void resetNetwork();
  public native void updateWIFIState();
  public native boolean needWIFIState();
}

public interface io.nekohasekai.libbox.PlatformInterface {
  public abstract int findConnectionOwner(int, java.lang.String, int, java.lang.String, int);
  // ConnectionOwner (struct) → int (uid, -1 = unknown)
  ...
}
```

**Также обнаружено**: `Libbox.newCommandServer(handler, int port)` не
требует PlatformInterface. CommandServer теперь чисто Clash-API RPC
gateway — VPNRouter Android не использует Clash dashboard и драйвит
lifecycle через Intent broadcasts на Avalonia-UI side. Поэтому
**CommandServer полностью dropped** из service path.

## Fix

### `VPNRouter.Android/VpnRouterService.java`

Imports — minus 4, plus 1:

```diff
-import io.nekohasekai.libbox.CommandServer;
-import io.nekohasekai.libbox.CommandServerHandler;
-import io.nekohasekai.libbox.SystemProxyStatus;
-import io.nekohasekai.libbox.OverrideOptions;
+import io.nekohasekai.libbox.BoxService;
```

Field — `CommandServer commandServer;` → `BoxService boxService;`.

`startLibboxService()` — короче на 6 строк:

```java
VpnRouterPlatformInterface platformInterface = new VpnRouterPlatformInterface(this);
boxService = Libbox.newService(pendingConfigJson, platformInterface);
boxService.start();
```

`stopTunnel()` — `commandServer.close()` → `boxService.close()`. Также
порядок: сперва закрываем boxService, потом currentPfd. libbox держит
fd через PlatformInterface.openTun return — закрытие service-первым
позволяет ему чисто отпустить fd до того как PFD освободится.

`VpnRouterCommandHandler` inner class **полностью удалён** (было ~25
LOC, 4 stub методa).

`findConnectionOwner` — return type `ConnectionOwner` → `int`,
тело меняется на `return -1;` (sing-box treats as unknown / fallback,
мы и так не enable'им process_name rules в Android sing-box config'е).

### `plans/vpnrouter-android-handbook.md` §2.1

Roadmap-ный summary заменён на актуальный с current API list. Section
2.2 `findConnectionOwner` row updated: `throw` → `return -1`.

## Acceptance question (a) answered

> Whether new BoxService flow needs CommandServer at all (drop or keep)

**Drop.** CommandServer в текущей libbox это Clash-API RPC gateway
(Connections / Groups / URLTest / Stats / system-proxy enable). VPNRouter
на Android рулит lifecycle'ом через Intent broadcasts (ACTION_START /
ACTION_STOP / ACTION_TUNNEL_UP / ACTION_TUNNEL_DOWN) и не выставляет
Clash dashboard. Drop'нули inner `VpnRouterCommandHandler` class и
полностью убрали CommandServer reference. -25 LOC. Если в будущем
понадобятся live Stats/Connections в UI, новый CommandServer создаётся
через `Libbox.newCommandServer(handler, int port)` (handler interface
имеет 4 метода: getSystemProxyStatus / postServiceClose / serviceReload
/ setSystemProxyEnabled).
