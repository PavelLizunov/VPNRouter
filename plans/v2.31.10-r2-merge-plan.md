piped-eval pattern. Same UX, much smaller heuristic surface.

`OrphanCleanup.KillOrphans()` was unconditionally killing sing-box on

the kill when `TunOwnershipLock.IsOwnedByAnyone()`. User-takeover sites
(Stop / Connect / Update) opt out via `respectTunLock: false`. 7 new
unit tests pin the contract.

## 8. MCP test r2 — live verify both fixes

### F-12 verification (Service+App coexistence)

```powershell
# 1. Get current sing-box PID
$beforePid = (Get-Process sing-box -EA SilentlyContinue).Id
"Before: sing-box pid = $beforePid"

# 2. Install Service via CLI
& 'C:\Program Files\VPNRouter\app\VPNRouter.CLI.exe' service install
& 'C:\Program Files\VPNRouter\app\VPNRouter.CLI.exe' service start

# 3. Wait for Service-spawned sing-box to settle
Start-Sleep 8

# 4. Note Service-spawned sing-box PID
$serviceSbPid = (Get-Process sing-box -EA SilentlyContinue).Id
"Service-spawned sing-box pid = $serviceSbPid"

# 5. Stop App + relaunch via shortcut → trampoline + App startup → triggers OrphanCleanup
Stop-Process -Name VPNRouter.App -Force -EA SilentlyContinue
Start-Sleep 2
& 'C:\ProgramData\Microsoft\Windows\Start Menu\Programs\VPNRouter.lnk'
Start-Sleep 8

# 6. Verify the SAME sing-box is still running (NOT killed by App startup)
$afterPid = (Get-Process sing-box -EA SilentlyContinue).Id
"After App restart: sing-box pid = $afterPid"
if ($afterPid -eq $serviceSbPid) {
    Write-Output "F-12 VERIFIED LIVE: sing-box survived App startup (TunLock honored)"
} else {
    Write-Output "F-12 STILL BROKEN: sing-box was killed; new pid $afterPid (was $serviceSbPid)"
}

# 7. Cleanup — uninstall Service to leave VM clean
& 'C:\Program Files\VPNRouter\app\VPNRouter.CLI.exe' service stop
& 'C:\Program Files\VPNRouter\app\VPNRouter.CLI.exe' service uninstall
```
