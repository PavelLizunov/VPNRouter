# v2.37.0-r4 — Flowseal-probe polish design

## Scope

r3 shipped the Flowseal-delegated DPI probe with one usability gap: the
hero chip only updates per-config («Тестирую (5/20): general (ALT3)»),
giving the user no feedback during the 6–20 s each config spends on its
TCP-byte-level checks. Also: r3 inherited Flowseal's `ipset_switched.flag`
safety net but never proactively cleans it up; admin-elevation pre-check
is implicit (script exits cleanly on non-admin but our UI doesn't surface
the message); long-running script has no hard timeout cap.

r4 adds five polish items, all backwards-compatible with r3's
`RunFlowsealProbeAsync` contract.

## Part A — Live per-target X/Y score parser

### Problem

User-visible behaviour pre-r4:

```
Тестирую (5/20): general (FAKE TLS AUTO ALT2)
   (… 12 seconds of nothing …)
Тестирую (6/20): general (ALT3)
```

Per the user complaint at end of r2 («он у тебя прошел очень быстро,
через bat файл занимает минуты») the slow probe is INTENTIONAL — but
during each 6–20 s window the user has zero signal that work is happening.

### Fix

Parse the per-test status lines Flowseal already emits:

```
[YT_LIVE@0][HTTP] code=200 size=262144 bytes (256 KB) status=OK
[YT_LIVE@0][TLS1.2] code=200 size=18432 bytes (18 KB) status=LIKELY_BLOCKED
[YT_LIVE@0][TLS1.3] code=000 size=0 bytes (0 KB) status=FAIL
```

Track `OkCount` and `TotalCount` per active config. Reset on each new
`[N/M]` header. Emit `FlowsealProgress(currentIndex, total, strategy, ok, totalChecks)`
on every status line so the UI can render:

```
Тестирую (5/20): general (FAKE TLS AUTO ALT2) · 12/18
```

### Code touch

- `VPNRouter.Core/Services/ZapretAutoStrategy.cs`:
  - Extend `FlowsealProgress` record: add `int OkCount`, `int TotalChecks` (default 0).
  - In `RunFlowsealProbeAsync.OutputDataReceived`:
    - Add new regex `^\[.+?\]\[(?:HTTP|TLS1\.[23])\].+?status=(\w+)$`.
    - Maintain `_currentOk`, `_currentTotal` per-config locals (reset on `[N/M]` parse).
    - On match: increment counters, emit progress.
- `VPNRouter.Core/Localization/Strings.cs`:
  - New string `ZapretOneTapLedeProbingFlowsealScored(int i, int total, string strategy, int ok, int totalChecks)`:
    Russian: «Тестирую ({i}/{total}): {strategy} · {ok}/{totalChecks}»
    English: «Testing ({i}/{total}): {strategy} · {ok}/{totalChecks}»
- `VPNRouter.App/Localization/Strings.cs`: pass-through.
- `VPNRouter.App/ViewModels/MainWindowViewModel.cs`:
  - `ProbeAndStartZapretAsync` progress handler: track latest `(ok, total)`,
    pick the scored variant when `totalChecks > 0`, fall back to plain
    «Тестирую (N/M): strategy» otherwise.

### Risk

Low. Strictly additive — pre-r4 callers receiving `FlowsealProgress(_,_,_)`
ignore the new defaulted fields. Regex is narrow (matches only `[id][HTTP|TLS1.2|TLS1.3]`
shape that Flowseal emits, won't match config headers).

## Part B — Ipset auto-restore B-4

### Problem

Flowseal's script switches `lists/ipset-all.txt` to "any" mode for the
duration of the sweep, backing up to `lists/ipset-all.test-backup.txt`
and creating `ipset_switched.flag` as a tombstone. The script's
`finally{}` block restores on graceful exit; its `trap{}` block restores
on Ctrl+C. But:

1. Our cancellation path is `proc.Kill(entireProcessTree: true)` —
   TerminateProcess bypasses BOTH `finally` AND `trap`, so on user-Stop
   mid-sweep the ipset stays in "any" mode and the flag stays on disk.
2. On next run the script detects the flag and restores (line 338-342 of
   `test zapret.ps1`) — but that only fires when the user opts to re-run
   the probe. They may use ipset-dependent strategies for hours/days
   before next probe, hitting the wide-open ipset the whole time.

### Fix

Two new helpers in `ZapretAutoStrategy`:

- `bool HasOrphanedIpsetFlag(string zapretInstallDir)`:
  Returns true if `ipset_switched.flag` exists at zapretRoot.
- `void RestoreIpsetAfterKill(string zapretInstallDir, ILogger?)`:
  - If `lists/ipset-all.test-backup.txt` exists: move it over
    `lists/ipset-all.txt` (matches `Set-IpsetMode -mode "restore"`).
  - If backup missing but flag present: log warning, leave ipset alone
    (script bug, don't make it worse).
  - Delete `ipset_switched.flag`.
  - Log result.

### Wire-up

- App startup (MainWindowViewModel constructor or first ProbeAndStart):
  call `HasOrphanedIpsetFlag` → if true, run `RestoreIpsetAfterKill` +
  log info "[ZapretAutoStrategy] Restored orphaned ipset from prior probe interrupt".
- `ProbeAndStartZapretAsync` finally{} block: call `RestoreIpsetAfterKill`
  unconditionally — idempotent if no flag exists. Catches the "cancelled
  mid-sweep" case while window still open.

### Risk

Low. File ops are deterministic. Worst case: backup file is corrupt or
empty (Flowseal already creates empty backup if no original ipset existed)
— we restore an empty file, which matches "any" mode anyway. Not a
regression vs current.

## C.2 — 10-minute hard timeout cap

### Problem

Flowseal sweep is bounded by per-config × test-suite-count × per-test
timeout. With a custom test suite or network flakiness, theoretical worst
case is ~30 min per sweep. User expects "few minutes" — anything over
10 min is a script bug, not normal slowness.

### Fix

In `RunFlowsealProbeAsync`:

```csharp
public static readonly TimeSpan FlowsealMaxSweepTime = TimeSpan.FromMinutes(10);

using var timeoutCts = CancellationTokenSource.CreateLinkedTokenSource(ct);
timeoutCts.CancelAfter(FlowsealMaxSweepTime);

await proc.WaitForExitAsync(timeoutCts.Token);
```

On cap-hit: kill process tree, return `FlowsealSweepResult` with
`Winner=null`, `Diagnostic="sweep_timeout"`.

### Risk

Very low. 10 min is well past 99th percentile (~7 min worst case per r3
release notes). User can re-run.

## C.3 — Admin elevation pre-check

### Problem

Flowseal's `test zapret.ps1` lines 320-325 exits with
`[ERROR] Run as Administrator to execute tests` if not elevated. Our
desktop app already requires admin for TUN setup so this should always
pass — but if for some reason the parent process loses elevation (UAC
quirk, scheduled task, service-mode restart), the script silently exits
and we surface "Ни одна стратегия не подошла" with no clue why.

### Fix

In `RunFlowsealProbeAsync` early return:

```csharp
if (!OperatingSystem.IsWindows()) {
    return new FlowsealSweepResult(null, 0, 0, "not_windows", ErrorLines: Array.Empty<string>());
}

using var identity = WindowsIdentity.GetCurrent();
var principal = new WindowsPrincipal(identity);
if (!principal.IsInRole(WindowsBuiltInRole.Administrator)) {
    logger?.Warning("[ZapretAutoStrategy] Cannot run Flowseal probe — not elevated");
    return new FlowsealSweepResult(null, 0, 0, "not_admin", ErrorLines: Array.Empty<string>());
}
```

ViewModel surfaces localized toast when result has `FullOutput == "not_admin"`.

### Risk

Very low. App already needs admin to function so this is double-coverage.

## C.4 — Surface lifted [ERROR] script lines

### Problem

When the script outputs `[ERROR]` or `[WARN]` lines (zapret service
conflict, curl missing, DPI suite fetch failed) those go to debug log
only. User sees "no strategy matched" and has no path forward.

### Fix

Ring-buffer the last 8 `[ERROR]`/`[WARN]` lines into the returned
`FlowsealSweepResult.ErrorLines` field. ViewModel can:

- If sweep returned no winner AND ErrorLines is non-empty: surface first
  line in toast.
- Always log full ErrorLines via Serilog.

### Code touch

- `FlowsealSweepResult` record: add `IReadOnlyList<string> ErrorLines` (default empty).
- `OutputDataReceived`: append lines matching `^\s*\[(?:ERROR|WARN|WARNING)\]` to a
  capped `List<string>` (cap=8).
- After process exit, copy into result.

### Risk

Low. New optional field, no breaking changes.

## Expected outcomes

- User sees fine-grained "X/Y checks ok" progress every ~1-2 s during
  each config.
- Cancellation no longer leaves ipset in "any" mode silently.
- Sweep can't get stuck >10 min.
- Non-elevated parent process gets a clear error instead of silent fail.
- Script errors surface in toast for diagnosis.

## NOT in r4 (deferred to r5+)

- Per-ISP catalog pre-seeding strategy order
- Probe result caching (warm-start on returning users)
- Replace Flowseal with bol-van/zapret2 (3-6 month timeline per zapret2 research)
- Live "best so far" winner update during sweep (Flowseal computes winner
  only at end — would need our own parallel scoring)
