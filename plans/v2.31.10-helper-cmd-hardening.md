# v2.31.10 — helper.cmd hardening audit

## Триггер

v2.31.7 → v2.31.8 cycle had a single critical CMD parser bug
(`%SVC_TRIES%` pre-expanded inside a parsed `if/else` block →
`if  gtr 20` → 100% upgrade failure for ~7 days, surfaced only
after spark-wraith reported «впн не хочет обновляться сам»).

The fix landed in v2.31.8-r10 with `setlocal EnableDelayedExpansion`
+ `!VAR!` for runtime-set vars. We pinned that one fix in
`HelperCmdParserGuardTests.HelperScriptTemplate_UsesEnableDelayedExpansion`
(1 test). This audit catalogs **every other** CMD-emitting code-path
on Windows so we can extend the lint-net to cover the same bug class
+ adjacent regressions before they fire on a real user.

## Симптом

Hypothetical (we want to prevent these BEFORE they happen):

- A future refactor moves the `set /a TRIES=0 ... if !TRIES! gtr 60`
  block back into a parent `if (...)` and silently re-introduces the
  v2.31.7 bug. xcopy never runs. Auto-update silently fails.
- Someone switches `!SVC_TRIES!` back to `%SVC_TRIES%` on the
  assumption that delayed-expansion is academic. Same outcome.
- A `set "VAR=..."` line drops the surrounding quotes and a user
  installing under `C:\Program Files (x86)\VPNRouter` triggers a
  parse error on the parenthesis.
- The 30-second parent-process wait or 10-second sc-stop wait gets
  removed «for performance», zombie helpers pile up in `%TEMP%`.
- The Service failure-recovery restore (`sc failure VPNRouter
  reset= 86400 actions= restart/60000/...`) gets dropped — future
  Service crashes silently stop auto-recovering, user sits
  disconnected with no retry.
- The `del /Q "%~f0"` self-delete drops out and `%TEMP%` collects
  one orphan helper per upgrade per machine forever.
- The log-path moves back to `%TEMP%\vpnrouter-update-{pid}.log`
  and the install-receipt banner reference («See LogsDir/update.log
  for details») becomes a dangling pointer.

Every one of those is a one-line edit away. Source-pin tests catch
them at PR time instead of after release.

variable expansion inside parenthesised blocks.

`%TEMP%\vpnr-self-repair-{ts}.ps1`) — separate hazard surface
(Defender ClickFix heuristics), already covered in

v2.31.10-r2. Not pinned here.

#### D — `repair.cmd` (static, hosted)

```cmd
:waitstop
sc query VPNRouter | find "STOPPED" >nul && goto stopdone
set /a tries+=1
if %tries% gtr 30 (
    echo   Service did not stop in 15s — proceeding anyway
    goto stopdone
)
ping -n 1 -w 500 127.0.0.1 >nul
goto waitstop
:stopdone
```

| Hazard | Currently safe? | Why | Test |
|---|---|---|---|
| `if %tries% gtr 30` at top-level, NOT wrapped in parent `(...)` | ✅ yes (today) | each `:waitstop` iteration is parsed line-by-line at top level — `%tries%` evaluates at execution time of the `if` line, not at parse time of an enclosing block. | flag-only |
| `enabledelayedexpansion` directive present | ✅ yes (line 31) | so we COULD switch to `!tries!` and be bullet-proof against future refactor that wraps the loop in an `if` | **flag for future hardening** — non-urgent |
| `powershell -ExecutionPolicy Bypass -Command` form | ⚠️ Defender ClickFix heuristic surface | same pattern that bit `SelfRepair.cs` in v2.31.10-r2. Currently unflagged. | flag for `v2.31.10-av-firewall-compat.md` follow-up |

Defense-in-depth recommendation for D: switch
`if %tries% gtr 30` → `if !tries! gtr 30` (since
`enabledelayedexpansion` is enabled). The `:waitstop` block is
top-level today and `%tries%` works, but a future refactor that
wraps the whole thing in an `if installed (...)` block would
silently re-introduce the v2.31.7 bug class. Cheap insurance.

Not blocking — flag for next stable cycle.

#### E — `update-helper.cmd` (static fallback)

```cmd
@echo off
setlocal
...
xcopy /s /y /q "%STAGING%\*" "%APPDIR%" >NUL 2>&1
if %ERRORLEVEL% NEQ 0 (
    echo ERROR: ...
    pause
    exit /b 1
)
```

| Hazard | Currently safe? | Why | Test |
|---|---|---|---|
| No `EnableDelayedExpansion` | ✅ yes | no nested if/set patterns; `%ERRORLEVEL%` is read at line-execution time of the top-level `if`, no enclosing block | not pinned |
| Service-aware | ❌ no | This is a legacy fallback that pre-dates v2.31.7-r1's Service-aware xcopy fix. If a user runs it while Service is installed + RUNNING, xcopy /R will skip locked files → mixed-version DLLs → InstallHealthCheck triggers SelfRepair on next launch. | flag for follow-up — should be deleted or updated to match `repair.cmd`'s sc-stop dance |

Recommendation for E: this file is the legacy in-zip fallback,
written before the in-app helper became Service-aware in v2.31.7.
Either delete it (users have `repair.cmd` web-hosted now) or sync
its logic with `repair.cmd`. Not blocking for this audit.

## Fix strategy

### What this audit ships

1. **`HelperCmdParserGuardTests.cs` extended from 1 → 6 tests**
   covering every actively-load-bearing pattern in emitter A
   (the primary helper). Each test reads the C# source, strips
   line-comments, and asserts a structural invariant (presence of
   safe pattern AND absence of dangerous pattern).

2. **`plans/v2.31.10-helper-cmd-hardening.md`** (this doc) — full
   inventory + per-hazard reasoning so future maintainers can decide
   which of the «not pinned» items deserve their own test.

### Test list (numbers map to hazard table above)

| # | Test | Pins |
|---|---|---|
| 1 | `HelperScriptTemplate_UsesEnableDelayedExpansion` (existing) | `setlocal EnableDelayedExpansion` directive + absence of `if %TRIES%`/`%SVC_TRIES%`/`%SVC_WAS_RUNNING%`/`%XCOPY_EXIT%` + presence of `if !TRIES!`/`!SVC_TRIES!` |
| 2 | `HelperScriptTemplate_AllSetLinesAreQuoted` (new) | every `set "VAR=...` line in the emitted block uses a quoted value (defends against unquoted Program Files path) |
| 3 | `HelperScriptTemplate_TimeoutGuardsPresent` (new) | both `if !TRIES! gtr` (parent wait) and `if !SVC_TRIES! gtr` (svc stop) loop bounds present |
| 4 | `HelperScriptTemplate_SelfDeletes` (new) | `del /Q "%~f0"` final cleanup line present |
| 5 | `HelperScriptTemplate_LogPathUsesLogsDir` (new) | `helperLog` C# variable built from `AppPaths.LogsDir`, not `Path.GetTempPath()` |
| 6 | `HelperScriptTemplate_ServiceFailureRecoveryRoundtrip` (new) | both `sc failure VPNRouter reset= 0 actions= ""` (disable) AND `sc failure VPNRouter reset= 86400 actions= restart/60000/restart/60000/restart/60000` (restore) lines present |

### What this audit does NOT ship (deferred)

- **Rewriting helper.cmd in PowerShell** — would solve all CMD parser
  hazards in one stroke. Trade-off: more AMSI heuristic surface
  (PowerShell scripts are scanned more aggressively than .cmd by
  Defender), bigger code-size footprint, harder to debug for users
  who can read `.cmd` but not PS scripts. **Recommendation: stay on
  CMD with discipline + lint-net**. Revisit if a future hazard
  emerges that's genuinely unfixable in CMD (unlikely — the parser
  bug class has only one root cause: parse-time `%var%` expansion in
  parenthesised blocks. `setlocal EnableDelayedExpansion` + `!var!`
  is the canonical fix and we already have it).

- **Pinning emitter B and C** (Zapret .bat files) — both are simple
  linear scripts with no parser-bug class hazards. Pinning them
  would over-constrain refactor freedom for low value.

- **Updating `update-helper.cmd` (static legacy fallback)** — flag
  for v2.31.10-r3 or later: either delete the file (web-hosted
  `repair.cmd` is the supported recovery path now) or sync its
  Service-stop logic with `repair.cmd`. Out of scope for parser-bug
  hardening.

- **Hardening `repair.cmd`** (`%tries%` → `!tries!` defense-in-depth) —
  flag for next stable cycle. Currently safe at top-level; cheap
  insurance for future maintainers.
