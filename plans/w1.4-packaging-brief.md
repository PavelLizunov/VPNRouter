# W1.4 — packaging: bundle the split-tunnel driver (gated + sha256-gated)

**Roadmap ref**: `plans/goal-w1.1-implementation-2026-07-04.md` (W1.4) · arch §6.2 · ABI pins `plans/w1-driver-abi-reference-2026-07-03.md`. **Effort**: ~0.5d. **Risk**: LOW-MED (ship-critical `build.ps1`, mitigated below).

## Why
Get the 3 driver files into the Windows install so `SplitTunnelDriverManager` can install the kernel service on first exclude-mode connect — but **without** auto-activating the feature for existing users before it's cut (goal §9 auto-ON-vs-opt-in "confirm at cut").

## What
- `build.ps1`: new **gated** step `[6c/9] Bundling split-tunnel driver`, behind a `-BundleSplitDriver` switch (**default off** — normal `-rN` ships don't bundle it → feature off by absence = fail-open path #1). When on: download the 3 files (`.sys`/`.cat`/`.inf`) from `mullvadvpn-app-binaries@cc0affb2` into `tools\driver-cache\<commit>\` (cached like singbox-cache), **HARD sha256 gate vs the ABI pins — mismatch = build FAIL** (a silent driver/ABI bump can't slip in), copy to `dist\driver\` (= the app's `AppContext.BaseDirectory\driver`), write `checksums.sha256`, ship `LICENSE.split-tunnel`.
- `LICENSE.split-tunnel` (new, repo root): attribution — dual GPL-3.0/MPL-2.0, pinned source/binary repos, "bundled verbatim, driven over IOCTL".
- `packaging/windows/uninstall.ps1`: + `sc stop`/`sc delete mullvad-split-tunnel` (best-effort, before the install-dir removal so the unloaded `.sys` doesn't lock the dir).

## Non-goals / invariants held
- **14/16-asset invariant unchanged**: the driver files ride *inside* the app ZIP (`dist\driver\`), not as standalone release assets.
- **Mac/Linux untouched**: they never run `build.ps1`; no driver in their builds.
- **No premature activation**: gate default off; the `.sys` isn't committed (downloaded on demand); activation = an explicit `-BundleSplitDriver` build at the ship-the-feature moment.
