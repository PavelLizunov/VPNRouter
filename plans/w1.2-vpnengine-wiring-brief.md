## Why
P1-P3 delivered + live-proved the driver core, but nothing wires it into the app yet. W1.2 makes the exclude-mode connect actually engage the driver (and disconnect disengage it), so excluded apps get the true OS-level split — while keeping the hard fail-open invariant: a null/failing driver leaves today's post-capture routing untouched.

## What (4 hooks, arch §5.1 — all fail-open, manager never throws)
- **Ctor** (`VpnEngine.cs:203`): add `ISplitTunnelDriver? splitDriver = null` param + `private readonly ISplitTunnelDriver? _splitDriver` field (mirror `IWindowsDnsHardening`). Null on non-Windows / tests-without-fake.
- **Hook 1 — engage** (end of `StartAsyncInternal` success branch, by the Unix-DNS block ~line 364): gate on `SplitTunnelPolicy.ShouldEngage(OperatingSystem.IsWindows(), settings.App.RoutingMode, settings.App.RoutingAppsMode, hasExcluded, driverSetting)` + yaml `true_split_driver: auto|off` (default auto). Resolve `settings.App.RoutingAppsExclude` names → DOS paths via `ProcessImagePath.ResolveNameToPath`; unresolved → log + skip (post-capture still covers). `await _splitDriver.EngageAsync(new SplitTunnelEngageRequest(dosPaths, settings.Tun?.Ipv4Address, settings.Tun?.Ipv6Address), ct)`. Covers failover restarts (they re-enter StartAsyncInternal) — engage is idempotent.
- **Hook 2 — re-engage** (end of successful `ApplyAsync` ~line 505): if `_splitDriver?.IsEngaged == true` OR `ShouldEngage` now true → re-`EngageAsync` with re-resolved paths (closes excluded-list change, TUN-IP change, include→exclude flip). `ShouldEngage`-false now (went include/full) → `DisengageAsync`.
- **Hook 3 — disengage** (`TeardownInternal` ~line 663, AFTER `_singBox?.Dispose()`): `_splitDriver?.DisengageAsync(...)` synchronously awaited with a 5 s timeout (teardown is sync; manager never-throws). Order matters — excluded stay on NIC binds until the last ms, then TUN is gone so new binds hit the same physical NIC. 0-gap.
- **Hook 4 — dispose** (`Dispose` ~line 757): `try { _splitDriver?.Dispose(); } catch { }` in both branches.
- **Startup sweep**: call `SweepStaleStateAsync` once at engine start (heals a stale ENGAGED from a crashed prior session in a never-engage session).

## Contract with W0.1 (§5.3 — pin with a test + a comment at hook 3)
HealthMonitor recovery (`OnSingBoxCrashed → AttemptRestart → Restart()`) happens **inside a live VpnEngine, without Stop()/StartAsync** → hooks 1/3 don't fire → **driver stays ENGAGED through the whole down-window + restart**. That IS the point: excluded live through the NIC while sing-box is down. After relaunch the TUN gets the same IP → no re-register needed.
