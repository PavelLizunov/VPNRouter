## Adversarial review — 3 independent agents

Spawned three read-only reviewers (one per high-risk change + one
cross-cutting). They surfaced **3 real issues, all fixed before cut**:

### FIXED — CRITICAL: custom-JSON DNS leak (full-tunnel / exclude)
#147 flipped `route.final` to the proxy in full-tunnel and exclude mode
(closing the traffic leak), but `StripUnsupportedFeatures` still forced
`dns.final` to the LOCAL resolver, so DNS queries for the tunnelled
traffic leaked to the ISP. `CustomConfigInjector` now mirrors
`ConfigGenerator.BuildDns`: full tunnel OR exclude OR StrictDns =>
`dns.final` = remote/proxy DNS. +3 `dns.final` assertions across the
mode tests so it can never regress silently.

### FIXED — MEDIUM: all-numeric secrets leaked into diagnostics bundle
`DiagnosticsRedactor`'s `_numberLike` fast-path returned values verbatim
for ANY key before the allowlist ran, so an all-digit Reality `short_id`
or numeric password survived into the exported support bundle. Added a
`SecretKeys` set; credential keys now skip the numeric/bool fast-path and
fall through to `***`. Legitimate numeric ports/counts unaffected.
+1 regression test.

### FIXED — HIGH (UX): Android Connect CTA auto-light-up dead path
#148's `OnFcEntryUpgraded` auto-select only fired when nothing was
selected, but `OnFcFound` auto-selects the first Ok candidate — so on the
common "first candidate fails deep verify, later one passes" path the CTA
never auto-enabled. Now selection is promoted off any non-Verified row to
the freshly verified one. (Safety was never affected — gate + backstop
held; this was convenience-only.)

### Verified CORRECT by the reviewers (no change needed)
- #147: route.final survives Strip/EnsureUrltest; include-split empty-list
  is byte-identical to old behaviour; process_name case preserved;
  per-app DNS direction correct.
- #148: persistence is Verified-only end-to-end; UI gate is
  single-source-of-truth; fail-closed Connect backstop; format-string
  arities all match; loop terminates; no infinite selection recursion.
- r4 pool.gz: bounded streaming decompress (decompression-bomb guarded),
  atomic temp+rename, raw fallback, 7 tests.
- r5 ExcludeRu: only over-filters RU (intended direction).
- r1-r3 diagnostics: fail-safe allowlist (unknown keys -> `***`),
  parse-failure omits whole file.

### Deferred (LOW / NIT — not blockers)
- r6 routing scrub `TryRemoveProcessName` is a no-op on macOS/Linux (`.exe`
  contract) and doesn't scrub the inactive Exclude list — correct on
  Windows (primary), weaker cross-platform. Backlog.
- URL userinfo (`user:pass@host`) preserved by `RedactUrlKeepHost` — very
  low likelihood (UI never generates userinfo URLs). Backlog.
- `\bauth\b` log regex misses `Authorization:` headers — JWTs still caught
  by the long-base64 scrubber. Backlog.
- Android cancel-during-deep-verify reports "Sources exhausted" instead of
  "Cancelled" (cosmetic; no weak candidate persisted). Backlog.

## Pre-existing issue found (NOT a v2.39 regression) — stale VisualDiff baselines

`VisualDiffTests` fails on `page-dpi-bypass` (26%), `page-tools` (26%),
`page-telegram` (11%) against the pinned baselines. Confirmed pre-existing:
- No v2.39 commit (`v2.38.2..HEAD`) touches these pages or the baseline PNGs.
- The baselines were last refreshed 2026-05-09 (`7b688f7`), BEFORE the v2.37
  Zapret one-button redesign (r21-r54, late May: Hero cards, ToggleButton
  tab strip) and the v2.38 changes that overhauled exactly these pages.
- VisualDiffTests `OperatingSystem.IsWindows()`-skip on CI's Linux runners,
  so the drift has been invisible — local Windows runs aren't in the ship
  flow. The 10-26% magnitude reflects the whole redesign, not subtle AA.

So this is accumulated baseline tech debt from already-shipped (and
MCP-verified) v2.37/v2.38 designs, surfaced by this sweep — not caused by
any v2.39 change. Flagged for a baseline refresh (desktop-UI; benefits from
a human eyeball of the three pages before re-pinning). Does NOT block r7.
