## Why
W1.0 proved the driver reaches ENGAGED and redirects excluded traffic past a full-tunnel sing-box, surviving its death. P1 ported the byte-exact protocol (buffers, event parser, pure decisions) — CI-testable, 66 green. P2 turns that into the runtime object that actually drives the driver: install/own the kernel service, open the one exclusive overlapped handle, create the WFP sublayers the driver needs, run the INITIALIZE→REGISTER→SET→verify engage flow, and tear it back down to inert on disengage — **without ever breaking the network on any failure**. It is the load-bearing piece between "protocol compiles" and "P3 goes live on the VM".

## What
New `VPNRouter.Core/Services/SplitTunnelDriverManager.cs`:
- `ISplitTunnelDriver` (cross-platform seam, mirrors `IWindowsDnsHardening`) + `SplitTunnelEngageRequest` record (excluded DOS paths + TUN v4/v6). Interface is the W1.2 test seam; the fake lands in W1.2.
- `sealed class SplitTunnelDriverManager : ISplitTunnelDriver` — `[SupportedOSPlatform("windows")]`, `#nullable enable`, no magic numbers. Lazy: ctor touches nothing (paths + logger + injected `QueryDosDevice` seam only). Owns: SCM service (create/adopt, never stop), one `SafeDeviceHandle` (exclusive, `FILE_FLAG_OVERLAPPED`), one auto-reset control event, 2 WFP sublayers, `NetworkChange` subscription, a `SemaphoreSlim(1,1)` serialising the whole control plane.
- `EngageAsync` → `bool` (never throws): files-present precheck → ensure service (collision guard) → create sublayers → open device → `GET_STATE!=STARTED?RESET` → INITIALIZE → REGISTER_PROCESSES(full snapshot) → REGISTER_IP_ADDRESSES + SET_CONFIGURATION → verify `ENGAGED`. Idempotent (re-engage = reinitialize). Every step's failure logs + returns false, leaving post-capture routing intact (§3 paths 1-8, 13).
- `DisengageAsync` (never throws, idempotent): RESET (service stays STARTED-inert) → close handle → delete sublayers.
- `Dispose`: best-effort RESET + close + unsubscribe. Never throws.
- **Crash-recovery sweep** (§1.3): first engage sweeps a stale `GET_STATE>STARTED` we didn't set → RESET (heals excluded-bound-to-yesterday's-IP).
- **NetworkChange self-subscribe** (§5.2): while engaged, debounce 2 s → re-detect internet NIC → `ShouldReRegister`? re-REGISTER_IP; fail → retry once @5 s → else disengage (§3 path 10).
- **NO event pump** — that is P3. A `_pumpHealthy` field + `IsPumpHealthy` property exist as the P3 seam (reports healthy in P2).

3. NIC helper.
4.
