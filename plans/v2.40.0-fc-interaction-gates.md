## Trigger
The interaction-contracts framework (Phase 1, `plans/interaction-contracts/`)
resolved the 9 Public Configs decisions. Several map to small code gates that
are not yet enforced. This is Phase 2 — the binary-changing fixes.

## Branch
`claude/v2.40-fc-interaction-gates` off `main` @ `2ba1b5e` (docs state =
binary-identical to the soaking v2.39.0-r7). Kept OFF main so the eventual
`v2.39.0` stable cut promotes exactly the soaked code. Merges to main + ships

## How
- F2: guard at top of `MainWindowViewModel.ApplyFreeConfigAsync` — reject when
  `entry.Status != FreeConfigStatus.Verified` (mirrors Android `ApplyFcConnectGate`
  + the `OnFreeConfigsUseClicked` backstop). Surface an actionable status.
- F1: reject Apply when the FC page operation is running. Desktop: an in-method
  `if (IsBusy) return` guard at the top of `ApplySelectedAsync` (NOT a button
  binding — the Apply button binds `IsEnabled` to `HasSelection` only, so it
  stays clickable during a search; the guard inside the command is the real
  block). Android: check `_fcOrchestrator.IsBusy` in `OnFreeConfigsUseClicked`.
  (N3 review fix: commit 5bca879's body said "via the IsBusy command guard +
  button binding" — the "+ button binding" half was imprecise; the command-body
  guard alone enforces F1.)
- F3: clamp in the desktop search entry, matching Android's click-handler clamp.
- F4: confirm/add an Android lifecycle hook that calls
  `StopFreeConfigsBackgroundWork()` on app pause/background.
