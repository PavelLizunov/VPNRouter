## Why this exists

The "user toggles autostart in UI → component starts at boot/login" path
has zero behavioural test coverage. It relies on:

1. `VPNRouter.Service/VPNRouterService.cs` — `ExecuteAsync` reads
   `settings.App.AutostartVpn / AutostartZapret / AutostartTgProxy`
   and dispatches one of three `AutostartXxxAsync` methods.
2. Each `AutostartXxxAsync` has a small set of guards (binary
   installed? secret configured?) before handing off to
   `ResilientStarter.StartWithBackoffAsync`.
3. `VPNRouter.Core/Models/AppSettings.cs` — the YAML schema side
   declaring the three flags with stable aliases.
4. `VPNRouter.App/ViewModels/MainWindowViewModel.cs` — the post-DBG-2
   App-side bootstrap that runs when no Service is installed.

This bug class has shipped before (autostart silently doesn't fire)
and went undetected for weeks because none of the above is fenced.
Sister tasks DBG-2 (App-side bootstrap) and DBG-4 (logging) may land
in parallel; we want a regression-test fence that catches if any of
them accidentally drops a guard.

## Strategy

**Source-pin tests** — read the .cs file as text, strip comments,
grep for structural invariants. Cheap to maintain, fail at PR time
when a refactor drops a guard. Same pattern as the existing
`HelperCmdParserGuardTests` introduced in T1 (commit `53e50f4`) for
the auto-update helper.cmd template.

**Behavioural tests** — for the one piece we can isolate cleanly
(`TgProxyUpdater.IsInstalled`), drop a small `IsInstalledAt(baseDir)`
internal overload and exercise the three states. Production
`IsInstalled()` keeps its public surface and just delegates.

The full Service / App boot flow needs SCM, TUN adapter, and a real
sing-box install — that's CI integration territory, not a unit test.
Source-pin closes the gap until/unless we add a richer integration
harness.

## Scope creep

Added one internal overload to `VPNRouter.Core/Services/TgProxyUpdater.cs`:

```csharp
internal static bool IsInstalledAt(string baseDir)
{
    var pythonExe = Path.Combine(baseDir, "python", "python.exe");
    var proxyDir = Path.Combine(baseDir, "proxy");
    return File.Exists(pythonExe) && Directory.Exists(proxyDir);
}
```

`IsInstalled()` is unchanged from a caller's perspective — it now
delegates to `IsInstalledAt(TgProxyDir)`. The overload is `internal`
to make clear that production code should always go through the
parameterless form (which uses the canonical `%ProgramData%` path).
`InternalsVisibleTo` for `VPNRouter.Tests` was already configured
in `VPNRouter.Core.csproj` (line 53), so no project-level changes
were needed.
